발표 방법 안내

이 파트의 학습 목표구현한 API의 설계 의도, 보안 조치, 배포 결과를 설명할 수 있습니다.

발표는 "무엇을 만들었는가"보다 "왜 이렇게 만들었고, 무엇을 막았으며, 그것을 어떻게 확인했는가"를 보여 주는 자리입니다. 시간이 짧으므로 하나를 깊게 보여 줍니다.

발표 순서

부록 D 체크리스트의 순서가 그대로 발표 순서입니다.

순서내용보여 줄 것
1한 문장 소개누가, 무엇을, 왜
2설계자원과 API 목록, 권한 표(명세서 화면)
3시연ALB 주소로 로그인, 핵심 기능, 막히는 장면(시연 스크립트)
4보안 조치 하나위협, 조치한 코드, 그것을 확인하는 테스트
5검증 기록테스트 통과, Actions의 배포 성공 화면
6예상 질문준비한 질문 2개와 답
7회고어려웠던 점, 개선하고 싶은 점

시간 배분

발표 시간은 모두 합쳐 40분입니다. 개인 발표라면 한 사람에 2분 안팎이므로, 3번(시연)과 4번(보안 조치 하나)에 집중하고 나머지는 한 문장씩만 말합니다. 3~4명 모둠으로 발표한다면 모둠 대표가 5~8분 동안 모둠원의 프로젝트 가운데 하나를 깊게 보여 주고, 나머지 프로젝트는 보안 조치 하나씩만 소개합니다. 어느 방식인지는 진행에 따라 정해집니다.

개인 발표 2분 예시시간
한 문장 소개와 권한 표 한 장20초
시연 스크립트 실행(201, 409, 403이 나오는 화면)50초
보안 조치 하나: 코드 세 줄과 테스트 이름30초
예상 질문 하나에 답20초

평가 기준(발표 20%)

기준좋은 발표아쉬운 발표
설계 의도"모임은 공개 자원이라 남의 것은 403으로 답합니다"처럼 선택의 이유를 말함API 목록을 읽기만 함
보안 조치위협, 조치, 확인 테스트가 한 줄로 이어짐"보안을 신경 썼습니다"처럼 근거 없이 말함
시연배포된 주소에서 성공과 실패(막힘)를 모두 보여 줌성공 화면만 보여 주거나 내 PC에서만 시연
