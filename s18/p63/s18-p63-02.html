9일 과정 핵심 정리

9일 동안 배운 것을 하나의 흐름으로 다시 봅니다. 매일 배운 것은 따로 떨어진 주제가 아니라, API 하나를 설계부터 운영까지 끌고 가는 한 줄의 과정이었습니다.

일차배운 것남은 습관
1일차REST와 HTTP, FastAPI 첫 API, Pydantic 검증, 응답 모델과 상태 코드, 오류 응답, 구조화자원은 URI로, 동작은 메서드로, 실패도 같은 모양으로
2일차의존성, 설정 분리, CORS, SQLAlchemy와 CRUD, 관계, Alembic스키마는 마이그레이션으로만 바꾼다
3일차회원가입과 해시, JWT, 권한, 리프레시 토큰, 계층 분리, 파일 업로드, 대여검사는 서비스에 한곳으로
4일차테스트, CI, Docker와 Compose, 로그와 헬스 체크확인은 테스트로, 실행 환경은 이미지로
5일차KISA 보안약점, 입력 검증, 업로드, 인가, 비밀정보, 인증 시도 제한, 오류 처리입력은 믿지 않고, 비밀은 코드에 두지 않는다
6일차경쟁 조건, 자동 점검, 진단과 조치, 클라우드와 IAM, VPC도구 결과는 판정하고, 권한은 최소로
7일차EC2, 서버의 Docker, RDS, Parameter Store, ECR, 운영 배포 구성공개할 것만 공개하고, 비밀은 역할로 읽는다
8일차S3, CloudWatch, ALB, OIDC 배포 자동화, 보안 점검, 장애 대응, 비용배포는 자동으로, 되돌릴 수 있게
