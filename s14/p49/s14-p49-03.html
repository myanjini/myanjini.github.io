도서 API 배포 완성

운영용 Compose로 도서 API를 배포하고, 내 PC에서 회원가입부터 대여, 반납, 토큰 재발급까지 전체 흐름을 확인합니다. 이 결과가 7일차 평가 대상입니다.

실습 목표ECR 이미지, Parameter Store, RDS를 묶은 운영 배포를 완성하고, 인증과 주요 기능이 동작하는지 확인할 수 있습니다.

  1. 운영용 Compose 파일 올리기(내 PC)

    앞 페이지의 compose.prod.yaml을 도서 API 폴더에 만들고 푸시합니다. Compose 파일은 이미지에 들어가지 않으므로 이미지를 다시 만들 필요는 없습니다.

    git add compose.prod.yaml
git commit -m "운영용 Compose 파일"
git push

  2. 서버 준비

    cd ~/book-api
git pull
echo "IMAGE=123456789012.dkr.ecr.ap-northeast-2.amazonaws.com/book-api:1.0.0" > .env
cat .env
IMAGE=123456789012.dkr.ecr.ap-northeast-2.amazonaws.com/book-api:1.0.0
docker compose -f compose.prod.yaml config --images
123456789012.dkr.ecr.ap-northeast-2.amazonaws.com/book-api:1.0.0

    서버의 ~/book-api 폴더는 이제 운영용 Compose 파일과 .env를 두는 곳으로만 씁니다. 다음 날부터는 소스가 바뀌어도 서버에서 빌드하지 않습니다.

  3. 기존 컨테이너 내리고 마이그레이션

    docker rm -f book-api
docker compose -f compose.prod.yaml run --rm api alembic upgrade head
INFO  [alembic.runtime.migration] Context impl PostgresqlImpl.
INFO  [alembic.runtime.migration] Will assume transactional DDL.

    RDS에는 오전에 이미 테이블을 만들었으므로 새로 적용할 리비전이 없어 위 두 줄만 보입니다. 새 리비전이 있는 버전을 배포할 때는 여기서 적용됩니다.

  4. 실행과 상태 확인

    docker compose -f compose.prod.yaml up -d
docker compose -f compose.prod.yaml ps --format "{{.Name}}  {{.Status}}"
book-api-api-1  Up 5 seconds (health: starting)
(30초쯤 뒤)
docker compose -f compose.prod.yaml ps --format "{{.Name}}  {{.Status}}"
book-api-api-1  Up 36 seconds (healthy)

  5. 관리자 지정

    내 PC의 브라우저에서 http://퍼블릭IP:8000/docs가 404인지 먼저 확인합니다. 운영 환경에서는 문서가 꺼져 있으므로, 이제부터는 curl로 확인합니다. 먼저 가입한 계정을 관리자로 지정합니다.

    docker compose -f compose.prod.yaml exec api python -m app.make_admin 내이메일@example.com

  6. 전체 흐름 확인(내 PC)

    내 PC의 터미널에서 실행합니다. Windows는 Git Bash에서 실행하면 같은 명령을 쓸 수 있습니다. API에는 내 서버 주소를 넣습니다.

    API=http://3.35.120.45:8000
curl -s -o /dev/null -w "%{http_code}\n" $API/docs
404
TOKEN=$(curl -s -X POST $API/auth/token -d "username=내이메일@example.com&password=내비밀번호" | python -c "import sys,json; print(json.load(sys.stdin)['access_token'])")
H="Authorization: Bearer $TOKEN"
curl -s -H "$H" $API/auth/me
{"id":1,"email":"내이메일@example.com","role":"admin"}
curl -s -X POST -H "$H" -H "Content-Type: application/json" $API/authors -d '{"name":"김하늘"}'
{"id":1,"name":"김하늘"}
curl -s -X POST -H "$H" -H "Content-Type: application/json" $API/books -d '{"title":"클라우드 입문","author_id":1,"price":15000,"stock":2}'
{"id":1,"title":"클라우드 입문",...,"stock":2,...}
curl -s -X POST -H "$H" -H "Content-Type: application/json" $API/loans -d '{"book_id":1}'
{"id":1,"user_id":1,"book":{"id":1,"title":"클라우드 입문",...},"loaned_at":"...","returned_at":null}
curl -s -X POST -H "$H" $API/loans/1/return
{"id":1,"user_id":1,"book":{...},"loaned_at":"...","returned_at":"2026-11-23T06:41:02..."}
curl -s -o /dev/null -w "%{http_code}\n" $API/auth/me
401

    응답의 세부 필드는 내 데이터에 따라 다릅니다. 마지막 줄처럼 토큰 없이 요청하면 401이어야 합니다. 리프레시 토큰으로 새 액세스 토큰을 받는 것(/auth/refresh)과 로그아웃(/auth/logout)도 확인합니다.

  7. 재부팅해도 다시 뜨는지 확인

    sudo reboot
(1~2분 뒤 Session Manager로 다시 접속)
bash; cd ~/book-api
docker compose -f compose.prod.yaml ps --format "{{.Name}}  {{.Status}}"
book-api-api-1  Up 40 seconds (healthy)

    Docker가 부팅할 때 자동으로 시작되고(systemctl enable), 컨테이너는 재시작 정책으로 다시 떴습니다. 재부팅해도 퍼블릭 IP는 바뀌지 않습니다(중지 후 시작과 다릅니다).
