배포 결과 자기 점검

배포가 "동작한다"와 "안전하게 배포되었다"는 다릅니다. 아래 질문에 직접 명령을 실행해 답해 보고, 예시 답안과 비교합니다.

실습 목표점검 질문으로 배포 상태를 확인하고, 문제가 있으면 바로 고칠 수 있습니다.

질문 1. 비밀 값이 코드, 이미지, 서버 파일, 컨테이너 설정 어디에도 남아 있지 않은가요? 어떻게 확인하나요?

예시 답안 보기

네 곳을 봅니다.

Windows에서 실행할 때

아래 명령에는 bash 문법(이름=값, $(...) 등)이 들어 있습니다. 내 PC가 Windows라면 명령 프롬프트가 아니라 Git Bash에서 실행합니다(S12-P40-03). EC2 서버의 접속 화면에서 실행하는 명령은 그대로 입력합니다.

# 코드(내 PC): 저장소 전체 기록에서 찾기
git log -p | grep -c -i -E "secret_key=.{20,}|postgresql\+psycopg://bookapi:[^$]"
0
# 이미지(서버): 빌드 기록과 환경 변수
docker history --no-trunc IMAGE주소 | grep -c -i secret
0
# 서버 파일
cat ~/book-api/.env
IMAGE=...
# 컨테이너 설정
docker inspect book-api-api-1 --format "{{json .Config.Env}}"

모두 비밀 값이 없어야 합니다. git log -p에서 나온다면 과거 커밋에 남은 것이므로, 그 값은 이미 새었다고 보고 교체합니다(S14-P47-04).

질문 2. 인터넷에서 이 서버에 닿을 수 있는 포트는 무엇인가요? 누구에게 열려 있나요?

예시 답안 보기

book-api-sg의 인바운드 규칙에 있는 TCP 8000, 내 IP/32 하나뿐이어야 합니다. 22번은 없습니다. 휴대폰의 모바일 데이터로 접속해 막히는지 확인합니다.

질문 3. RDS에 인터넷이나 다른 자원에서 닿을 수 있나요?

예시 답안 보기

아니요. 프라이빗 서브넷, 퍼블릭 액세스 꺼짐, 보안 그룹은 book-api-sg에서 오는 5432만 허용합니다. aws rds describe-db-instances의 PubliclyAccessible이 False인지 다시 봅니다.

질문 4. API 문서와 오류 응답이 내부 정보를 보여 주지 않나요?

예시 답안 보기

/docs, /redoc, /openapi.json이 404이고, 잘못된 요청의 422 응답에 입력 값이 되돌아오지 않으며, 500 응답에는 오류 코드와 요청 ID만 있어야 합니다(S10-P35). 응답 헤더에 server: uvicorn이 없는지도 봅니다(curl -I).

질문 5. 지금 서버에서 도는 코드가 정확히 어느 커밋인지 말할 수 있나요?

예시 답안 보기

.env의 이미지 태그(1.0.0)와 ECR에서 같은 digest를 가리키는 커밋 태그(git-4f2c9a1)로 알 수 있습니다. latest를 썼다면 답하기 어렵습니다.

질문 6. 서버가 재부팅되거나 컨테이너가 죽으면 누가 다시 살리나요? 앱이 응답하지 않는 상태는 어떻게 알아채나요?

예시 답안 보기

Docker 서비스의 자동 시작과 컨테이너 재시작 정책이 다시 살립니다. 응답하지 않는 상태는 healthcheck가 unhealthy로 표시하지만, 지금은 아무도 그 표시를 보지 않습니다. 8일차에 CloudWatch 경보와 ALB의 상태 검사로 알림을 받게 합니다.

질문 7. 로그는 어디에 있고, 로그에 비밀 값이나 개인정보가 찍히지 않나요?

예시 답안 보기

docker compose -f compose.prod.yaml logs api로 볼 수 있고, Docker가 서버 디스크에 최대 30MB까지 보관합니다. S10에서 만든 마스킹 덕분에 이메일과 토큰이 가려져야 합니다. 서버가 사라지면 로그도 사라지므로 8일차에 CloudWatch Logs로 보냅니다.

질문 8. 업로드한 표지 이미지는 어디에 저장되나요? 이 서버를 지우면 어떻게 되나요?

예시 답안 보기

서버의 Docker 볼륨(uploads)에 있으므로 서버를 지우면 함께 사라집니다. 서버를 두 대로 늘리면 서로 다른 파일을 갖게 됩니다. 8일차에 S3로 옮깁니다.
