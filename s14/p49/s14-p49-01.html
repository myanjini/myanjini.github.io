운영 배포 구성 점검

이 파트의 학습 목표EC2, RDS, ECR, Parameter Store를 연결해 도서 API의 운영 배포를 완성할 수 있습니다.

7일차의 마지막 파트입니다. 지금까지 만든 것을 배포 구성도에 겹쳐 보고, 운영 배포라고 부르려면 무엇이 더 갖춰져야 하는지 점검합니다.

오늘 만든 것은 구성도의 VPC, EC2, RDS, ECR, Parameter Store, IAM 역할입니다. ALB, S3, CloudWatch, GitHub Actions 배포는 8일차에 더합니다.

운영 설정 항목

항목지금운영 배포에서
이미지docker run으로 ECR 이미지 실행운영용 Compose 파일에 이미지 태그를 적어 실행
비밀 값Parameter Store그대로
실행 환경APP_ENV=developmentproduction: /docs, /redoc, /openapi.json을 끔(S10-P35)
재시작--restart unless-stoppedCompose 파일에 적어 누가 실행해도 같게
상태 확인직접 curlCompose의 healthcheck로 Docker가 주기적으로 확인
로그Docker 기본(크기 제한 없음)파일 크기와 개수 제한(8GiB 디스크가 차지 않게)
마이그레이션일회용 컨테이너로 실행배포 순서에 넣음: 이미지 받기, 마이그레이션, 교체
DB 연결RDS, SSL(sslmode=require)그대로
접근보안 그룹: 내 IP의 8000만그대로(8일차에 ALB로 바꿈)
관리자 계정없음make_admin으로 한 명 지정

운영 설정의 기준은 "서버에 접속한 사람이 기억에 의존하지 않고, 파일 하나로 같은 상태를 다시 만들 수 있는가"입니다. 명령을 길게 외워 치는 대신 설정을 파일로 남기면, 다른 사람이 이어받거나 서버를 새로 만들 때도 같은 결과가 나옵니다.
