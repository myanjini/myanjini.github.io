정리: 비밀정보 관리

핵심 요약

주제핵심
보관소비밀 값은 서버 파일이 아니라 Parameter Store의 SecureString(KMS 암호화)에 둡니다.
권한EC2 역할은 /book-api/*만 읽을 수 있고, 읽은 기록은 CloudTrail에 남습니다.
앱SSM_PREFIX가 있으면 시작할 때 값을 읽어 환경 변수로 넣고, 기존 설정 검증을 그대로 거칩니다.
등록비밀 값은 명령 기록에 남지 않게 콘솔에서 입력합니다.
교체새 값 등록, 앱 재시작, 확인 순서. DB 암호는 RDS와 Parameter Store를 함께 바꿉니다.

확인 퀴즈

Parameter Store에 DB 접속 주소를 String(평문) 유형으로 저장하면 무엇이 문제인가요?

비밀이 섞인 값은 SecureString으로 저장합니다.

컨테이너 로그에 NoCredentialsError가 나고 바로 멈춥니다. 가장 먼저 확인할 것은 무엇인가요?

컨테이너가 역할의 임시 자격 증명을 받지 못한 경우입니다.

비밀 값을 aws ssm put-parameter --value로 등록하지 않고 콘솔에서 입력한 이유는 무엇인가요?

명령 기록 파일도 비밀 값이 새는 흔한 경로입니다.
