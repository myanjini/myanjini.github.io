검색 API 보안 조치

재고 보고서 API를 위험한 코드로 먼저 만들어 SQL 삽입을 직접 재현하고, 안전한 코드로 고친 뒤 회귀 테스트를 남깁니다.

실습 목표문자열로 조립한 SQL의 삽입 공격을 재현하고, 값 바인딩과 허용 목록으로 고칠 수 있습니다.

실습용 취약 코드입니다

이 페이지의 "위험한 코드"는 공격을 직접 확인하려고 일부러 만든 것입니다. 내 PC에서만 실행하고, 확인이 끝나면 바로 안전한 코드로 바꿉니다. Git에 올리거나 서버에 배포하지 않습니다. 공격 실습은 내가 만든 서비스에서만 합니다. 허락받지 않은 남의 서비스에 시도하면 법에 따라 처벌받습니다.

  1. 스키마와 위험한 보고서 API 만들기

    app/schemas.py 맨 아래에 응답 모델을 추가하고, 앞 페이지의 위험한 저장소 코드와 아래 라우터를 만듭니다.

    app/schemas.py
    class StockReportRow(BaseModel):
    """재고 보고서의 한 줄"""
    title: str
    author: str
    stock: int
    app/routers/reports.py
    from fastapi import APIRouter

from app.dependencies import CurrentUserDep, SessionDep
from app.repositories import reports as report_repo
from app.schemas import StockReportRow

router = APIRouter(prefix="/reports", tags=["보고서"])


@router.get("/stock", response_model=list[StockReportRow], summary="재고 현황 보고서")
def stock_report(db: SessionDep, user: CurrentUserDep, keyword: str = "", order_by: str = "stock"):
    return report_repo.stock_report(db, keyword, order_by)

    app/main.py에서 reports를 가져와 app.include_router(reports.router)를 추가합니다. 개발용 SQLite로 서버를 실행합니다(uvicorn app.main:app --reload).

  2. 정상 사용 확인

    Swagger UI에서 user1으로 로그인하고 GET /reports/stock을 호출합니다. keyword를 비우면 모든 도서가, 파이썬을 넣으면 제목에 파이썬이 든 도서만 나옵니다.

  3. SQL 삽입 재현

    keyword에 앞 페이지의 공격 값을 그대로 넣고 실행합니다.

    zz%' UNION SELECT email, hashed_password, 0 FROM users --
    확인기대하는 결과내 결과
    응답 상태200
    응답 내용title에 사용자 이메일, author에 $argon2id$로 시작하는 해시
    order_by에 stock; DROP TABLE books500. 서버 로그에 You can only execute one statement at a time.

    일반 사용자 한 명이 모든 사용자의 계정 정보를 가져갔습니다. 서버 터미널의 ERROR 로그에서 실행된 SQL 문장을 찾아 공격 값이 어떻게 섞였는지도 확인합니다.

  4. 안전한 코드로 고치기

    저장소는 앞 페이지의 안전한 코드로 바꿉니다. 라우터에서도 입력을 좁혀, 저장소까지 가기 전에 한 번 더 막습니다.

    app/routers/reports.py
    from typing import Literal

from fastapi import APIRouter, Query

from app.dependencies import CurrentUserDep, SessionDep
from app.repositories import reports as report_repo
from app.schemas import StockReportRow

router = APIRouter(prefix="/reports", tags=["보고서"])


@router.get("/stock", response_model=list[StockReportRow], summary="재고 현황 보고서")
def stock_report(
    db: SessionDep,
    user: CurrentUserDep,
    keyword: str = Query(default="", max_length=100, description="제목에 들어간 글자"),
    order_by: Literal["title", "stock"] = Query(default="stock", description="정렬 기준"),
):
    return report_repo.stock_report(db, keyword, order_by)

    값 바인딩(저장소)과 허용 목록(라우터와 저장소 모두)을 겹쳐 쓰는 것을 다중 방어라고 합니다. 한쪽을 누가 실수로 지워도 다른 쪽이 막아 줍니다.

  5. 같은 공격 다시 하기

    요청기대하는 결과내 결과
    keyword에 공격 값200, []. 그런 제목의 도서가 없을 뿐입니다.
    keyword에 파이썬정상 결과
    order_by에 stock; DROP TABLE books422, Input should be 'title' or 'stock'

  6. 회귀 테스트 남기기

    tests/test_attacks.py를 새로 만듭니다. 이 파일에 오늘 고친 약점을 하나씩 테스트로 쌓아 갑니다. 4일차에 만든 CI가 있으므로, 나중에 누가 보고서 코드를 다시 문자열 조립으로 바꾸면 푸시하는 순간 실패로 알려 줍니다.

    tests/test_attacks.py
    """보안약점을 고친 뒤 다시 생기지 않는지 확인하는 테스트"""
import pytest

from tests.helpers import create_book

SQLI = "zz%' UNION SELECT email, hashed_password, 0 FROM users --"


def test_report_sql_injection_does_not_leak_users(client, auth_headers, author_id):
    create_book(client, auth_headers, author_id, title="파이썬 첫걸음", stock=3)
    response = client.get("/reports/stock", params={"keyword": SQLI}, headers=auth_headers)
    assert response.status_code == 200
    assert response.json() == []  # 그런 제목의 도서가 없을 뿐, 사용자 정보는 나오지 않습니다.


def test_report_rejects_unknown_order_by(client, auth_headers):
    response = client.get("/reports/stock", params={"order_by": "stock; DROP TABLE books"}, headers=auth_headers)
    assert response.status_code == 422
    pytest tests/test_attacks.py
