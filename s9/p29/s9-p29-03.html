KISA 가이드의 보안약점 분류

KISA 가이드가 보안약점을 어떻게 나누는지 보고, 웹 API에 초점을 맞춘 국제 기준인 OWASP API Security Top 10과 비교합니다.

설계 단계와 구현 단계

2021년판 소프트웨어 개발보안 가이드는 설계 단계에서 갖춰야 할 보안 요구항목 20개와, 구현 단계에서 없애야 할 보안약점 49개를 제시합니다. 설계 단계 항목은 입력데이터 검증 및 표현, 보안기능, 에러처리, 세션통제의 4개 유형으로, 구현 단계 보안약점은 다음 7개 유형으로 나뉩니다.

구현 단계 유형개수대표 보안약점이 과정
입력데이터 검증 및 표현17SQL 삽입, 경로 조작 및 자원 삽입, 크로스사이트 스크립트, 운영체제 명령어 삽입, 위험한 형식 파일 업로드, 서버사이드 요청 위조S9-P30, S9-P31

가이드의 판과 언어별 가이드

보안약점의 이름과 개수는 가이드의 판마다 조금씩 바뀝니다. 실제 업무에서는 KISA 누리집에서 최신판을 받아 확인합니다. KISA는 언어별 예제를 담은 시큐어코딩 가이드도 내고 있으며, Python 시큐어코딩 가이드는 2023년 개정본이 최신입니다. 오늘 실습의 안전한 코드 패턴은 이 가이드의 Python 예제와 같은 원칙을 따릅니다.

OWASP API Security Top 10

OWASP는 웹 보안 지식을 공개하는 국제 비영리 단체입니다. API에서 자주 일어나는 위험 10가지를 정리한 목록을 2019년에 처음 냈고, 2023년에 개정했습니다. KISA 가이드가 "어떤 코드가 약점인가"를 중심으로 나눈다면, OWASP 목록은 "API에서 실제로 무엇이 자주 뚫리는가"를 중심으로 순위를 매깁니다.

OWASP API 2023뜻KISA 유형과 이 과정
API1 객체 수준 인가 취약(BOLA)번호만 바꿔 남의 데이터에 접근보안기능(부적절한 인가), S9-P32
API2 인증 취약약한 로그인, 토큰 검증 실수보안기능, S5, S10-P34
API3 객체 속성 수준 인가 취약(BOPLA)응답에 필요 이상의 필드 노출, 보내면 안 되는 필드 수정보안기능, 캡슐화, S9-P32-04

OWASP API 2023 목록에는 SQL 삽입 같은 삽입 공격이 따로 없습니다. 덜 중요해서가 아니라 일반 웹 보안 목록에서 이미 다루기 때문입니다. 두 기준을 함께 보면, KISA 가이드로 빠짐없이 점검하고 OWASP 목록으로 API에서 특히 조심할 곳을 알 수 있습니다.
