인증 모듈 적용

이 파트의 학습 목표프로젝트에 인증과 객체 수준 권한 검사를 적용할 수 있습니다.

인증은 템플릿에 이미 들어 있습니다. 그래도 "들어 있다"와 "내 프로젝트에서 동작한다"는 다릅니다. 이번 페이지에서는 인증의 각 부분이 무엇을 하는지 다시 확인하고, 내 프로젝트에서 실제로 동작하는지 시험합니다.

실습 목표재사용한 인증 코드의 구성을 설명하고, 회원가입, 로그인, 토큰 검사, 로그인 실패 제한이 동작하는지 확인할 수 있습니다.

  1. 명령으로 흐름 확인

    Windows에서 실행할 때

    아래 명령에는 bash 문법(이름=값, $(...) 등)이 들어 있습니다. 내 PC가 Windows라면 명령 프롬프트가 아니라 Git Bash에서 실행합니다(S12-P40-03). EC2 서버의 접속 화면에서 실행하는 명령은 그대로 입력합니다.

    B=http://localhost:8000
curl -s -X POST $B/auth/signup -H "Content-Type: application/json" -d '{"email":"user1@example.com","password":"practice-pass-1"}'
{"id":1,"email":"user1@example.com","role":"user"}

TOKEN=$(curl -s -X POST $B/auth/token -d "username=user1@example.com&password=practice-pass-1" | python -c "import sys,json;print(json.load(sys.stdin)['access_token'])")
curl -s $B/auth/me -H "Authorization: Bearer $TOKEN"
{"id":1,"email":"user1@example.com","role":"user"}

curl -s -X POST $B/studies -H "Content-Type: application/json" -d '{"title":"x","capacity":3}'
{"code":"NOT_AUTHENTICATED","message":"로그인이 필요합니다."}

  2. 실패 제한 확인

    for i in 1 2 3 4 5 6; do curl -s -o /dev/null -w "%{http_code} " -X POST $B/auth/token -d "username=user1@example.com&password=wrong-pass"; done; echo
401 401 401 401 401 429

    여섯 번째는 비밀번호를 확인하기 전에 429로 막힙니다. 시험이 끝나면 15분을 기다리거나, 개발용 SQLite 파일이라면 login_failures 기록을 지우고 계속합니다.

  3. 관리자 계정 만들기

    curl -s -X POST $B/auth/signup -H "Content-Type: application/json" -d '{"email":"admin@example.com","password":"practice-pass-9"}' > /dev/null
python -m app.make_admin admin@example.com
admin@example.com 사용자를 관리자로 바꿨습니다.

    관리자 기능이 명세에 없다면 이 단계는 건너뜁니다. 관리자로 가입하는 API를 따로 만들지 않는 이유는, 누구나 관리자가 될 수 있는 길을 만들지 않기 위해서입니다.
