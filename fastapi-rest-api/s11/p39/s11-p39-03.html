보안 테스트 작성

보안 테스트는 "공격을 다시 해 보고, 막히는지 확인"하는 테스트입니다. 강사가 준 테스트가 공격을 어떻게 재현하는지 살펴본 뒤, 비어 있는 부분을 채우는 테스트를 직접 씁니다.

실습 목표공격 입력을 재현하는 보안 테스트를 작성해, 같은 약점이 다시 생기지 않게 할 수 있습니다.

보안 테스트의 모양

보안 테스트도 S7에서 배운 테스트와 같습니다. 공격 입력으로 요청하고(준비와 실행), "막혔는지"와 "피해가 없는지"를 함께 확인합니다(검증). 상태 코드만 보면 부족합니다. 403이 나와도 공지가 이미 지워졌을 수 있기 때문입니다.

tests/test_security.py
def test_07_cannot_delete_others_notice(client, login, notice):
    headers = login("bob")
    res = client.delete(f"/notices/{notice}", headers=headers)
    assert res.status_code == 404
    assert client.get(f"/notices/{notice}").status_code == 200  # 공지가 그대로 남아 있어야 합니다.

재현하기 어려운 공격을 테스트하는 방법

어려움테스트에서 쓴 방법테스트
외부 서버에 요청하는 기능monkeypatch로 requests.get을 가짜 함수로 바꿔 실제로 요청하지 않고, 불렸는지만 기록합니다.test_05, test_15
끝나지 않는 반복가짜 함수가 21번째 호출에서 예외를 내 테스트가 멈추게 하고, 호출 횟수가 3 이하인지 봅니다.test_15
동시 요청threading.Barrier로 스레드들이 모두 준비될 때까지 기다렸다가 한꺼번에 출발시킵니다.test_14, test_22
코드 실행 공격해가 없는 함수(os.mkdir)를 실행하게 하는 데이터를 보내고, 폴더가 생겼는지 확인합니다.test_20, test_24
예측 가능한 난수같은 시드로 같은 수가 나오는 성질을 이용해, 저장된 값이 예측한 값과 다른지 봅니다.test_12
테스트끼리 섞이지 않게tmp_path와 monkeypatch.chdir로 테스트마다 빈 폴더에서 앱을 새로 불러옵니다.conftest.py

가짜로 바꾸지 않으면 멈출 수 있습니다

링크 미리 보기를 테스트할 때 requests.get을 가짜로 바꾸지 않으면, 조치 전 코드에서는 연결이 실패할 때마다 다시 시도하느라 테스트가 영원히 끝나지 않습니다. 외부 요청이 있는 기능의 테스트는 항상 가짜로 바꿔 씁니다.

def test_04_upload_size_limited(client, login):
    headers = login("alice")
    big = b"a" * (2 * 1024 * 1024 + 1)  # 2MB보다 1바이트 큰 파일
    res = client.post("/files", files={"file": ("big.txt", big)}, headers=headers)
    assert res.status_code == 413


def test_05_preview_rejects_plain_http(client, login, monkeypatch):
    called = []
    monkeypatch.setattr(requests, "get", lambda url, **kw: called.append(url))
    headers = login("alice")
    res = client.get("/link-preview", params={"url": "http://example.com/"}, headers=headers)
    assert res.status_code == 400
    assert called == []
