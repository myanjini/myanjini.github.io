보안약점 진단 1

먼저 지금까지 가장 많이 다룬 두 유형, 입력데이터 검증 및 표현과 보안기능부터 진단합니다. 아래 질문은 어디를 봐야 하는지 알려 주는 길잡이입니다. 답을 알려 주지는 않으므로, 질문에 해당하는 코드를 찾아 직접 판단합니다.

실습 목표입력이 들어오는 곳과 보안 결정을 내리는 곳을 찾아, 약점과 그 근거를 진단표에 적을 수 있습니다.

서버 띄우기

cd security-lab
uvicorn app:app --reload

브라우저에서 http://127.0.0.1:8000/docs를 열고, 회원가입과 로그인을 해 둡니다. 로그인 응답의 access_token을 복사해 두면 다른 요청의 Authorization 헤더에 Bearer 토큰 형식으로 넣을 수 있습니다. 시험용 공지도 두세 개 만들어 둡니다.

입력데이터 검증 및 표현

요령은 "사용자가 보낸 값이 어디까지 흘러가는가"를 따라가는 것입니다. 경로 매개변수, 쿼리 매개변수, 요청 본문, 헤더, 업로드한 파일의 이름과 내용이 모두 사용자가 보낸 값입니다.

확인해 볼 요청 예시

아래 요청은 약점이 있는지 확인하는 데 쓸 수 있는 입력입니다. 결과를 보고 무슨 일이 일어났는지 직접 해석합니다.

GET /notices?q=%' UNION SELECT id, username, password_hash FROM users --
GET /notices?sort=likes DESC
GET /files/%2e%2e%2fboard.db
POST /admin/notices/1/pin   (헤더 X-Role: admin)

/files/../board.db처럼 쓰면 브라우저와 HTTP 클라이언트가 ..를 먼저 정리해 버립니다. 그래서 .과 /를 %2e, %2f로 바꿔 보냅니다.
