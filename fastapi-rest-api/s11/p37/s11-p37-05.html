핵심 요약

주제핵심
위험한 함수eval, pickle.loads, yaml.load, shell=True는 밖에서 온 데이터를 코드처럼 실행할 수 있습니다. JSON, safe_load, 인자 목록을 씁니다.
bandit(정적 분석)내 코드에서 위험한 모양을 찾습니다. 심각도와 신뢰도를 보고 판정합니다.
pip-audit(의존성 점검)설치한 패키지 버전을 취약점 데이터베이스와 대조합니다. 결과는 날마다 바뀝니다.
판정오탐은 근거를 확인한 뒤 규칙 번호를 적은 nosec과 주석으로 남기고, 애매하면 고칩니다.
CI푸시할 때마다 점검하고, 결과가 있으면 빌드를 실패시킵니다.
한계인가 누락, 경쟁 조건, 업무 규칙 오류는 도구가 찾지 못합니다. 사람의 진단이 꼭 필요합니다.

확인 퀴즈

외부에서 받은 YAML 설정 파일을 읽을 때 알맞은 코드는 무엇인가요?

safe_load는 기본 자료형만 만들고, Python 객체를 만드는 태그는 거부합니다.

bandit 결과에서 Confidence가 Low라는 것은 무엇을 뜻하나요?

피해의 크기는 Severity(심각도)입니다. 신뢰도가 낮을수록 사람이 더 꼼꼼히 따져 판정합니다.

지난주에 통과하던 pip-audit 단계가 코드를 고치지 않았는데 오늘 실패했습니다. 알맞은 대응은 무엇인가요?

쓰던 패키지에 새 취약점이 공개된 것입니다. 도구가 제 역할을 한 것이므로 버전을 올려 대응합니다.
