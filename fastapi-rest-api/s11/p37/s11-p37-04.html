CI에 보안 점검 추가

점검은 사람이 기억해서 할 때보다 매번 자동으로 할 때 효과가 큽니다. S7에서 만든 GitHub Actions 워크플로에 두 도구를 추가해, 푸시할 때마다 테스트와 함께 보안 점검이 돌게 합니다.

실습 목표CI에 보안 점검 단계를 추가하고, 점검이 실패하면 빌드가 실패하는 것을 확인할 수 있습니다.

  1. 워크플로에 단계 추가

    .github/workflows/test.yml의 테스트 실행 단계 아래에 세 단계를 덧붙입니다.

    .github/workflows/test.yml(덧붙이는 부분)
          - name: 보안 점검 도구 설치
        run: pip install bandit pip-audit

      - name: 보안 점검(코드, bandit)
        run: bandit -r app -ll

      - name: 보안 점검(패키지, pip-audit)
        run: pip-audit -r requirements.txt
    단계실패하는 경우
    보안 점검 도구 설치설치가 안 될 때
    bandit심각도 Medium 이상인 결과가 하나라도 있을 때(-ll)
    pip-audit알려진 취약점이 있는 패키지가 하나라도 있을 때

    점검 도구는 requirements.txt에 넣지 않았으므로 따로 설치 단계를 둡니다. 전체 파일은 다음과 같습니다.

    전체 워크플로 보기
    .github/workflows/test.yml
    name: test

# 언제 실행할까요: main 브랜치에 푸시할 때와, main으로 가는 풀 리퀘스트를 만들 때
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest  # GitHub가 빌려주는 리눅스 서버에서 실행합니다.
    steps:
      - name: 코드 내려받기
        uses: actions/checkout@v7

      - name: Python 설치
        uses: actions/setup-python@v7
        with:
          python-version: "3.12"
          cache: pip  # 내려받은 패키지를 저장해 두었다가 다음 실행에서 다시 씁니다.

      - name: 패키지 설치
        run: pip install -r requirements.txt

      - name: 테스트 실행
        run: pytest --cov=app --cov-report=term-missing

      - name: 보안 점검 도구 설치
        run: pip install bandit pip-audit

      - name: 보안 점검(코드, bandit)
        run: bandit -r app -ll

      - name: 보안 점검(패키지, pip-audit)
        run: pip-audit -r requirements.txt

  2. 푸시하고 결과 확인

    git add .
git commit -m "경쟁 조건 조치와 보안 점검 추가"
git push

    GitHub 저장소의 Actions 탭에서 새 실행을 열고, 보안 점검 두 단계가 초록색으로 끝났는지 확인합니다.

  3. 실패하는 것도 확인

    점검이 정말 빌드를 막는지 일부러 확인해 봅니다. 새 브랜치를 만들고 아무 서비스 파일에나 아래 두 줄을 넣어 푸시합니다. 풀 리퀘스트를 만들면 bandit 단계가 빨간색으로 실패하고, 로그에 B307(eval 사용)이 보입니다. 확인했으면 브랜치를 지웁니다.

    일부러 넣는 위험한 코드(확인 후 지웁니다)
    def debug_eval(expr: str):
    return eval(expr)

새 취약점 때문에 갑자기 실패할 때

코드를 고치지 않았는데 어느 날 pip-audit 단계가 실패할 수 있습니다. 쓰고 있던 패키지에 새 취약점이 공개된 것입니다. 이것은 도구가 제 역할을 한 것이므로 단계를 끄지 말고, 앞 페이지의 순서대로 버전을 올립니다. GitHub의 Dependabot을 켜 두면 취약한 패키지를 올리는 풀 리퀘스트를 자동으로 만들어 줍니다.
