역직렬화가 왜 코드 실행이 되나요

직렬화는 객체를 저장하거나 보내려고 바이트로 바꾸는 것이고, 역직렬화는 그 바이트를 다시 객체로 되살리는 것입니다. pickle은 객체를 되살리는 방법까지 데이터 안에 적어 둘 수 있습니다. 공격자가 그 방법 자리에 "os.system을 불러라"를 적어 보내면, 서버는 데이터를 읽는 순간 그 명령을 실행합니다. 아래는 해가 없는 함수(print)로 확인해 보는 예입니다.

pickle_demo.py
import pickle

class Payload:
    def __reduce__(self):                 # "나를 되살릴 때 이 함수를 이 인자로 불러라"
        return (print, ("pickle.loads가 이 줄을 실행했습니다.",))

data = pickle.dumps(Payload())            # 공격자가 만든 데이터
pickle.loads(data)                        # 서버가 읽는 순간 print가 실행됩니다.
python pickle_demo.py
pickle.loads가 이 줄을 실행했습니다.

yaml도 같습니다. yaml.load(text, Loader=yaml.Loader)는 !!python/object/apply:os.system ["명령"] 같은 태그를 만나면 그 함수를 실행합니다. yaml.safe_load는 문자열, 숫자, 목록, 딕셔너리 같은 기본 자료형만 만들고, 이런 태그를 만나면 오류를 냅니다. 원칙은 간단합니다. 밖에서 온 데이터는 "값만 읽는" 형식(JSON, safe_load)으로 읽습니다.

자동 점검 도구의 두 종류

정적 분석(SAST)의존성 점검(SCA)
무엇을 보나요내가 쓴 소스 코드설치한 외부 패키지와 버전
어떻게 찾나요코드를 실행하지 않고 위험한 모양(함수 이름, 인자)을 찾습니다.패키지 이름과 버전을 공개된 취약점 데이터베이스와 대조합니다.
이 과정의 도구banditpip-audit
잘 찾는 것eval, pickle, shell=True, md5, 하드코드된 비밀번호 문자열, 문자열로 만든 SQL알려진 취약점(CVE)이 있는 버전
못 찾는 것인가 누락, 경쟁 조건, 업무 규칙 오류, 응답에 섞인 중요정보아직 알려지지 않은 취약점, 내 코드의 약점

SAST는 Static Application Security Testing, SCA는 Software Composition Analysis의 줄임말입니다. 두 도구 모두 "모양"을 보고 판단하므로 위험하지 않은 코드를 위험하다고 하는 오탐(거짓 양성)과, 위험한 코드를 놓치는 미탐(거짓 음성)이 반드시 있습니다. S9에서 고친 남의 대여 기록 조회(BOLA)는 코드 모양이 평범해서 어떤 도구도 찾지 못합니다. 자동 점검은 사람의 진단을 대신하지 못하고, 사람이 놓치기 쉬운 것을 빠짐없이 훑어 주는 보조 수단입니다.

다음 가운데 bandit 같은 정적 분석 도구가 찾기 가장 어려운 것은 무엇인가요?

인가 누락은 "있어야 할 검사가 없는" 문제라 코드 모양으로는 드러나지 않습니다. 사람이 업무 규칙을 알고 봐야 찾습니다.
