상태 코드 선택하기

요청이 성공했는지, 실패했다면 왜 실패했는지를 상태 코드로 정확히 알려 주면 API를 쓰는 쪽이 훨씬 편해집니다. 이 과정에서 쓰는 상태 코드의 기준을 정리합니다.

상태 코드언제 쓰나요이 과정의 예
200 OK조회, 수정이 성공했을 때GET /books, PATCH /books/1
201 Created새 자원을 만들었을 때POST /books
204 No Content성공했지만 돌려줄 내용이 없을 때DELETE /books/1
404 Not Found요청한 자원이 없을 때없는 번호의 도서 조회
409 Conflict지금 상태와 충돌해 처리할 수 없을 때이미 등록된 ISBN으로 등록
422 Unprocessable Content요청 데이터가 규칙에 맞지 않을 때가격에 음수 입력(FastAPI가 자동으로 보냄)

FastAPI는 따로 정하지 않으면 성공 응답을 모두 200으로 보냅니다. 201과 204는 우리가 직접 정해야 합니다.

from fastapi import status

@app.post("/books", status_code=status.HTTP_201_CREATED)
...

@app.delete("/books/{book_id}", status_code=status.HTTP_204_NO_CONTENT)
...

status_code=201처럼 숫자를 바로 써도 동작합니다. 하지만 status.HTTP_201_CREATED처럼 이름을 쓰면 코드를 읽는 사람이 뜻을 바로 알 수 있고 오타도 줄어듭니다.

404와 409를 헷갈리지 않으려면

찾는 대상이 아예 없으면 404, 대상은 있지만 지금 상태 때문에 요청을 들어줄 수 없으면 409입니다. 이미 대여 중인 도서를 또 대여하려는 경우도 409입니다(3일차 통합 실습).
