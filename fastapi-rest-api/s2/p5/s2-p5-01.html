응답 모델과 데이터 계약

이 파트의 학습 목표입력 모델과 출력 모델을 분리하고 상황에 맞는 상태 코드를 반환할 수 있습니다.

지금까지는 목록에 들어 있는 딕셔너리를 그대로 돌려주었습니다. 편하지만, 밖으로 나가면 안 되는 값까지 함께 나갈 수 있습니다. 응답의 모양을 미리 정해 두는 방법을 배웁니다.

내부 값이 새어 나가는 문제

서점에서 도서마다 매입가(cost)를 관리한다고 해 봅시다. 매입가는 내부에서만 쓰는 값이라 손님이 보면 안 됩니다. 그런데 목록에 매입가를 추가하고 지금처럼 딕셔너리를 그대로 돌려주면, 응답에도 매입가가 그대로 나갑니다.

{
  "id": 1,
  "title": "파이썬 첫걸음",
  "author": "김하늘",
  "price": 18000,
  "isbn": "9791100000011",
  "cost": 12000
}

코드를 고칠 때마다 "이 값이 응답에 나가도 되나?"를 사람이 일일이 확인하기는 어렵습니다. 그래서 응답에 들어갈 항목을 모델로 정해 두고, 그 밖의 값은 자동으로 빠지게 만듭니다.

데이터 계약

API를 쓰는 쪽과 만드는 쪽이 "이 요청에는 이런 모양의 응답이 온다"고 약속하는 것을 데이터 계약이라고 합니다. 응답 모양이 정해져 있으면 화면을 만드는 개발자는 문서만 보고 작업할 수 있고, 서버 코드가 바뀌어도 약속한 모양은 지켜집니다.

입력 모델과 출력 모델을 나눕니다

같은 도서라도 받을 때와 돌려줄 때 필요한 항목이 다릅니다. 새 도서를 등록할 때 클라이언트는 번호(id)를 보내지 않습니다. 번호는 서버가 정하기 때문입니다. 반대로 돌려줄 때는 번호가 꼭 있어야 합니다. 그래서 용도별로 모델을 따로 만듭니다.

모델용도특징
BookCreate등록(POST), 전체 수정(PUT) 요청id가 없습니다. 클라이언트가 보내는 값만 있습니다.
BookUpdate일부 수정(PATCH) 요청모든 항목이 선택입니다. 바꿀 항목만 보냅니다.
BookRead응답id가 있고, cost처럼 감출 값은 없습니다.

response_model이 하는 일

class BookRead(BaseModel):
    id: int
    title: str
    author: str
    price: int
    isbn: str | None = None


@app.get("/books/{book_id}", response_model=BookRead)
def get_book(book_id: int):
    return find_book(book_id)    # cost가 들어 있는 딕셔너리를 돌려줘도

경로 데코레이터에 response_model=BookRead를 적으면, 함수가 돌려준 값을 FastAPI가 BookRead의 모양으로 다시 걸러서 보냅니다. BookRead에 없는 cost는 응답에서 빠집니다.

반대로 BookRead에 꼭 있어야 하는 값(예: title)이 돌려준 값에 없으면, 클라이언트 잘못이 아니라 서버 코드의 잘못이므로 500 오류가 납니다. 응답 모델은 서버가 약속을 어기지 않게 막아 주는 장치이기도 합니다.

앞으로 다시 만날 장면

3일차에 회원 기능을 만들면 비밀번호 해시라는 값이 생깁니다. 이 값도 같은 방법으로 응답에서 빼고, 5일차 개발 보안 단원에서 응답 필드를 최소화하는 원칙으로 다시 점검합니다.
