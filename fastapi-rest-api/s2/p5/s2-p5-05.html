정리: 응답 설계

핵심 요약

  • 입력 모델(BookCreate, BookUpdate)과 출력 모델(BookRead)을 나누면 용도에 맞는 항목만 주고받을 수 있습니다.
  • response_model은 응답을 출력 모델 모양으로 걸러 내부 값이 새어 나가지 않게 합니다.
  • 생성은 201, 내용 없는 성공은 204, 없는 자원은 404, 상태 충돌은 409를 씁니다.
  • PUT은 전체를 바꾸고, PATCH는 exclude_unset=True로 보낸 항목만 바꿉니다.

확인 퀴즈

함수가 cost가 들어 있는 딕셔너리를 돌려줍니다. 응답에서 cost를 빼는 가장 알맞은 방법은 무엇인가요?

출력 모델을 정해 두면 FastAPI가 모든 응답을 그 모양으로 걸러 줍니다. 원본 데이터를 지우면 내부에서도 쓸 수 없게 됩니다.

도서를 삭제한 뒤 돌려줄 내용이 없습니다. 어떤 상태 코드가 알맞은가요?

204 No Content는 성공했지만 본문이 없다는 뜻입니다.

PATCH /books/1에 {"price": 19000}만 보냈습니다. exclude_unset=True 없이 model_dump()를 쓰면 어떻게 되나요?

BookUpdate의 기본값이 모두 None이므로, 보내지 않은 항목도 None으로 꺼내져 덮어쓰게 됩니다.
