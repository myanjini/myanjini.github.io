API 문서 다듬기

API 문서는 우리 API를 쓰는 사람이 가장 먼저 보는 설명서입니다. 코드 몇 줄로 Swagger UI 화면을 훨씬 알아보기 쉽게 만드는 과정을 강사 화면으로 봅니다.

앱 정보

app = FastAPI(
    title="도서 관리 API",
    description="도서를 등록하고 조회, 수정, 삭제하는 API입니다.",
    version="0.1.0",
)

문서 맨 위에 API 이름, 설명, 버전이 표시됩니다.

태그로 묶고 요약 붙이기

@app.get("/books", response_model=list[BookRead], tags=["도서"], summary="도서 목록 조회")
def list_books(author: str | None = None):
    """저자 이름(author)을 주면 그 저자의 도서만 돌려줍니다."""
    ...
설정문서에서 바뀌는 곳
tags=["도서"]같은 태그의 API가 한 묶음으로 모입니다. 태그가 없으면 모두 default 아래에 섞입니다.
summary="..."API 목록에서 경로 옆에 보이는 한 줄 설명입니다.
함수의 설명 문자열API를 펼쳤을 때 보이는 자세한 설명이 됩니다.

오류 응답 알려 주기

@app.get("/books/{book_id}", ..., responses={404: {"description": "도서를 찾을 수 없음"}})

이 API가 어떤 오류를 낼 수 있는지 문서의 Responses 영역에 표시됩니다. API를 쓰는 사람은 이 목록을 보고 오류 처리를 준비합니다.

요청 예시 값

class BookCreate(BaseModel):
    title: str = Field(min_length=1, max_length=100, examples=["FastAPI 실전"])
    author: str = Field(min_length=1, max_length=50, examples=["최유나"])
    price: int = Field(ge=0, le=1_000_000, examples=[27000])
    isbn: str | None = Field(default=None, pattern=r"^\d{13}$", examples=["9791100000035"])

Try it out을 눌렀을 때 Request body 칸이 "string", 0 같은 의미 없는 값 대신 실제와 비슷한 예시로 채워집니다.

문서는 두 가지

/docs의 Swagger UI 말고도 /redoc에 읽기 전용 문서가 있습니다. 두 화면 모두 /openapi.json이라는 같은 명세를 보여 주는 것이라, 코드만 고치면 둘 다 함께 바뀝니다.
