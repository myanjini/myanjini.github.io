단일 파일의 한계

이 파트의 학습 목표APIRouter로 기능별 라우터를 분리하고 패키지 구조를 설계할 수 있습니다.

main.py 한 파일이 150줄을 넘었습니다. 지금은 괜찮아 보여도, 앞으로 저자, 회원, 대여 기능이 더해지면 문제가 커집니다.

한 파일에 모든 코드가 있으면

문제실제로 겪는 일
찾기 어렵습니다도서 등록 코드를 고치려는데 모델, 오류 처리, 다른 API 사이를 계속 위아래로 스크롤해야 합니다.
함께 고치기 어렵습니다두 사람이 같은 파일의 다른 기능을 고치면 Git에서 충돌이 자주 납니다.
영향 범위가 넓어집니다한 기능을 고쳤는데 같은 파일의 다른 기능이 망가지기 쉽고, 어디까지 확인해야 할지 알기 어렵습니다.
재사용이 어렵습니다모델이나 오류 클래스를 다른 기능에서 쓰려면 결국 같은 파일에 또 코드를 붙이게 됩니다.

해결 방법은 역할에 따라 파일을 나누는 것입니다. 데이터 모양(모델), 오류, 기능별 API를 각자의 파일에 두면, 고칠 곳을 바로 찾을 수 있고 한 파일을 고쳐도 다른 파일은 영향을 덜 받습니다.
