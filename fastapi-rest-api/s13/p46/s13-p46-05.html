7일차 오전 핵심 요약

교시만든 것핵심
1교시실습 VPC, 보안 그룹 2개NAT 없는 퍼블릭과 프라이빗 구성, 출처를 IP와 보안 그룹으로 좁힌 규칙
2교시EC2 서버IAM 역할 연결, 키 페어 없이 Session Manager 접속, IMDSv2 확인
3교시EC2의 도서 API 컨테이너서버에서 설치, 빌드, 실행. 비밀 값은 소스 밖의 권한 600 파일
4교시RDS PostgreSQL프라이빗 서브넷, 퍼블릭 액세스 끔, 암호화, SSL 강제, 마이그레이션

지금 도서 API는 다음 경로로 동작합니다. 내 PC → 인터넷 → 인터넷 게이트웨이 → EC2(book-api-sg: 내 IP의 8000만) → 컨테이너 → RDS(book-api-db-sg: book-api-sg의 5432만, SSL).

확인 퀴즈

RDS 생성 화면에서 서브넷 그룹을 "새로 만들기"로 두면 생길 수 있는 문제는 무엇인가요?

VPC의 모든 서브넷이 들어가므로, 프라이빗 서브넷만 넣은 서브넷 그룹을 먼저 만들어 고릅니다.

내 PC에서 RDS 엔드포인트를 조회하면 10.0.11.x 주소가 나옵니다. 내 PC에서 접속할 수 없는 가장 직접적인 이유는 무엇인가요?

퍼블릭 액세스를 끄면 공용 IP를 받지 않습니다. 보안 그룹도 API 서버만 허용하므로 겹겹이 막혀 있습니다.

DATABASE_URL 끝의 ?sslmode=require를 지우면 어떻게 되나요?

기본값은 가능하면 SSL을 쓰는 prefer입니다. 지금은 RDS가 SSL을 강제하므로 연결되지만, 앱 쪽에서도 require 이상을 명시해 두는 것이 안전합니다.

7일차 오후 예고

오후에는 이 구성을 운영에 맞게 다듬습니다. 서버 파일에 있는 비밀 키와 DB 암호를 Parameter Store로 옮기고, 이미지를 내 PC에서 한 번 만들어 ECR에 올린 뒤 서버는 받아서 실행만 하게 바꿉니다. 마지막으로 운영용 Compose 파일로 재시작과 상태 확인까지 갖춘 배포를 완성합니다.
