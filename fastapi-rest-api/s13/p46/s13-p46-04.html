RDS 보안 설정

데이터베이스 보안은 "닿지 못하게"(네트워크), "읽혀도 알 수 없게"(암호화), "권한을 꼭 필요한 만큼만"(계정) 세 겹으로 생각합니다. 네트워크는 앞에서 막았으니, 나머지 두 겹을 정리합니다.

저장 데이터 암호화

RDS의 암호화를 켜면 디스크에 저장되는 데이터, 자동 백업, 스냅샷, 읽기 복제본이 모두 암호화됩니다. 키는 AWS KMS(키 관리 서비스)가 관리하고, 기본으로 AWS 관리형 키 aws/rds를 씁니다. 앱은 아무것도 바꿀 필요가 없습니다. 읽고 쓸 때 RDS가 알아서 풀고 잠급니다.

주의할 점은 암호화는 만들 때만 정할 수 있다는 것입니다. 암호화하지 않고 만든 DB를 나중에 암호화하려면 스냅샷을 찍고, 스냅샷을 암호화해 복사한 뒤, 그것으로 새 DB를 만들어야 합니다. 그래서 처음부터 켭니다.

전송 구간 암호화(SSL/TLS)

EC2와 RDS 사이를 오가는 SQL과 결과에는 비밀번호 해시, 이메일 같은 개인정보가 들어 있습니다. PostgreSQL 15 이상의 RDS는 rds.force_ssl이 기본으로 켜져 있어 암호화하지 않은 연결을 거부합니다. 앞 실습에서 sslmode=disable이 거부된 이유입니다.

sslmode암호화서버 확인쓰임
disable안 함안 함RDS에서는 거부됩니다.
require함안 함이번 실습. 엿보기는 막지만, 상대가 진짜 RDS인지는 확인하지 않습니다.
verify-full함인증서와 호스트 이름까지 확인권장. RDS 인증서 묶음 파일이 필요합니다.

verify-full을 쓰려면 AWS가 공개한 서울 리전용 인증서 묶음(ap-northeast-2-bundle.pem)을 받아 컨테이너에 넣고 위치를 알려 줍니다. 아래는 그 모양입니다. 이 과정에서는 VPC 안에서만 오가는 연결이라 require로 진행하고, 운영 구성으로 바꿀 때 적용 여부를 다시 검토합니다.

mkdir -p ~/certs
curl -fsSL -o ~/certs/rds-ca.pem https://truststore.pki.rds.amazonaws.com/ap-northeast-2/ap-northeast-2-bundle.pem

# DATABASE_URL 끝을 이렇게 바꾸고
...?sslmode=verify-full&sslrootcert=/app/certs/rds-ca.pem
# 컨테이너에 인증서 폴더를 읽기 전용으로 붙입니다.
docker run ... -v ~/certs:/app/certs:ro ...

마스터 암호와 앱 계정

수칙이번 과정에서
마스터 암호는 길고 무작위로secrets.token_urlsafe(24)로 만든 32자
암호를 코드와 이미지에 넣지 않기지금은 서버의 권한 600 파일, 오늘 오후에 Parameter Store의 SecureString으로 옮김(S14-P47)
앱은 마스터 계정을 쓰지 않기마스터 계정은 DB 안의 모든 것을 할 수 있습니다. 실제 서비스에서는 테이블 읽기와 쓰기만 할 수 있는 앱 전용 계정을 따로 만들고, 마이그레이션처럼 테이블을 바꾸는 작업만 별도 계정으로 합니다. 이 과정은 단순하게 마스터 계정 하나를 씁니다.
AWS가 암호를 관리하게 하기(선택)생성 화면의 "AWS Secrets Manager에서 관리"를 고르면 AWS가 암호를 만들고 주기적으로 바꿔 줍니다. Secrets Manager는 비밀 값마다 요금이 붙어 이번에는 쓰지 않습니다.

정리하면, 도서 API의 데이터는 프라이빗 서브넷과 보안 그룹으로 닿지 못하게 막고, 디스크와 전송 구간 모두 암호화하고, 암호는 무작위로 만들어 코드 밖에 둡니다. 5일차에 비밀번호를 해시로 저장한 것까지 합치면, DB가 통째로 새더라도 사용자의 비밀번호 원문은 알 수 없습니다.

RDS를 암호화하지 않고 만들었습니다. 나중에 암호화하려면 어떻게 하나요?

저장 데이터 암호화는 만들 때만 정할 수 있습니다.
