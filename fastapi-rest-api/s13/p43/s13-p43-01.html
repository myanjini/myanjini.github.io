6일차 복습

이 파트의 학습 목표설계한 대로 VPC와 서브넷, 보안 그룹을 만들 수 있습니다.

7일차는 6일차 오후에 만든 설계표를 실제 AWS 자원으로 바꾸는 날입니다. 오전에는 네트워크, 서버, 데이터베이스를 차례로 만들고 도서 API를 띄웁니다. 시작하기 전에 어제 배운 내용을 질문으로 떠올려 봅니다.

스스로 떠올리기

질문 1. 진단 실습에서 bandit이 찾지 못한 약점에는 어떤 것이 있었나요? 왜 못 찾았나요?

예시 답안 보기

남의 공지 삭제(부적절한 인가), X-Role 헤더로 관리자 판단, 좋아요 경쟁 조건, 전역 변수로 공유한 사용자 정보, 링크 미리 보기의 SSRF 등이 있었습니다. 평범한 코드 모양으로 이루어져 있어서, 업무 규칙과 실행 상황을 알아야 문제인지 판단할 수 있기 때문입니다(S11-P38).

질문 2. EC2 서버가 Parameter Store의 비밀 값을 읽을 때 액세스 키 대신 무엇을 쓰나요? 그 방식의 장점은 무엇인가요?

예시 답안 보기

서버에 붙인 IAM 역할을 씁니다. AWS가 임시 자격 증명을 서버에 주고 자동으로 바꿔 주므로, 코드나 이미지 어디에도 오래 쓰는 비밀 값이 남지 않습니다(S12-P41).

질문 3. 서브넷이 퍼블릭인지 프라이빗인지는 무엇으로 정해지나요?

예시 답안 보기

연결된 라우팅 테이블에 0.0.0.0/0 → 인터넷 게이트웨이 경로가 있는지로 정해집니다(S12-P42-01).

질문 4. DB 보안 그룹의 인바운드 규칙 출처에 IP 대신 API 서버의 보안 그룹을 적는 이유는 무엇인가요?

예시 답안 보기

API 서버의 IP가 바뀌거나 서버가 늘어나도 규칙을 고칠 필요가 없고, 그 보안 그룹이 붙지 않은 자원은 DB에 닿을 수 없기 때문입니다(S12-P42-02).
