접속이 안 될 때 점검 순서

"브라우저에서 안 열려요"는 배포에서 가장 흔한 문제입니다. 원인은 여러 겹 가운데 어디에나 있을 수 있으므로, 안쪽(컨테이너)부터 바깥쪽(인터넷)으로 한 겹씩 확인합니다. 한 단계가 통과하면 그 안쪽은 문제가 아니라는 뜻입니다.

순서확인할 곳명령이나 방법통과하지 못하면
1컨테이너가 실행 중인가docker ps -aSTATUS가 Exited이면 docker logs book-api로 이유를 봅니다. 흔한 원인은 설정 파일의 SECRET_KEY 누락이나 짧은 값(시작할 때 검증 오류)입니다.
2컨테이너 안의 앱이 응답하나docker exec book-api python -c "import urllib.request; print(urllib.request.urlopen('http://localhost:8000/health').read())"앱이 시작 중이거나 오류입니다. 로그를 봅니다.
3서버의 포트가 컨테이너에 이어졌나curl localhost:8000/health(서버에서)docker ps의 PORTS에 0.0.0.0:8000->8000/tcp가 있는지 봅니다. -p를 빠뜨렸으면 컨테이너를 다시 만듭니다.
4보안 그룹이 내 요청을 허용하나curl https://checkip.amazonaws.com(내 PC)와 book-api-sg의 인바운드 규칙 비교내 IP가 바뀌었으면 규칙을 고칩니다. 포트가 8000인지도 봅니다.
5주소가 맞나콘솔의 퍼블릭 IP, 주소창의 http://와 :8000서버를 재시작했다면 퍼블릭 IP가 바뀌었습니다. https://로 열면 연결되지 않습니다(8일차에 HTTPS를 붙입니다).
6인터넷 경로가 있나서브넷의 라우팅 테이블, 인스턴스의 퍼블릭 IP 유무프라이빗 서브넷에 만들었거나 퍼블릭 IP가 없으면 밖에서 닿지 않습니다.
7그 밖의 방화벽네트워크 ACL, 회사나 기관의 방화벽기본 네트워크 ACL은 모두 허용입니다. 기관 네트워크가 8000번 같은 포트를 막는 경우가 있으니 강사에게 확인합니다.

증상으로 위치를 짐작할 수도 있습니다. 브라우저가 한참 기다리다 "시간 초과"가 나면 보통 4~7번(요청이 서버에 닿지 않음), 바로 "연결 거부"가 나면 3번(서버에는 닿았지만 그 포트에서 기다리는 프로그램이 없음), 500 오류가 나면 1~2번(앱 안의 문제)입니다.

점검해 보기. 어제는 잘 열리던 API가 오늘 아침 "시간 초과"로 열리지 않습니다. 서버는 어제 저녁에 중지했고 오늘 다시 시작했습니다. 무엇부터 확인하겠어요?

예시 답안 보기

시간 초과이므로 요청이 서버에 닿지 않는 바깥쪽 문제일 가능성이 큽니다. 서버를 다시 시작했으니 퍼블릭 IP가 바뀌었을 것이고(5번), 교육장의 공인 IP가 바뀌었을 수도 있습니다(4번). 콘솔에서 새 퍼블릭 IP를 확인하고, checkip으로 내 IP를 확인해 보안 그룹과 비교합니다. 컨테이너는 --restart unless-stopped 덕분에 서버와 함께 다시 시작되었을 것이므로 1번은 나중에 봅니다.
