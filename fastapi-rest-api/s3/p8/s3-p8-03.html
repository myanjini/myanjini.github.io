공통 파라미터 의존성

페이지 나누기 의존성을 함수 대신 클래스로 만들어 검사 규칙과 자동 완성까지 챙기는 방법을 강사 화면으로 봅니다.

함수 의존성의 아쉬운 점

앞 페이지의 pagination은 딕셔너리를 돌려줍니다. 그래서 경로 함수에서 page["limit"]처럼 꺼내야 하고, page["limt"]로 오타를 내도 VSCode가 알려 주지 않습니다. 음수나 너무 큰 값을 막는 규칙도 없습니다.

클래스 의존성

app/dependencies.py
from typing import Annotated

from fastapi import Depends, Query


class Pagination:
    """목록 API가 함께 쓰는 페이지 나누기 값입니다."""

    def __init__(
        self,
        skip: int = Query(default=0, ge=0, description="건너뛸 개수"),
        limit: int = Query(default=10, ge=1, le=100, description="가져올 최대 개수"),
    ):
        self.skip = skip
        self.limit = limit


# 타입과 의존성을 한 이름으로 묶어 두면 여러 함수에서 짧게 쓸 수 있습니다.
PageDep = Annotated[Pagination, Depends()]
코드뜻
Query(default=0, ge=0)쿼리 파라미터의 기본값과 규칙입니다. Field와 쓰는 법이 같습니다.
Annotated[Pagination, Depends()]Depends() 안을 비워 두면 앞에 적은 클래스(Pagination)를 의존성으로 씁니다. FastAPI가 클래스를 호출해 객체를 만들어 넣어 줍니다.

경로 함수에서 쓰기

app/routers/books.py
@router.get("", response_model=list[BookRead], summary="도서 목록 조회")
def list_books(page: PageDep, author: str | None = None):
    """저자 이름(author)으로 거르고, skip과 limit으로 나눠 돌려줍니다."""
    result = BOOKS
    if author is not None:
        result = [book for book in result if book["author"] == author]
    return result[page.skip : page.skip + page.limit]

이제 page.skip, page.limit처럼 속성으로 꺼내므로, 철자를 틀리면 VSCode가 바로 밑줄을 그어 줍니다. 리스트의 [시작 : 끝]은 그 범위만 잘라 내는 Python 문법입니다.
