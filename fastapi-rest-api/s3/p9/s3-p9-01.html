설정과 비밀정보 분리

이 파트의 학습 목표환경 변수로 설정을 분리하고 CORS와 미들웨어를 적용할 수 있습니다.

곧 데이터베이스 주소와 비밀 키 같은 값이 필요해집니다. 이런 값을 코드에 바로 적으면 생기는 문제와, 코드 밖에서 관리하는 방법을 배웁니다.

코드에 적으면 생기는 문제

DATABASE_URL = "postgresql://admin:MyPassw0rd@db.example.com/books"
SECRET_KEY = "a9f3c1..."
문제설명
비밀이 새어 나갑니다코드를 Git에 올리는 순간 비밀번호와 비밀 키가 저장소에 남습니다. 나중에 지워도 이력에서 찾을 수 있습니다.
환경마다 코드를 고쳐야 합니다내 PC에서는 SQLite, 7일차 AWS에서는 RDS를 씁니다. 실행하는 곳마다 코드를 바꾸면 실수하기 쉽습니다.

비밀정보를 코드에 직접 적는 것은 5일차에 배울 KISA 보안약점 중 "하드코딩된 중요정보"에 해당합니다. 처음부터 습관을 들여 둡니다.

환경 변수와 .env 파일

환경 변수는 운영체제가 실행 중인 프로그램에 넘겨주는 이름과 값의 쌍입니다. 코드는 값 대신 "DATABASE_URL이라는 환경 변수를 읽는다"는 사실만 압니다. 개발할 때 환경 변수를 매번 입력하기는 번거로우므로, 프로젝트 폴더의 .env 파일에 적어 두고 읽게 합니다.

.env
DATABASE_URL=sqlite:///./books.db
SECRET_KEY=a9f3c1...

.env는 .gitignore에 넣어 Git에 올리지 않습니다. 대신 어떤 값이 필요한지 알려 주는 .env.example을 함께 올리고, 비밀 값 자리는 change-me처럼 비워 둡니다.

pydantic-settings

app/config.py
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    """환경 변수와 .env 파일에서 설정값을 읽습니다. 이름은 대소문자를 가리지 않습니다."""

    model_config = SettingsConfigDict(env_file=".env", env_file_encoding="utf-8")

    app_name: str = "도서 관리 API"
    database_url: str = "sqlite:///./books.db"
    secret_key: str  # 기본값이 없으므로 반드시 설정해야 합니다.
    cors_origins: list[str] = ["http://localhost:5173"]


settings = Settings()

요청 본문을 모델로 검사했던 것처럼, 설정도 모델로 정의하고 검사합니다. 값을 찾는 순서는 환경 변수, .env 파일, 기본값 순입니다. 이름은 대소문자를 가리지 않아서 .env의 SECRET_KEY가 secret_key 필드로 들어갑니다.

필드특징
secret_key: str기본값이 없어 반드시 설정해야 합니다. 없으면 서버가 시작하지 않고 오류를 냅니다. 비밀 값을 빠뜨린 채 실행되는 일을 막아 줍니다.
cors_origins: list[str]목록 값은 .env에 ["http://localhost:5173"]처럼 JSON 형식으로 적습니다.
