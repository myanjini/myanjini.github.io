미들웨어와 CORS

모든 요청에 공통으로 적용하고 싶은 일은 미들웨어로 처리합니다. 미들웨어로 해결하는 대표 문제인 CORS도 함께 알아봅니다.

미들웨어

미들웨어는 모든 요청이 경로 함수에 닿기 전과, 응답이 클라이언트로 나가기 전에 한 번씩 거치는 관문입니다. 의존성이 "필요한 API에만" 붙는다면, 미들웨어는 "모든 요청"에 적용됩니다. 처리 시간 기록, 공통 헤더 추가처럼 예외 없이 해야 하는 일에 씁니다.

CORS

웹 화면을 만드는 개발자가 http://localhost:5173에서 실행되는 웹 화면으로 우리 API(http://127.0.0.1:8000)를 호출한다고 해 봅시다. 브라우저는 보안을 위해, 화면이 열린 곳과 출처(Origin)가 다른 서버의 응답을 기본적으로 읽지 못하게 막습니다. 출처는 프로토콜, 주소, 포트 세 가지가 모두 같아야 같은 출처입니다.

화면 주소API 주소같은 출처인가요
http://localhost:5173http://127.0.0.1:8000아니요(주소와 포트가 다름)
http://127.0.0.1:8000/docshttp://127.0.0.1:8000예

다른 출처의 화면이 API를 쓰려면, 서버가 응답 헤더로 "이 출처는 허용한다"고 알려 줘야 합니다. 이 규칙을 CORS(Cross-Origin Resource Sharing)라고 하고, FastAPI에서는 CORSMiddleware로 설정합니다.

curl과 Swagger UI에서는 문제가 없던 이유

CORS는 브라우저가 지키는 규칙입니다. curl은 브라우저가 아니고, Swagger UI는 API와 같은 출처(127.0.0.1:8000)에서 열리기 때문에 지금까지는 CORS를 만날 일이 없었습니다.

모두 허용은 피합니다

allow_origins=["*"]로 모든 출처를 허용하면 당장은 편하지만, 어떤 사이트의 화면이든 우리 API를 호출할 수 있게 됩니다. 허용할 출처를 설정 파일에 명확히 적습니다. 8일차 보안 점검표에서 다시 확인하는 항목입니다.
