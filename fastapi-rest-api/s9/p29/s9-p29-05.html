정리: 개발보안의 틀

핵심 요약

  • 보안약점은 공격에 쓰일 수 있는 결함이고, 보안 취약점은 그중 실제로 공격할 수 있게 된 것입니다.
  • 소프트웨어 개발보안은 요구사항부터 운영까지 단계마다 보안 활동을 넣는 것이며, 늦게 고칠수록 비용이 커집니다.
  • 공공 정보화사업은 감리 대상 사업 전체에 개발보안이 의무이고, 기준은 KISA 소프트웨어 개발보안 가이드입니다.
  • 가이드는 설계 단계 보안 요구항목과, 구현 단계 보안약점 7개 유형을 제시합니다.
  • OWASP API Security Top 10은 API에서 자주 뚫리는 위험의 순위이며, 1위는 객체 수준 인가 취약입니다.

확인 퀴즈

다음 중 구현 단계 보안약점의 "입력데이터 검증 및 표현" 유형에 속하는 것은 무엇인가요?

외부 입력이 파일 경로로 흘러가는 경로 조작은 입력데이터 검증 및 표현 유형입니다. 나머지는 보안기능, 시간 및 상태, 에러처리입니다.

SQL 삽입이 가능한 코드가 있지만 그 기능이 아직 외부에 공개되지 않았습니다. 알맞은 설명은 무엇인가요?

아직 공격할 수 없어도 결함은 남아 있습니다. 개발 단계에서 고치는 것이 가장 싸고 안전합니다.

로그인한 사용자가 URL의 번호만 바꿔 남의 대여 기록을 읽을 수 있습니다. OWASP API 2023의 어느 항목인가요?

번호로 가리킨 객체에 대한 권한을 확인하지 않은 것이므로 BOLA입니다.
