소프트웨어 개발보안이란

보안은 서비스를 다 만든 뒤에 덧붙이는 것이 아니라, 만드는 과정 전체에서 챙기는 것입니다. 그 생각을 제도로 정리한 것이 소프트웨어 개발보안입니다.

보안약점과 보안 취약점

용어뜻예
보안약점(weakness)공격에 쓰일 수 있는 코드나 설계의 결함사용자 입력을 SQL 문장에 그대로 이어 붙인 코드
보안 취약점(vulnerability)보안약점 중 실제로 공격할 수 있는 상태가 된 것그 코드가 인터넷에 공개된 API에서 실행되어, 누구나 사용자 정보를 빼낼 수 있는 상태

보안약점은 아직 공격받지 않았어도 코드에 남아 있는 "사고의 씨앗"입니다. 소프트웨어 개발보안은 개발 과정에서 이 씨앗을 찾아 없애는 활동이며, 그중 코드를 안전하게 작성하는 일을 시큐어코딩이라고 부릅니다.

왜 개발 단계에서 하나요

보안약점은 늦게 발견할수록 고치는 비용이 커집니다. 코드를 쓸 때 발견하면 한 줄을 고치면 되지만, 운영 중에 사고로 발견하면 원인 분석, 긴급 수정, 피해 복구, 사용자 통지까지 해야 합니다. 그래서 단계마다 할 일을 나눠 둡니다.

개발 단계보안 활동이 과정에서
요구사항 분석보안 요구사항 정의(누가 무엇을 할 수 있는가, 어떤 정보를 보호하는가)3일차 권한 표, 9일차 미니 프로젝트 명세서
설계위협을 예상하고 보안 기능을 설계(인증 방식, 데이터 암호화, 접근 통제)3일차 토큰 설계, 6일차 AWS 네트워크 설계
구현시큐어코딩, 자동 점검 도구로 코드 검사5일차, 6일차 오전
테스트보안 테스트, 보안약점 진단오늘 만드는 회귀 테스트, 6일차 진단 실습
배포와 운영비밀정보 관리, 패치, 모니터링7일차와 8일차 AWS 단원

공공 정보화사업의 개발보안 제도

우리나라는 행정기관과 공공기관이 발주하는 정보화사업에 소프트웨어 개발보안을 의무로 적용합니다. 2012년 12월 개발비 40억 원 이상 사업부터 시작해, 2014년에는 20억 원 이상, 2015년부터는 정보시스템 감리 대상이 되는 모든 사업으로 넓어졌습니다. 감리 과정에서는 보안약점을 제거했는지 확인하고, 이 일을 맡는 전문가로 소프트웨어 보안약점 진단원 제도를 운영합니다.

제도의 기준이 되는 문서가 행정안전부와 한국인터넷진흥원(KISA)이 펴낸 소프트웨어 개발보안 가이드입니다. 공공 사업이 아니더라도 국내 개발자가 보안약점을 정리할 때 가장 널리 참고하는 기준이어서, 이 과정도 이 가이드의 분류를 따릅니다.
