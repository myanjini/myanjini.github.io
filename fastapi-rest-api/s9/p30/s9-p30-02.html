SQL 삽입 재현과 방어

ORM을 쓰면 SQL 삽입이 저절로 막힙니다. 그런데 집계나 보고서처럼 SQL을 직접 써야 할 때 실수하면 그대로 뚫립니다. 새로 만들 재고 보고서 API로 재현합니다.

위험한 코드

저자별 재고를 보여 주는 보고서를 만들면서 SQL을 직접 작성했습니다. 검색어와 정렬 기준을 f-string으로 SQL 문장에 이어 붙였습니다.

app/repositories/reports.py
"""보고서 저장소: 집계와 보고서는 SQL로 직접 작성합니다."""
from sqlalchemy import text
from sqlalchemy.orm import Session


def stock_report(db: Session, keyword: str, order_by: str) -> list[dict]:
    # 위험한 코드: 사용자가 보낸 값을 SQL 문장에 그대로 이어 붙였습니다.
    sql = f"""
        SELECT b.title, a.name AS author, b.stock
        FROM books b JOIN authors a ON a.id = b.author_id
        WHERE b.title LIKE '%{keyword}%'
        ORDER BY {order_by}
    """
    return [dict(row) for row in db.execute(text(sql)).mappings()]

공격

공격자는 로그인한 일반 사용자입니다. 검색어 자리에 다음 값을 보냅니다.

zz%' UNION SELECT email, hashed_password, 0 FROM users --

이 값이 들어간 뒤의 SQL은 다음과 같습니다.

SELECT b.title, a.name AS author, b.stock
FROM books b JOIN authors a ON a.id = b.author_id
WHERE b.title LIKE '%zz%' UNION SELECT email, hashed_password, 0 FROM users --%'
ORDER BY stock
조각공격자의 의도
zz%'작은따옴표로 원래의 문자열을 일찍 닫습니다.
UNION SELECT email, hashed_password, 0 FROM users다른 테이블의 결과를 같은 모양(3열)으로 덧붙입니다.
--그 줄의 나머지(%')를 주석으로 만들어 문법 오류를 피합니다.

응답에는 도서 대신 모든 사용자의 이메일과 비밀번호 해시가 나옵니다.

[
  {"title": "user1@example.com", "author": "$argon2id$v=19$m=65536,t=3,p=4$aincZQLhGn...", "stock": 0},
  {"title": "user2@example.com", "author": "$argon2id$v=19$m=65536,t=3,p=4$jaLDcGI17l...", "stock": 0},
  ...
]

검색어는 데이터여야 하는데, SQL 문장의 구조가 되어 버렸습니다. 이것이 SQL 삽입입니다. 3일차에 비밀번호를 해시로 저장해 두지 않았다면 비밀번호 원문이 그대로 나왔을 것입니다. 정렬 기준도 마찬가지로, order_by=stock; DROP TABLE books를 보내면 SQLite는 "한 번에 한 문장만 실행할 수 있다"는 오류로 막아 주지만, 공격자가 SQL 구조를 바꿀 수 있다는 사실은 같습니다.

방어 1: 값 바인딩

SQL 문장에는 :pattern 같은 자리표시만 두고, 값은 따로 넘깁니다. 데이터베이스는 문장의 구조를 먼저 해석한 뒤 값을 그 자리에 데이터로만 넣으므로, 값 안의 따옴표나 UNION이 구조를 바꿀 수 없습니다.

sql = text("SELECT ... WHERE b.title LIKE :pattern ...")
db.execute(sql, {"pattern": f"%{keyword}%"})

방어 2: 바인딩할 수 없는 곳은 허용 목록

값 바인딩은 값 자리에만 쓸 수 있습니다. 열 이름, 테이블 이름, ORDER BY 뒤의 정렬 기준은 SQL 구조의 일부라 바인딩할 수 없습니다. 이런 곳은 허용 목록에서 꺼낸 값만 넣습니다.

app/repositories/reports.py
"""보고서 저장소: 집계와 보고서는 SQL로 직접 작성합니다."""
from sqlalchemy import text
from sqlalchemy.orm import Session

# 정렬 기준은 값 바인딩을 쓸 수 없으므로 허용 목록에서 꺼낸 글자만 SQL에 넣습니다.
ORDER_COLUMNS = {"title": "title", "stock": "stock"}


def stock_report(db: Session, keyword: str, order_by: str) -> list[dict]:
    sql = text(f"""
        SELECT b.title, a.name AS author, b.stock
        FROM books b JOIN authors a ON a.id = b.author_id
        WHERE b.title LIKE :pattern
        ORDER BY {ORDER_COLUMNS[order_by]}, b.id
    """)
    # :pattern 자리에는 값이 따로 전달되므로 SQL 문장의 구조를 바꿀 수 없습니다.
    rows = db.execute(sql, {"pattern": f"%{keyword}%"}).mappings()
    return [dict(row) for row in rows]

ORM을 써도 남는 위험

SQLAlchemy ORM의 select(Book).where(Book.title.contains(q))는 자동으로 값 바인딩을 쓰므로 안전합니다. 하지만 다음처럼 ORM 안에서도 문자열을 이어 붙이면 똑같이 뚫립니다.

위험한 코드안전한 코드
text(f"... WHERE name = '{name}'")text("... WHERE name = :name")와 값 따로 넘기기
.order_by(text(sort))허용 목록 딕셔너리에서 꺼낸 열 객체
.where(text(f"price > {p}")).where(Book.price > p)
