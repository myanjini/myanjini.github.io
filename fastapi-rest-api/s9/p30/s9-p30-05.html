정리: SQL 삽입과 경로 조작

핵심 요약

  • 입력데이터 검증 보안약점은 외부 입력이 SQL, 경로, HTML, 셸 명령의 구조에 섞여 들어가서 생깁니다.
  • 받을 때는 Pydantic으로 타입, 길이, 형식을 허용 목록 방식으로 좁히고, 쓸 때는 쓰는 곳에 맞게 처리합니다.
  • SQL은 값 바인딩(:이름)으로 값과 구조를 나누고, 바인딩할 수 없는 정렬 기준과 열 이름은 허용 목록에서 꺼냅니다.
  • 파일 경로는 resolve()로 정규화한 뒤 is_relative_to()로 기준 폴더 안인지 확인합니다.
  • 고친 약점은 공격 값을 담은 회귀 테스트로 남겨 CI가 지키게 합니다.

확인 퀴즈

SQLAlchemy에서 SQL 삽입에 안전한 코드는 무엇인가요?

값 바인딩은 SQL 구조와 값을 따로 보내므로 값이 구조를 바꿀 수 없습니다.

ORDER BY 뒤의 정렬 기준을 사용자에게서 받을 때 알맞은 방법은 무엇인가요?

열 이름은 바인딩할 수 없으므로 허용 목록을 씁니다. 따옴표 제거나 길이 제한은 금지 목록 방식이라 우회될 수 있습니다.

(FILES_DIR / name).resolve() 다음에 꼭 해야 하는 검사는 무엇인가요?

정규화만으로는 ../가 풀린 실제 경로를 얻을 뿐입니다. 그 경로가 기준 폴더 안인지 확인해야 막힙니다.
