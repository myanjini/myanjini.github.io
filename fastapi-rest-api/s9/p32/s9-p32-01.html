부적절한 인가

이 파트의 학습 목표객체 수준 권한 검사 누락과 과도한 데이터 노출을 찾아 고칠 수 있습니다.

인증은 잘 되어 있어도 인가에서 한 번만 실수하면 다른 사람의 데이터가 그대로 보입니다. API에서 가장 흔하고 피해가 큰 보안약점입니다.

두 가지 인가

기능 수준 인가이 사용자가 이 기능을 써도 되는가?require_admin: 관리자만 저자 등록API5 BFLA

KISA 가이드는 이런 약점을 보안기능 유형의 부적절한 인가와 적절한 인증 없는 중요 기능 허용으로 다룹니다. 이름은 다르지만 "누가, 무엇에, 무엇을 할 수 있는지 매번 확인하라"는 같은 원칙입니다.

번호를 추측하기 어려운 무작위 값(UUID)으로 바꾸는 것도 도움이 되지만 해결책은 아닙니다. 번호는 로그, 공유된 링크, 다른 API의 응답으로 새어 나갈 수 있습니다. 권한 검사는 번호 형식과 상관없이 반드시 서버에서 합니다.
