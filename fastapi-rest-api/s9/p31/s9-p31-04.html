명령어 삽입과 SSRF

도서 API에는 아직 없지만 기능을 늘리다 보면 곧 만나게 되는 두 가지 보안약점을 정리합니다. 서버가 명령을 실행하거나 다른 주소로 요청을 보내는 곳입니다.

운영체제 명령어 삽입

표지 이미지의 썸네일을 외부 프로그램으로 만든다고 해 봅시다. 명령을 문자열로 만들어 셸로 실행하면, 파일 이름에 ; rm -rf / 같은 값이 들어갔을 때 그 명령까지 실행됩니다.

# 위험한 코드: 파일 이름이 셸 명령의 일부가 됩니다.
subprocess.run(f"convert {path} -resize 200x200 {thumb_path}", shell=True)
# 안전한 코드: 명령과 인자를 목록으로 나눠 넘기면 셸을 거치지 않습니다.
subprocess.run(["convert", str(path), "-resize", "200x200", str(thumb_path)], check=True)

목록으로 넘기면 각 값은 프로그램에 전달되는 인자 하나일 뿐이고, 셸이 해석하지 않습니다. shell=True와 os.system()은 쓰지 않는 것을 원칙으로 합니다. 6일차의 자동 점검 도구(bandit)도 이 코드를 찾아냅니다.

서버사이드 요청 위조(SSRF)

"표지 이미지를 URL로 등록하기" 기능을 만들면, 서버가 사용자가 준 주소로 직접 요청을 보냅니다. 공격자가 http://169.254.169.254/latest/meta-data/ 같은 주소를 주면 어떻게 될까요? 이 주소는 AWS EC2 안에서만 닿는 서버 정보 주소로, 서버에 부여된 권한 정보를 내줄 수 있습니다. 공격자는 바깥에서 닿을 수 없는 내부 주소를 우리 서버를 시켜 대신 부르게 됩니다. 이것이 서버사이드 요청 위조이며, 7일차에 서버를 AWS로 옮기면 실제 위험이 됩니다.

검사 함수 예시
import ipaddress
import socket
from urllib.parse import urlparse


def check_public_url(url: str) -> None:
    """https이고, 인터넷의 공개 주소를 가리키는 URL만 허용합니다."""
    parts = urlparse(url)
    if parts.scheme != "https" or not parts.hostname:
        raise AppError(422, "INVALID_URL", "https 주소만 쓸 수 있습니다.")
    for *_, sockaddr in socket.getaddrinfo(parts.hostname, 443):
        ip = ipaddress.ip_address(sockaddr[0])
        if not ip.is_global:  # 127.0.0.1, 10.x.x.x, 169.254.169.254 같은 내부 주소
            raise AppError(422, "INVALID_URL", "내부 주소로는 요청할 수 없습니다.")
추가로 지킬 것이유
허용하는 도메인 목록이 있다면 그것을 씁니다.내부 주소를 막는 것보다 "이 도메인만"이 더 안전합니다.
요청할 때 리디렉션을 따라가지 않습니다.처음 주소는 공개 주소여도 내부 주소로 넘겨 보낼 수 있습니다.
검사한 IP로 요청합니다.검사할 때와 요청할 때 도메인이 다른 IP를 가리키게 바꾸는 공격이 있습니다.
EC2에서는 IMDSv2를 씁니다.서버 정보 주소를 토큰 없이는 못 읽게 합니다. 7일차에 설정합니다.
