정리: 입력데이터 검증

핵심 요약

  • 저장형 XSS는 API가 저장하고 내준 값이 화면에서 실행되는 공격입니다. 출력하는 곳에서 글자로 처리하고, API는 JSON을 정확한 Content-Type으로 내줍니다.
  • X-Content-Type-Options: nosniff로 브라우저가 형식을 짐작하지 못하게 합니다.
  • 업로드 파일은 확장자(허용 목록)와 내용(매직 넘버)을 함께 확인하고, 확인한 형식으로 새 이름을 지어 실행되지 않는 곳에 저장합니다.
  • 셸 명령은 shell=True 없이 인자 목록으로 실행합니다.
  • 서버가 사용자가 준 주소로 요청할 때는 https와 공개 주소만 허용하고, 가능하면 도메인 허용 목록을 씁니다.

확인 퀴즈

API가 도서 제목 <script>...</script>를 JSON으로 돌려줍니다. 스크립트가 실행되지 않게 하는 가장 알맞은 곳은 어디인가요?

XSS는 출력하는 곳에서 HTML로 해석될 때 일어나므로, 출력할 때 글자로 다루는 것이 핵심입니다.

cover.png라는 이름의 파일이 실제로 png인지 확인하는 방법으로 알맞은 것은 무엇인가요?

이름과 content_type은 보내는 쪽이 정합니다. 내용의 형식 표시를 확인해야 합니다.

다음 중 명령어 삽입에 안전한 코드는 무엇인가요?

인자 목록으로 넘기면 셸을 거치지 않아 값이 명령으로 해석되지 않습니다.
