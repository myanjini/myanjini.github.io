정리: 컨테이너화

핵심 요약

  • 이미지는 실행에 필요한 모든 것을 담은 읽기 전용 꾸러미이고, 컨테이너는 이미지를 실행한 것입니다.
  • Dockerfile은 한 줄마다 레이어를 만들고, 바뀌지 않은 레이어는 캐시로 재사용합니다. 잘 바뀌지 않는 패키지 설치를 코드 복사보다 먼저 둡니다.
  • .dockerignore로 .env, .venv, 개발 데이터를 이미지에서 뺍니다. 비밀 값은 실행할 때 -e로 넘깁니다.
  • 컨테이너 안의 서버는 0.0.0.0으로 실행하고, -p 내PC:컨테이너로 포트를 연결합니다.
  • 관리자가 아닌 사용자로 실행하고, 쓸 폴더에만 쓰기 권한을 줍니다.

확인 퀴즈

코드 한 줄만 고치고 다시 빌드했는데 pip install이 처음부터 다시 실행되었습니다. 가장 알맞은 원인은 무엇인가요?

코드가 바뀌면 그 COPY 레이어부터 다시 만듭니다. 패키지 설치가 그 뒤에 있으면 함께 다시 실행됩니다.

.env를 이미지에 넣으면 안 되는 이유는 무엇인가요?

이미지는 레지스트리로 공유됩니다. 비밀 값은 실행할 때 환경 변수로 넘깁니다.

컨테이너에서 uvicorn app.main:app을 --host 없이 실행하면 어떻게 되나요?

127.0.0.1은 컨테이너 안에서만 닿는 주소입니다. 밖에서 받으려면 0.0.0.0으로 실행합니다.
