컨테이너의 개념

이 파트의 학습 목표Dockerfile을 작성해 API 이미지를 만들고 실행할 수 있습니다.

오전에 CI 러너가 빈 서버에 Python과 패키지를 매번 설치하는 것을 봤습니다. 실행에 필요한 것을 통째로 묶어 어디서나 똑같이 실행하는 방법이 컨테이너입니다.

"내 PC에서는 되는데"의 원인

도서 API를 다른 컴퓨터에서 실행하려면 Python 3.12 이상, 정확한 버전의 패키지들, 운영체제에 맞는 설정이 모두 같아야 합니다. 하나라도 다르면 "내 PC에서는 되는데 서버에서는 안 된다"는 일이 생깁니다. 7일차에 AWS 서버에 배포할 때도 같은 문제를 만나게 됩니다.

컨테이너는 프로그램과 그 프로그램이 실행되는 데 필요한 모든 것(운영체제 파일, Python, 패키지, 코드)을 하나로 묶어 다른 프로그램과 분리된 공간에서 실행하는 기술입니다. Docker는 컨테이너를 만들고 실행하는 가장 널리 쓰이는 도구입니다.

이미지와 컨테이너

이미지(image)컨테이너(container)
무엇인가요실행에 필요한 파일을 모두 담은 읽기 전용 꾸러미이미지를 바탕으로 실제로 실행 중인 프로그램
비유프로그램 설치 파일설치해서 실행한 프로그램
개수하나의 이미지로컨테이너를 여러 개 실행할 수 있습니다.
만드는 명령docker builddocker run
바뀌나요바뀌지 않습니다.실행 중에 파일이 생길 수 있지만, 컨테이너를 지우면 함께 사라집니다.

이미지를 만드는 방법은 Dockerfile이라는 글자 파일에 적습니다. 만든 이미지는 레지스트리라는 저장소(Docker Hub 등)에 올려 다른 컴퓨터와 나눌 수 있습니다. 7일차에는 AWS의 레지스트리인 ECR에 올립니다.

가상환경, 가상머신과 무엇이 다른가요

방법분리하는 범위특징
가상환경(.venv)Python 패키지만Python 버전과 운영체제는 내 PC 것을 그대로 씁니다.
컨테이너운영체제 파일, Python, 패키지, 코드운영체제의 핵심(커널)은 함께 쓰므로 몇 초 만에 시작하고 가볍습니다.
가상머신운영체제 전체컴퓨터 한 대를 통째로 흉내 내므로 무겁고 시작이 느립니다.

Docker 컨테이너는 리눅스 커널 위에서 실행됩니다. Windows와 macOS의 Docker Desktop은 내부에 작은 리눅스를 두고 그 위에서 컨테이너를 실행하므로, 내 PC가 Windows여도 컨테이너 안은 리눅스입니다.

레이어와 캐시

이미지는 Dockerfile의 명령 한 줄마다 레이어라는 층이 하나씩 쌓여 만들어집니다. Docker는 이미 만든 레이어를 기억해 두었다가, 그 줄과 그 줄에 쓰인 파일이 바뀌지 않았으면 다시 만들지 않고 그대로 씁니다. 이것을 레이어 캐시라고 합니다.

그래서 자주 바뀌는 것(소스 코드)은 아래쪽 줄에, 잘 바뀌지 않는 것(패키지 설치)은 위쪽 줄에 둡니다. 코드 한 줄을 고칠 때마다 패키지를 모두 다시 설치하지 않게 하려는 것입니다.
