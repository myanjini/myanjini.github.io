API에 로깅 적용

API 전체에 로그 설정을 적용하고, 서비스에서 중요한 사건을 기록합니다. 데이터베이스를 일부러 멈춰 오류 로그를 요청 ID로 찾아봅니다.

실습 목표JSON 로그와 요청 ID를 적용하고, docker compose logs로 요청과 오류를 추적할 수 있습니다.

    앞 페이지의 app/logging_config.py를 만들고, app/config.py에 수준 설정을 추가합니다.

    app/config.py

  2. main.py 고치기

    가져오기를 추가하고, 라우터를 연결하기 전에 setup_logging을 부르고, 미들웨어를 바꿉니다.

    app/main.py 전체 펼치기
    app/main.py
    import logging
import time
import uuid

from fastapi import FastAPI, Request
from fastapi.middleware.cors import CORSMiddleware
from fastapi.responses import JSONResponse
from fastapi.staticfiles import StaticFiles
from sqlalchemy import text
from sqlalchemy.exc import SQLAlchemyError

from app.config import settings
from app.dependencies import SessionDep
from app.errors import AppError
from app.logging_config import request_id_var, setup_logging
from app.routers import auth, authors, books, loans
from app.services.covers import COVER_DIR

setup_logging(settings.log_level)

app = FastAPI(
    title=settings.app_name,
    description="도서를 등록하고 조회, 수정, 삭제하는 API입니다.",
    version="0.1.0",
)

# 이 주소에서 실행되는 웹 화면만 브라우저에서 이 API를 호출할 수 있습니다.
app.add_middleware(
    CORSMiddleware,
    allow_origins=settings.cors_origins,
    allow_methods=["*"],
    allow_headers=["*"],
)


logger = logging.getLogger("app.request")


@app.middleware("http")
async def log_requests(request: Request, call_next):
    request_id_var.set(uuid.uuid4().hex[:16])  # 이 요청에서 남기는 모든 로그에 같은 ID가 붙습니다.
    start = time.perf_counter()
    info = {"method": request.method, "path": request.url.path}
    try:
        response = await call_next(request)  # 실제 경로 함수가 여기서 실행됩니다.
    except Exception:
        info["duration_ms"] = round((time.perf_counter() - start) * 1000, 1)
        logger.exception("처리하지 못한 오류", extra={**info, "status": 500})
        raise  # 응답은 FastAPI의 기본 처리에 맡깁니다. 5일차에 안전한 오류 응답으로 바꿉니다.
    duration_ms = round((time.perf_counter() - start) * 1000, 1)
    response.headers["X-Request-ID"] = request_id_var.get()
    response.headers["X-Process-Time"] = f"{duration_ms}ms"
    logger.info("요청 처리", extra={**info, "status": response.status_code, "duration_ms": duration_ms})
    return response


@app.exception_handler(AppError)
def handle_app_error(request: Request, exc: AppError):
    # 어떤 AppError든 같은 모양의 JSON으로 바꿔 응답합니다.
    return JSONResponse(
        status_code=exc.status_code,
        content={"code": exc.code, "message": exc.message},
        headers=exc.headers,
    )


@app.get("/", tags=["기본"])
def read_root():
    return {"message": f"{settings.app_name}에 오신 것을 환영합니다."}


@app.get("/health", tags=["기본"])
def health_check(db: SessionDep):
    try:
        db.execute(text("SELECT 1"))  # 데이터베이스에 가장 가벼운 질의를 보내 봅니다.
    except SQLAlchemyError:
        logger.exception("데이터베이스 연결 확인 실패")
        return JSONResponse(status_code=503, content={"status": "error", "database": "unreachable"})
    return {"status": "ok", "database": "ok"}


app.include_router(auth.router)
app.include_router(authors.router)
app.include_router(books.router)
app.include_router(loans.router)

# 올린 표지 파일을 /covers/파일이름 주소로 내보냅니다.
COVER_DIR.mkdir(parents=True, exist_ok=True)
app.mount("/covers", StaticFiles(directory=COVER_DIR), name="covers")

    서버 시작 메시지부터 JSON 한 줄씩 나옵니다. Swagger UI에서 요청을 보내면 "message": "요청 처리" 로그가 찍히고, 응답 헤더에 x-request-id가 있습니다. pytest도 실행해 모두 통과하는지 확인합니다.

  6. 컨테이너에서 요청 추적하기

    docker compose up -d --build

    Swagger UI에서 user1으로 일부러 틀린 비밀번호로 한 번 로그인하고, 올바르게 로그인한 뒤 도서를 하나 대여합니다. 대여 응답 헤더의 x-request-id를 복사해 그 요청의 로그만 찾습니다.

    docker compose logs api --no-log-prefix | Select-String 요청ID      # Windows PowerShell
docker compose logs api --no-log-prefix | grep 요청ID               # macOS
    {"time": "...", "level": "INFO", "logger": "app.services.loans", "message": "도서 대여", "request_id": "ad824d09a715491f", "user_id": 1, "book_id": 1, "loan_id": 2}
{"time": "...", "level": "INFO", "logger": "app.request", "message": "요청 처리", "request_id": "ad824d09a715491f", "method": "POST", "path": "/loans", "status": 201, "duration_ms": 20.7}

    서비스의 "도서 대여" 로그와 미들웨어의 "요청 처리" 로그가 같은 ID로 묶였습니다. 로그인 실패는 "level": "WARNING"으로 남고, 입력한 비밀번호는 어디에도 없어야 합니다.

  7. 데이터베이스를 멈추고 오류 찾기

    docker compose stop db

    브라우저에서 /books를 열면 Internal Server Error가 나옵니다. 최근 로그에서 ERROR를 찾습니다.

    docker compose logs api --no-log-prefix --since 1m | Select-String ERROR     # Windows PowerShell
docker compose logs api --no-log-prefix --since 1m | grep ERROR              # macOS
    {"time": "...", "level": "ERROR", "logger": "app.request", "message": "처리하지 못한 오류", "request_id": "...",
 "method": "GET", "path": "/books", "duration_ms": ..., "status": 500,
 "error": "Traceback (most recent call last): ... sqlalchemy.exc.OperationalError: (psycopg.OperationalError) ..."}

    어떤 요청(GET /books)에서 무슨 오류(데이터베이스 연결 실패)가 났는지 로그 한 줄로 알 수 있습니다. 확인했으면 데이터베이스를 다시 시작합니다.

    docker compose start db

문제 해결

증상원인과 해결
KeyError: "Attempt to overwrite 'filename' in LogRecord"extra에 filename, name, message처럼 로그 기록이 원래 쓰는 이름을 넣었습니다. original_name처럼 다른 이름을 씁니다.
로그가 JSON이 아니라 글자로 나옴setup_logging을 부르지 않았거나, 라우터를 가져오기 전에 다른 곳에서 로그 설정을 했습니다.
모든 로그의 request_id가 -미들웨어를 등록하지 않았습니다. 서버 시작 메시지처럼 요청 밖의 로그는 -가 맞습니다.
로그가 늦게 보임Dockerfile의 PYTHONUNBUFFERED=1이 빠졌습니다.
