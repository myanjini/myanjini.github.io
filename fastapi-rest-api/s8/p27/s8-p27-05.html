정리: Compose

핵심 요약

  • Compose는 여러 컨테이너를 compose.yaml 하나로 정의하고 docker compose up으로 함께 실행합니다.
  • 서비스끼리는 서비스 이름(db)을 주소로 씁니다. 데이터베이스 포트는 바깥에 열지 않습니다.
  • 데이터는 볼륨에 보관해 컨테이너를 지워도 남게 합니다. PostgreSQL 18은 /var/lib/postgresql에 연결합니다.
  • depends_on과 healthcheck로 데이터베이스가 준비된 뒤에 API를 시작합니다.
  • 마이그레이션은 docker compose run --rm api alembic upgrade head로 적용하고, 데이터는 pg_dump로 백업합니다.

확인 퀴즈

api 컨테이너에서 데이터베이스 주소의 호스트로 알맞은 것은 무엇인가요?

Compose 네트워크에서는 서비스 이름이 주소입니다. 컨테이너 안의 127.0.0.1은 자기 자신입니다.

docker compose down 뒤 up했더니 데이터가 그대로 있었습니다. 그 이유는 무엇인가요?

down은 컨테이너와 네트워크만 지웁니다. 볼륨까지 지우려면 -v를 붙입니다.

처음 실행한 뒤 .env의 POSTGRES_PASSWORD를 바꿨더니 인증 오류가 납니다. 이유로 알맞은 것은 무엇인가요?

공식 이미지는 빈 볼륨일 때만 사용자를 만듭니다. 이후 비밀번호를 바꾸려면 데이터베이스 안에서 직접 바꿔야 합니다.
