compose.yaml 작성

compose.yaml을 한 부분씩 읽고, API가 PostgreSQL에 접속하는 데 필요한 준비를 봅니다.

compose.yaml

compose.yaml
services:
  db:
    image: postgres:18
    environment:
      POSTGRES_USER: bookapi
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}  # .env에서 읽어 옵니다.
      POSTGRES_DB: bookapi
    volumes:
      - db-data:/var/lib/postgresql  # 데이터를 컨테이너 밖 볼륨에 저장합니다.
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U bookapi -d bookapi"]
      interval: 5s
      timeout: 3s
      retries: 10

  api:
    build: .
    ports:
      - "8000:8000"
    environment:
      DATABASE_URL: postgresql+psycopg://bookapi:${POSTGRES_PASSWORD}@db:5432/bookapi
      SECRET_KEY: ${SECRET_KEY}
    volumes:
      - uploads:/app/uploads  # 올린 표지를 컨테이너 밖 볼륨에 저장합니다.
    depends_on:
      db:
        condition: service_healthy  # db가 연결을 받을 준비가 된 뒤에 시작합니다.

volumes:
  db-data:
  uploads:
부분설명
image: postgres:18PostgreSQL 공식 이미지 18판입니다. 7일차 RDS에서도 18판을 씁니다.
environment(db)공식 이미지는 처음 시작할 때 이 값으로 사용자, 비밀번호, 데이터베이스를 만듭니다.
db-data:/var/lib/postgresql데이터베이스 파일을 db-data 볼륨에 보관합니다.
healthcheckpg_isready로 연결을 받을 준비가 되었는지 5초마다 확인합니다.
build: .이 폴더의 Dockerfile로 API 이미지를 만듭니다.
DATABASE_URLpostgresql+psycopg://사용자:비밀번호@호스트:포트/데이터베이스 형식입니다. 호스트는 서비스 이름 db입니다.
depends_on ... service_healthydb의 healthcheck가 통과한 뒤에 api를 시작합니다. 데이터베이스가 아직 준비되지 않았는데 API가 먼저 접속하다 실패하는 일을 막습니다.
uploads:/app/uploads올린 표지 이미지를 볼륨에 보관합니다.

PostgreSQL 18부터 바뀐 볼륨 위치

인터넷의 많은 예제는 볼륨을 /var/lib/postgresql/data에 연결합니다. 이것은 17판까지의 방법입니다. 18판부터 공식 이미지는 /var/lib/postgresql에 연결하도록 바뀌었습니다. 18판에서 예전 경로로 연결하면 컨테이너가 시작하지 못하거나, 데이터가 볼륨이 아닌 곳에 저장되어 컨테이너를 지울 때 사라질 수 있습니다.

PostgreSQL 드라이버

SQLAlchemy가 PostgreSQL과 대화하려면 드라이버가 필요합니다. 주소의 postgresql+psycopg는 psycopg(3판) 드라이버를 쓰겠다는 뜻입니다. [binary]를 붙이면 따로 PostgreSQL 프로그램을 설치하지 않아도 되는 판이 설치됩니다.

pip install "psycopg[binary]"

.env에 비밀번호 추가하기

데이터베이스 비밀번호도 비밀 값이므로 compose.yaml에 적지 않고 .env에 넣습니다. Compose가 .env를 읽어 ${POSTGRES_PASSWORD}와 ${SECRET_KEY}를 채웁니다.

.env
POSTGRES_PASSWORD=추측하기어려운값

그런데 이 줄을 추가하면 로컬에서 uvicorn이나 pytest를 실행할 때 오류가 납니다.

pydantic_core._pydantic_core.ValidationError: 1 validation error for Settings
postgres_password
  Extra inputs are not permitted [type=extra_forbidden, input_value='...', input_type=str]

pydantic-settings는 .env에 설정 클래스에 없는 이름이 있으면 오타일 수 있다고 보고 거부합니다. 이제 .env를 앱과 Compose가 함께 쓰므로, 모르는 이름은 무시하도록 설정을 바꿉니다.

app/config.py
    model_config = SettingsConfigDict(
        env_file=".env",
        env_file_encoding="utf-8",
        extra="ignore",  # .env에 Compose가 쓰는 값(POSTGRES_PASSWORD)이 있어도 오류 없이 넘어갑니다.
    )

env_file을 쓰지 않은 이유

Compose에는 env_file: .env로 파일의 모든 값을 컨테이너에 넘기는 방법도 있습니다. 하지만 지금 .env의 DATABASE_URL은 로컬용 SQLite 주소라서, 통째로 넘기면 컨테이너도 SQLite를 쓰게 됩니다. 그래서 environment에 컨테이너용 값을 직접 적고, 비밀 값만 ${...}로 가져옵니다.
