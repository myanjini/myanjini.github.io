점검 도구 보기

점검을 사람 눈으로만 하면 빠뜨리기 쉽습니다. AWS는 설정을 자동으로 훑어 보여 주는 도구를 여럿 제공합니다. 이번 실습에서 쓸 도구와 각 도구가 보는 범위를 정리합니다.

도구무엇을 보나요요금이번 실습
IAM Access Analyzer(외부 액세스)S3 버킷, IAM 역할, KMS 키 같은 자원의 정책을 분석해, 내 계정 밖(다른 계정, 공개)에서 접근할 수 있는 자원을 찾습니다.추가 요금 없음분석기 결과 확인(기관이 만들어 둔 경우)
IAM Access Analyzer(정책 검사)정책을 저장할 때 문법 오류, 지나치게 넓은 권한 같은 문제를 알려 줍니다. S12에서 JSON 편집기 아래에 보인 경고입니다.추가 요금 없음역할의 인라인 정책 다시 열어 보기
IAM Access Analyzer(미사용 액세스)오래 쓰지 않은 역할, 권한을 찾습니다.역할과 사용자 수에 따라 요금개념만. 대신 역할의 "마지막 액세스" 탭으로 확인
Trusted AdvisorAWS의 모범 사례와 계정 설정을 비교합니다. 기본 지원 플랜에서도 보안 항목 일부(루트 MFA, 특정 포트 무제한 개방, S3 버킷 권한, 공개된 EBS와 RDS 스냅샷)를 볼 수 있습니다.기본 항목은 무료보안 항목 새로 고침 후 확인

IAM의 마지막 액세스 정보

IAM 콘솔에서 역할을 열고 마지막 액세스 탭을 보면, 그 역할이 각 서비스를 마지막으로 언제 썼는지 나옵니다. 오래 쓰지 않은 서비스의 권한은 지워도 되는 후보입니다. 예를 들어 EC2 역할에 실습 중 시험 삼아 붙였다가 쓰지 않은 권한이 있다면 여기서 드러납니다. 단, 정보는 몇 시간 늦게 반영되므로 오늘 처음 쓴 권한은 아직 안 보일 수 있습니다.

Security Hub

실무에서는 Security Hub로 여러 점검 결과를 한곳에 모으고, AWS 기초 보안 모범 사례 같은 기준으로 계정 전체를 자동 점검합니다. 점검 항목 수에 따라 요금이 붙어 이 과정에서는 쓰지 않지만, 오늘 손으로 하는 점검을 자동으로 계속 해 주는 서비스라고 기억해 둡니다.

도구가 보지 못하는 것

S11에서 bandit이 인가 누락을 찾지 못한 것처럼, 이 도구들도 "이 서비스에서 이 역할이 정말 이 권한을 써야 하는가"는 판단하지 못합니다. 도구 결과는 점검의 출발점이고, 최종 판단은 서비스의 구조를 아는 사람이 합니다.
