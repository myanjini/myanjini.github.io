스스로 묻고 답하기

질문 1. 누가 이 서비스를 쓰나요? 사용자 유형마다 할 수 있는 일이 다른가요?

예시 답안 보기

예(스터디 모임 관리): 로그인하지 않은 사람도 모임 목록을 봅니다. 로그인한 사용자는 모임을 열거나 참가 신청을 합니다. 모임을 연 사람(개설자)은 자기 모임을 수정, 삭제하고 참가자 명단을 봅니다. 관리자는 문제가 있는 모임을 지웁니다. 같은 "로그인 사용자"라도 자원마다 개설자인지에 따라 할 수 있는 일이 달라지므로, 역할 검사와 함께 소유자 검사가 필요합니다.

질문 2. 어떤 데이터를 다루나요? 그 가운데 남이 보면 안 되는 것은 무엇인가요?

예시 답안 보기

예: 사용자 이메일과 비밀번호(해시), 모임 정보, 누가 어느 모임에 참가했는지. 모임 정보는 공개해도 되지만, 참가자 명단은 개설자만 봐야 합니다. 명단에서도 이메일은 가립니다(S10-P33-03의 마스킹).

질문 3. 무엇이 위험한가요? 이 서비스에서 공격자가 가장 하고 싶은 일은 무엇일까요?

예시 답안 보기

예: 남의 모임 번호로 수정, 삭제 요청 보내기(OWASP API1), 참가자 명단으로 이메일 모으기(API3), 마지막 남은 자리를 동시에 여러 명이 신청하기(경쟁 조건), 요청 본문에 owner_id를 넣어 남을 개설자로 만들기(입력데이터 검증), 비밀번호 무차별 대입(반복된 인증시도 제한 기능 부재), 모임 소개에 스크립트 넣기(크로스사이트 스크립트, 화면이 생겼을 때).

질문 4. 위협마다 어떻게 막고, 막았다는 것을 어떻게 확인하나요?

예시 답안 보기

예: "남의 모임 수정"은 수정 함수에 개설자 검사를 넣어 막고(403), "다른 사용자가 수정하면 403이고 제목이 그대로다" 테스트로 확인합니다. 위협, 대책, 테스트를 한 줄로 묶어 두면 내일 구현과 테스트가 그대로 이어집니다.

질문 5. 하루 안에 끝내려면 무엇을 빼야 하나요?

예시 답안 보기

예: 파일 업로드, 알림, 검색 정렬 옵션 여러 개, 화면. 빼더라도 "인증, 소유자 검사, 입력 검증, 테스트, 배포"는 빼지 않습니다.
