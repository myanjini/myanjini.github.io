정리: 목록 조회

핵심 요약

  • 수정은 찾기, 검사하기, 속성 바꾸기, commit, refresh 순서이고, 삭제는 찾기, db.delete, commit 순서입니다.
  • 검색 조건은 목록에 모아 where(*conditions)로 겁니다.
  • 정렬처럼 SQL 문장 일부가 되는 값은 Literal로 허용한 값만 받습니다.
  • 목록 응답에 전체 개수를 함께 주면 클라이언트가 페이지를 계산할 수 있습니다.

확인 퀴즈

세션에서 꺼낸 book의 가격을 바꾼 뒤 데이터베이스에 반영하려면 무엇이 꼭 필요한가요?

세션이 지켜보는 객체는 속성을 바꾸고 commit하면 반영됩니다.

정렬 기준을 sort: str로 받아 그대로 SQL에 넣지 않고 Literal로 제한하는 이유는 무엇인가요?

정렬 열 이름은 값이 아니라 문장 일부라 따로 전달되지 않습니다. 허용 목록으로 막아야 안전합니다.

가격으로 정렬할 때 Book.id를 두 번째 기준으로 붙이는 이유는 무엇인가요?

순서가 매번 같아야 페이지를 넘길 때 도서가 겹치거나 빠지지 않습니다.
