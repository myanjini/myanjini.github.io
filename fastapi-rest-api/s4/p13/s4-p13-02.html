1:N 관계와 외래키

저자 한 명이 여러 도서를 쓰는 관계를 1:N 관계라고 합니다. 데이터베이스와 SQLAlchemy에서 이 관계를 표현하는 방법을 배웁니다.

외래키

외래키(foreign key)는 다른 테이블의 기본키를 가리키는 열입니다. books.author_id가 authors.id를 가리키도록 정하면, 데이터베이스는 없는 저자 번호가 들어오지 못하게 막을 수 있습니다.

author_id: Mapped[int] = mapped_column(ForeignKey("authors.id"))

SQLite는 기본적으로 외래키를 검사하지 않습니다

PostgreSQL은 외래키를 항상 검사하지만, SQLite는 기본 설정에서 검사하지 않습니다. 그래서 이 과정에서는 도서를 등록할 때 저자가 있는지 코드에서 직접 확인합니다. 어느 데이터베이스를 쓰든 클라이언트에게 알기 쉬운 오류를 주려면 어차피 이 확인이 필요합니다.

relationship

외래키만 있으면 도서에서 저자 이름을 얻을 때마다 번호로 저자를 다시 찾아야 합니다. relationship을 정의하면 book.author.name처럼 객체를 따라가듯 쓸 수 있습니다.

class Author(Base):
    books: Mapped[list["Book"]] = relationship(back_populates="author")


class Book(Base):
    author_id: Mapped[int] = mapped_column(ForeignKey("authors.id"))
    author: Mapped["Author"] = relationship(back_populates="books")
속성테이블에 열이 생기나요값
Book.author_id예저자 번호(정수)
Book.author아니요Author 객체 하나
Author.books아니요Book 객체 목록

back_populates는 두 속성이 같은 관계의 양쪽 끝이라고 알려 줍니다. 그래서 book.author를 바꾸면 author.books에도 반영됩니다. "Book"처럼 따옴표로 감싼 것은 아직 아래에서 정의되지 않은 클래스를 이름으로 가리키기 위해서입니다.
