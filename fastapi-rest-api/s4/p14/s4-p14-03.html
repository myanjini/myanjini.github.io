리비전 생성과 적용

Alembic으로 테이블을 처음부터 만들고, 데이터를 지키면서 새 열을 추가해 봅니다. 되돌리기도 직접 실행합니다.

실습 목표리비전을 자동 생성하고, 검토한 뒤 적용하고 되돌릴 수 있습니다.

  1. 설치, 초기화, env.py 수정

    서버를 끄고 앞 페이지대로 alembic 설치, alembic init migrations, env.py 수정, app/main.py의 create_all 삭제를 마칩니다.

  2. 마지막으로 한 번 데이터베이스 지우기

    지금의 books.db는 create_all이 만든 것이라 Alembic 기록이 없습니다. Alembic이 처음부터 만들도록 한 번만 더 지웁니다. 이번이 마지막입니다.

  3. 첫 리비전 자동 생성

    alembic revision --autogenerate -m "create authors and books"

    출력에 Detected added table 'authors', Detected added table 'books'가 보이고, migrations/versions에 파일이 하나 생깁니다. 파일을 열어 upgrade에 두 테이블을 만드는 코드가, downgrade에 두 테이블을 지우는 코드가 있는지 확인합니다.

    자동 생성된 upgrade 함수 예시 보기
    def upgrade() -> None:
    op.create_table('authors',
    sa.Column('id', sa.Integer(), nullable=False),
    sa.Column('name', sa.String(length=50), nullable=False),
    sa.PrimaryKeyConstraint('id'),
    sa.UniqueConstraint('name')
    )
    op.create_table('books',
    sa.Column('id', sa.Integer(), nullable=False),
    sa.Column('title', sa.String(length=100), nullable=False),
    sa.Column('price', sa.Integer(), nullable=False),
    sa.Column('isbn', sa.String(length=13), nullable=True),
    sa.Column('author_id', sa.Integer(), nullable=False),
    sa.ForeignKeyConstraint(['author_id'], ['authors.id'], ),
    sa.PrimaryKeyConstraint('id'),
    sa.UniqueConstraint('isbn')
    )

  4. 적용하고 데이터 넣기

    alembic upgrade head

    head는 가장 최신 리비전을 뜻합니다. 서버를 실행하고 S4-P13-04처럼 저자 세 명과 도서 네 권을 등록합니다. 이 데이터가 다음 단계에서 살아남는지 볼 것입니다.

  5. 모델에 출간 연도 추가

    app/models.py
        isbn: Mapped[str | None] = mapped_column(String(13), unique=True)
    published_year: Mapped[int | None]  # 출간 연도. 기존 도서에는 값이 없으므로 None을 허용합니다.

    응답과 요청에서도 쓰도록 스키마의 BookCreate, BookUpdate, BookRead에 같은 항목을 추가합니다.

    app/schemas.py
    # BookCreate, BookUpdate
published_year: int | None = Field(default=None, ge=1900, le=2100)

# BookRead
published_year: int | None = None

    이 상태에서 서버만 다시 시작하고 GET /books를 부르면 오류가 납니다. 모델에는 열이 있는데 데이터베이스에는 아직 없기 때문입니다. 마이그레이션이 필요한 순간입니다.

  6. 두 번째 리비전 생성과 검토

    alembic revision --autogenerate -m "add published_year to books"

    Detected added column 'books.published_year'가 보이면, 새 리비전 파일을 열어 내용을 확인합니다.

    def upgrade() -> None:
    with op.batch_alter_table('books', schema=None) as batch_op:
        batch_op.add_column(sa.Column('published_year', sa.Integer(), nullable=True))


def downgrade() -> None:
    with op.batch_alter_table('books', schema=None) as batch_op:
        batch_op.drop_column('published_year')

    기존 도서에는 출간 연도가 없으므로 nullable=True(값 없음 허용)인지 꼭 확인합니다.

  7. 적용하고 데이터 확인

    alembic upgrade head
alembic current
alembic history

    current는 지금 적용된 리비전을, history는 리비전 사슬을 보여 줍니다. 서버에서 GET /books를 부르면 등록했던 도서가 그대로 있고, published_year가 null로 붙어 있습니다. 데이터를 지우지 않고 열을 추가했습니다. PATCH /books/1로 {"published_year": 2024}를 보내 값도 넣어 봅니다.

  8. 되돌리고 다시 적용하기

    alembic downgrade -1
alembic upgrade head

    -1은 한 단계 뒤로라는 뜻입니다. 되돌리면 published_year 열이 사라지고, 다시 적용하면 열이 생깁니다. 하지만 1번 도서에 넣었던 2024는 돌아오지 않습니다. 열을 지우는 순간 그 열의 데이터도 함께 사라지기 때문입니다.

  9. 패키지 목록 갱신

    pip freeze > requirements.txt

    migrations 폴더와 alembic.ini는 Git에 함께 올립니다. 다른 사람도 alembic upgrade head 한 번으로 같은 테이블을 만들 수 있어야 하기 때문입니다.
