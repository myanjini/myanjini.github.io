업로드 API를 S3로 전환

S3 버킷을 만들고 EC2 역할에 권한을 더한 뒤, 표지 저장을 S3로 바꾼 새 버전(1.1.0)을 배포합니다. 브라우저에서 표지 주소를 열어 미리 서명된 URL로 이미지가 보이는지 확인합니다.

실습 목표비공개 S3 버킷에 표지를 저장하고, 미리 서명된 URL로 제공할 수 있습니다.

  1. 버킷 만들기(내 PC)

    이름이 전 세계에서 겹치지 않도록 식별자와 무작위 글자 4개를 붙입니다.

    Windows에서 실행할 때

    아래 명령에는 bash 문법(이름=값, $(...) 등)이 들어 있습니다. 내 PC가 Windows라면 명령 프롬프트가 아니라 Git Bash에서 실행합니다(S12-P40-03). EC2 서버의 접속 화면에서 실행하는 명령은 그대로 입력합니다.

    python -c "import secrets; print(secrets.token_hex(2))"
7f3k
BUCKET=book-api-covers-student07-7f3k
aws s3api create-bucket --bucket $BUCKET --region ap-northeast-2 --create-bucket-configuration LocationConstraint=ap-northeast-2
aws s3api put-bucket-tagging --bucket $BUCKET --tagging "TagSet=[{Key=Owner,Value=student07}]"

aws s3api get-public-access-block --bucket $BUCKET --query PublicAccessBlockConfiguration
{
    "BlockPublicAcls": true,
    "IgnorePublicAcls": true,
    "BlockPublicPolicy": true,
    "RestrictPublicBuckets": true
}
aws s3api get-bucket-encryption --bucket $BUCKET --query "ServerSideEncryptionConfiguration.Rules[0].ApplyServerSideEncryptionByDefault.SSEAlgorithm"
"AES256"

    퍼블릭 액세스 차단 네 가지가 모두 true, 기본 암호화가 AES256(SSE-S3)인지 확인합니다. secrets.token_hex(2)의 결과는 실행할 때마다 다르므로 위의 7f3k 대신 내 값을 씁니다.

  2. 역할에 권한 더하기

    IAM 콘솔에서 book-api-ec2-role을 열고 권한 추가, 인라인 정책 생성, JSON에 앞 페이지의 정책을 붙여 넣습니다. Resource의 버킷 이름을 내 버킷으로 바꾸고, 이름은 book-api-s3-covers로 합니다.

  3. 코드 바꾸고 확인(내 PC)

    앞 페이지대로 covers.py, main.py, config.py를 고치고 테스트를 더합니다. 운영용 Compose에도 버킷 설정을 더합니다(S15-P51에서 로그 설정까지 한꺼번에 바꾼 최종 파일을 봅니다). 지금은 environment에 아래 줄만 더하고, 볼륨 두 줄을 지웁니다.

    compose.prod.yaml의 environment에 추가
          COVER_BUCKET: ${COVER_BUCKET:?COVER_BUCKET을 .env에 적어 주세요}  # 표지를 저장할 S3 버킷
    pytest -q

  4. 새 버전 올리기(내 PC)

    REGISTRY=123456789012.dkr.ecr.ap-northeast-2.amazonaws.com
aws ecr get-login-password --region ap-northeast-2 | docker login --username AWS --password-stdin $REGISTRY
docker build --platform linux/amd64 -t $REGISTRY/book-api:1.1.0 -t $REGISTRY/book-api:git-$(git rev-parse --short HEAD) .
docker push $REGISTRY/book-api:1.1.0
docker push $REGISTRY/book-api:git-$(git rev-parse --short HEAD)

  5. 서버에서 바꾸기(EC2)

    cd ~/book-api
git pull
cat > .env <<EOF
IMAGE=123456789012.dkr.ecr.ap-northeast-2.amazonaws.com/book-api:1.1.0
COVER_BUCKET=book-api-covers-student07-7f3k
EOF
aws ecr get-login-password --region ap-northeast-2 | docker login --username AWS --password-stdin 123456789012.dkr.ecr.ap-northeast-2.amazonaws.com
docker compose -f compose.prod.yaml pull
docker compose -f compose.prod.yaml up -d
docker compose -f compose.prod.yaml ps --format "{{.Name}}  {{.Image}}  {{.Status}}"
book-api-api-1  123456789012.dkr.ecr.ap-northeast-2.amazonaws.com/book-api:1.1.0  Up 35 seconds (healthy)

    .env에는 비밀이 아닌 두 값만 있습니다.

  6. 표지 올리고 받아 보기(내 PC)

    API=http://3.35.120.45:8000
curl -s -X POST -H "Authorization: Bearer $TOKEN" -F "file=@cover.png" $API/books/1/cover
{"id":1,"title":"클라우드 입문",...,"cover_url":"/covers/667aefff1d7445a1bf430bce05e5c681.png",...}

curl -s -o /dev/null -D - $API/covers/667aefff1d7445a1bf430bce05e5c681.png | grep -i -E "^(HTTP|location)"
HTTP/1.1 307 Temporary Redirect
location: https://book-api-covers-student07-7f3k.s3.ap-northeast-2.amazonaws.com/covers/667aefff1d7445a1bf430bce05e5c681.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=...&X-Amz-Expires=300&X-Amz-Security-Token=...&X-Amz-Signature=...

aws s3 ls s3://$BUCKET/covers/
2026-11-24 10:12:03      48213 667aefff1d7445a1bf430bce05e5c681.png

    브라우저에서 $API/covers/이름.png를 열면 S3 주소로 넘어가 이미지가 보입니다. 주소창의 X-Amz-Expires=300은 5분 유효를 뜻합니다. 5분 뒤에 같은 S3 주소를 다시 열면 AccessDenied(Request has expired)가 나옵니다. 버킷의 객체 주소에서 ? 뒤를 지우고 열어도 AccessDenied입니다. 버킷이 비공개이기 때문입니다.

확인내 결과
버킷 이름
퍼블릭 액세스 차단 네 가지
표지 주소의 응답 코드와 Location의 X-Amz-Expires
서명 부분을 지운 S3 주소의 결과

어제 서버에 올린 표지

어제 서버 볼륨에 저장한 표지는 S3로 옮겨지지 않았으므로 주소를 열면 S3가 AccessDenied를 돌려줍니다(역할에 목록 조회 권한이 없어 "없음" 대신 "거부"로 보입니다). 실습에서는 표지를 다시 올립니다. 실제 서비스라면 옮기는 스크립트를 따로 실행합니다.
