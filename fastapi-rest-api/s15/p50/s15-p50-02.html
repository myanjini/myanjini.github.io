S3 핵심 개념

S3(Simple Storage Service)는 파일을 "객체"로 저장하는 서비스입니다. 서버의 디스크와 달리 용량 걱정이 없고, 서버가 몇 대든 같은 곳을 함께 씁니다. 대신 잘못 설정하면 전 세계에 파일을 공개하게 되므로, 접근 제어를 정확히 알고 써야 합니다.

버킷과 객체

용어뜻이번 실습
버킷(bucket)객체를 담는 최상위 통입니다. 이름은 전 세계 모든 AWS 계정에서 겹치지 않아야 합니다. 리전을 골라 만듭니다.book-api-covers-student07-7f3k(식별자와 무작위 글자를 붙임)
객체(object)저장한 파일 하나입니다. 내용, 메타데이터(Content-Type 등), 키로 이루어집니다.표지 이미지 한 장
키(key)버킷 안에서 객체의 이름입니다. covers/abc.png처럼 /를 넣어 폴더처럼 쓸 수 있지만, 실제 폴더는 없습니다.covers/32자리이름.png

기본으로 막혀 있는 것들

예전에는 버킷을 실수로 공개해 개인정보가 새는 사고가 많았습니다. 지금은 새로 만드는 버킷에 다음 설정이 기본으로 켜져 있습니다. 이번 실습은 이 기본값을 그대로 둡니다.

설정기본값뜻
퍼블릭 액세스 차단네 가지 모두 켜짐버킷 정책이나 ACL로 누군가 "모두에게 공개"를 설정해도 무시하고 막습니다.
객체 소유권버킷 소유자 적용(ACL 비활성화)객체마다 따로 권한을 주는 ACL을 쓰지 않고, IAM과 버킷 정책으로만 권한을 정합니다.
기본 암호화SSE-S3저장되는 모든 객체를 S3가 관리하는 키로 암호화합니다.

공개하지 않고 보여 주기: 미리 서명된 URL

버킷을 공개하지 않으면 브라우저는 표지 이미지를 어떻게 받을까요? 미리 서명된 URL(presigned URL)을 씁니다. 권한이 있는 쪽(도서 API)이 "이 객체를, 이 시간 동안만 내려받아도 된다"는 서명을 붙인 URL을 만들어 주면, 그 URL을 가진 사람은 권한 없이도 정해진 시간 동안 객체를 받을 수 있습니다.

장점설명
버킷은 계속 비공개URL을 모르거나 시간이 지나면 받을 수 없습니다.
서버를 거치지 않음이미지 내용은 S3에서 브라우저로 바로 갑니다. 서버의 네트워크와 CPU를 쓰지 않습니다.
권한 확인 지점이 하나URL을 만들어 주는 API에서 "누가 볼 수 있는가"를 판단할 수 있습니다.

미리 서명된 URL도 비밀번호처럼

URL 자체가 열쇠입니다. 유효 시간 안에는 누구에게 전달되든 열립니다. 그래서 유효 시간을 짧게(이번에는 5분) 두고, URL을 로그에 그대로 남기지 않습니다. 또 서명에 쓴 자격 증명이 먼저 만료되면 URL도 그때 함께 만료됩니다. EC2 역할의 임시 자격 증명으로 만든 URL은 길게 잡아도 몇 시간을 넘기지 못합니다.
