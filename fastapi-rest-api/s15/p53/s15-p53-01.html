배포 파이프라인 설계

이 파트의 학습 목표테스트, 보안 점검, 이미지 빌드, 배포를 하나의 파이프라인으로 자동화할 수 있습니다.

배포를 사람이 하면 단계를 빠뜨리거나, 테스트를 건너뛰거나, 누가 언제 무엇을 배포했는지 기록이 남지 않습니다. 배포 파이프라인은 정해진 순서를 매번 똑같이 실행하고, 실패하면 멈추고, 모든 실행을 기록합니다.

단계하는 일실패하면
testS7, S11에서 만든 테스트와 bandit, pip-audit배포하지 않습니다.
이미지이미지를 빌드해 ECR에 git-커밋 태그로 푸시배포하지 않습니다. 태그 변경 불가라 같은 커밋을 두 번 올리면 실패합니다.
배포Systems Manager Run Command로 EC2에 명령을 보내, .env의 IMAGE를 바꾸고 이미지 받기, 마이그레이션, 컨테이너 교체서버는 이전 컨테이너가 계속 돕니다(마이그레이션에서 실패한 경우).
확인ALB로 /health를 여러 번 시도실행이 실패로 표시되고 알림을 받습니다.

OIDC: 장기 액세스 키 없이 AWS에 접근

GitHub Actions가 ECR에 푸시하고 EC2에 명령을 보내려면 AWS 권한이 필요합니다. 예전에는 IAM 사용자의 액세스 키를 저장소 Secrets에 넣었지만, 그 키는 지우기 전까지 영원히 유효하고 저장소 설정을 볼 수 있는 사람에게 노출될 위험이 있습니다(S12-P41-04).

OIDC(OpenID Connect)를 쓰면 GitHub가 워크플로 실행마다 "이 실행은 어느 저장소의 어느 브랜치에서 왔다"는 서명된 토큰을 발급하고, AWS가 그 토큰을 확인해 IAM 역할의 임시 자격 증명을 줍니다. 저장소에는 비밀 값이 하나도 없습니다.

준비할 것어디에내용
OIDC 자격 증명 공급자IAM, 계정에 한 번token.actions.githubusercontent.com을 믿을 수 있는 발급자로 등록
배포 역할IAM신뢰 정책: 내 저장소의 main 브랜치에서 온 토큰만. 권한 정책: ECR 푸시(이 저장소만), 이 인스턴스에만 Run Command
워크플로 권한워크플로 파일id-token: write로 토큰 발급을 허용
저장소 변수GitHub 저장소 설정역할 ARN, 인스턴스 ID, ALB 주소. 비밀이 아니므로 Variables에 둡니다.

신뢰 정책의 핵심: 누가 이 역할을 맡을 수 있나

배포 역할의 신뢰 정책
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "arn:aws:iam::123456789012:oidc-provider/token.actions.githubusercontent.com"
      },
      "Action": "sts:AssumeRoleWithWebIdentity",
      "Condition": {
        "StringEquals": {
          "token.actions.githubusercontent.com:aud": "sts.amazonaws.com",
          "token.actions.githubusercontent.com:sub": "repo:내아이디@아이디번호/book-api@저장소번호:ref:refs/heads/main"
        }
      }
    }
  ]
}

sub 조건이 가장 중요합니다. 이 조건이 없거나 repo:*처럼 넓으면 GitHub의 다른 사람의 저장소에서 온 토큰도 이 역할을 맡을 수 있습니다. 내 저장소의 main 브랜치로 정확히 좁혀서, 풀 리퀘스트나 다른 브랜치에서 실행된 워크플로는 배포 권한을 얻지 못하게 합니다.

sub에는 아이디 번호와 저장소 번호가 들어갑니다

2026-07-15 이후에 만든 GitHub 저장소는 sub에 이름과 함께 바뀌지 않는 번호가 들어갑니다. 형식은 repo:아이디@아이디번호/저장소@저장소번호:ref:refs/heads/브랜치입니다. 저장소 이름을 바꾸거나 누군가 같은 이름을 다시 쓰더라도 다른 저장소로 구분하려는 변경입니다. 번호가 빠진 예전 형식으로 적으면 배포 단계가 Not authorized to perform sts:AssumeRoleWithWebIdentity로 실패합니다.

두 번호는 브라우저에서 https://api.github.com/repos/내아이디/book-api를 열어 확인합니다. 맨 위의 "id"가 저장소 번호이고, "owner" 안의 "id"가 아이디 번호입니다. 비공개 저장소는 이 주소가 404를 돌려주므로 gh api repos/내아이디/book-api --jq ".id, .owner.id"로 확인합니다. 2026-07-15 이전에 만든 저장소는 예전 형식(repo:내아이디/book-api:ref:refs/heads/main)을 그대로 씁니다.
