로그 조회와 경보 설정

로그 그룹을 만들고 컨테이너 로그를 CloudWatch로 보냅니다. Logs Insights로 요청 ID를 따라가 한 요청의 로그를 찾고, CPU와 상태 검사 경보를 만들어 메일로 받아 봅니다.

실습 목표컨테이너 로그를 CloudWatch에서 검색하고, 서버 이상을 알리는 경보를 설정할 수 있습니다.

  1. 로그 그룹 만들기(내 PC)

    aws logs create-log-group --log-group-name /book-api/app --tags Owner=student07
aws logs put-retention-policy --log-group-name /book-api/app --retention-in-days 30
aws logs describe-log-groups --log-group-name-prefix /book-api --query "logGroups[].[logGroupName,retentionInDays]" --output text
/book-api/app	30

  2. 역할에 권한 더하기

    IAM 콘솔에서 book-api-ec2-role에 앞 페이지의 정책을 인라인 정책 book-api-logs로 더합니다. Resource의 계정 ID를 내 값으로 바꿉니다.

  3. Compose 바꾸고 다시 시작(내 PC, EC2)

    내 PC에서 compose.prod.yaml을 앞 페이지의 최종 파일로 바꿔 푸시하고, 서버에서 받아 다시 시작합니다. 이미지는 그대로(1.1.0)입니다.

    cd ~/book-api
git pull
docker compose -f compose.prod.yaml up -d
docker compose -f compose.prod.yaml ps --format "{{.Name}}  {{.Status}}"
book-api-api-1  Up 40 seconds (healthy)

  4. 로그 확인

    내 PC에서 요청을 몇 번 보낸 뒤, 응답 헤더의 요청 ID를 적어 둡니다.

    curl -s -D - -o /dev/null http://3.35.120.45:8000/books | grep -i x-request-id
x-request-id: 3bdf17d7efda407c

aws logs tail /book-api/app --since 5m
2026-11-24T01:12:03.412000+00:00 7c1e... {"time": "...", "level": "INFO", "logger": "app.request", "message": "요청 처리", "request_id": "3bdf17d7efda407c", "method": "GET", "path": "/books", "status": 200, "duration_ms": 12.4}

    aws logs tail에 --follow를 붙이면 새 로그가 들어오는 대로 보여 줍니다. 콘솔의 CloudWatch, 로그 그룹, /book-api/app에서도 같은 로그를 볼 수 있습니다.

  5. Logs Insights로 요청 추적

    CloudWatch 콘솔의 Logs Insights에서 로그 그룹 /book-api/app을 고르고 아래 질의를 실행합니다. 요청 ID는 내 값으로 바꿉니다.

    요청 ID로 한 요청 찾기
    fields @timestamp, level, message, method, path, status, duration_ms
| filter request_id = "3bdf17d7efda407c"
| sort @timestamp asc

    사용자가 "오류가 났고 요청 ID가 3bdf...였다"고 알려 주면, 이 질의 하나로 그 요청에서 남은 모든 로그(경고, 오류 포함)를 시간 순서로 볼 수 있습니다. 다음 질의는 최근 오류 응답을 경로별로 셉니다. 일부러 틀린 비밀번호로 로그인하거나 없는 도서를 몇 번 조회한 뒤 실행해 봅니다.

    4xx, 5xx 응답 집계
    fields @timestamp, path, status
| filter status >= 400
| stats count() as requests by status, path
| sort requests desc
| limit 20

  6. 알림 받을 곳 만들기(SNS)

    aws sns create-topic --name book-api-alerts --tags Key=Owner,Value=student07 --query TopicArn --output text
arn:aws:sns:ap-northeast-2:123456789012:book-api-alerts
aws sns subscribe --topic-arn arn:aws:sns:ap-northeast-2:123456789012:book-api-alerts --protocol email --notification-endpoint 내메일@example.com

    메일함에 온 "AWS Notification - Subscription Confirmation" 메일의 Confirm subscription을 눌러야 알림을 받습니다. SNS(Simple Notification Service)는 메시지를 메일, 문자 같은 여러 곳으로 나눠 보내는 서비스입니다.

  7. 경보 두 개 만들기

    Windows에서 실행할 때

    아래 명령에는 bash 문법(이름=값, $(...) 등)이 들어 있습니다. 내 PC가 Windows라면 명령 프롬프트가 아니라 Git Bash에서 실행합니다(S12-P40-03). EC2 서버의 접속 화면에서 실행하는 명령은 그대로 입력합니다.

    INSTANCE=i-0123456789abcdef0
TOPIC=arn:aws:sns:ap-northeast-2:123456789012:book-api-alerts

aws cloudwatch put-metric-alarm --alarm-name book-api-cpu-high \
  --namespace AWS/EC2 --metric-name CPUUtilization --dimensions Name=InstanceId,Value=$INSTANCE \
  --statistic Average --period 300 --evaluation-periods 2 --threshold 80 \
  --comparison-operator GreaterThanOrEqualToThreshold \
  --alarm-actions $TOPIC --ok-actions $TOPIC --tags Key=Owner,Value=student07

aws cloudwatch put-metric-alarm --alarm-name book-api-status-check \
  --namespace AWS/EC2 --metric-name StatusCheckFailed --dimensions Name=InstanceId,Value=$INSTANCE \
  --statistic Maximum --period 60 --evaluation-periods 2 --threshold 1 \
  --comparison-operator GreaterThanOrEqualToThreshold \
  --alarm-actions $TOPIC --tags Key=Owner,Value=student07
    경보조건뜻
    book-api-cpu-high5분 평균 CPU 80% 이상이 2번 연속서버가 10분 넘게 바쁩니다. 무한 반복이나 공격을 의심합니다.
    book-api-status-check1분 동안 상태 검사 실패가 2번 연속서버나 그 아래 하드웨어에 문제가 생겼습니다.

  8. 경보가 오는지 시험

    aws cloudwatch set-alarm-state --alarm-name book-api-cpu-high --state-value ALARM --state-reason "알림 시험"

    몇 분 안에 "ALARM: book-api-cpu-high" 메일이 옵니다. 경보 상태는 다음 평가 때 실제 지표에 따라 OK로 돌아오고, OK 알림도 옵니다(--ok-actions).
