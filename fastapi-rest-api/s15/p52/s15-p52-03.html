ALB 뒤로 API 옮기기

ALB를 만들어 도서 API 앞에 두고, EC2 보안 그룹을 ALB에서 오는 요청만 허용하도록 바꿉니다. 마지막에 서버 IP로는 더 이상 직접 접속되지 않는지 확인합니다.

실습 목표ALB와 대상 그룹을 구성하고, 서버로 들어오는 길을 ALB 하나로 좁힐 수 있습니다.

  1. ALB 보안 그룹, 대상 그룹, ALB 만들기

    앞 페이지의 표대로 콘솔에서 세 가지를 차례로 만듭니다.

  2. EC2 보안 그룹에 ALB 허용 추가

    book-api-sg의 인바운드 규칙 편집에서 규칙을 하나 더합니다. 소스에는 sg-를 입력해 book-api-alb-sg를 고릅니다.

    유형포트소스설명
    사용자 지정 TCP8000book-api-alb-sgfrom ALB

    대상 그룹의 대상이 healthy가 될 때까지 30초쯤 기다립니다.

  3. ALB로 접속

    Windows에서 실행할 때

    아래 명령에는 bash 문법(이름=값, $(...) 등)이 들어 있습니다. 내 PC가 Windows라면 명령 프롬프트가 아니라 Git Bash에서 실행합니다(S12-P40-03). EC2 서버의 접속 화면에서 실행하는 명령은 그대로 입력합니다.

    aws elbv2 describe-load-balancers --names book-api-alb --query "LoadBalancers[0].[DNSName,State.Code]" --output text
book-api-alb-1234567890.ap-northeast-2.elb.amazonaws.com	active

aws elbv2 describe-target-health --target-group-arn $(aws elbv2 describe-target-groups --names book-api-tg --query "TargetGroups[0].TargetGroupArn" --output text) --query "TargetHealthDescriptions[].[Target.Id,TargetHealth.State]" --output text
i-0123456789abcdef0	healthy

ALB=http://book-api-alb-1234567890.ap-northeast-2.elb.amazonaws.com
curl -s $ALB/health
{"status":"ok","database":"ok"}

    휴대폰의 모바일 데이터로도 열어 봅니다. 이제는 어디서든 열려야 합니다.

  4. 서버로 가는 직접 경로 닫기

    book-api-sg에서 "내 IP"의 8000번 규칙을 삭제합니다. 남는 인바운드 규칙은 ALB 보안 그룹에서 오는 8000번 하나입니다.

    curl -s --max-time 5 http://3.35.120.45:8000/health; echo "exit=$?"
exit=28
curl -s $ALB/health
{"status":"ok","database":"ok"}

    exit=28은 시간 초과입니다. 서버의 IP로는 내 PC에서도 접속되지 않고, ALB로만 접속됩니다.

  5. 진짜 사용자 IP 확인

    ALB로 틀린 비밀번호 로그인을 한 번 보내고, Logs Insights나 서버의 DB에서 기록된 IP가 내 공인 IP인지 확인합니다. 서버에서는 컨테이너 안에서 확인합니다.

    docker compose -f compose.prod.yaml exec api python -c "from app.database import SessionLocal; from sqlalchemy import text; print(SessionLocal().execute(text('select ip from login_failures order by id desc limit 1')).first())"
('203.0.113.25',)

    FORWARDED_ALLOW_IPS가 빠져 있으면 10.0.1.x나 10.0.2.x(ALB의 사설 IP)가 나옵니다.

  6. 헬스 체크 동작 보기

    서버에서 컨테이너를 잠깐 멈추고, 대상 상태와 ALB 응답을 봅니다. 확인한 뒤 바로 다시 시작합니다.

    docker compose -f compose.prod.yaml stop
(30초 뒤 내 PC에서)
curl -s -o /dev/null -w "%{http_code}\n" $ALB/health
502
docker compose -f compose.prod.yaml start

    뒤에 정상 대상이 하나도 없으면 ALB는 502나 503을 돌려줍니다. 서버가 한 대뿐이라 대신 받을 곳이 없기 때문입니다. 서버를 두 대 이상 두면 한 대가 멈춰도 서비스가 이어집니다.
