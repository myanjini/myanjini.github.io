ALB 구성 과정 보기

ALB는 보안 그룹, 대상 그룹, 로드 밸런서 순서로 만듭니다. 콘솔에서 고를 값과 이유를 정리합니다.

1. ALB 보안 그룹

항목값
이름book-api-alb-sg, VPC book-api-vpc
인바운드HTTP 80, 출처 0.0.0.0/0(HTTPS를 쓰면 443도)
아웃바운드기본값(모두 허용). ALB가 EC2의 8000번으로 요청을 보냅니다.

2. 대상 그룹

항목값이유
대상 유형인스턴스EC2 인스턴스를 직접 등록합니다.
이름book-api-tg
프로토콜과 포트HTTP, 8000컨테이너가 열어 둔 포트입니다. ALB와 EC2 사이는 VPC 안이므로 HTTP를 씁니다.
VPCbook-api-vpc
헬스 체크 경로/healthDB 연결까지 확인하는 경로입니다(S8).
고급: 정상 임계값, 비정상 임계값2, 2두 번 연속 성공하면 정상, 두 번 연속 실패하면 비정상
고급: 간격, 제한 시간15초, 5초기본값(30초)보다 빨리 알아챕니다.
고급: 성공 코드200/health는 DB가 끊기면 503을 돌려주므로, 그때는 비정상이 됩니다.
대상 등록book-api-server, 포트 8000

3. 로드 밸런서

항목값이유
유형Application Load BalancerHTTP와 HTTPS를 이해하는 7계층 로드 밸런서
이름book-api-alb
체계인터넷 경계인터넷에서 접속합니다.
IP 주소 유형IPv4
네트워크 매핑book-api-vpc, 가용 영역 a와 c의 퍼블릭 서브넷ALB는 두 가용 영역 이상이 필요합니다.
보안 그룹book-api-alb-sg만(default 제거)
리스너HTTP 80, 기본 작업: book-api-tg로 전달
태그Owner

ALB가 "활성"이 되기까지 2~3분 걸립니다. 그동안 대상 그룹의 대상 탭에서 상태가 initial에서 healthy로 바뀌는지 봅니다. unhealthy로 남으면 대부분 EC2 보안 그룹이 ALB에서 오는 8000번을 막고 있는 것입니다. 다음 실습에서 이 순서로 고칩니다.
