검증 오류 읽기

일부러 잘못된 데이터를 보내 422 응답을 받아 보고, 응답만 보고 무엇이 잘못되었는지 찾아냅니다.

질문 1. Swagger UI에서 POST /books에 아래 데이터를 보내 보세요. 응답의 loc와 msg는 무엇이고, 무엇이 잘못되었다는 뜻인가요?

{"title": "", "author": "최유나", "price": 27000}

예시 답안 보기

loc는 ["body", "title"], msg는 String should have at least 1 character입니다. 요청 본문의 title이 최소 길이 1을 채우지 못했다는 뜻입니다. type은 string_too_short로 나옵니다.

질문 2. 이번에는 가격에 음수를 넣어 보내 보세요. 어떤 규칙에 걸렸나요?

{"title": "FastAPI 실전", "author": "최유나", "price": -1000}

예시 답안 보기

loc는 ["body", "price"], msg는 Input should be greater than or equal to 0입니다. Field(ge=0) 규칙에 걸렸습니다.

질문 3. author를 빼고 보내면 어떤 응답이 오나요? 그리고 왜 이 검사가 서버에 꼭 있어야 할까요?

{"title": "FastAPI 실전", "price": 27000}

예시 답안 보기

loc는 ["body", "author"], msg는 Field required입니다. 필수 항목이 빠졌다는 뜻입니다.

화면(클라이언트)에서 입력을 검사하더라도, 누군가 curl 같은 도구로 화면을 거치지 않고 서버에 직접 요청할 수 있습니다. 그래서 서버의 검사가 마지막 방어선이 됩니다.
