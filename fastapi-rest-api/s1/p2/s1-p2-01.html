FastAPI와 Uvicorn

이 파트의 학습 목표가상환경에 FastAPI를 설치하고 첫 API 서버를 실행할 수 있습니다.

API 서버를 만들 때 쓰는 두 도구, FastAPI와 Uvicorn이 각각 무슨 일을 하는지 알아봅니다.

웹 프레임워크가 필요한 이유

API 서버는 매번 비슷한 일을 반복합니다. 요청을 받아 주소와 메서드를 확인하고, 함께 온 데이터를 꺼내 검사하고, 결과를 JSON으로 바꿔 돌려줍니다. 이런 반복 작업을 대신해 주는 도구가 웹 프레임워크입니다. 덕분에 우리는 "이 요청이 오면 무엇을 할지"만 작성하면 됩니다.

FastAPI의 특징

특징설명
타입 힌트로 검증함수에 book_id: int처럼 타입을 적으면 FastAPI가 요청 값을 그 타입으로 바꾸고, 바꿀 수 없으면 자동으로 오류를 돌려줍니다.
자동 API 문서작성한 코드를 바탕으로 /docs 주소에 API 문서를 만들어 줍니다. 이 문서 화면에서 API를 직접 호출해 볼 수도 있습니다.
빠른 성능여러 요청을 동시에 처리하는 비동기 방식을 지원해, 기다리는 시간이 많은 서버에서 효율이 좋습니다.
Python 표준 문법새로운 문법을 배우지 않고 Python 함수와 클래스로 작성합니다.

Uvicorn은 무엇을 하나요

FastAPI로 작성한 코드는 혼자서 네트워크 요청을 받지 못합니다. 컴퓨터의 포트(예: 8000번)를 열고 요청을 기다렸다가 FastAPI에 넘겨 주는 서버 프로그램이 필요하고, 그 역할을 Uvicorn이 맡습니다.

식당에 비유하면 Uvicorn은 손님을 맞아 주문을 받아 주방에 전달하는 홀 직원이고, FastAPI는 주문서를 보고 음식을 만드는 주방입니다. 메뉴와 조리법(우리가 작성하는 코드)은 주방에 있습니다.

Uvicorn과 FastAPI가 주고받는 방식에는 ASGI라는 정해진 약속이 있습니다. 이 약속 덕분에 서버 프로그램과 웹 프레임워크를 따로 골라 조합할 수 있습니다. 지금은 이름만 기억해 두면 충분합니다.

우리가 실행할 명령

이 과정에서는 fastapi dev main.py 명령으로 서버를 실행합니다. 이 명령이 내부에서 Uvicorn을 실행해 주므로 Uvicorn을 따로 실행할 일은 거의 없습니다.
