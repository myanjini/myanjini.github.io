요청 제한의 운영 방식

요청 제한은 애플리케이션 한곳에서만 하지 않습니다. 요청이 서버에 닿기 전의 여러 단계에서 나눠 맡습니다.

위치잘하는 일못하는 일
애플리케이션(오늘 만든 것)계정별 실패 횟수처럼 업무를 알아야 하는 규칙요청이 이미 서버까지 와서 서버의 힘을 쓴 뒤에 막습니다.
WAF(웹 방화벽, AWS WAF)IP별 요청 수 제한, 알려진 공격 패턴과 봇 차단누가 어떤 계정으로 몇 번 실패했는지는 모릅니다.
로드 밸런서, API 게이트웨이연결 수 관리, API 전체의 초당 요청 수 제한세밀한 업무 규칙

두 겹이 함께 있어야 합니다. 대량의 요청은 앞단에서 걸러 서버를 지키고, 앞단을 통과한 정교한 시도는 애플리케이션이 업무 규칙으로 막습니다. 8일차에 로드 밸런서를 구성할 때 이 구조를 다시 봅니다.

로그인 말고도 제한할 곳

회원가입(가짜 계정 대량 생성), 대여(S6의 1인 3권 한도), 업로드(S6의 2MB 제한)처럼 남용될 수 있는 기능도 요청 제한의 대상입니다. OWASP API 목록의 API4(제한 없는 자원 소비)와 API6(민감한 업무 흐름 무제한 접근)이 이것입니다.
