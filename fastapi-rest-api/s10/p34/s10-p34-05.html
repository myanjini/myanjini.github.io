정리: 인증 강화

핵심 요약

  • 로그인은 무차별 대입, 사전 공격, 크리덴셜 스터핑, 패스워드 스프레이의 대상이 됩니다.
  • NIST 최신 지침은 길이와 금지 목록을 중시하고, 조합 규칙과 정기 변경을 강제하지 않습니다. 정책은 서비스와 규정에 맞게 조직이 정합니다.
  • 계정 기준과 IP 기준을 함께 쓰고, 비밀번호 확인 전에 검사해 429와 Retry-After로 응답합니다.
  • 없는 계정도 똑같이 막아 가입 여부를 숨기고, 성공하면 실패 기록을 지웁니다.
  • 대량 공격은 WAF 같은 앞단에서, 업무 규칙이 필요한 공격은 애플리케이션에서 막습니다.

확인 퀴즈

흔한 비밀번호 하나를 수천 개 계정에 한 번씩 넣어 보는 공격을 막는 데 효과적인 것은 무엇인가요?

계정마다 실패가 한 번뿐이라 계정 기준 제한에 걸리지 않습니다. IP 기준 제한과 금지 목록이 막습니다.

로그인 잠금을 비밀번호 확인 전에 검사하는 이유는 무엇인가요?

확인 후에 막으면 응답 차이로 맞혔는지 알 수 있습니다.

서명 알고리즘을 none으로 바꾼 토큰이 통과하지 못하는 이유는 무엇인가요?

허용 알고리즘을 고정하지 않으면 헤더의 alg를 믿게 되어 서명 검사를 건너뛸 수 있습니다.
