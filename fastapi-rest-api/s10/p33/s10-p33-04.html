전송 구간 보호

저장을 아무리 잘 해도 오가는 길에서 새면 소용없습니다. 비밀번호와 토큰이 지나가는 길을 보호하는 방법을 정리합니다. 실제 적용은 8일차에 합니다.

HTTPS

HTTP는 내용을 그대로 보내므로 같은 와이파이, 회사 네트워크, 중간의 통신 장비에서 로그인 요청의 비밀번호와 응답의 토큰을 그대로 볼 수 있습니다. HTTPS는 TLS로 통신을 암호화하고, 접속한 서버가 진짜인지 인증서로 확인합니다. KISA 가이드의 중요정보 평문 전송 약점을 막는 기본 방법입니다.

구간보호 방법이 과정
사용자와 서버 사이HTTPS(TLS 인증서)8일차 로드 밸런서에 ACM 인증서 적용(S15-P52-04)
서버와 데이터베이스 사이데이터베이스 연결 암호화7일차 RDS 전송 구간 SSL(S13-P46-04)
서버와 외부 서비스 사이https 주소만 사용S9-P31-04의 URL 검사

HSTS

사용자가 주소창에 http://로 들어오면 첫 요청은 암호화되지 않은 채 갑니다. Strict-Transport-Security: max-age=31536000; includeSubDomains 헤더를 받은 브라우저는 그 뒤 1년 동안 이 사이트에 항상 HTTPS로만 접속합니다. 이 헤더는 HTTPS 응답에만 의미가 있으므로 HTTPS를 적용하는 곳에서 함께 설정합니다.

쿠키 보안 속성

도서 API는 토큰을 응답 본문으로 주지만, 웹 서비스에서는 리프레시 토큰을 쿠키에 담는 경우가 많습니다(S5-P18-04). 그때는 다음 속성을 반드시 붙입니다.

속성뜻막는 것
SecureHTTPS 연결에서만 보냅니다.평문 전송 중 탈취
HttpOnlyJavaScript가 읽을 수 없습니다.XSS로 토큰 탈취(S9-P31)
SameSite=Strict 또는 Lax다른 사이트에서 보낸 요청에는 쿠키를 붙이지 않습니다.크로스사이트 요청 위조(CSRF)
FastAPI에서 쿠키를 설정하는 예
response.set_cookie("refresh_token", token, httponly=True, secure=True, samesite="strict",
                    max_age=14 * 24 * 3600, path="/auth")
