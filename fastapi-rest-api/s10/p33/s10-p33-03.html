비밀정보 정리

내 프로젝트에서 비밀 값을 점검하고, 약한 비밀 키로는 서버가 시작하지 않게 막고, 관리자 목록 화면의 이메일을 가립니다.

실습 목표비밀 값을 점검하고 정리하며, 약한 키를 거부하는 설정과 개인정보 마스킹을 적용할 수 있습니다.

    app/config.py
    from pydantic import field_validator
from pydantic_settings import BaseSettings, SettingsConfigDict

# 예시나 기본값으로 흔히 쓰이는, 비밀 키로 쓰면 안 되는 값
WEAK_SECRETS = {"change-me", "changeme", "secret", "secret-key", "your-secret-key"}


class Settings(BaseSettings):
    """환경 변수와 .env 파일에서 설정값을 읽습니다. 이름은 대소문자를 가리지 않습니다."""

    model_config = SettingsConfigDict(
        env_file=".env",
        env_file_encoding="utf-8",
        extra="ignore",  # .env에 Compose가 쓰는 값(POSTGRES_PASSWORD)이 있어도 오류 없이 넘어갑니다.
        hide_input_in_errors=True,  # 설정 오류 메시지에 입력한 값(비밀 키)을 찍지 않습니다.
    )

    app_name: str = "도서 관리 API"
    database_url: str = "sqlite:///./books.db"
    secret_key: str  # 기본값이 없으므로 반드시 설정해야 합니다.
    access_token_expire_minutes: int = 15  # 액세스 토큰 유효 시간(분). 재발급이 생겨 짧게 줄입니다.
    refresh_token_expire_days: int = 14  # 리프레시 토큰 유효 기간(일)
    upload_dir: str = "uploads"  # 올린 파일을 저장할 폴더
    log_level: str = "INFO"  # DEBUG, INFO, WARNING, ERROR 중 하나
    cors_origins: list[str] = ["http://localhost:5173"]

    @field_validator("secret_key")
    @classmethod
    def check_secret_key(cls, value: str) -> str:
        """예시 값이나 짧은 값으로는 서버가 시작하지 않게 합니다."""
        if len(value) < 32 or value.lower() in WEAK_SECRETS:
            raise ValueError("SECRET_KEY는 secrets 모듈로 만든 32자 이상의 값이어야 합니다.")
        return value


settings = Settings()

  5. 관리자 목록에서 이메일 가리기

    관리자도 목록 화면에서는 누가 누구인지만 알면 됩니다. 전체 이메일은 한 명을 골라 상세 조회할 때만 보여 줍니다. 필요한 만큼만 보여 주는 것이 개인정보 보호의 기본입니다.

    app/privacy.py
    """개인정보와 비밀 값을 가리는 도구"""


def mask_email(email: str) -> str:
    """user1@example.com을 us***@example.com처럼 앞 두 글자와 도메인만 남깁니다."""
    local, _, domain = email.partition("@")
    if not domain:
        return "***"
    return f"{local[:2]}***@{domain}"
    app/schemas.py
    class UserSummary(UserRead):
    """목록 화면용 사용자 정보. 이메일은 일부만 보여 줍니다."""

    @field_serializer("email")
    def mask_email_field(self, email: str) -> str:
        return mask_email(email)

    app/schemas.py 위쪽 가져오기에 field_serializer와 from app.privacy import mask_email를 추가합니다. field_serializer는 응답으로 바꿀 때만 값을 바꾸므로 데이터베이스의 값은 그대로입니다.

def test_admin_user_list_masks_email(client, make_user):
    admin = make_user("admin@example.com", role="admin")
    users = client.get("/admin/users", headers=admin).json()
    assert users[0]["email"] == "ad***@example.com"
    detail = client.get(f"/admin/users/{users[0]['id']}", headers=admin).json()
    assert detail["email"] == "admin@example.com"  # 상세 조회에서만 전체를 보여 줍니다.
