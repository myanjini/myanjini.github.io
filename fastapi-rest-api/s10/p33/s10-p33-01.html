중요정보와 암호화

이 파트의 학습 목표중요정보의 평문 저장, 전송과 하드코딩을 찾아 안전하게 바꿀 수 있습니다.

비밀번호, 토큰, 비밀 키, 개인정보처럼 새면 피해가 생기는 정보를 중요정보라고 합니다. 중요정보를 어떻게 저장하고, 어떤 알고리즘으로 보호하고, 비밀 값을 어떻게 만드는지 정리합니다.

도서 API의 중요정보

중요정보어디에 있나요지금의 보호
비밀번호회원가입, 로그인 요청Argon2 해시로만 저장(S5-P15)
리프레시 토큰로그인 응답, refresh_tokens 테이블SHA-256 해시로만 저장(S5-P18)
JWT 서명 키(SECRET_KEY).env코드와 Git에서 분리(S3-P9)
데이터베이스 비밀번호.env의 POSTGRES_PASSWORD코드와 Git에서 분리(S8-P27)
이메일users 테이블, 관리자 API 응답오늘 목록 화면에서 일부를 가립니다.

KISA 가이드의 보안기능 유형에는 이와 관련된 보안약점이 여럿 있습니다. 중요정보 평문 저장, 중요정보 평문 전송, 하드코드된 중요정보, 취약한 암호화 알고리즘 사용, 충분하지 않은 키 길이 사용, 적절하지 않은 난수 값 사용입니다.

인코딩, 해시, 암호화

방법되돌릴 수 있나요보호하나요예
인코딩누구나 되돌립니다.보호하지 않습니다. 모양만 바꿉니다.Base64, JWT의 페이로드(S5-P16)
해시되돌릴 수 없습니다.원래 값을 숨기고, 같은지만 확인합니다.비밀번호(Argon2), 리프레시 토큰(SHA-256)
암호화키가 있으면 되돌립니다.키가 없는 사람에게서 내용을 숨깁니다.HTTPS 통신, 디스크 암호화

"Base64로 바꿨으니 안전하다"는 흔한 착각입니다. Base64는 암호가 아닙니다. 다시 꺼내 써야 하는 값(예: 외부 서비스의 API 키를 데이터베이스에 보관)은 암호화하고, 확인만 하면 되는 값(비밀번호)은 해시합니다.

비밀 값은 secrets로 만듭니다

Python의 random 모듈은 게임이나 시뮬레이션용입니다. 몇 개의 결과를 보면 다음 값을 예측할 수 있고, 같은 시드(seed)를 주면 같은 값이 나옵니다.

>>> import random
>>> random.seed(42); random.randint(0, 999999)
670487
>>> random.seed(42); random.randint(0, 999999)
670487

토큰, 비밀 키, 인증 번호처럼 추측되면 안 되는 값은 운영체제의 안전한 난수를 쓰는 secrets 모듈로 만듭니다. 도서 API는 리프레시 토큰을 secrets.token_urlsafe(32)로 만들고 있습니다.

함수용도
secrets.token_urlsafe(32)URL에 넣어도 되는 43글자 토큰(비밀 키, 리프레시 토큰)
secrets.token_hex(32)64글자 16진수 문자열
secrets.randbelow(1000000)0부터 999999 사이의 인증 번호
secrets.compare_digest(a, b)걸리는 시간으로 내용을 짐작할 수 없게 두 값을 비교
