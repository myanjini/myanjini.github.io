정보가 새는 응답 찾기

도서 API의 응답과 로그를 공격자의 눈으로 다시 보며 정보가 새는 곳을 찾습니다. 아래는 모두 지금 코드에서 실제로 나온 결과입니다.

1. 422 응답이 보낸 값을 되돌려 줍니다

POST /auth/signup  {"email": "leak@example.com", "password": "pw-leak"}

422 {"detail": [{"type": "string_too_short", "loc": ["body", "password"],
      "msg": "String should have at least 10 characters", "input": "pw-leak", "ctx": {"min_length": 10}}]}

FastAPI의 기본 422 응답은 검사에 실패한 값을 input에 그대로 담습니다. 비밀번호가 응답에 실려 돌아오고, 이 응답을 기록하는 장비나 브라우저 확장 프로그램이 있으면 그곳에 남습니다.

2. SQL 오류에 값이 들어 있습니다

(sqlite3.IntegrityError) UNIQUE constraint failed: users.email
[SQL: INSERT INTO users (email, hashed_password, role) VALUES (?, ?, 'user')]
[parameters: ('user1@example.com', '$argon2id$v=19$m=65536,t=3,p=4$abc$def')]

SQLAlchemy의 오류 메시지는 SQL 문장과 함께 넘긴 값까지 보여 줍니다. 처리하지 못한 오류로 로그에 남으면 이메일과 비밀번호 해시가 로그에 쌓입니다. S9-P30에서 SQL 삽입 오류 로그에 SQL 문장이 그대로 찍힌 것도 같은 이유입니다.

3. 500 응답에 요청 ID가 없습니다

처리하지 못한 오류가 나면 Internal Server Error라는 글자만 갑니다. 내부 정보가 새지는 않지만 형식이 다른 응답과 다르고, 요청 ID 헤더도 빠져 사용자가 알려 줄 단서가 없습니다. 개발할 때 FastAPI(debug=True)로 바꾸면 트레이스백 전체가 화면에 나오므로 운영에서는 절대 쓰지 않습니다.

4. 응답 헤더가 내부를 알려 줍니다

헤더알려 주는 것
server: uvicorn서버 프로그램 이름. 공격자는 그 프로그램의 알려진 취약점부터 시험합니다.
x-process-time: 1.7ms처리 시간. 계정이 있을 때와 없을 때의 시간 차이처럼 내부 동작을 짐작하는 단서가 됩니다.

5. 운영 환경에서 API 문서가 열려 있습니다

/docs와 /openapi.json은 모든 API의 주소, 매개변수, 오류 코드를 보여 줍니다. /admin 아래의 관리자 API 목록도 그대로 보입니다. 개발과 테스트 때는 꼭 필요하지만, 일반 사용자에게 공개하는 운영 서버에서는 끕니다. OWASP API 목록의 API8(보안 설정 오류)과 API9(부적절한 자산 관리)에 해당합니다.

질문. 다섯 가지 중 내 서비스에서 가장 먼저 고칠 것을 고르고, 그 이유를 적어 보세요.

예시 답안 보기

1번(422의 비밀번호 반환)과 2번(로그 속 이메일과 해시)을 먼저 고칩니다. 실제 중요정보가 응답과 로그에 남는 문제이기 때문입니다. 3번과 4번은 공격 단서를 줄이는 일이고, 5번은 운영 환경 설정이므로 배포 전까지 반드시 처리합니다. 순서와 상관없이 다음 실습에서 다섯 가지를 모두 고칩니다.
