비밀정보 이전

도서 API가 Parameter Store에서 비밀 값을 읽게 코드를 바꾸고, 비밀 키와 DB 접속 정보를 Parameter Store로 옮긴 뒤, EC2에서 비밀 값 파일 없이 컨테이너를 실행합니다.

실습 목표비밀 값을 Parameter Store의 SecureString으로 옮기고, 서버 디스크에 비밀 값 파일 없이 API를 실행할 수 있습니다.

  1. 내 PC: 코드 바꾸기

    boto3를 설치하고 패키지 목록을 다시 저장합니다.

    pip install boto3
pip freeze > requirements.txt

    app/config.py 맨 위에 import os를 추가하고, 앞 페이지의 load_ssm_parameters 함수를 settings = Settings() 바로 위에 넣습니다. tests/test_ssm.py도 만듭니다.

    pytest -q
...
64 passed
bandit -r app -ll -q
pip-audit -r requirements.txt
No known vulnerabilities found

git add .
git commit -m "Parameter Store에서 비밀 값 읽기"
git push

  2. Parameter Store에 등록

    새 비밀 키를 만듭니다. 오전에 서버에서 만든 값은 파일에 평문으로 있었으므로, 옮기는 김에 새 값으로 바꿉니다.

    python -c "import secrets; print(secrets.token_urlsafe(32))"

    콘솔에서 앞 페이지의 표대로 두 파라미터를 만듭니다. /book-api/DATABASE_URL의 값은 오전에 ~/book-api.env에 적은 RDS 주소(postgresql+psycopg://bookapi:...@...:5432/bookapi?sslmode=require) 그대로입니다. 그다음 CLI로 등록 결과를 확인합니다. --with-decryption을 붙이지 않았으므로 값은 암호화된 채로 보입니다.

    aws ssm get-parameters --names /book-api/SECRET_KEY /book-api/DATABASE_URL --query "Parameters[].[Name,Type,Version]" --output table
------------------------------------------------
|                 GetParameters                |
+--------------------------+---------------+---+
|  /book-api/DATABASE_URL  |  SecureString |  1|
|  /book-api/SECRET_KEY    |  SecureString |  1|
+--------------------------+---------------+---+

  3. EC2: 역할로 읽히는지 확인

    Session Manager로 접속해 확인합니다. 값이 화면에 찍히지 않도록 이름과 글자 수만 봅니다.

    Windows에서 실행할 때

    아래 명령에는 bash 문법(이름=값, $(...) 등)이 들어 있습니다. 내 PC가 Windows라면 명령 프롬프트가 아니라 Git Bash에서 실행합니다(S12-P40-03). EC2 서버의 접속 화면에서 실행하는 명령은 그대로 입력합니다.

    aws ssm get-parameters --names /book-api/SECRET_KEY /book-api/DATABASE_URL --with-decryption --query "Parameters[].[Name,length(Value)]" --output text
/book-api/DATABASE_URL	128
/book-api/SECRET_KEY	43

aws ssm get-parameter --name /other-app/DB_PASSWORD
An error occurred (AccessDeniedException) when calling the GetParameter operation: User: arn:aws:sts::123456789012:assumed-role/book-api-ec2-role/i-0123... is not authorized to perform: ssm:GetParameter on resource: arn:aws:ssm:ap-northeast-2:123456789012:parameter/other-app/DB_PASSWORD ...

TOKEN=$(curl -s -X PUT http://169.254.169.254/latest/api/token -H "X-aws-ec2-metadata-token-ttl-seconds: 60")
curl -s -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/instance-id; echo
i-0123456789abcdef0
aws ec2 describe-instances --instance-ids i-0123456789abcdef0 --query "Reservations[].Instances[].MetadataOptions.[HttpTokens,HttpPutResponseHopLimit]" --output text
An error occurred (UnauthorizedOperation) ...

    역할은 /book-api/ 아래만 읽을 수 있고, 다른 경로는 거부됩니다. 마지막 명령은 서버의 역할에 EC2 조회 권한이 없어 거부되는 것이 정상입니다. 홉 제한은 내 PC에서 확인합니다.

    aws ec2 describe-instances --filters Name=tag:Name,Values=book-api-server --query "Reservations[].Instances[].MetadataOptions.[HttpTokens,HttpPutResponseHopLimit]" --output text
required	2

    값이 1이면 내 PC에서 aws ec2 modify-instance-metadata-options --instance-id 인스턴스ID --http-put-response-hop-limit 2 --http-tokens required로 바꿉니다.

  4. EC2: 새 코드로 이미지 만들고 실행

    이번에도 서버에서 빌드합니다. 다음 파트에서 ECR로 바꿉니다.

    cd ~/book-api
git pull
docker build -t book-api .
docker rm -f book-api
docker run -d --name book-api -p 8000:8000 \
  -e SSM_PREFIX=/book-api/ -e AWS_DEFAULT_REGION=ap-northeast-2 -e APP_ENV=development \
  -v book-uploads:/app/uploads --restart unless-stopped book-api
curl -s localhost:8000/health
{"status":"ok","database":"ok"}

    환경 변수로 넣은 것은 비밀이 아닌 세 가지뿐입니다. 컨테이너가 시작하면서 Parameter Store에서 비밀 키와 DB 주소를 읽어 RDS에 연결했습니다. 비밀 키를 바꿨으므로 오전에 받은 토큰은 더 이상 쓸 수 없습니다. 다시 로그인합니다.

  5. 비밀 값 파일 지우고 확인

    rm ~/book-api.env
docker inspect book-api --format "{{json .Config.Env}}"
["SSM_PREFIX=/book-api/","AWS_DEFAULT_REGION=ap-northeast-2","APP_ENV=development","PATH=...","LANG=C.UTF-8",...]
grep -rl "postgresql+psycopg" ~ 2>/dev/null
(아무것도 나오지 않음)

    컨테이너 설정에도, 서버 디스크에도 비밀 값이 없습니다. 값은 컨테이너 프로세스의 메모리에만 있습니다.
