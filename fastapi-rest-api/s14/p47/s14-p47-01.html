클라우드에서 비밀정보 다루기

이 파트의 학습 목표Parameter Store로 비밀정보를 관리하고 IAM 역할로 안전하게 읽을 수 있습니다.

오전에 도서 API의 비밀 키와 DB 암호를 EC2 홈 폴더의 파일(~/book-api.env)에 두었습니다. 권한을 600으로 막았지만, 서버의 디스크에 비밀 값이 평문으로 남아 있습니다. 이번 파트에서는 비밀 값을 서버 밖의 보관소로 옮기고, 서버는 IAM 역할로 필요할 때만 읽게 바꿉니다.

서버 파일에 비밀 값을 두면 생기는 문제

문제예
복사본이 늘어남서버를 두 대로 늘리면 파일도 두 벌이 되고, 값을 바꿀 때 모든 서버를 찾아다녀야 합니다.
디스크와 백업에 남음서버의 디스크 스냅샷이나 이미지를 만들면 비밀 값도 함께 복사됩니다.
누가 읽었는지 모름서버에 접속한 사람은 누구나 cat으로 읽을 수 있고, 기록이 남지 않습니다.
바꾸기 어려움값을 바꾼 이력과 이전 값이 남지 않아, 잘못 바꾸면 되돌리기 어렵습니다.

값이 몇 개이고 교체를 직접 해도 되는 작은 서비스는 Parameter Store의 SecureString으로 충분합니다. DB 암호를 정기적으로 자동 교체해야 하는 서비스라면 Secrets Manager를 고려합니다.

앱이 비밀 값을 읽는 흐름

앱은 액세스 키 없이 EC2에 붙은 역할의 임시 자격 증명으로 요청합니다(S12-P41). 역할의 정책이 /book-api/* 읽기만 허용하므로, 앱은 자기 비밀 값만 읽을 수 있습니다. 누가 언제 어떤 파라미터를 읽었는지는 CloudTrail에 기록됩니다.

컨테이너가 인스턴스 메타데이터에 닿는 조건

앱은 서버가 아니라 서버 안의 컨테이너에서 돌기 때문에, 메타데이터 서비스까지 네트워크를 한 단계 더 거칩니다. IMDSv2의 응답이 거칠 수 있는 단계 수(홉 제한)가 1이면 컨테이너까지 오지 못합니다. Amazon Linux 2023으로 만든 인스턴스는 컨테이너를 위해 홉 제한이 2로 정해지므로 이번 구성에서는 따로 할 일이 없습니다. 실습에서 값을 확인해 봅니다.
