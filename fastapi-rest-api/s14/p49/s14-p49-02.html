운영용 Compose 설정

S8에서 만든 개발용 Compose 파일은 PostgreSQL 컨테이너를 함께 띄우고, 소스에서 이미지를 빌드했습니다. 운영용은 데이터베이스를 RDS로, 이미지를 ECR로, 비밀 값을 Parameter Store로 바꾼 별도의 파일입니다.

compose.prod.yaml
# 운영(EC2)용 Compose 파일
# - 이미지는 ECR에서 받습니다. 어떤 이미지를 쓸지는 같은 폴더의 .env에 IMAGE=... 로 적습니다.
# - 비밀 값(SECRET_KEY, DATABASE_URL)은 이 파일에도 .env에도 적지 않고, 앱이 Parameter Store에서 읽습니다.
# - 데이터베이스는 RDS를 쓰므로 db 서비스가 없습니다.
services:
  api:
    image: ${IMAGE:?IMAGE를 .env에 적어 주세요}
    restart: unless-stopped
    ports:
      - "8000:8000"
    environment:
      APP_ENV: production              # /docs, /redoc, /openapi.json을 끕니다.
      SSM_PREFIX: /book-api/           # 이 경로 아래의 비밀 값을 읽습니다.
      AWS_DEFAULT_REGION: ap-northeast-2
      LOG_LEVEL: INFO
    volumes:
      - uploads:/app/uploads
    healthcheck:
      test: ["CMD", "python", "-c", "import urllib.request; urllib.request.urlopen('http://localhost:8000/health')"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 20s
    logging:
      driver: json-file
      options:
        max-size: "10m"   # 로그 파일 하나가 10MB를 넘으면 새 파일로 바꿉니다.
        max-file: "3"     # 최대 3개까지만 남겨 디스크가 차지 않게 합니다.

volumes:
  uploads:
설정뜻
image: ${IMAGE:?...}실행할 이미지를 같은 폴더의 .env에서 읽습니다. 값이 없으면 :? 뒤의 문구를 보여 주고 멈춥니다. 태그를 파일에 고정하지 않아, 배포할 때 .env 한 줄만 바꿉니다.
build가 없음서버에서 빌드하지 않습니다.
environment비밀이 아닌 설정만 적습니다. SSM_PREFIX로 비밀 값을 읽습니다.
restart: unless-stopped컨테이너가 죽거나 서버가 재부팅되면 다시 시작합니다.
healthcheck30초마다 컨테이너 안에서 /health를 부릅니다. 세 번 연속 실패하면 unhealthy로 표시됩니다. start_period 동안의 실패는 세지 않아, Parameter Store를 읽고 시작하는 시간을 기다려 줍니다.
loggingDocker가 모으는 로그 파일을 10MB씩 최대 3개로 제한합니다.
db 서비스가 없음데이터베이스는 RDS입니다.

운영용 파일도 저장소에 함께 올립니다. 비밀 값이 하나도 없으므로 올려도 안전하고, 서버의 설정이 어떤지 코드처럼 리뷰하고 이력을 남길 수 있습니다.

Compose의 .env와 앱의 .env

서버 폴더의 .env는 Compose가 ${IMAGE} 같은 변수를 채울 때 읽는 파일이고, 컨테이너 안으로 들어가지 않습니다. 이미지에는 .dockerignore 때문에 내 PC의 .env도 들어가지 않습니다(S8-P26). 그래서 서버의 .env에는 비밀이 아닌 IMAGE만 둡니다.
