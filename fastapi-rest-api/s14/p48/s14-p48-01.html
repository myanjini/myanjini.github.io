컨테이너 레지스트리와 ECR

이 파트의 학습 목표컨테이너 이미지를 ECR에 올리고 EC2에서 받아 실행할 수 있습니다.

컨테이너 레지스트리는 Docker 이미지를 보관하고 나눠 주는 저장소입니다. S8에서 python:3.12-slim을 내려받은 Docker Hub가 공개 레지스트리의 예입니다. 내 서비스의 이미지는 아무나 받을 수 없는 프라이빗 레지스트리에 둡니다.

레지스트리를 쓰면 달라지는 것

서버에서 빌드(오전)레지스트리에서 받기(지금부터)
서버에 필요한 것소스 코드, Git 접근 권한, 빌드 도구이미지를 받을 권한만
같은 이미지인가서버마다 빌드한 시점의 패키지가 달라질 수 있음한 번 만든 이미지를 모든 서버가 똑같이 받음
되돌리기이전 커밋을 받아 다시 빌드이전 버전 태그의 이미지를 받아 실행
빌드 부담작은 서버의 CPU와 메모리를 씀내 PC나 CI가 빌드

Amazon ECR

ECR(Elastic Container Registry)은 AWS의 컨테이너 레지스트리입니다. 저장소(repository)를 만들고 그 안에 태그가 붙은 이미지를 올립니다.

기능뜻이번 실습
프라이빗 저장소IAM 권한이 있어야 올리고 받을 수 있습니다.book-api 저장소
태그 변경 불가(Immutable)이미 있는 태그로 다른 이미지를 올리지 못하게 합니다. 1.0.0이 언제나 같은 이미지를 가리키게 됩니다.켬
이미지 스캔올린 이미지 안의 운영체제 패키지와 라이브러리에 알려진 취약점이 있는지 검사합니다. 기본 스캔은 추가 요금이 없습니다.푸시할 때 스캔
수명 주기 정책오래된 이미지를 규칙에 따라 자동으로 지웁니다.개념만(S18 정리 때 직접 삭제)
암호화저장된 이미지는 기본으로 암호화됩니다.기본값

요금은 저장한 이미지의 용량(GB당 월 요금)과, 다른 리전이나 인터넷으로 내보낸 데이터에 붙습니다. 같은 리전의 EC2가 받는 것은 데이터 전송 요금이 없습니다. 실습 이미지 몇 개는 1GB를 넘지 않습니다.

pip-audit과 이미지 스캔의 차이

S11의 pip-audit은 requirements.txt의 Python 패키지만 봅니다. ECR 스캔은 이미지 안의 운영체제 패키지(베이스 이미지인 Debian의 라이브러리 등)까지 봅니다. 서로 보는 범위가 다르므로 둘 다 씁니다.
