이미지 푸시 과정 보기

이미지를 ECR에 올리는 과정은 저장소 만들기, 로그인, 태그 붙이기, 푸시, 스캔 결과 확인의 다섯 단계입니다. 각 단계의 명령과 뜻을 먼저 봅니다.

단계명령뜻
1. 저장소 만들기aws ecr create-repository이미지를 담을 저장소를 만듭니다. 한 번만 합니다.
2. 로그인aws ecr get-login-password | docker loginAWS 권한으로 12시간 동안 쓸 수 있는 레지스트리 암호를 받아 Docker에 로그인합니다.
3. 태그 붙이기docker build -t 레지스트리/book-api:1.0.0이미지 이름에 레지스트리 주소가 들어가야 그곳으로 올라갑니다.
4. 푸시docker push이미지를 올립니다. 이미 있는 층(layer)은 다시 올리지 않습니다.
5. 스캔 결과aws ecr describe-image-scan-findings심각도별 취약점 수를 확인합니다.

레지스트리 주소

ECR의 주소는 계정ID.dkr.ecr.리전.amazonaws.com이고, 이미지 전체 이름은 주소/저장소:태그입니다.

123456789012.dkr.ecr.ap-northeast-2.amazonaws.com/book-api:1.0.0

로그인과 푸시

푸시 명령의 모양
REGISTRY=123456789012.dkr.ecr.ap-northeast-2.amazonaws.com
aws ecr get-login-password --region ap-northeast-2 | docker login --username AWS --password-stdin $REGISTRY
docker build --platform linux/amd64 -t $REGISTRY/book-api:1.0.0 .
docker push $REGISTRY/book-api:1.0.0
부분뜻
get-login-password내 IAM 권한으로 레지스트리 암호를 받아 화면 대신 다음 명령으로 넘깁니다.
--password-stdin암호를 명령 기록에 남기지 않고 표준 입력으로 받습니다.
--platform linux/amd64EC2(x86_64)에서 돌아갈 이미지를 만듭니다. Apple Silicon Mac에서 이 옵션을 빼면 ARM용 이미지가 만들어져 EC2에서 exec format error로 실행되지 않습니다. Intel이나 AMD PC에서는 붙여도 결과가 같습니다.

로그인 정보가 남는 곳

docker login에 성공하면 Docker가 레지스트리 암호를 ~/.docker/config.json(또는 운영체제의 자격 증명 저장소)에 저장합니다. 12시간 뒤에 만료되지만, 이 파일을 공유하거나 저장소에 올리지 않습니다.

스캔 결과 읽기

aws ecr describe-image-scan-findings --repository-name book-api --image-id imageTag=1.0.0 --query "imageScanFindings.findingSeverityCounts"
{
    "MEDIUM": 6,
    "LOW": 14,
    "INFORMATIONAL": 3
}

숫자는 베이스 이미지의 시점에 따라 다릅니다. HIGH나 CRITICAL이 있으면 결과를 열어 어떤 패키지인지 보고, 베이스 이미지를 최신으로 다시 받아 빌드(docker build --pull)하거나 고친 버전으로 올립니다. 운영체제 패키지의 취약점은 아직 고친 버전이 없는 경우도 많아, S11-P37처럼 근거를 들어 판정하고 기록합니다.
