정리: 권한 검사

핵심 요약

  • get_current_user 의존성이 토큰을 꺼내고, 검증하고, 사용자를 찾습니다. 실패하면 401입니다.
  • 토큰을 검증할 때는 서명 방식(algorithms)을 고정하고, exp와 sub가 있는지 확인합니다.
  • 사용자 정보가 필요하면 매개변수(user: CurrentUserDep)로, 검사만 필요하면 dependencies=[Depends(...)]로 연결합니다.
  • 인가는 두 가지입니다. 역할 검사(require_admin)와 데이터 주인 검사(check_can_modify)입니다.
  • 순서는 인증(401), 대상 찾기(404), 권한 검사(403)입니다.

확인 퀴즈

Authorization 헤더 없이 DELETE /books/5를 보냈습니다. 결과는 무엇인가요?

누구인지 확인할 수 없으므로 권한 검사까지 가지 않고 401입니다.

일반 사용자의 역할을 admin으로 바꿨습니다. 이 사용자가 관리자 기능을 쓰려면 어떻게 해야 하나요?

역할은 토큰이 아니라 데이터베이스에서 요청마다 읽으므로 바로 반영됩니다.

저자 등록 API에 dependencies=[Depends(require_admin)]를 쓴 이유로 알맞은 것은 무엇인가요?

결과 값이 필요 없는 검사용 의존성은 데코레이터의 dependencies에 넣습니다.
