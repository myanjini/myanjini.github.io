현재 사용자 의존성

이 파트의 학습 목표현재 사용자 의존성으로 API를 보호하고 소유자와 역할에 따라 권한을 검사할 수 있습니다.

보호된 API마다 "토큰을 꺼내고, 검증하고, 사용자를 찾는" 코드를 반복해 쓸 수는 없습니다. 2일차에 배운 의존성으로 이 일을 한곳에 모읍니다.

토큰 검증 함수

app/security.py
def decode_access_token(token: str) -> int | None:
    """토큰이 올바르면 사용자 번호를, 아니면 None을 돌려줍니다."""
    try:
        payload = jwt.decode(
            token,
            settings.secret_key,
            algorithms=[ALGORITHM],              # 이 방식으로 서명한 토큰만 받습니다.
            options={"require": ["exp", "sub"]},  # 만료 시각과 사용자 번호가 꼭 있어야 합니다.
        )
    except jwt.InvalidTokenError:  # 서명이 틀렸거나, 만료되었거나, 형식이 깨진 경우
        return None
    return int(payload["sub"])
옵션하는 일
algorithms=[ALGORITHM]우리가 정한 HS256으로 서명한 토큰만 받습니다. 헤더의 alg를 바꿔 서명 검사를 피하려는 토큰을 막습니다.
options={"require": [...]}exp나 sub가 없는 토큰을 거부합니다. 만료 시각이 없으면 영원히 쓸 수 있는 토큰이 되기 때문입니다.
except jwt.InvalidTokenError서명 불일치, 만료, 형식 오류를 모두 이 한 가지 예외로 잡습니다. 만료 검사는 jwt.decode가 알아서 합니다.

현재 사용자 의존성

app/dependencies.py
# 요청의 Authorization 헤더에서 "Bearer 토큰"의 토큰 부분을 꺼내 줍니다.
# tokenUrl은 Swagger UI의 Authorize 창이 로그인할 때 부를 주소입니다.
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/auth/token", auto_error=False)
TokenDep = Annotated[str | None, Depends(oauth2_scheme)]

BEARER = {"WWW-Authenticate": "Bearer"}


def get_current_user(db: SessionDep, token: TokenDep) -> User:
    """토큰을 검사해 지금 요청을 보낸 사용자를 돌려줍니다."""
    if token is None:
        raise AppError(401, "NOT_AUTHENTICATED", "로그인이 필요합니다.", headers=BEARER)
    user_id = decode_access_token(token)
    if user_id is None:
        raise AppError(401, "INVALID_TOKEN", "토큰이 유효하지 않거나 만료되었습니다.", headers=BEARER)
    user = db.get(User, user_id)
    if user is None:  # 토큰은 올바르지만 그사이 탈퇴한 사용자
        raise AppError(401, "INVALID_TOKEN", "토큰이 유효하지 않거나 만료되었습니다.", headers=BEARER)
    return user


CurrentUserDep = Annotated[User, Depends(get_current_user)]

OAuth2PasswordBearer는 기본적으로 헤더가 없으면 스스로 401을 보내는데, 그 응답은 {"detail": "Not authenticated"} 모양이라 우리 API의 {"code", "message"} 형식과 다릅니다. 그래서 auto_error=False로 토큰이 없을 때 None만 받고, 오류는 직접 만듭니다.

상황응답
Authorization 헤더가 없음401, NOT_AUTHENTICATED, 로그인이 필요합니다.
서명이 틀림, 만료됨, 형식이 깨짐401, INVALID_TOKEN
토큰은 올바르지만 그 사용자가 없음401, INVALID_TOKEN
모두 통과User 객체를 돌려줍니다.

토큰에는 사용자 번호만 들어 있으므로, 요청마다 데이터베이스에서 사용자를 다시 읽습니다. 번거로워 보이지만 장점이 있습니다. 관리자로 바꾸거나 탈퇴 처리한 결과가 토큰을 새로 받지 않아도 다음 요청부터 바로 반영됩니다.
