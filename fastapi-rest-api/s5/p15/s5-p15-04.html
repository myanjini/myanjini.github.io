회원가입 API

사용자 테이블을 만들고 회원가입 API를 구현합니다. 데이터베이스에 비밀번호가 해시로만 저장되는지 직접 확인합니다.

실습 목표비밀번호를 해시로 저장하는 회원가입 API를 만들고, 중복 이메일을 409로 막을 수 있습니다.

  1. 설치하고 User 모델 추가

    서버를 끄고 pip install "pwdlib[argon2]"를 실행합니다. 앞 페이지의 User 클래스를 app/models.py의 Author 위에 추가합니다.

  2. 리비전 만들고 적용

    alembic revision --autogenerate -m "create users"
alembic upgrade head

    리비전 파일을 열어 users 테이블만 만드는지 확인한 뒤 적용합니다. 2일차에 넣은 저자와 도서 데이터는 그대로 남습니다.

  3. security.py 만들기

    app/security.py를 새로 만들고 앞 페이지의 코드를 넣습니다.

  4. 스키마 추가

    app/schemas.py 맨 위의 가져오기에 EmailStr를 더하고, UserCreate와 UserRead를 AuthorCreate 위에 추가합니다.

    app/schemas.py
    from pydantic import BaseModel, ConfigDict, EmailStr, Field

  5. 인증 라우터 만들기

    app/routers/auth.py
    from fastapi import APIRouter, status
from sqlalchemy import select

from app.dependencies import SessionDep
from app.errors import AppError
from app.models import User
from app.schemas import UserCreate, UserRead
from app.security import hash_password

router = APIRouter(prefix="/auth", tags=["인증"])


@router.post("/signup", response_model=UserRead, status_code=status.HTTP_201_CREATED, summary="회원가입",
             responses={409: {"description": "이미 가입된 이메일"}})
def signup(db: SessionDep, user_in: UserCreate):
    email = user_in.email.lower()  # 대문자로 적어도 같은 이메일로 봅니다.
    if db.scalar(select(User).where(User.email == email)) is not None:
        raise AppError(409, "DUPLICATE_EMAIL", "이미 가입된 이메일입니다.")
    user = User(email=email, hashed_password=hash_password(user_in.password))
    db.add(user)
    db.commit()
    db.refresh(user)
    return user

    이메일을 소문자로 바꿔 저장하고 비교합니다. 이렇게 하지 않으면 User1@Example.com과 user1@example.com이 다른 사람으로 가입됩니다. 저장할 때는 hash_password를 거친 값만 hashed_password에 넣습니다.

  6. 앱에 연결

    app/main.py
    from app.routers import auth, authors, books

app.include_router(auth.router)
app.include_router(authors.router)
app.include_router(books.router)

  7. Swagger UI로 확인

    서버를 실행하고 /docs에 새로 생긴 인증 묶음에서 POST /auth/signup으로 요청을 보냅니다.

    요청 본문기대하는 결과내 결과
    {"email": "user1@example.com", "password": "practice-pass-1"}201, {"id": 1, "email": "user1@example.com", "role": "user"}
    {"email": "User1@Example.com", "password": "practice-pass-1"}409, DUPLICATE_EMAIL
    {"email": "not-an-email", "password": "practice-pass-1"}422, value is not a valid email address
    {"email": "user9@example.com", "password": "short"}422, String should have at least 8 characters

    마지막 요청으로 만든 user2@example.com은 S5-P17에서 "다른 사용자"로 씁니다.

  8. 데이터베이스에서 직접 확인

    응답에 비밀번호가 없다는 것만으로는 부족합니다. 실제로 무엇이 저장되었는지 봅니다.

    python -c "import sqlite3; print(sqlite3.connect('books.db').execute('select email, hashed_password from users').fetchall())"

    hashed_password가 $argon2id$로 시작하고, 어디에도 practice-pass-1이라는 글자가 보이지 않으면 성공입니다. 두 사용자의 해시가 완전히 다르다는 것도 확인합니다.
