방향배울 것지금 구성에서 바뀌는 점첫 연습
컨테이너 운영Amazon ECS와 Fargate, 컨테이너 오케스트레이션(Kubernetes, Amazon EKS)서버(EC2)를 직접 관리하지 않고, 컨테이너 여러 개를 자동으로 띄우고 늘리고 교체합니다. 배포 중 중단도 없앨 수 있습니다.프로젝트를 ECS Fargate 서비스로 옮기고 ALB에 연결
코드로 만드는 인프라(IaC)AWS CloudFormation, AWS CDK, Terraform콘솔에서 누르던 VPC, 보안 그룹, RDS, 역할을 코드로 적고 Git으로 관리합니다. 같은 환경을 여러 번 만들고 한 번에 지울 수 있습니다.이번 과정의 VPC와 보안 그룹을 코드로 다시 만들기
보안 심화OWASP ASVS(검증 기준), 위협 모델링, 동적 점검(DAST) 도구, AWS WAF, Secrets Manager 자동 교체점검표를 더 체계적인 기준으로 바꾸고, 실행 중인 API를 공격자처럼 점검하며, 비밀 값을 자동으로 교체합니다.프로젝트를 ASVS 인증 항목으로 점검하고 결과표 만들기
관측성지표(메트릭), 분산 추적(OpenTelemetry, AWS X-Ray), 대시보드와 경보 설계로그만으로는 알기 어려운 "어디가 느린가", "얼마나 실패하는가"를 숫자와 추적으로 봅니다.요청 수, 오류율, 응답 시간을 CloudWatch 대시보드로 만들기

백엔드 개발 자체를 넓히는 주제

주제왜 필요한가
비동기 데이터베이스 접근(async SQLAlchemy)요청이 많을 때 기다리는 시간을 줄입니다(S1-P3-04의 async def).
캐시(Redis)자주 읽는 데이터를 데이터베이스 대신 메모리에서 돌려줍니다. 로그인 실패 횟수 같은 값도 여기에 둡니다.
백그라운드 작업 큐메일 발송, 이미지 변환처럼 오래 걸리는 일을 요청과 떼어 처리합니다.
API 버전 관리와 문서화이미 쓰는 사용자를 깨뜨리지 않고 API를 바꿉니다.
