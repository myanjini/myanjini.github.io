README 작성

README는 저장소에 처음 온 사람이 가장 먼저 읽는 문서입니다. 평가하는 사람도 README로 프로젝트를 처음 만납니다. 템플릿 안내였던 README를 내 프로젝트 소개로 다시 씁니다.

실습 목표실행 방법, API 목록, 보안 조치 요약, 배포 확인 방법을 담은 README를 작성할 수 있습니다.

README에 담을 것

순서항목쓰는 법
1프로젝트 소개누가, 무엇을, 왜. 한 문장
2실행 방법처음 받은 사람이 그대로 따라 하면 실행되는 명령. 테스트 실행과 통과 개수까지
3API 목록docs/api-spec.md 링크. 핵심 API 몇 개는 표로
4보안 조치 요약위협, 조치, 확인 테스트를 한 줄씩. 자기 진단표 링크
5배포배포 구성 한 줄, 확인 방법(/health, 시연 스크립트). 과정이 끝나면 자원을 지우므로 주소는 "과정 중에만 접속 가능"으로 적습니다.

예시(스터디 모임 API)

README.md
# 스터디 모임 API

회원이 스터디 모임을 열고, 다른 회원이 정원 안에서 참가 신청을 하는 API입니다.

## 실행 방법

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env               # SECRET_KEY를 새로 만들어 채웁니다.
alembic upgrade head
uvicorn app.main:app --reload      # http://localhost:8000/docs
pytest -q                          # 28개 통과
```

## API 목록

자세한 명세는 [docs/api-spec.md](docs/api-spec.md)를 봅니다.

## 보안 조치 요약

| 위협 | 조치 | 테스트 |
|---|---|---|
| 남의 모임 수정, 삭제 | 서비스에서 개설자 검사(403) | tests/test_permissions.py |
| 참가자 이메일 수집 | 명단은 개설자만, 이메일 가림 | tests/test_permissions.py |
| 정원 초과(동시 신청) | 조건부 UPDATE, 유일 제약 | tests/test_members.py |
| 소유자 필드 조작 | 정의하지 않은 필드 422 | tests/test_studies.py |
| 비밀번호 무차별 대입 | 15분에 5번 실패하면 429 | tests/test_auth.py |

자기 진단 결과는 [docs/security-diagnosis.md](docs/security-diagnosis.md)에 있습니다.

## 배포

GitHub Actions(OIDC) → ECR → EC2(Docker Compose) → RDS PostgreSQL, ALB로 공개합니다.
비밀 값은 Parameter Store(/project-api/)에 있고 저장소와 서버 파일에는 없습니다.
배포 주소는 과정 중에만 접속할 수 있습니다.
