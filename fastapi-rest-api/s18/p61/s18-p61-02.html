AWS 배포

8일차에 만든 배포 구성(EC2, RDS, ALB, 배포 워크플로)을 그대로 써서 프로젝트를 배포합니다. 새로 만드는 것은 프로젝트만의 이미지 저장소, 데이터베이스, 비밀 값, 로그 그룹뿐이고, 나머지는 권한 범위를 넓혀 함께 씁니다.

실습 목표기존 배포 파이프라인과 서버를 재사용해 프로젝트를 AWS에 배포하고, ALB 주소로 동작을 확인할 수 있습니다.

무엇을 새로 만들고 무엇을 바꾸나요

자원도서 API프로젝트할 일
ECR 저장소book-apiproject-api새로 만들기
RDS의 데이터베이스와 계정bookapi(마스터 계정)projectapi(앱 전용 계정 projectapp)같은 RDS 안에 새로 만들기
Parameter Store/book-api/*/project-api/*새로 만들기
로그 그룹/book-api/app/project-api/app새로 만들기
EC2 역할book-api-ec2-role같은 역할파라미터와 로그 권한에 새 경로 추가
배포 역할book-api-github-deploy같은 역할신뢰 정책에 새 저장소, ECR 권한에 새 저장소 추가
EC2, ALB, 대상 그룹8000번, /health같은 포트, 같은 경로도서 API 컨테이너를 내리고 프로젝트 컨테이너를 올리기

RDS에 앱 전용 계정을 만드는 이유

7일차에는 단순하게 마스터 계정 하나로 도서 API를 연결했고, 실제 서비스에서는 앱 전용 계정을 따로 만든다고 했습니다(S13-P46-04). 같은 RDS에 두 앱이 함께 있게 되었으므로 이번에는 그렇게 합니다. 프로젝트 계정은 자기 데이터베이스(projectapi)에만 접속할 수 있고, 도서 API의 데이터는 볼 수 없습니다. 하나가 뚫려도 다른 하나는 지킬 수 있습니다.

  1. ECR 저장소와 로그 그룹(내 PC)

    Windows에서 실행할 때

    아래 명령에는 bash 문법(이름=값, $(...) 등)이 들어 있습니다. 내 PC가 Windows라면 명령 프롬프트가 아니라 Git Bash에서 실행합니다(S12-P40-03). EC2 서버의 접속 화면에서 실행하는 명령은 그대로 입력합니다.

    aws ecr create-repository --repository-name project-api --image-tag-mutability IMMUTABLE \
  --image-scanning-configuration scanOnPush=true --tags Key=Owner,Value=student07 \
  --query repository.repositoryUri --output text
123456789012.dkr.ecr.ap-northeast-2.amazonaws.com/project-api

aws logs create-log-group --log-group-name /project-api/app --tags Owner=student07
aws logs put-retention-policy --log-group-name /project-api/app --retention-in-days 30

  2. 앱 전용 DB 계정 암호와 비밀 값(내 PC)

    앱 계정 암호와 JWT 서명 키를 새로 만들어 Parameter Store에 넣습니다. 도서 API의 값을 다시 쓰지 않습니다. 앱 계정 암호는 다음 단계에서 한 번 더 입력해야 하므로, 화면에 한 번 출력해 복사해 둡니다.

    APP_PW=$(python -c "import secrets; print(secrets.token_urlsafe(24))")
echo $APP_PW        # 다음 단계에서 붙여 넣을 값. 복사한 뒤 clear로 화면을 지웁니다.

aws ssm put-parameter --name /project-api/SECRET_KEY --type SecureString --tags Key=Owner,Value=student07 \
  --value "$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"
aws ssm put-parameter --name /project-api/DATABASE_URL --type SecureString --tags Key=Owner,Value=student07 \
  --value "postgresql+psycopg://projectapp:$APP_PW@book-api-db.xxxxxxxxxxxx.ap-northeast-2.rds.amazonaws.com:5432/projectapi?sslmode=require"
unset APP_PW

  3. 데이터베이스와 계정 만들기(EC2)

    Session Manager로 EC2에 접속해 마스터 계정으로 RDS에 들어갑니다(S13-P46-03). \password는 암호를 화면에 보이지 않게 두 번 묻습니다. 앞 단계에서 복사한 값을 붙여 넣습니다. 이렇게 하면 암호가 명령 기록에 남지 않습니다.

    psql "host=book-api-db.xxxxxxxxxxxx.ap-northeast-2.rds.amazonaws.com dbname=bookapi user=bookapi sslmode=require"
    psql에서 한 줄씩 실행
    CREATE ROLE projectapp LOGIN;
\password projectapp
GRANT projectapp TO bookapi;
CREATE DATABASE projectapi OWNER projectapp;
REVOKE ALL ON DATABASE projectapi FROM PUBLIC;
REVOKE ALL ON DATABASE bookapi FROM PUBLIC;
    명령하는 일
    CREATE ROLE projectapp LOGIN로그인할 수 있는 계정을 만듭니다. 관리 권한은 주지 않습니다.
    \password projectapp암호를 정합니다.
    GRANT projectapp TO bookapiRDS의 마스터 계정은 완전한 관리자(슈퍼유저)가 아닙니다. PostgreSQL 16부터는 다른 계정을 데이터베이스의 주인으로 정하려면 그 계정의 권한을 쓸 수 있어야 해서, 이 줄이 없으면 다음 줄이 must be able to SET ROLE 오류로 실패합니다.
    CREATE DATABASE projectapi OWNER projectapp프로젝트 데이터베이스를 만들고 주인을 앱 계정으로 정합니다. 주인이므로 마이그레이션으로 테이블을 만들 수 있습니다.
    REVOKE ALL ON DATABASE ... FROM PUBLICPostgreSQL은 기본으로 모든 계정이 모든 데이터베이스에 접속할 수 있게 해 둡니다. 이 권한을 거둬, 각 앱 계정이 자기 데이터베이스에만 접속하게 합니다.
    psql "host=book-api-db.xxxxxxxxxxxx.ap-northeast-2.rds.amazonaws.com dbname=bookapi user=projectapp sslmode=require" -c "select 1"
psql: error: ... FATAL:  permission denied for database "bookapi"
DETAIL:  User does not have CONNECT privilege.

    앱 계정으로 도서 API 데이터베이스에 접속하면 거부되는 것을 확인합니다.

  4. EC2 역할 권한 넓히기(콘솔)

    IAM에서 book-api-ec2-role을 열고 두 인라인 정책의 Resource를 목록으로 바꿉니다. 정책 이름은 그대로 둡니다.

    book-api-read-parameters
    {
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ReadAppParameters",
      "Effect": "Allow",
      "Action": [
        "ssm:GetParameter",
        "ssm:GetParameters"
      ],
      "Resource": [
        "arn:aws:ssm:ap-northeast-2:123456789012:parameter/book-api/*",
        "arn:aws:ssm:ap-northeast-2:123456789012:parameter/project-api/*"
      ]
    }
  ]
}
    book-api-logs
    {
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AppLogs",
      "Effect": "Allow",
      "Action": ["logs:CreateLogStream", "logs:PutLogEvents"],
      "Resource": [
        "arn:aws:logs:ap-northeast-2:123456789012:log-group:/book-api/app:*",
        "arn:aws:logs:ap-northeast-2:123456789012:log-group:/project-api/app:*"
      ]
    }
  ]
}

  5. 배포 역할 넓히기(콘솔)

    book-api-github-deploy 역할의 신뢰 관계에서 sub 조건을 목록으로 바꿉니다. 목록의 값 가운데 하나와 같으면 허용됩니다. 새 저장소 study-api의 번호는 S15-P53-01에서처럼 https://api.github.com/repos/내아이디/study-api에서 확인합니다. 권한 정책에서는 ECR 푸시 문장의 Resource에 새 저장소를 더합니다. 배포 명령을 보낼 수 있는 서버(ssm:SendCommand의 인스턴스)는 같으므로 바꾸지 않습니다.

    신뢰 정책의 Condition 일부
    "token.actions.githubusercontent.com:sub": [
  "repo:내아이디@아이디번호/book-api@book-api저장소번호:ref:refs/heads/main",
  "repo:내아이디@아이디번호/study-api@study-api저장소번호:ref:refs/heads/main"
]
    권한 정책의 ECR 문장
    {
  "Sid": "EcrPushAppImages",
  "Effect": "Allow",
  "Action": [
    "ecr:BatchCheckLayerAvailability",
    "ecr:InitiateLayerUpload",
    "ecr:UploadLayerPart",
    "ecr:CompleteLayerUpload",
    "ecr:PutImage",
    "ecr:BatchGetImage"
  ],
  "Resource": [
    "arn:aws:ecr:ap-northeast-2:123456789012:repository/book-api",
    "arn:aws:ecr:ap-northeast-2:123456789012:repository/project-api"
  ]
}

  6. 서버 준비(EC2)

    cd ~/book-api && docker compose -f compose.prod.yaml down
mkdir ~/project-api && cd ~/project-api
cat > compose.prod.yaml        # 내 저장소의 compose.prod.yaml 내용을 붙여 넣고 Ctrl+D
echo "IMAGE=pending" > .env    # 첫 배포가 실제 이미지 주소로 바꿉니다.
docker compose -f compose.prod.yaml config --services
api

    도서 API 컨테이너를 내리면 ALB는 잠시 502를 돌려줍니다. 첫 배포가 끝나면 같은 8000번에서 프로젝트가 응답합니다. 도서 API는 ~/book-api에 그대로 있으므로, 필요하면 프로젝트를 내리고 up -d로 다시 띄울 수 있습니다.

  7. GitHub 변수 등록과 배포

    프로젝트 저장소의 Settings, Secrets and variables, Actions, Variables에 도서 API 저장소와 같은 값으로 세 변수를 등록합니다. 비밀 값이 아니므로 Secrets가 아닌 Variables에 둡니다.

    이름값
    AWS_DEPLOY_ROLE_ARNarn:aws:iam::123456789012:role/book-api-github-deploy
    EC2_INSTANCE_IDi-0123456789abcdef0
    ALB_DNS_NAMEbook-api-alb-1234567890.ap-northeast-2.elb.amazonaws.com

    변수가 생기면 배포 단계가 더는 건너뛰어지지 않습니다. Actions 화면의 deploy 워크플로에서 Run workflow를 누르거나, README를 고쳐 푸시합니다. 테스트, 이미지 빌드와 푸시, Run Command(마이그레이션, 실행), ALB 확인 순서로 진행됩니다.
