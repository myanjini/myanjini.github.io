내 저장소에 CI 적용

내 GitHub 계정에 저장소를 만들어 도서 API를 올리고, CI가 실행되는 모습을 확인합니다. 일부러 테스트를 실패시켜 CI가 잡아내는지도 봅니다.

실습 목표GitHub Actions 워크플로를 저장소에 추가하고, 실패한 CI 기록을 읽고 고칠 수 있습니다.

평가 안내

이 실습의 결과물은 4일차 실습 결과물 평가(5%) 대상입니다. 내 GitHub 저장소의 Actions 화면에 테스트가 통과한 실행 기록이 있는지 확인합니다.

  1. 올리기 전 점검

    requirements.txt를 갱신하고, .gitignore에 다음이 모두 있는지 확인합니다. 하나라도 빠지면 비밀 키나 개발 데이터가 GitHub에 올라갑니다.

    pip freeze > requirements.txt

  2. 워크플로 파일 만들기

    book-api 안에 .github/workflows 폴더를 만들고 앞 페이지의 test.yml을 넣습니다. 폴더 이름 앞의 점(.)과 workflows의 s를 빠뜨리지 않도록 주의합니다.

  3. GitHub에 빈 저장소 만들기

    GitHub에 로그인해 오른쪽 위 +, New repository를 누릅니다. 이름은 book-api, 공개 범위는 Private로 하고, README나 .gitignore를 추가하는 선택은 모두 끈 채로 만듭니다. 만든 뒤 나오는 화면의 저장소 주소(https://github.com/내아이디/book-api.git)를 복사합니다.

  4. Git 저장소로 만들고 올리기

    book-api 폴더에서 실행합니다. Git을 처음 쓴다면 첫 두 줄로 이름과 이메일을 등록합니다.

    git config --global user.name "내 이름"
git config --global user.email "내GitHub이메일@example.com"

git init -b main
git add .
git status

    git status가 보여 주는 "올릴 파일 목록"을 꼭 확인합니다. .env, books.db, .venv, uploads가 보이면 멈추고 .gitignore를 고친 뒤 git reset으로 목록을 비우고 다시 git add .합니다. 문제없으면 올립니다.

    git commit -m "도서 API와 테스트, CI 워크플로"
git remote add origin https://github.com/내아이디/book-api.git
git push -u origin main

    처음 올릴 때 GitHub 로그인 창이 뜨면 브라우저에서 로그인을 허락합니다.

  5. CI 실행 확인

    GitHub 저장소 화면에서 Actions 탭을 누르면 방금 푸시로 실행된 워크플로가 보입니다. 누르고 test 잡을 열면 스텝별 기록이 나옵니다. 테스트 실행 스텝을 펼쳐 25 passed와 커버리지 표를 확인합니다. 전체가 끝나면 초록색 체크 표시가 붙습니다.

    확인내 결과
    걸린 시간
    테스트 결과

  6. 일부러 실패시키기

    tests/test_books.py의 test_health에서 기대 값을 201로 바꾸고 올립니다. 이번에는 내 컴퓨터에서 pytest를 실행하지 않고 바로 올려 봅니다.

    git add .
git commit -m "test_health 기대 값 변경"
git push

    Actions 탭에 빨간 X 표시가 붙습니다. 테스트 실행 스텝의 기록에서 FAILED tests/test_books.py::test_health - assert 200 == 201을 찾습니다. 내 컴퓨터에서 보던 pytest 출력과 같습니다. GitHub에 이메일 알림 설정이 켜져 있다면 실패 알림 메일도 옵니다.

  7. 고쳐서 다시 올리기

    기대 값을 200으로 되돌리고, 이번에는 올리기 전에 내 컴퓨터에서 pytest로 확인한 뒤 올립니다. Actions 탭에서 다시 초록색이 되는지 확인합니다.

    pytest
git add .
git commit -m "test_health 기대 값 되돌림"
git push

문제 해결

증상원인과 해결
Actions 탭에 아무것도 없음파일 위치가 .github/workflows/test.yml이 아닙니다. 폴더 이름의 점과 s를 확인합니다.
Invalid workflow fileYAML 들여쓰기가 틀렸습니다. 탭 대신 공백을 썼는지, steps 아래 항목의 - 위치가 맞는지 봅니다.
패키지 설치 스텝에서 No matching distribution found for pywin32Windows 전용 패키지가 requirements.txt에 들어갔습니다. 그 줄을 지우고 다시 올립니다.
테스트 스텝에서 ModuleNotFoundError: No module named 'jwt'requirements.txt를 갱신하지 않았습니다. pip freeze > requirements.txt 뒤 다시 올립니다.
git push에서 Authentication failedGitHub는 비밀번호로 푸시할 수 없습니다. 로그인 창이 뜨지 않는다면 강사에게 개인 액세스 토큰 발급을 요청합니다.
.env를 실수로 올림저장소에서 지워도 기록에 남습니다. 그 SECRET_KEY는 유출된 것으로 보고 새 값으로 바꿉니다.
