풀 리퀘스트 검사

여럿이 일할 때는 main에 바로 푸시하지 않고, 브랜치에서 작업한 뒤 풀 리퀘스트(pull request)로 "이 변경을 main에 합쳐 주세요"라고 요청합니다. 워크플로의 pull_request 조건 덕분에 풀 리퀘스트를 만들면 CI가 실행되고, 결과가 풀 리퀘스트 화면에 표시됩니다.

저장소의 Settings, Branches(또는 Rules)에서 main 브랜치 보호 규칙을 만들고 Require status checks to pass에 test를 지정하면, 테스트가 통과하지 않은 풀 리퀘스트는 합칠 수 없게 됩니다. 사람이 깜빡해도 규칙이 막아 줍니다.

이 보호 규칙은 공개 저장소나 유료 플랜에서 쓸 수 있습니다. 무료 계정의 비공개 저장소라면 CI 결과 표시까지만 확인합니다.

비밀 값 등록(Secrets)

배포할 때는 진짜 비밀 값이 필요합니다. 비밀 값은 워크플로 파일에 적지 않고 Settings, Secrets and variables, Actions에서 이름과 값을 등록한 뒤, 워크플로에서 이름으로 불러 씁니다.

      - name: 비밀 값이 필요한 단계(예시)
        run: python some_script.py
        env:
          API_TOKEN: ${{ secrets.API_TOKEN }}
규칙이유
등록한 값은 다시 볼 수 없습니다등록한 사람도 고칠 수만 있고 읽을 수는 없습니다.
실행 기록에는 ***로 가려집니다그래도 echo로 일부러 출력하거나 다른 곳으로 보내는 코드는 쓰지 않습니다.
테스트용 키는 등록하지 않아도 됩니다conftest.py의 테스트 전용 키는 비밀이 아닙니다. 운영 서버의 SECRET_KEY와 반드시 다른 값이어야 합니다.
