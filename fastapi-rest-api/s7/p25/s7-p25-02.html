테스트 워크플로 작성

테스트 워크플로 파일을 한 줄씩 읽어 봅니다. 러너가 빈 서버에서 시작한다는 것을 기억하면, 왜 이 단계들이 필요한지 이해할 수 있습니다.

워크플로 파일

.github/workflows/test.yml
name: test

# 언제 실행할까요: main 브랜치에 푸시할 때와, main으로 가는 풀 리퀘스트를 만들 때
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest  # GitHub가 빌려주는 리눅스 서버에서 실행합니다.
    steps:
      - name: 코드 내려받기
        uses: actions/checkout@v7

      - name: Python 설치
        uses: actions/setup-python@v7
        with:
          python-version: "3.12"
          cache: pip  # 내려받은 패키지를 저장해 두었다가 다음 실행에서 다시 씁니다.

      - name: 패키지 설치
        run: pip install -r requirements.txt

      - name: 테스트 실행
        run: pytest --cov=app --cov-report=term-missing
부분설명
name: testActions 화면에 보이는 워크플로 이름입니다.
on:main 브랜치에 푸시할 때와, main으로 합치려는 풀 리퀘스트를 만들거나 고칠 때 실행합니다.
runs-on: ubuntu-latest최신 우분투 리눅스 러너를 씁니다. 내 PC가 Windows여도 괜찮습니다. Python 코드는 운영체제와 상관없이 같게 동작하도록 써 왔습니다.
uses: actions/checkout@v7빈 러너에 내 저장소의 코드를 내려받습니다. @v7은 액션의 버전입니다.
uses: actions/setup-python@v7지정한 버전의 Python을 설치합니다. 이 과정의 최소 버전인 3.12로 시험합니다. cache: pip는 내려받은 패키지를 저장해 두었다가 다음 실행을 빠르게 합니다.
run: pip install -r requirements.txt빈 서버이므로 패키지를 모두 설치합니다. requirements.txt에 빠진 패키지가 있으면 여기서, 또는 테스트에서 실패합니다.
run: pytest ...테스트를 실행합니다. 하나라도 실패하면 pytest가 실패 신호(0이 아닌 종료 코드)를 내고, 워크플로가 실패로 표시됩니다.

YAML 작성 규칙

  • 들여쓰기로 구조를 나타냅니다. 탭은 쓸 수 없고 공백만 씁니다. 이 파일은 2칸씩 들여씁니다.
  • -로 시작하는 줄은 목록의 한 항목입니다. steps 아래의 각 단계가 목록입니다.
  • # 뒤는 주석입니다.

비밀 키는 어떻게 하나요

러너에는 .env가 없습니다. 하지만 S7-P23에서 conftest.py가 테스트용 SECRET_KEY를 넣도록 만들었기 때문에 워크플로에 따로 적을 것이 없습니다. 진짜 비밀 값이 필요한 경우는 S7-P25-04에서 다룹니다.

requirements.txt 갱신

3일차 이후 pwdlib, pyjwt, 오늘은 pytest, pytest-cov를 설치했습니다. 이 패키지들이 requirements.txt에 없으면 러너에서 ModuleNotFoundError가 납니다. 올리기 전에 반드시 갱신합니다.

pip freeze > requirements.txt
