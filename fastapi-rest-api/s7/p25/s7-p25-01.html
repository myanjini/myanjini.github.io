CI와 GitHub Actions

이 파트의 학습 목표저장소에 코드를 올릴 때마다 테스트가 자동으로 실행되도록 CI를 구성할 수 있습니다.

"내 컴퓨터에서는 되는데요"는 개발자가 가장 자주 하는 말 중 하나입니다. 코드를 올릴 때마다 깨끗한 컴퓨터에서 테스트를 실행해 이 문제를 막는 방법이 CI입니다.

지속적 통합(CI)

CI(Continuous Integration, 지속적 통합)는 여러 사람이 고친 코드를 자주 합치고, 합칠 때마다 자동으로 테스트해서 문제를 일찍 찾는 방식입니다. 일주일 동안 각자 고친 코드를 한꺼번에 합치면 어디서 깨졌는지 찾기 어렵지만, 올릴 때마다 확인하면 방금 올린 변경이 원인임을 바로 압니다.

CI가 막아 주는 일예
테스트를 깜빡 잊고 올림바쁜 날 pytest를 실행하지 않고 올려도 CI가 실행합니다.
내 컴퓨터에만 있는 것에 기대는 코드requirements.txt에 빠진 패키지, Git에 올리지 않은 .env, 내 PC에만 있는 데이터베이스
망가진 코드가 main에 합쳐짐풀 리퀘스트에서 테스트가 실패하면 합치지 못하게 설정할 수 있습니다.

GitHub Actions

GitHub Actions는 GitHub가 제공하는 CI 서비스입니다. 저장소에 설정 파일을 넣어 두면, 정한 일이 일어날 때 GitHub가 빌려주는 서버에서 정한 명령을 실행합니다. 공개 저장소는 무료이고, 비공개 저장소도 매달 일정 시간까지 무료로 쓸 수 있습니다.

용어뜻이 과정의 예
워크플로(workflow)자동으로 실행할 작업 전체를 적은 YAML 파일. .github/workflows 폴더에 둡니다..github/workflows/test.yml
실행 조건(on)워크플로를 실행하는 사건main에 푸시, main으로 가는 풀 리퀘스트
잡(job)서버 한 대에서 실행되는 작업 묶음test
러너(runner)잡을 실행하는 서버ubuntu-latest(GitHub가 빌려주는 리눅스)
스텝(step)잡 안에서 차례로 실행하는 단계 하나코드 내려받기, Python 설치, 패키지 설치, 테스트 실행
액션(action)다른 사람이 만들어 둔 재사용 가능한 스텝actions/checkout, actions/setup-python
