실습 계정과 콘솔

기관이 준비한 실습 계정으로 AWS 관리 콘솔에 로그인하고, 서울 리전을 확인합니다. 이어서 명령으로 AWS를 다루는 AWS CLI를 설치하고, 액세스 키 없이 로그인되는지 확인합니다.

실습 목표실습 계정으로 콘솔과 AWS CLI에 로그인하고, 서울 리전에서 작업할 준비를 마칠 수 있습니다.

실습 계정 수칙(부록 E)

서울 리전에서만 자원을 만들고, 모든 자원에 Owner 태그를 붙입니다. 액세스 키는 만들지 않습니다. 계정 정보(비밀번호, MFA 코드, 로그인 주소)는 화면 공유나 메신저에 올리지 않습니다.

  1. 콘솔에 로그인

    기관이 안내한 방식으로 로그인합니다. 방식은 두 가지 가운데 하나입니다.

    안내받은 것로그인 방법
    계정 ID(12자리 숫자)나 별칭, IAM 사용자 이름, 비밀번호AWS 로그인 화면에서 IAM 사용자로 로그인합니다. 처음이면 비밀번호를 바꾸고 MFA(추가 인증)를 등록하라는 안내가 나옵니다.
    AWS 접근 포털 주소(https://...awsapps.com/start)IAM Identity Center 방식입니다. 포털에 로그인한 뒤 실습 계정과 권한을 골라 콘솔로 들어갑니다.

    루트 사용자(계정을 만든 이메일 주소로 로그인하는 사용자)로는 로그인하지 않습니다. 이유는 다음 파트(S12-P41-01)에서 배웁니다.

  2. 서울 리전 확인

    콘솔 오른쪽 위의 리전 메뉴가 아시아 태평양(서울) ap-northeast-2인지 확인합니다. 다르면 눌러서 서울로 바꿉니다. 주소창의 주소에도 region=ap-northeast-2가 들어 있습니다. IAM처럼 리전 구분이 없는 서비스는 리전 메뉴에 "Global"이 보이는데, 정상입니다.

  3. 서비스 찾기와 즐겨찾기

    위쪽 검색창에 서비스 이름을 입력하면 바로 찾을 수 있습니다. 앞으로 자주 쓸 서비스를 즐겨찾기(별 모양)에 추가해 두면 위쪽 막대에서 바로 열 수 있습니다.

  4. AWS CLI 설치

    AWS CLI는 AWS를 명령으로 다루는 공식 도구입니다. 콘솔에서 클릭으로 하는 일을 명령 한 줄로 할 수 있고, 같은 작업을 정확히 반복하기 좋습니다. 버전 2를 설치합니다.

    운영체제설치 방법
    Windows명령 프롬프트에서 msiexec.exe /i https://awscli.amazonaws.com/AWSCLIV2.msi를 실행하거나, 같은 주소의 설치 파일을 내려받아 실행합니다.
    macOShttps://awscli.amazonaws.com/AWSCLIV2.pkg를 내려받아 실행합니다.
    LinuxAWS 문서의 설치 안내("Installing or updating to the latest version of the AWS CLI")를 따릅니다.

    설치한 뒤 터미널을 새로 열고 버전을 확인합니다. 뒤에서 쓸 aws login 명령은 2.32.0 이상에서만 쓸 수 있습니다.

    aws --version
aws-cli/2.42.1 Python/3.13.11 Windows/11 exe/AMD64

    위 출력은 예시입니다. 버전 숫자와 뒷부분은 설치한 시점과 운영체제에 따라 다르게 보입니다.

  5. 명령을 실행할 터미널 정하기

    6일차부터 9일차까지 내 PC에서 실행하는 AWS 명령은 bash 문법으로 씁니다. 값을 이름에 담는 VPC=vpc-..., 명령의 결과를 끼워 넣는 $(...), 긴 명령을 다음 줄로 잇는 줄 끝의 \ 같은 문법입니다. 이 문법은 Windows의 명령 프롬프트와 PowerShell에서는 동작하지 않습니다.

    어디서 실행하나요쓸 터미널
    macOS기본 터미널을 그대로 씁니다.
    WindowsGit Bash를 씁니다. Git을 설치할 때 함께 설치되며, 시작 메뉴에서 Git Bash를 검색해 엽니다.
    EC2 서버(Session Manager 접속 화면)서버가 리눅스이므로 어느 PC에서 접속하든 명령을 그대로 입력합니다.

    Windows라면 Git Bash를 처음 열었을 때 다음 두 줄을 한 번만 실행합니다.

    echo 'export MSYS_NO_PATHCONV=1' >> ~/.bashrc
source ~/.bashrc

    Git Bash에는 /로 시작하는 값을 Windows 경로로 바꿔 주는 기능이 있습니다. 그대로 두면 Parameter Store 이름 /book-api/SECRET_KEY나 로그 그룹 이름 /book-api/app이 C:/Program Files/Git/book-api/...로 바뀌어 AWS에 전달되고, "찾을 수 없다"는 오류가 납니다. 위 설정이 이 변환을 끕니다. ~/.bashrc에 적어 두었으므로 Git Bash를 새로 열 때마다 자동으로 적용됩니다.

    Git Bash에서 할 일명령
    AWS CLI 확인aws --version(명령 프롬프트와 같은 결과가 나와야 합니다)
    가상환경 켜기source .venv/Scripts/activate(Windows의 가상환경은 bin이 아니라 Scripts 폴더에 있습니다)

    1~5일차처럼 써도 되는 것

    가상환경, pip, fastapi dev, pytest, docker처럼 지금까지 명령 프롬프트에서 하던 일은 계속 명령 프롬프트에서 해도 됩니다. bash 문법이 들어간 명령만 Git Bash에서 실행하면 됩니다. 이후 페이지에서 bash 문법을 쓰는 곳에는 이 안내를 다시 붙여 둡니다.

  6. 액세스 키 없이 CLI 로그인

    예전에는 CLI를 쓰려고 "액세스 키"라는 오래 쓰는 비밀 값을 만들어 컴퓨터에 저장했습니다. 지금은 콘솔에 로그인하듯 브라우저로 로그인하고, 잠깐만 쓸 수 있는 임시 자격 증명을 받는 방식을 권장합니다. 로그인 방식에 맞는 명령을 고릅니다.

    콘솔 로그인 방식CLI 로그인 명령
    IAM 사용자aws login
    AWS 접근 포털(IAM Identity Center)처음 한 번 aws configure sso로 포털 주소와 계정을 등록하고, 그 뒤로는 aws sso login
    aws login
No AWS region has been configured. ...
AWS Region [us-east-1]: ap-northeast-2
Attempting to open your default browser.
...
Updated profile default to use arn:aws:iam::123456789012:user/student07 credentials.

    리전을 물으면 ap-northeast-2를 입력합니다. 브라우저가 열리면 지금 로그인한 콘솔 세션을 고르거나 다시 로그인합니다. 받은 임시 자격 증명은 CLI가 알아서 갱신합니다.

  7. 누구로 로그인했는지 확인

    aws sts get-caller-identity
{
    "UserId": "AIDASAMPLEUSERID",
    "Account": "123456789012",
    "Arn": "arn:aws:iam::123456789012:user/student07"
}

aws configure get region
ap-northeast-2

aws ec2 describe-availability-zones --query "AvailabilityZones[].ZoneName" --output text
ap-northeast-2a	ap-northeast-2b	ap-northeast-2c	ap-northeast-2d

    sts get-caller-identity는 "지금 이 CLI가 누구의 권한으로 요청하는가"를 알려 줍니다. 권한 문제를 만났을 때 가장 먼저 실행할 명령입니다. 계정 ID와 사용자 이름(또는 역할 이름)이 안내받은 것과 같은지 확인합니다.

확인내 결과
로그인한 계정 ID(뒤 4자리만)
Arn의 사용자 또는 역할 이름
aws --version의 버전

AccessDenied가 나올 때

실습 계정은 필요한 서비스만 쓸 수 있게 권한이 좁혀져 있습니다. 명령이 AccessDenied로 실패하면 먼저 aws sts get-caller-identity로 내 계정과 리전을 확인하고, 그래도 안 되면 오류 메시지 전체를 강사에게 보여 줍니다. 오류 메시지에 계정 ID가 들어 있으므로 공개된 곳에는 올리지 않습니다.
