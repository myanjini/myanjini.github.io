정책 문서 읽기

IAM 정책은 JSON 문서입니다. 몇 가지 요소만 알면 어떤 정책이든 "누가 무엇을 어디에 할 수 있는지" 읽어 낼 수 있습니다. 오늘 만들 역할에 붙일 정책을 예로 읽어 봅니다.

정책의 구조

book-api-read-parameters(정책 문서)
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ReadBookApiParameters",
      "Effect": "Allow",
      "Action": [
        "ssm:GetParameter",
        "ssm:GetParameters"
      ],
      "Resource": "arn:aws:ssm:ap-northeast-2:123456789012:parameter/book-api/*"
    }
  ]
}
요소뜻위 정책에서
Version정책 문법의 판입니다. 항상 "2012-10-17"을 씁니다. 날짜처럼 보이지만 바꾸는 값이 아닙니다.2012-10-17
Statement규칙 목록입니다. 규칙을 여러 개 둘 수 있습니다.규칙 1개
Sid규칙에 붙이는 이름입니다(선택).ReadBookApiParameters
Effect허용(Allow)인지 거부(Deny)인지Allow
Action어떤 동작인지. 서비스:동작 형식입니다.Parameter Store에서 값 하나, 여러 개를 읽는 동작
Resource어떤 자원에 대해서인지. ARN으로 적습니다.서울 리전, 이 계정의 /book-api/로 시작하는 파라미터만
Condition추가 조건입니다(선택). 특정 IP에서만, MFA를 했을 때만 같은 조건을 겁니다.없음

ARN(Amazon Resource Name)은 AWS 자원의 전체 이름입니다. arn:aws:서비스:리전:계정ID:자원 모양이고, IAM처럼 리전 구분이 없는 서비스는 리전 자리가 비어 있습니다(arn:aws:iam::123456789012:role/book-api-ec2-role). *는 "아무것이나"를 뜻하는 와일드카드입니다.

AWS가 요청을 판단하는 순서

순서규칙
1아무 정책도 허용하지 않으면 거부합니다(기본 거부).
2어떤 정책이든 Allow로 허용하면 허용 후보가 됩니다.
3어느 한 정책이라도 Deny로 명시하면, 허용이 있어도 거부합니다(명시적 거부가 이깁니다).
4권한 경계나 기관의 조직 정책(SCP)이 있으면, 그 범위 안에 있는 허용만 인정합니다.

도서 API의 권한 검사와 같은 원칙입니다. 처음에는 모두 막고, 필요한 것만 열고, 막아야 할 것은 확실하게 막습니다.

최소 권한 원칙

최소 권한 원칙은 일을 하는 데 꼭 필요한 권한만 주는 것입니다. 권한이 넓을수록 실수와 공격의 피해가 커집니다. 아래 정책은 모든 서비스의 모든 동작을 모든 자원에 허용합니다. 이 정책이 붙은 서버가 S11에서 본 SSRF 같은 약점으로 뚫리면, 공격자는 계정 전체를 손에 넣습니다.

쓰면 안 되는 정책
{
  "Version": "2012-10-17",
  "Statement": [
    { "Effect": "Allow", "Action": "*", "Resource": "*" }
  ]
}
넓은 권한좁힌 권한
"Action": "ssm:*"ssm:GetParameter, ssm:GetParameters(읽기만)
"Resource": "*".../parameter/book-api/*(내 서비스의 파라미터만)
관리자용 관리형 정책(AdministratorAccess)용도별 관리형 정책이나 직접 쓴 정책

신뢰 정책: 누가 역할을 맡을 수 있나

역할에는 정책이 두 종류 붙습니다. 위에서 본 권한 정책은 "역할을 맡은 쪽이 무엇을 할 수 있는가"이고, 신뢰 정책은 "누가 이 역할을 맡을 수 있는가"입니다. EC2용 역할의 신뢰 정책은 EC2 서비스만 이 역할을 맡을 수 있게 합니다. 콘솔에서 역할을 만들 때 자동으로 만들어집니다.

신뢰 정책(EC2용 역할)
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": { "Service": "ec2.amazonaws.com" },
      "Action": "sts:AssumeRole"
    }
  ]
}

읽어 보기. 맨 위의 book-api-read-parameters 정책이 붙은 역할로 다음 일을 할 수 있나요? (1) /book-api/SECRET_KEY 읽기 (2) /other-app/DB_PASSWORD 읽기 (3) /book-api/SECRET_KEY 값 바꾸기

예시 답안 보기

(1) 됩니다. Action과 Resource가 모두 맞습니다. (2) 안 됩니다. Resource가 /book-api/로 시작하지 않으므로 기본 거부입니다. (3) 안 됩니다. 값을 바꾸는 ssm:PutParameter가 Action에 없습니다. 서버는 비밀 값을 읽기만 하면 되므로 쓰기 권한을 주지 않습니다.
