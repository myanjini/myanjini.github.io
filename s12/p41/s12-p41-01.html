IAM 핵심 개념

이 파트의 학습 목표IAM 정책을 읽고 최소 권한의 역할을 만들 수 있습니다.

IAM(Identity and Access Management)은 AWS 계정 안에서 "누가(인증) 무엇을 할 수 있는가(인가)"를 관리하는 서비스입니다. S5에서 도서 API에 로그인과 권한 검사를 만든 것과 같은 일을, AWS 자원에 대해 해 주는 서비스라고 생각하면 됩니다.

IAM의 구성 요소

구성 요소뜻이 과정에서
루트 사용자계정을 만들 때 쓴 이메일 주소로 로그인하는 사용자입니다. 계정 안의 모든 것을 할 수 있고, 권한을 줄일 수 없습니다.쓰지 않습니다. 기관 관리자가 MFA를 걸어 보관합니다.
IAM 사용자사람(또는 프로그램) 하나에 해당하는 오래 쓰는 신원입니다. 비밀번호나 액세스 키를 가집니다.기관이 IAM 사용자 방식이라면 내 실습 계정
그룹IAM 사용자의 묶음입니다. 그룹에 권한을 주면 속한 사용자 모두가 받습니다.기관이 "수강생" 그룹에 실습 권한을 줍니다.
역할필요할 때 잠깐 "쓰는" 신원입니다. 비밀번호나 장기 키가 없고, 역할을 맡으면 몇 시간짜리 임시 자격 증명을 받습니다.EC2 서버가 맡을 역할을 오늘 만듭니다.
정책무엇을 허용하고 거부하는지 적은 JSON 문서입니다. 사용자, 그룹, 역할에 붙입니다.다음 페이지에서 읽는 법을 배웁니다.

역할이 중요한 이유

역할은 "직무 모자"와 비슷합니다. 모자를 쓰는 동안만 그 직무의 권한을 갖고, 벗으면 사라집니다. EC2 서버가 Parameter Store의 비밀 값을 읽으려면 권한이 필요한데, 서버 안에 액세스 키를 넣어 두는 대신 서버에 역할을 붙이면 AWS가 임시 자격 증명을 서버에 주고 자동으로 바꿔 줍니다. 서버의 코드나 이미지 어디에도 오래 쓰는 비밀 값이 남지 않습니다. S10에서 "비밀 값은 코드에서 분리한다"고 배운 원칙을 클라우드에서 지키는 방법입니다.

누가 역할을 맡나요예
AWS 서비스EC2 인스턴스가 역할을 맡아 ECR에서 이미지를 받습니다(오늘 만드는 역할).
다른 계정이나 외부 신원GitHub Actions가 OIDC로 역할을 맡아 배포합니다(8일차 S15-P53).
사람IAM Identity Center로 로그인하면 사실은 "권한 세트"에 해당하는 역할을 맡은 것입니다.

루트 사용자 보호와 MFA

루트 사용자의 비밀번호가 새면 계정 전체를 잃습니다. 그래서 루트 사용자에는 반드시 MFA(Multi-Factor Authentication, 다중 인증)를 걸고, 계정 설정 변경처럼 루트만 할 수 있는 일을 할 때만 씁니다. MFA는 비밀번호(아는 것)에 휴대폰 인증 앱이나 보안 키(가진 것)를 더해, 비밀번호가 새도 로그인할 수 없게 합니다. 내 IAM 사용자에도 MFA를 등록합니다.

권한 경계

실습 계정에는 기관이 권한 경계(Permissions Boundary)를 걸어 두었을 수 있습니다. 권한 경계는 "아무리 많은 권한을 받아도 이 범위는 넘을 수 없다"는 상한선입니다. 학생이 역할을 만들 수 있게 하되, 그 역할이 실습 범위를 넘는 권한을 갖지 못하게 막는 장치입니다. 역할을 만들 때 기관이 안내한 권한 경계를 붙여야 하는 경우가 있습니다(S12-P41-03).
