IAM 역할 만들기

7일차에 만들 EC2 서버가 맡을 IAM 역할을 미리 만듭니다. 서버가 해야 할 일은 세 가지입니다. Session Manager로 접속을 받고, ECR에서 이미지를 내려받고, Parameter Store에서 도서 API의 비밀 값을 읽습니다. 이 세 가지만 허용하는 역할을 만듭니다.

실습 목표EC2용 IAM 역할을 만들고, 꼭 필요한 권한만 붙일 수 있습니다.

붙일 정책

필요한 일정책종류
Session Manager로 접속(SSH 없이)AmazonSSMManagedInstanceCoreAWS 관리형 정책
ECR에서 이미지 내려받기AmazonEC2ContainerRegistryPullOnlyAWS 관리형 정책
/book-api/ 파라미터 읽기book-api-read-parameters직접 쓰는 정책(인라인)

AWS 관리형 정책은 AWS가 만들어 관리하는 정책입니다. ECR에는 읽기 전용 정책(ReadOnly)도 있지만, 이미지 목록을 보는 권한까지 포함되므로 내려받기만 허용하는 PullOnly를 고릅니다. Parameter Store는 관리형 정책이 모든 파라미터를 대상으로 하므로, 내 서비스의 경로만 읽게 정책을 직접 씁니다. SecureString(암호화된 문자열)으로 저장한 값도 AWS가 기본으로 제공하는 키(aws/ssm)로 암호화했다면 이 정책만으로 읽을 수 있습니다.

  1. 역할 만들기 시작

    콘솔에서 IAM을 열고 역할, 역할 생성을 누릅니다. 신뢰할 수 있는 엔터티 유형은 AWS 서비스, 사용 사례는 EC2를 고릅니다. 이 선택이 앞 페이지의 신뢰 정책을 만듭니다.

  2. 관리형 정책 붙이기

    권한 추가 화면의 검색창에서 두 정책을 찾아 체크합니다.

    기관이 권한 경계를 안내했다면, 같은 화면 아래쪽의 권한 경계 설정을 펼쳐 안내받은 정책을 고릅니다. 고르지 않으면 역할 생성이 거부될 수 있습니다.

  3. 이름과 태그

    항목값
    역할 이름book-api-ec2-role-내식별자(예: book-api-ec2-role-student07)
    설명도서 API EC2 서버용: Session Manager, ECR 내려받기, /book-api 파라미터 읽기
    태그키 Owner, 값 내 식별자

    한 계정을 여러 학생이 함께 쓰면 이름이 겹치지 않게 식별자를 붙입니다. 학생마다 계정이 따로 있다면 book-api-ec2-role로 해도 됩니다. 아래에서는 book-api-ec2-role로 적습니다. 마지막으로 역할 생성을 누릅니다.

  4. 파라미터 읽기 정책 추가

    만든 역할을 열고 권한 추가, 인라인 정책 생성을 누릅니다. 편집기를 JSON으로 바꾸고 앞 페이지의 정책을 붙여 넣은 뒤, 123456789012를 내 계정 ID로 바꿉니다. 정책 이름은 book-api-read-parameters로 합니다.

    편집기의 경고

    JSON 편집기 아래에 오류나 경고가 보이면 읽어 봅니다. IAM은 정책을 저장하기 전에 문법 오류, 존재하지 않는 동작 이름, 지나치게 넓은 권한 같은 문제를 알려 줍니다.

  5. CLI로 확인

    aws iam get-role --role-name book-api-ec2-role --query "Role.Arn" --output text
arn:aws:iam::123456789012:role/book-api-ec2-role

aws iam list-attached-role-policies --role-name book-api-ec2-role --query "AttachedPolicies[].PolicyName"
[
    "AmazonSSMManagedInstanceCore",
    "AmazonEC2ContainerRegistryPullOnly"
]

aws iam list-role-policies --role-name book-api-ec2-role
{
    "PolicyNames": [
        "book-api-read-parameters"
    ]
}

    list-attached-role-policies는 역할에 붙인 관리형 정책을, list-role-policies는 역할 안에 직접 쓴 인라인 정책을 보여 줍니다.

콘솔이 만들어 주는 인스턴스 프로파일

EC2에 역할을 붙일 때는 사실 역할을 담는 "인스턴스 프로파일"이라는 그릇을 붙입니다. 콘솔에서 EC2 사용 사례로 역할을 만들면 같은 이름의 인스턴스 프로파일이 자동으로 함께 만들어지므로 따로 할 일은 없습니다. 7일차에 EC2를 만들 때 이 이름을 고릅니다.
