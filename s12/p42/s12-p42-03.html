배포 네트워크 설계

지금까지 배운 내용으로 도서 API를 배포할 네트워크를 설계합니다. 7일차에는 이 설계표를 보며 콘솔에서 그대로 만들고, 8일차에 ALB를 더할 때 보안 그룹을 고칩니다. 설계표가 이 파트의 산출물입니다.

실습 목표EC2와 RDS의 배치도를 그리고, 꼭 필요한 연결만 여는 보안 그룹 규칙 표를 작성할 수 있습니다.

  1. 요구사항 확인

    번호요구사항
    R1도서 API는 EC2 한 대에서 Docker 컨테이너로 8000번 포트로 실행합니다.
    R27일차에는 실습하는 내 컴퓨터(교육장의 공인 IP)에서만 API에 접속할 수 있어야 합니다.
    R3서버 접속은 Session Manager로만 합니다. SSH(22번 포트)는 열지 않습니다.
    R4데이터베이스는 RDS for PostgreSQL이고, 인터넷에서 닿지 않아야 하며, API 서버만 접속합니다.
    R5NAT 게이트웨이는 쓰지 않습니다.
    R68일차에는 ALB를 앞에 두고, 인터넷의 사용자는 ALB를 통해서만 API에 접속합니다.
    R7모든 자원에 Owner 태그를 붙이고, 이름은 book-api-로 시작합니다.

  2. 내 공인 IP 확인

    R2를 위해 교육장(또는 내 컴퓨터)의 공인 IP를 확인합니다. 아래 명령은 AWS가 제공하는 주소 확인 서비스에 요청해 내 공인 IP를 돌려받습니다. 보안 그룹에는 /32를 붙여 "이 주소 하나"로 적습니다.

    curl https://checkip.amazonaws.com
203.0.113.25

    교육장의 여러 컴퓨터가 같은 공인 IP를 쓰는 경우가 많습니다. 집에서 복습할 때는 공인 IP가 바뀌므로 규칙을 다시 고쳐야 합니다.

  3. 서브넷 설계

    빈칸을 채웁니다. 가용 영역은 a와 c를 씁니다.

    이름가용 영역CIDR종류들어갈 자원

    book-api-public-cap-northeast-2c퍼블릭
    book-api-private-aap-northeast-2a프라이빗
    book-api-private-cap-northeast-2c프라이빗

  4. 보안 그룹 규칙 표(7일차)

    각 보안 그룹의 인바운드 규칙을 적습니다. 아웃바운드는 기본값(모두 허용)으로 둡니다.

    보안 그룹프로토콜과 포트출처이유
    book-api-sg(EC2)
    book-api-db-sg(RDS)

  5. 보안 그룹 규칙 표(8일차, ALB 추가 뒤)

    보안 그룹프로토콜과 포트출처이유
    book-api-alb-sg(ALB)
    book-api-sg(EC2)
    book-api-db-sg(RDS)

  6. 배치도 그리기

    종이나 그리기 도구(draw.io 등)에 VPC, 가용 영역 2개, 서브넷 4개, 인터넷 게이트웨이, EC2, RDS를 그리고, 보안 그룹 규칙에 따라 허용되는 연결을 화살표로 표시합니다. 사진이나 파일로 저장해 두면 7일차에 만들 때 그대로 따라갈 수 있습니다.
