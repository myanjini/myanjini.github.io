대여, 반납 구현

설계를 바탕으로 직접 구현합니다. 먼저 힌트 없이 시도하고, 15분이 지나도 막히는 단계만 힌트를 펼칩니다.

실습 목표마이그레이션, 서비스 계층, 트랜잭션, 권한 검사를 결합해 대여와 반납 API를 구현할 수 있습니다.

평가 안내

이 실습의 결과물은 3일차 실습 결과물 평가(5%) 대상입니다. 강사 풀이(S6-P21-04)를 보기 전에 제출한 코드로, S6-P21-02의 시험 표대로 대여와 반납이 동작하는지 확인합니다.

  1. Loan 모델과 리비전

    app/models.py 맨 아래에 Loan을 추가하고 리비전을 만들어 적용합니다.

    힌트 보기
    app/models.py
    class Loan(Base):
    """누가 어떤 도서를 언제 빌리고 반납했는지 기록합니다."""

    __tablename__ = "loans"

    id: Mapped[int] = mapped_column(primary_key=True)
    user_id: Mapped[int] = mapped_column(ForeignKey("users.id"))
    book_id: Mapped[int] = mapped_column(ForeignKey("books.id"))
    loaned_at: Mapped[datetime] = mapped_column(server_default=func.now())
    returned_at: Mapped[datetime | None]  # 반납하기 전에는 None

    book: Mapped["Book"] = relationship()

    리비전에 loans 테이블만 만드는지 확인합니다. 새 테이블이므로 외래키 이름을 고칠 필요가 없습니다.

  2. 스키마

    대여 요청 본문과 응답 모델을 만듭니다. 응답에는 도서 번호와 제목이 보이면 좋습니다.

    힌트 보기

    파일 맨 위에 from datetime import datetime을 추가합니다.

    app/schemas.py
    class LoanCreate(BaseModel):
    """대여 요청 본문"""
    book_id: int = Field(gt=0, examples=[1])


class BookBrief(BaseModel):
    """대여 응답에 넣는 도서 요약"""

    model_config = ConfigDict(from_attributes=True)

    id: int
    title: str


class LoanRead(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    id: int
    user_id: int
    book: BookBrief
    loaned_at: datetime
    returned_at: datetime | None = None

  3. 저장소

    app/repositories/loans.py를 만듭니다. 서비스가 필요로 하는 질문을 함수로 만듭니다. "이 사람이 이 도서를 반납하지 않고 빌리고 있나?", "이 사람이 반납하지 않은 대여는 몇 건인가?", "이 도서의 대여 기록이 있나?"

    힌트 보기

    "반납하지 않음"은 Loan.returned_at.is_(None) 조건입니다. 개수는 도서 목록에서 쓴 select(func.count()).select_from(Loan).where(...)를 씁니다.

  4. 서비스

    app/services/loans.py에 borrow, return_book, my_loans를 만듭니다. 검사를 모두 마친 뒤 재고 변경과 대여 기록 추가를 하고, 마지막에 한 번만 commit합니다.

    힌트 보기

    대여 순서: 도서 찾기, 중복 대여 검사, 권수 검사, 재고 검사, change_stock(db, book, -1, "대여"), 대여 기록 추가, commit.

    반납 순서: 대여 기록 찾기(404), 본인 또는 관리자인지 검사(403), 이미 반납했는지 검사(409), returned_at에 현재 시각 넣기, change_stock(db, loan.book, 1, "반납"), commit.

    현재 시각은 리프레시 토큰에서 쓴 datetime.now(timezone.utc)를 씁니다.

  5. 라우터와 연결

    app/routers/loans.py를 만들고 app/main.py에 연결합니다. GET /loans/me의 응답 모델은 목록입니다.

    힌트 보기

    응답 모델은 response_model=list[LoanRead]입니다. main.py에서는 from app.routers import auth, authors, books, loans와 app.include_router(loans.router)를 추가합니다.

  6. 도서 삭제 규칙

    요구사항 9번을 위해 도서 서비스의 delete_book을 고칩니다.

    힌트 보기

    권한 검사 바로 아래에서 대여 저장소로 기록이 있는지 묻고, 있으면 AppError(409, "BOOK_HAS_LOANS", ...)를 냅니다.

시험 표

user1이 재고 2권인 도서 A를 등록하고, 재고 1권인 B, 재고 5권인 C와 D를 등록한 뒤 시작합니다. 사용자를 바꿀 때는 Authorize 창에서 Logout 후 다시 로그인합니다. user2는 S5-P17에서 관리자로 바꾼 계정입니다.

순서계정요청기대하는 결과내 결과
1로그인 안 함A 대여401
2user1A 대여201. A의 재고 1
3user1A 대여409 ALREADY_LOANED
4user3A 대여201. A의 재고 0
5user1B, C 대여 뒤 D 대여B와 C는 201, D는 409 LOAN_LIMIT_EXCEEDED
6user32번에서 만든 user1의 대여 반납403
7user12번 대여 반납200, returned_at에 시각. A의 재고 1
8user12번 대여 한 번 더 반납409 ALREADY_RETURNED
9user1GET /loans/me최근 것부터 3건. A는 반납 시각이 있음
10user1A 삭제409 BOOK_HAS_LOANS
11user2(관리자)4번에서 만든 user3의 대여 반납200

A의 재고가 0인 상태에서 다른 사람이 A를 빌리면 409 OUT_OF_STOCK이어야 합니다. 4번 뒤에 user2로 확인해 봅니다. 마지막으로 재고 기록을 보고 "대여"와 "반납"이 순서대로 남았는지 확인합니다.

시각이 9시간 다르게 보여요

loaned_at과 returned_at은 세계 표준시(UTC)로 저장합니다. 한국 시간보다 9시간 늦게 보이는 것이 정상입니다. 서버는 UTC로 저장하고, 화면에 보여 줄 때 사용자의 지역 시간으로 바꾸는 것이 일반적입니다.
