정리: 파일과 백그라운드 작업

핵심 요약

  • 파일은 multipart/form-data 형식으로 받고, 매개변수 타입은 UploadFile입니다.
  • filename과 content_type은 보내는 쪽이 정하므로 믿지 않습니다. 형식은 허용 목록으로, 크기는 한도보다 1바이트 더 읽어 검사합니다.
  • 저장할 이름은 uuid로 새로 짓고, 데이터베이스에는 주소만 저장합니다.
  • 파일 작업은 rollback되지 않으므로, 지우는 일은 commit이 성공한 뒤에 합니다.
  • BackgroundTasks는 응답 뒤에 가벼운 작업을 실행합니다. 꼭 실행되어야 하는 무거운 작업에는 작업 큐를 씁니다.

확인 퀴즈

업로드한 파일을 올린 사람이 정한 이름 그대로 저장하면 생기는 문제가 아닌 것은 무엇인가요?

이름은 크기와 상관이 없습니다. 나머지는 모두 서버가 이름을 새로 지어야 하는 이유입니다.

3MB 파일을 올렸을 때 서버가 읽는 양은 얼마인가요?

read(MAX_COVER_SIZE + 1)로 한도보다 1바이트만 더 읽어 보고 넘었는지 판단합니다.

표지를 바꿀 때 이전 파일을 commit 뒤에 지우는 이유는 무엇인가요?

파일 삭제는 rollback으로 되돌릴 수 없으므로, 데이터베이스 반영이 확실해진 뒤에 합니다.
