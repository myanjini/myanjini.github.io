내 코드 점검과 결과 판정

도서 API에 bandit과 pip-audit을 실행하고, 나온 결과를 하나씩 "진짜 약점인지, 오탐인지" 판정합니다. 도구의 결과를 그대로 받아들이지 않고 근거를 들어 판정하는 것이 이 실습의 핵심입니다.

실습 목표점검 도구의 결과를 근거를 들어 판정하고, 판정 기록을 코드와 문서에 남길 수 있습니다.

  1. bandit 실행

    도서 API 프로젝트 폴더에서 실행합니다. 5일차까지의 코드라면 앞 페이지와 같은 결과 3건이 나옵니다.

    bandit -r app
    번호규칙위치심각도/신뢰도내 결과
    1B608 문자열로 만든 SQLapp/repositories/reports.pyMedium / Low
    2B105 하드코드된 비밀번호app/routers/auth.py(로그인 응답)Low / Medium
    3B105 하드코드된 비밀번호app/routers/auth.py(토큰 재발급 응답)Low / Medium

  2. 결과 판정

    각 결과의 코드를 열어 보고, 아래 질문에 먼저 답한 뒤 예시 답안과 비교합니다.

    판정 1. B105가 가리키는 "token_type": "bearer"는 하드코드된 비밀번호인가요?

    예시 답안 보기

    오탐입니다. bandit은 이름에 token이나 password가 들어간 자리에 문자열이 들어가면 의심합니다. 하지만 bearer는 OAuth2 표준이 정한 토큰 종류의 이름이라 모두에게 공개된 값입니다. 심각도도 Low라서, 다음 단계에서 Medium 이상만 보게 하면 보고되지 않습니다. 코드는 고치지 않습니다.

    판정 2. B608이 가리키는 보고서 SQL은 SQL 삽입 약점인가요? 문장의 어느 부분에 무엇이 들어가는지 따져 보세요.

    예시 답안 보기

    오탐입니다. f-문자열로 들어가는 것은 ORDER_COLUMNS[order_by]뿐인데, 이 값은 허용 목록 딕셔너리에서 꺼낸 "title"이나 "stock" 둘 중 하나입니다. 목록에 없는 값은 앞 단계에서 422로 막히고(S9-P30), 사용자가 보낸 검색어는 :pattern 자리에 따로 전달됩니다. 사용자 입력이 SQL 문장의 구조에 들어갈 길이 없습니다. 신뢰도가 Low인 것도 bandit 스스로 확신하지 못한다는 뜻입니다.

    오탐이라고 결론 내리기 전에

    "도구가 늘 틀리더라"는 생각으로 판정하면 안 됩니다. 값이 어디서 와서 어디로 가는지 실제 코드를 따라가 보고, 가능하면 S9에서처럼 공격 값을 넣어 확인한 뒤에 오탐이라고 적습니다. 판정이 애매하면 진짜 약점으로 보고 고치는 편이 안전합니다.

  3. 판정을 코드에 남기기

    B608은 Medium이라 그대로 두면 CI에서 계속 실패합니다. 판정 근거를 주석으로 적고 # nosec B608을 답니다. 여러 줄 문자열에서는 문자열이 끝나는 줄 뒤에 답니다. 문자열 안에 쓰면 주석이 아니라 SQL 문장의 일부가 되어 버립니다.

    app/repositories/reports.py
    def stock_report(db: Session, keyword: str, order_by: str) -> list[dict]:
    sql = text(f"""
        SELECT b.title, a.name AS author, b.stock
        FROM books b JOIN authors a ON a.id = b.author_id
        WHERE b.title LIKE :pattern
        ORDER BY {ORDER_COLUMNS[order_by]}, b.id
    """)  # nosec B608
    # 위 판정: 정렬 열 자리에는 ORDER_COLUMNS에 있는 값만 들어가므로 bandit B608은 오탐입니다.
    # :pattern 자리에는 값이 따로 전달되므로 SQL 문장의 구조를 바꿀 수 없습니다.
    rows = db.execute(sql, {"pattern": f"%{keyword}%"}).mappings()
    return [dict(row) for row in rows]
    bandit -r app -ll

  4. pip-audit 실행

    pip-audit -r requirements.txt
No known vulnerabilities found

    지금은 취약한 패키지가 없습니다. 만약 취약점이 나온다면 다음 순서로 처리합니다.

    순서할 일
    1ID로 검색해 내용을 읽고, 도서 API가 그 기능을 쓰는지 확인합니다.
    2Fix Versions 이상으로 requirements.txt의 버전을 올리고 pip install -r requirements.txt를 다시 실행합니다.
    3pytest로 전체 테스트를 돌려 올린 버전에서도 잘 동작하는지 확인합니다.
    4고친 버전이 아직 없으면, 위험을 기록해 두고 쓰는 기능을 피하거나 다른 패키지를 검토합니다.

  5. 판정 기록 남기기

    판정 결과는 팀이 함께 볼 수 있게 문서로 남깁니다. 같은 경고를 다음 사람이 다시 검토하지 않아도 되고, 나중에 코드가 바뀌어 판정이 달라져야 할 때 근거를 확인할 수 있습니다.

    도구규칙위치판정근거조치

    banditB105auth.py 로그인, 재발급 응답오탐bearer는 표준이 정한 공개 값없음(Low라 CI에서 보지 않음)
