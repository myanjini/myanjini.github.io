bandit과 pip-audit 실행

bandit과 pip-audit을 설치하고 실행해, 결과 화면의 각 줄이 무엇을 뜻하는지 읽는 법을 익힙니다. 다음 페이지의 실습에서 이 결과를 하나씩 판정합니다.

설치

두 도구는 서비스를 실행하는 데는 필요 없고 개발과 점검에만 씁니다. 가상 환경에 설치하되 requirements.txt에는 넣지 않습니다. 운영 이미지(S8)에 점검 도구가 들어가지 않게 하려는 것입니다.

pip install bandit pip-audit

자주 쓰는 옵션

옵션뜻
-l, -ll, -lll심각도 Low 이상, Medium 이상, High만 보여 줍니다.
-i, -ii, -iii신뢰도 Low 이상, Medium 이상, High만 보여 줍니다.
-q진행 메시지를 줄이고 결과만 보여 줍니다.
-x tests폴더를 점검에서 뺍니다.
-f json -o bandit.json결과를 JSON 파일로 저장합니다. 보고서를 만들 때 씁니다.

bandit은 보여 준 결과가 하나라도 있으면 종료 코드 1로, 없으면 0으로 끝납니다. 종료 코드는 프로그램이 성공했는지를 운영체제에 알리는 숫자로, 0이 성공입니다. CI는 이 숫자를 보고 단계의 성공과 실패를 정합니다(S11-P37-04).

검토한 결과 오탐이라고 판정한 줄에는 # nosec B608처럼 규칙 번호를 적은 주석을 달아 다음부터 보고하지 않게 할 수 있습니다. 번호 없이 # nosec만 쓰면 그 줄의 모든 규칙을 끄게 되므로 꼭 번호를 적고, 왜 오탐인지도 바로 옆에 주석으로 남깁니다.

pip-audit 실행과 결과 읽기

pip-audit은 PyPA(Python 패키지 관리 도구를 만드는 단체)가 만든 도구입니다. 패키지 목록을 PyPI와 OSV(공개 취약점 데이터베이스)의 취약점 정보와 대조합니다. -r로 requirements.txt를 주면 그 목록을 점검합니다.

pip-audit -r requirements.txt
No known vulnerabilities found

취약점이 있으면 어떻게 보이는지, 일부러 오래된 버전을 적은 파일로 확인해 봅니다. 이 파일은 확인만 하고 지웁니다.

old-requirements.txt(시험용)
requests==2.31.0
Jinja2==3.1.2
pip-audit -r old-requirements.txt
Found 16 known vulnerabilities in 2 packages
Name     Version ID              Fix Versions
-------- ------- --------------- ------------
requests 2.31.0  PYSEC-....-.... 2.32.0
requests 2.31.0  PYSEC-....-.... 2.32.4
...
jinja2   3.1.2   PYSEC-....-.... 3.1.3
jinja2   3.1.2   PYSEC-....-.... 3.1.6
...
열뜻
Name, Version취약한 패키지와 지금 버전
ID취약점 번호입니다. PYSEC, GHSA, CVE 같은 접두어로 시작합니다. 번호로 검색하면 내용과 영향을 볼 수 있습니다.
Fix Versions그 취약점이 고쳐진 버전입니다. 이 버전 이상으로 올리면 됩니다.

번호와 개수는 실행하는 날마다 달라집니다. 새로운 취약점이 계속 공개되기 때문입니다. 어제 깨끗했던 requirements.txt가 오늘은 취약하다고 나올 수 있으므로, 한 번 점검하고 끝내지 않고 정기적으로 다시 점검합니다. pip-audit도 취약점을 찾으면 종료 코드 1로 끝납니다.

인터넷 연결

pip-audit은 실행할 때마다 취약점 정보를 인터넷에서 받아 옵니다. 기관 네트워크에서 막혀 있으면 오류가 나므로, 그때는 강사에게 알리고 다음 실습으로 넘어갑니다.
