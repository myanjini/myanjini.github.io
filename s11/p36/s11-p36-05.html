경쟁 조건을 막는 열쇠는 "애플리케이션에서 확인하고 애플리케이션에서 계산"하던 일을 데이터베이스에 맡기는 것입니다. 애플리케이션의 검사는 빠른 안내용으로 남기고, 최종 판단은 데이터베이스의 조건과 제약이 합니다.

확인 퀴즈

book.stock -= 1 뒤에 commit하는 코드가 동시 요청에서 문제가 되는 이유는 무엇인가요?

실제 문장은 SET stock=0처럼 숫자를 저장합니다. 계산식(stock - 1)을 데이터베이스에 보내야 합니다.

조건부 UPDATE가 성공했는지는 무엇으로 알 수 있나요?

조건에 맞지 않으면 예외 없이 0개의 행을 바꿉니다. 그래서 바뀐 행의 수를 꼭 확인합니다.

대여 테이블에 (user_id, book_id) 전체가 아니라 부분 유일 인덱스를 쓴 이유는 무엇인가요?

반납하지 않은(returned_at이 비어 있는) 대여에만 "한 건" 규칙을 적용합니다.
