정리: 로드 밸런서

핵심 요약

주제핵심
ALB 구성보안 그룹, 대상 그룹(HTTP 8000, /health), 로드 밸런서(퍼블릭 서브넷 2개, 리스너 80) 순서로 만듭니다.
보안 그룹인터넷에 열린 곳은 ALB뿐. EC2는 ALB 보안 그룹에서 오는 8000번만 받습니다.
사용자 IPFORWARDED_ALLOW_IPS로 ALB가 붙인 X-Forwarded-For만 믿습니다. 로그인 실패 제한이 사용자별로 동작합니다.
헬스 체크정상 대상에만 요청을 보내고, 정상 대상이 없으면 502, 503을 돌려줍니다.
HTTPSACM 인증서, DNS 검증, 443 리스너, 80을 443으로 리디렉션, DNS 연결 순서입니다.

확인 퀴즈

대상이 계속 unhealthy입니다. 가장 먼저 확인할 것은 무엇인가요?

헬스 체크 요청도 ALB에서 EC2로 가므로, 보안 그룹이 막으면 실패합니다.

FORWARDED_ALLOW_IPS를 *(모두 믿음)로 두면 무엇이 문제인가요?

헤더는 사용자가 마음대로 만들 수 있으므로, 믿을 수 있는 프록시가 붙인 부분만 씁니다.

ALB 뒤로 옮긴 뒤에도 EC2에 퍼블릭 IP를 남겨 둔 이유는 무엇인가요?

들어오는 길은 보안 그룹이 막고, 나가는 길로만 씁니다.
