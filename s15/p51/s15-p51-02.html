컨테이너 로그 전송

컨테이너의 로그를 CloudWatch로 보내는 방법은 여러 가지가 있습니다. 이번에는 Docker에 들어 있는 awslogs 로그 드라이버를 씁니다. 앱 코드는 바꾸지 않고 운영용 Compose의 설정만 바꿉니다.

awslogs 로그 드라이버

로그 드라이버는 Docker가 컨테이너의 출력(표준 출력과 표준 오류)을 어디로 보낼지 정하는 부품입니다. 지금까지는 서버의 파일에 저장하는 json-file을 썼습니다. awslogs로 바꾸면 Docker 엔진이 컨테이너 출력을 받아 CloudWatch Logs로 바로 보냅니다. 보낼 때는 서버(EC2)의 IAM 역할 권한을 씁니다.

compose.prod.yaml의 logging 부분
    logging:
      driver: awslogs            # 로그를 CloudWatch Logs로 보냅니다.
      options:
        awslogs-region: ap-northeast-2
        awslogs-group: /book-api/app
        awslogs-create-group: "false"   # 로그 그룹은 미리 만들어 둡니다(보존 기간을 정하려고).
옵션뜻
awslogs-region로그를 보낼 리전
awslogs-group로그 그룹 이름
awslogs-create-group: "false"로그 그룹을 Docker가 만들지 않습니다. 미리 만들어 보존 기간을 정해 두고, 역할에는 그룹 만들기 권한을 주지 않습니다.
로그 스트림 이름적지 않으면 컨테이너 ID가 스트림 이름이 됩니다. 컨테이너를 새로 만들 때마다 새 스트림이 생깁니다.

Docker 20.10부터는 다른 로그 드라이버를 써도 서버에 작은 임시 사본을 남기는 "이중 로깅"이 기본이라, docker compose logs도 그대로 쓸 수 있습니다.

IAM 권한

EC2 역할이 이 로그 그룹 안에 스트림을 만들고 로그를 넣는 것만 허용합니다.

인라인 정책 book-api-logs
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "BookApiLogs",
      "Effect": "Allow",
      "Action": ["logs:CreateLogStream", "logs:PutLogEvents"],
      "Resource": "arn:aws:logs:ap-northeast-2:123456789012:log-group:/book-api/app:*"
    }
  ]
}

최종 운영용 Compose 파일

S3 설정, 로그 드라이버, 그리고 다음 파트(ALB)에서 필요한 FORWARDED_ALLOW_IPS까지 넣은 8일차 오전의 최종 파일입니다. 볼륨이 하나도 없다는 점에 주목합니다. 서버에 남는 데이터가 없으므로, 서버를 지우고 새로 만들어도 서비스가 그대로 이어집니다.

compose.prod.yaml
# 운영(EC2)용 Compose 파일
# - 이미지는 ECR에서 받습니다. 어떤 이미지를 쓸지는 같은 폴더의 .env에 IMAGE=... 로 적습니다.
# - 비밀 값(SECRET_KEY, DATABASE_URL)은 이 파일에도 .env에도 적지 않고, 앱이 Parameter Store에서 읽습니다.
# - 데이터베이스는 RDS를 쓰므로 db 서비스가 없습니다.
# - 표지는 S3에, 로그는 CloudWatch Logs에 저장하므로 서버에 볼륨이 필요 없습니다.
services:
  api:
    image: ${IMAGE:?IMAGE를 .env에 적어 주세요}
    restart: unless-stopped
    ports:
      - "8000:8000"
    environment:
      APP_ENV: production              # /docs, /redoc, /openapi.json을 끕니다.
      SSM_PREFIX: /book-api/           # 이 경로 아래의 비밀 값을 읽습니다.
      AWS_DEFAULT_REGION: ap-northeast-2
      LOG_LEVEL: INFO
      COVER_BUCKET: ${COVER_BUCKET:?COVER_BUCKET을 .env에 적어 주세요}  # 표지를 저장할 S3 버킷
      FORWARDED_ALLOW_IPS: 10.0.0.0/16  # 이 범위(VPC 안의 ALB)가 보낸 X-Forwarded-For만 믿습니다.
    healthcheck:
      test: ["CMD", "python", "-c", "import urllib.request; urllib.request.urlopen('http://localhost:8000/health')"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 20s
    logging:
      driver: awslogs            # 로그를 CloudWatch Logs로 보냅니다.
      options:
        awslogs-region: ap-northeast-2
        awslogs-group: /book-api/app
        awslogs-create-group: "false"   # 로그 그룹은 미리 만들어 둡니다(보존 기간을 정하려고).

FORWARDED_ALLOW_IPS는 다음 파트에서

이 값이 무엇인지는 S15-P52-01에서 설명합니다. 지금 넣어 두어도 ALB가 없는 동안에는 동작에 영향이 없습니다.
