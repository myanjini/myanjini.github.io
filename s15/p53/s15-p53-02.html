배포 워크플로 보기

배포 워크플로 파일과 배포 역할의 권한 정책을 읽어 봅니다. 기존 테스트 워크플로는 다시 쓰고, 새 파일 deploy.yml을 만듭니다.

테스트 워크플로를 불러 쓰기

test.yml에 workflow_call을 더하면 다른 워크플로가 이것을 한 단계처럼 불러 쓸 수 있습니다. main에 푸시할 때는 deploy.yml이 테스트를 부르므로, test.yml 자체는 풀 리퀘스트에서만 실행되게 바꿉니다. 그러지 않으면 푸시할 때 테스트가 두 번 돕니다.

.github/workflows/test.yml의 on 부분
on:
  pull_request:
    branches: [main]
  workflow_call:  # 배포 워크플로(deploy.yml)가 이 워크플로를 불러 씁니다. main 푸시 때는 거기서 실행됩니다.

배포 워크플로

.github/workflows/deploy.yml
name: deploy

# main에 푸시하면 테스트를 거쳐 EC2까지 배포합니다. Actions 화면에서 직접 실행할 수도 있습니다.
on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  id-token: write  # GitHub가 이 실행을 증명하는 OIDC 토큰을 발급할 수 있게 합니다.

concurrency:
  group: deploy           # 배포는 한 번에 하나씩만 실행합니다.
  cancel-in-progress: false

env:
  AWS_REGION: ap-northeast-2
  ECR_REPOSITORY: book-api

jobs:
  test:
    uses: ./.github/workflows/test.yml  # 테스트와 보안 점검(test.yml)을 그대로 다시 씁니다.

  deploy:
    needs: test  # 테스트가 통과해야 시작합니다.
    runs-on: ubuntu-latest
    steps:
      - name: 코드 내려받기
        uses: actions/checkout@v7

      - name: AWS 자격 증명 받기(OIDC, 액세스 키 없음)
        uses: aws-actions/configure-aws-credentials@v6
        with:
          role-to-assume: ${{ vars.AWS_DEPLOY_ROLE_ARN }}
          aws-region: ${{ env.AWS_REGION }}

      - name: ECR 로그인
        id: ecr
        uses: aws-actions/amazon-ecr-login@v2

      - name: 이미지 빌드와 푸시
        run: |
          IMAGE=${{ steps.ecr.outputs.registry }}/$ECR_REPOSITORY:git-${GITHUB_SHA::7}
          docker build -t "$IMAGE" .
          docker push "$IMAGE"
          echo "IMAGE=$IMAGE" >> "$GITHUB_ENV"

      - name: EC2에 배포(Systems Manager Run Command)
        env:
          INSTANCE_ID: ${{ vars.EC2_INSTANCE_ID }}
          REGISTRY: ${{ steps.ecr.outputs.registry }}
        run: |
          cat > commands.json <<EOF
          {"commands": [
            "set -e",
            "cd /home/ssm-user/book-api",
            "aws ecr get-login-password --region $AWS_REGION | docker login --username AWS --password-stdin $REGISTRY",
            "sed -i 's|^IMAGE=.*|IMAGE=$IMAGE|' .env",
            "docker compose -f compose.prod.yaml pull",
            "docker compose -f compose.prod.yaml run --rm api alembic upgrade head",
            "docker compose -f compose.prod.yaml up -d",
            "docker image prune -f"
          ]}
          EOF
          COMMAND_ID=$(aws ssm send-command --instance-ids "$INSTANCE_ID" \
            --document-name AWS-RunShellScript --comment "deploy ${GITHUB_SHA::7}" \
            --parameters file://commands.json --query Command.CommandId --output text)
          echo "명령 ID: $COMMAND_ID"
          for i in $(seq 1 60); do  # 최대 5분 동안 5초마다 결과를 확인합니다.
            sleep 5
            STATUS=$(aws ssm get-command-invocation --command-id "$COMMAND_ID" --instance-id "$INSTANCE_ID" \
              --query Status --output text 2>/dev/null || echo Pending)
            case "$STATUS" in Pending|InProgress|Delayed) continue ;; *) break ;; esac
          done
          aws ssm get-command-invocation --command-id "$COMMAND_ID" --instance-id "$INSTANCE_ID" \
            --query "[StandardOutputContent, StandardErrorContent]" --output text
          echo "결과: $STATUS"
          test "$STATUS" = "Success"

      - name: 배포 확인(ALB로 /health 호출)
        run: curl -fsS --retry 12 --retry-delay 10 --retry-all-errors "http://${{ vars.ALB_DNS_NAME }}/health"
부분뜻
permissions: id-token: write이 실행이 OIDC 토큰을 발급받을 수 있게 합니다. contents: read로 저장소는 읽기만 합니다.
concurrency: deploy푸시가 연달아 와도 배포는 하나씩 차례로 실행합니다.
uses: ./.github/workflows/test.yml테스트와 보안 점검을 그대로 실행합니다. needs: test로 통과해야 배포를 시작합니다.
configure-aws-credentialsOIDC 토큰으로 배포 역할을 맡아 임시 자격 증명을 받습니다.
amazon-ecr-loginECR에 로그인하고 레지스트리 주소를 steps.ecr.outputs.registry로 알려 줍니다.
git-${GITHUB_SHA::7}커밋 해시 앞 7자로 태그를 붙입니다. 어떤 커밋이 배포되었는지 이미지 이름으로 알 수 있습니다.
commands.json서버에서 실행할 명령 목록입니다. set -e로 하나라도 실패하면 거기서 멈춥니다. 마이그레이션이 실패하면 컨테이너를 교체하지 않습니다.
aws ssm send-commandRun Command로 EC2에 명령을 보냅니다. SSH나 열린 포트 없이, Session Manager와 같은 SSM 에이전트가 받아 root 권한으로 실행합니다.
결과 확인 반복문최대 5분 동안 5초마다 명령 상태를 보고, 출력과 오류를 실행 기록에 남깁니다. Success가 아니면 실패로 끝납니다.
curl --retry새 컨테이너가 뜨고 ALB가 정상으로 볼 때까지 10초 간격으로 최대 12번 시도합니다.

배포 역할의 권한

배포 역할의 인라인 정책 book-api-deploy
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "EcrLogin",
      "Effect": "Allow",
      "Action": "ecr:GetAuthorizationToken",
      "Resource": "*"
    },
    {
      "Sid": "EcrPushBookApi",
      "Effect": "Allow",
      "Action": [
        "ecr:BatchCheckLayerAvailability",
        "ecr:InitiateLayerUpload",
        "ecr:UploadLayerPart",
        "ecr:CompleteLayerUpload",
        "ecr:PutImage",
        "ecr:BatchGetImage"
      ],
      "Resource": "arn:aws:ecr:ap-northeast-2:123456789012:repository/book-api"
    },
    {
      "Sid": "RunDeployCommandOnBookApiServer",
      "Effect": "Allow",
      "Action": "ssm:SendCommand",
      "Resource": [
        "arn:aws:ec2:ap-northeast-2:123456789012:instance/i-0123456789abcdef0",
        "arn:aws:ssm:ap-northeast-2::document/AWS-RunShellScript"
      ]
    },
    {
      "Sid": "ReadCommandResult",
      "Effect": "Allow",
      "Action": "ssm:GetCommandInvocation",
      "Resource": "*"
    }
  ]
}

ECR 로그인(GetAuthorizationToken)은 자원을 지정할 수 없어 *이지만, 실제로 올리는 권한은 book-api 저장소 하나로 좁혔습니다. Run Command는 이 인스턴스 하나와 AWS-RunShellScript 문서에만 허용합니다. 이 역할로는 다른 서버에 명령을 보내거나, 이미지를 지우거나, 비밀 값을 읽을 수 없습니다.

서버 쪽 권한은 이미 있습니다

Run Command는 서버의 SSM 에이전트가 받으므로, EC2 역할의 AmazonSSMManagedInstanceCore로 충분합니다. 서버에서 ECR에 로그인하고 이미지를 받는 권한도 S12에서 붙였습니다.
