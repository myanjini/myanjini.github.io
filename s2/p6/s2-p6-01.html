HTTPException과 예외 처리기

이 파트의 학습 목표일관된 오류 응답을 설계하고 API 문서를 정리할 수 있습니다.

오류가 났을 때 클라이언트가 무엇이 잘못되었는지 프로그램으로 판단할 수 있도록, 오류 응답의 모양을 하나로 정하는 방법을 배웁니다.

HTTPException 다시 보기

raise HTTPException(status_code=404, detail="도서를 찾을 수 없습니다.")

이렇게 하면 응답은 {"detail": "도서를 찾을 수 없습니다."}입니다. 간단하지만 두 가지 아쉬움이 있습니다.

  • 화면을 만드는 개발자가 오류 종류에 따라 다르게 처리하려면 메시지 문장을 비교해야 합니다. 메시지 문구를 조금만 바꿔도 화면 쪽 코드가 깨집니다.
  • 개발자마다 detail에 문장을 넣기도 하고 딕셔너리를 넣기도 해, 오류 모양이 제각각이 되기 쉽습니다.

공통 오류 형식 정하기

이 과정에서는 우리가 일부러 보내는 오류를 모두 다음 모양으로 통일합니다.

{
  "code": "BOOK_NOT_FOUND",
  "message": "3번 도서를 찾을 수 없습니다."
}
항목누가 읽나요설명
code프로그램오류 종류를 나타내는 고정된 이름입니다. 한 번 정하면 바꾸지 않습니다.
message사람화면에 보여 줄 수 있는 설명입니다. 문구는 언제든 다듬어도 됩니다.

사용자 정의 예외와 예외 처리기

오류를 낼 때 쓸 예외 클래스를 직접 만들고, 그 예외가 발생하면 공통 형식으로 바꿔 주는 예외 처리기를 등록합니다.

class AppError(Exception):
    """이 앱이 일부러 보내는 오류. 상태 코드, 오류 코드, 메시지를 담습니다."""

    def __init__(self, status_code: int, code: str, message: str):
        self.status_code = status_code
        self.code = code
        self.message = message


@app.exception_handler(AppError)
def handle_app_error(request: Request, exc: AppError):
    # 어떤 AppError든 같은 모양의 JSON으로 바꿔 응답합니다.
    return JSONResponse(
        status_code=exc.status_code,
        content={"code": exc.code, "message": exc.message},
    )

이제 어디서든 raise AppError(404, "BOOK_NOT_FOUND", "...")를 실행하면, 함수는 그 자리에서 멈추고 예외 처리기가 실행되어 공통 형식의 응답이 나갑니다. 처리기의 request 매개변수는 지금은 쓰지 않지만, FastAPI가 처리기를 부를 때 넘겨주므로 자리를 만들어 둡니다.

422 오류는 그대로 둡니다

입력 검증에 실패했을 때 FastAPI가 보내는 422 응답은 어떤 항목이 왜 틀렸는지 자세히 알려 주는 별도 형식입니다. 이 과정에서는 그 형식을 그대로 씁니다. 오류 응답에 어떤 정보까지 담아도 되는지는 5일차 개발 보안 단원에서 다시 점검합니다.
