User 모델과 회원가입

사용자 테이블을 만들고, 비밀번호를 해시로 바꿔 저장하는 코드를 강사 화면으로 봅니다. 다음 페이지 실습에서 이 코드를 그대로 씁니다.

해시 도구 설치

pip install "pwdlib[argon2]"

pwdlib는 비밀번호 해시를 만들고 검증하는 작은 라이브러리입니다. [argon2]를 붙이면 Argon2 계산 모듈도 함께 설치됩니다.

User 모델

app/models.py의 Author 클래스 위에 추가합니다.

app/models.py
class User(Base):
    __tablename__ = "users"

    id: Mapped[int] = mapped_column(primary_key=True)
    email: Mapped[str] = mapped_column(String(255), unique=True)
    # 비밀번호 원문이 아니라 해시만 저장합니다.
    hashed_password: Mapped[str] = mapped_column(String(255))
    # 역할: 일반 사용자는 "user", 관리자는 "admin"
    role: Mapped[str] = mapped_column(String(20), default="user")
열설명
email로그인할 때 쓰는 아이디입니다. 같은 이메일로 두 번 가입할 수 없도록 unique=True를 줍니다.
hashed_password비밀번호 해시입니다. 이름에 hashed를 넣어 원문이 아니라는 것을 코드에서도 바로 알 수 있게 합니다.
role역할입니다. 가입하면 "user"로 시작하고, 관리자는 "admin"입니다. S5-P17에서 씁니다.

해시 함수 모음: security.py

인증에 관련된 계산을 한 파일에 모읍니다. 오늘 오전 내내 이 파일에 함수가 늘어납니다.

app/security.py
from pwdlib import PasswordHash

# 지금 권장되는 알고리즘(Argon2)으로 비밀번호 해시를 만드는 도구입니다.
password_hash = PasswordHash.recommended()


def hash_password(password: str) -> str:
    """비밀번호를 해시로 바꿉니다. 같은 비밀번호도 호출할 때마다 다른 결과가 나옵니다."""
    return password_hash.hash(password)


def verify_password(password: str, hashed: str) -> bool:
    """입력한 비밀번호가 저장된 해시와 맞는지 확인합니다."""
    return password_hash.verify(password, hashed)

PasswordHash.recommended()는 pwdlib가 권장하는 설정(Argon2)으로 도구를 만듭니다. 나중에 더 안전한 설정이 권장되면 이 한 줄만 바꾸면 됩니다.

Python 대화형 셸에서 직접 확인해 봅시다. 같은 비밀번호를 두 번 해시하면 솔트가 달라 결과가 다르지만, 검증은 둘 다 통과합니다.

>>> from app.security import hash_password, verify_password
>>> h1 = hash_password("practice-pass-1")
>>> h2 = hash_password("practice-pass-1")
>>> h1 == h2
False
>>> verify_password("practice-pass-1", h1), verify_password("practice-pass-1", h2)
(True, True)
>>> verify_password("wrong-pass", h1)
False

입력 모델과 출력 모델

1일차에 도서의 매입가를 응답에서 감췄던 것처럼, 사용자 응답에서는 비밀번호 해시를 감춥니다. 해시도 유출되면 공격자가 대입을 시도할 재료가 되므로 응답에 절대 넣지 않습니다.

app/schemas.py
class UserCreate(BaseModel):
    """회원가입에 쓰는 입력 모델"""
    email: EmailStr = Field(examples=["user1@example.com"])
    password: str = Field(min_length=8, max_length=64, examples=["practice-pass-1"])


class UserRead(BaseModel):
    """사용자 응답 모델. 비밀번호 해시는 넣지 않습니다."""

    model_config = ConfigDict(from_attributes=True)

    id: int
    email: str
    role: str

EmailStr은 이메일 형식인지 검사하는 타입입니다. @가 없거나 도메인 부분이 이상하면 422로 막습니다. 1일차에 설치한 fastapi[standard]에 검사 모듈(email-validator)이 들어 있어 따로 설치하지 않아도 됩니다. 비밀번호는 우선 길이만 8~64자로 제한합니다. 더 꼼꼼한 비밀번호 규칙은 5일차 보안 단원에서 추가합니다.

마이그레이션

모델을 추가했으니 2일차에 배운 순서대로 리비전을 만들고 확인한 뒤 적용합니다.

alembic revision --autogenerate -m "create users"
...
INFO  [alembic.autogenerate.compare.tables] Detected added table 'users'

새로 생긴 리비전 파일의 upgrade에 users 테이블을 만드는 코드만 들어 있는지 확인합니다. 다른 테이블을 지우거나 바꾸는 코드가 섞여 있다면 모델을 잘못 고친 것입니다.

def upgrade() -> None:
    op.create_table('users',
    sa.Column('id', sa.Integer(), nullable=False),
    sa.Column('email', sa.String(length=255), nullable=False),
    sa.Column('hashed_password', sa.String(length=255), nullable=False),
    sa.Column('role', sa.String(length=20), nullable=False),
    sa.PrimaryKeyConstraint('id'),
    sa.UniqueConstraint('email')
    )
