보호된 API 적용

현재 사용자 의존성을 도서 API에 연결합니다. 어떤 API를 보호할지 정하고, 보호하는 두 가지 방법을 비교합니다.

어떤 API를 보호하나요

도서 목록과 상세 조회는 누구나 볼 수 있어야 합니다. 도서관 서가는 회원이 아니어도 둘러볼 수 있는 것과 같습니다. 데이터를 바꾸는 등록, 수정, 삭제만 로그인한 사용자에게 허락합니다.

방법 1: 매개변수로 받기

경로 함수에서 현재 사용자 정보가 필요하면 매개변수로 받습니다. 도서를 등록할 때는 누가 등록했는지 기록해야 하므로 이 방법을 씁니다.

app/routers/books.py
@router.post("", response_model=BookRead, status_code=status.HTTP_201_CREATED, summary="도서 등록", ...)
def create_book(db: SessionDep, user: CurrentUserDep, book_in: BookCreate):
    ...
    book = Book(**book_in.model_dump(), owner_id=user.id)  # 등록한 사람을 기록합니다.

user: CurrentUserDep 한 줄이면 FastAPI가 경로 함수를 실행하기 전에 get_current_user를 먼저 실행합니다. 검사에서 막히면 경로 함수는 실행되지 않고 401이 나갑니다.

create_book도 SessionDep을 받고 get_current_user도 SessionDep을 받습니다. 그래도 세션은 두 개가 아니라 하나만 열립니다. FastAPI는 한 요청 안에서 같은 의존성을 한 번만 실행하고 그 결과를 나눠 쓰기 때문입니다.

방법 2: 검사만 하기

사용자 정보는 필요 없고 "통과했는가"만 중요할 때는 경로 데코레이터의 dependencies에 넣습니다. 저자 등록과 삭제는 관리자만 할 수 있게 하는데, 함수 안에서 관리자 정보를 쓸 일은 없으므로 이 방법이 어울립니다.

app/dependencies.py
def require_admin(user: CurrentUserDep) -> User:
    """관리자가 아니면 403으로 막습니다."""
    if user.role != "admin":
        raise AppError(403, "FORBIDDEN", "관리자만 사용할 수 있습니다.")
    return user
app/routers/authors.py
@router.post("", response_model=AuthorRead, status_code=status.HTTP_201_CREATED, summary="저자 등록",
             dependencies=[Depends(require_admin)],  # 관리자만 호출할 수 있습니다.
             responses={409: {"description": "이미 등록된 저자 이름"}})
def create_author(db: SessionDep, author_in: AuthorCreate):

require_admin은 CurrentUserDep을 받으므로, 로그인하지 않았으면 401이, 로그인했지만 관리자가 아니면 403이 나갑니다. 의존성을 겹쳐 쌓아 인증과 인가를 차례로 검사하는 구조입니다.

내 정보 조회 API

Swagger UI에서 달라지는 점

보호된 API가 생기면 /docs 오른쪽 위에 Authorize 버튼이 나타나고, 보호된 API 옆에는 자물쇠 그림이 붙습니다. GET /books처럼 보호하지 않은 API에는 자물쇠가 없습니다. Authorize 창에서 로그인하면 자물쇠가 잠긴 모양으로 바뀌고, 그때부터 보내는 요청에 토큰이 자동으로 들어갑니다. 창의 Logout 버튼은 Swagger UI가 기억한 토큰을 지울 뿐 서버에는 아무것도 보내지 않습니다.
