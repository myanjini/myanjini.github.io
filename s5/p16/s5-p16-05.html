정리: 토큰 발급

핵심 요약

  • 로그인할 때 한 번 비밀번호를 확인하고, 이후에는 액세스 토큰을 Authorization: Bearer 헤더에 넣어 보냅니다.
  • JWT는 헤더, 페이로드, 서명의 세 부분입니다. 페이로드는 누구나 읽을 수 있으므로 민감한 정보를 넣지 않습니다.
  • 서명은 비밀 키로 계산하므로, 키를 모르면 내용을 바꾼 토큰을 만들 수 없습니다. 비밀 키는 서버 전체의 열쇠입니다.
  • OAuth2 Password Flow의 로그인 API는 username과 password를 폼 형식으로 받고 access_token, token_type을 돌려줍니다.
  • 이메일이 틀린 경우와 비밀번호가 틀린 경우의 응답은 메시지와 걸리는 시간 모두 같게 만듭니다.

확인 퀴즈

JWT 페이로드에 대한 설명으로 알맞은 것은 무엇인가요?

페이로드는 Base64URL로 적은 것일 뿐이라 누구나 읽습니다. 대신 내용을 바꾸면 서명이 맞지 않습니다.

없는 이메일로 로그인할 때도 가짜 해시로 비밀번호 검증을 한 번 하는 이유는 무엇인가요?

검증을 건너뛰면 없는 이메일의 응답이 훨씬 빨라져, 시간만 재 보고도 가입 여부를 알 수 있게 됩니다.

웹 화면 개발자가 로그인 요청을 JSON으로 보냈더니 422가 나왔습니다. 알맞은 안내는 무엇인가요?

OAuth2 Password Flow 규칙에 따라 로그인 API는 폼 형식으로 받습니다.
