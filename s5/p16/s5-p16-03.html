로그인 API가 사용자를 확인하고 토큰을 만들어 돌려주기까지의 코드를 강사 화면으로 봅니다.

JWT 라이브러리와 설정

pip install pyjwt

PyJWT는 JWT를 만들고 검증하는 라이브러리입니다. 가져올 때 이름은 jwt입니다. 토큰 유효 시간은 환경마다 다르게 정할 수 있도록 설정에 추가합니다.

app/config.py
    secret_key: str  # 기본값이 없으므로 반드시 설정해야 합니다.
    access_token_expire_minutes: int = 30  # 액세스 토큰 유효 시간(분)

토큰 만들기

app/security.py
ALGORITHM = "HS256"  # 비밀 키 하나로 서명하고 검증하는 방식


def create_access_token(user_id: int) -> str:
    """사용자 번호와 만료 시각을 담아 서명한 JWT를 만듭니다."""
    expire = datetime.now(timezone.utc) + timedelta(minutes=settings.access_token_expire_minutes)
    payload = {"sub": str(user_id), "exp": expire}
    return jwt.encode(payload, settings.secret_key, algorithm=ALGORITHM)

jwt.encode는 페이로드와 비밀 키로 서명까지 붙인 JWT 문자열을 돌려줍니다. 만료 시각은 datetime으로 넣으면 PyJWT가 초 단위 숫자로 바꿔 줍니다. 시각은 서버가 있는 지역과 상관없도록 UTC(세계 표준시)로 계산합니다. sub는 표준에서 문자열로 정해 두었기 때문에 str(user_id)로 넣습니다.

사용자 확인하기

app/security.py
# 없는 이메일로 로그인할 때 비교용으로 쓰는 가짜 해시입니다.
DUMMY_HASH = password_hash.hash("dummy-password")
app/routers/auth.py
# 401 응답에는 어떤 방식으로 인증해야 하는지 알려 주는 헤더를 붙입니다.
BEARER = {"WWW-Authenticate": "Bearer"}


def authenticate(db: Session, email: str, password: str) -> User | None:
    """이메일과 비밀번호가 맞으면 사용자를, 틀리면 None을 돌려줍니다."""
    user = db.scalar(select(User).where(User.email == email.lower()))
    if user is None:
        verify_password(password, DUMMY_HASH)  # 없는 이메일도 비슷한 시간이 걸리게 합니다.
        return None
    if not verify_password(password, user.hashed_password):
        return None
    return user

이메일이 틀린 경우와 비밀번호가 틀린 경우를 똑같이 다룹니다. 두 경우의 응답이 다르면 공격자가 "이 이메일은 가입되어 있다"는 사실을 알아낼 수 있기 때문입니다. 메시지뿐 아니라 걸리는 시간도 비슷해야 합니다. 비밀번호 해시 검증은 일부러 느리게 만든 계산이라, 없는 이메일일 때 검증을 건너뛰면 응답이 눈에 띄게 빨라집니다. 그래서 없는 이메일이어도 가짜 해시로 한 번 검증해 시간을 맞춥니다.

401 응답에 헤더 붙이기

HTTP 규칙상 401 응답에는 어떤 방식으로 인증해야 하는지 알려 주는 WWW-Authenticate 헤더를 붙입니다. 지금의 AppError는 헤더를 담을 수 없으므로 하나를 더 받게 고칩니다.

app/errors.py
class AppError(Exception):
    """이 앱이 일부러 보내는 오류. 상태 코드, 오류 코드, 메시지를 담습니다."""

    def __init__(self, status_code: int, code: str, message: str, headers: dict[str, str] | None = None):
        self.status_code = status_code
        self.code = code
        self.message = message
        self.headers = headers  # 응답 헤더에 함께 보낼 값(401의 WWW-Authenticate 등)
app/main.py
    return JSONResponse(
        status_code=exc.status_code,
        content={"code": exc.code, "message": exc.message},
        headers=exc.headers,
    )

headers는 기본값이 None이라 지금까지 쓰던 AppError(404, ...) 같은 코드는 고치지 않아도 됩니다.

로그인 API

app/schemas.py
class Token(BaseModel):
    """로그인 응답. OAuth2 규칙에 맞춰 이름을 정합니다."""
    access_token: str
    token_type: str = "bearer"
app/routers/auth.py
@router.post("/token", response_model=Token, summary="로그인(토큰 발급)",
             responses={401: {"description": "이메일 또는 비밀번호가 틀림"}})
def login(db: SessionDep, form: Annotated[OAuth2PasswordRequestForm, Depends()]):
    # OAuth2 규칙상 입력 칸 이름은 username입니다. 이 앱에서는 이메일을 넣습니다.
    user = authenticate(db, form.username, form.password)
    if user is None:
        raise AppError(401, "INVALID_CREDENTIALS", "이메일 또는 비밀번호가 올바르지 않습니다.", headers=BEARER)
    return {"access_token": create_access_token(user.id), "token_type": "bearer"}

Annotated[OAuth2PasswordRequestForm, Depends()]는 2일차에 만든 Pagination처럼 클래스를 의존성으로 쓰는 방법입니다. FastAPI가 폼에서 값을 읽어 form.username, form.password에 넣어 줍니다. 응답의 access_token과 token_type은 OAuth2 표준이 정한 이름이므로 바꾸지 않습니다.

Swagger UI의 Authorize 버튼

다음 파트에서 보호된 API를 하나라도 만들면 /docs 오른쪽 위에 Authorize 버튼이 생깁니다. 버튼을 누르면 로그인 창이 열리고, username에 이메일, password에 비밀번호를 넣으면 Swagger UI가 /auth/token을 대신 호출해 토큰을 받아 둡니다. 그 뒤로 보내는 요청에는 Swagger UI가 Authorization 헤더를 자동으로 붙여 줍니다. 이번 파트에서는 아직 버튼이 없으니 POST /auth/token을 직접 호출해 봅니다.
