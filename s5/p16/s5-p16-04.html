로그인 API 구현

로그인 API를 만들고, 받은 토큰을 직접 풀어 보며 JWT가 정말 앞에서 배운 구조인지 확인합니다.

실습 목표로그인 시 JWT를 발급하고, 토큰의 내용과 서명 검증을 직접 확인할 수 있습니다.

  1. 설치하고 설정 추가

    서버를 끄고 pip install pyjwt를 실행합니다. app/config.py에 access_token_expire_minutes를 추가하고, .env.example에도 한 줄을 더해 다른 사람이 이 설정이 있다는 것을 알 수 있게 합니다.

    .env.example
    ACCESS_TOKEN_EXPIRE_MINUTES=30

    .env에는 적지 않아도 됩니다. 값이 없으면 기본값 30이 쓰입니다.

  2. AppError에 headers 추가

    앞 페이지대로 app/errors.py와 app/main.py의 오류 처리기를 고칩니다.

  3. security.py에 토큰 함수 추가

    app/security.py 전체 펼치기
    app/security.py
    from datetime import datetime, timedelta, timezone

import jwt
from pwdlib import PasswordHash

from app.config import settings

# 지금 권장되는 알고리즘(Argon2)으로 비밀번호 해시를 만드는 도구입니다.
password_hash = PasswordHash.recommended()

# 없는 이메일로 로그인할 때 비교용으로 쓰는 가짜 해시입니다.
DUMMY_HASH = password_hash.hash("dummy-password")


def hash_password(password: str) -> str:
    """비밀번호를 해시로 바꿉니다. 같은 비밀번호도 호출할 때마다 다른 결과가 나옵니다."""
    return password_hash.hash(password)


def verify_password(password: str, hashed: str) -> bool:
    """입력한 비밀번호가 저장된 해시와 맞는지 확인합니다."""
    return password_hash.verify(password, hashed)


ALGORITHM = "HS256"  # 비밀 키 하나로 서명하고 검증하는 방식


def create_access_token(user_id: int) -> str:
    """사용자 번호와 만료 시각을 담아 서명한 JWT를 만듭니다."""
    expire = datetime.now(timezone.utc) + timedelta(minutes=settings.access_token_expire_minutes)
    payload = {"sub": str(user_id), "exp": expire}
    return jwt.encode(payload, settings.secret_key, algorithm=ALGORITHM)

  4. Token 스키마와 로그인 API 추가

    app/schemas.py의 UserRead 아래에 Token을 추가하고, app/routers/auth.py를 아래 전체 코드로 바꿉니다.

    app/routers/auth.py 전체 펼치기
    app/routers/auth.py
    from typing import Annotated

from fastapi import APIRouter, Depends, status
from fastapi.security import OAuth2PasswordRequestForm
from sqlalchemy import select
from sqlalchemy.orm import Session

from app.dependencies import SessionDep
from app.errors import AppError
from app.models import User
from app.schemas import Token, UserCreate, UserRead
from app.security import DUMMY_HASH, create_access_token, hash_password, verify_password

router = APIRouter(prefix="/auth", tags=["인증"])


@router.post("/signup", response_model=UserRead, status_code=status.HTTP_201_CREATED, summary="회원가입",
             responses={409: {"description": "이미 가입된 이메일"}})
def signup(db: SessionDep, user_in: UserCreate):
    email = user_in.email.lower()  # 대문자로 적어도 같은 이메일로 봅니다.
    if db.scalar(select(User).where(User.email == email)) is not None:
        raise AppError(409, "DUPLICATE_EMAIL", "이미 가입된 이메일입니다.")
    user = User(email=email, hashed_password=hash_password(user_in.password))
    db.add(user)
    db.commit()
    db.refresh(user)
    return user


# 401 응답에는 어떤 방식으로 인증해야 하는지 알려 주는 헤더를 붙입니다.
BEARER = {"WWW-Authenticate": "Bearer"}


def authenticate(db: Session, email: str, password: str) -> User | None:
    """이메일과 비밀번호가 맞으면 사용자를, 틀리면 None을 돌려줍니다."""
    user = db.scalar(select(User).where(User.email == email.lower()))
    if user is None:
        verify_password(password, DUMMY_HASH)  # 없는 이메일도 비슷한 시간이 걸리게 합니다.
        return None
    if not verify_password(password, user.hashed_password):
        return None
    return user


@router.post("/token", response_model=Token, summary="로그인(토큰 발급)",
             responses={401: {"description": "이메일 또는 비밀번호가 틀림"}})
def login(db: SessionDep, form: Annotated[OAuth2PasswordRequestForm, Depends()]):
    # OAuth2 규칙상 입력 칸 이름은 username입니다. 이 앱에서는 이메일을 넣습니다.
    user = authenticate(db, form.username, form.password)
    if user is None:
        raise AppError(401, "INVALID_CREDENTIALS", "이메일 또는 비밀번호가 올바르지 않습니다.", headers=BEARER)
    return {"access_token": create_access_token(user.id), "token_type": "bearer"}

  5. Swagger UI로 로그인

    서버를 실행하고 POST /auth/token을 펼칩니다. 요청 본문이 JSON 칸이 아니라 username, password 같은 입력 칸으로 나오는 것이 폼 형식입니다. grant_type, scope, client_id, client_secret은 표준에 있는 선택 항목이라 비워 둡니다.

    입력기대하는 결과내 결과
    username user1@example.com, password practice-pass-1200, access_token과 "token_type": "bearer"
    username user1@example.com, password wrong-pass401, INVALID_CREDENTIALS, 응답 헤더에 www-authenticate: Bearer
    username nobody@example.com, password wrong-pass위와 똑같은 401 응답

    첫 번째 응답의 access_token 값을 복사해 둡니다.

  6. JSON으로 보내면 어떻게 되는지 확인

    로그인 API가 폼만 받는다는 것을 curl로 확인합니다. 새 터미널을 열어 실행합니다(PowerShell이라면 curl.exe).

    curl -i -X POST http://127.0.0.1:8000/auth/token -d "username=user1@example.com&password=practice-pass-1"
curl -i -X POST http://127.0.0.1:8000/auth/token -H "Content-Type: application/json" -d "{\"username\": \"user1@example.com\", \"password\": \"practice-pass-1\"}"

    -d만 쓰면 curl은 폼 형식으로 보내므로 첫 번째는 200입니다. 두 번째는 JSON이라 FastAPI가 폼에서 username을 찾지 못해 422(Field required)를 돌려줍니다. 웹 화면을 만드는 사람에게 "로그인은 폼으로 보내야 한다"고 알려 줘야 하는 이유입니다.

  7. 토큰 풀어 보기

    서버를 실행한 터미널이 아닌 다른 터미널에서, 가상환경을 켜고 book-api 폴더에서 python을 실행합니다. 토큰 자리에 복사한 값을 붙여 넣습니다.

    >>> import jwt
>>> token = "토큰"
>>> jwt.get_unverified_header(token)
{'alg': 'HS256', 'typ': 'JWT'}
>>> payload = jwt.decode(token, options={"verify_signature": False})
>>> payload
{'sub': '1', 'exp': 1795237482}
>>> from datetime import datetime
>>> datetime.fromtimestamp(payload["exp"])

    비밀 키 없이도 내용을 읽을 수 있습니다. 마지막 줄은 만료 시각을 내 컴퓨터의 시간으로 보여 주는데, 로그인한 시각에서 30분 뒤여야 합니다. exp 숫자는 로그인한 시각에 따라 다릅니다.

  8. 서명 검증해 보기

    >>> from app.config import settings
>>> jwt.decode(token, settings.secret_key, algorithms=["HS256"])
{'sub': '1', 'exp': 1795237482}
>>> jwt.decode(token, "this-is-not-the-server-secret-key-0123", algorithms=["HS256"])
jwt.exceptions.InvalidSignatureError: Signature verification failed

    서버의 비밀 키로는 검증이 통과하고, 다른 키로는 InvalidSignatureError가 납니다. 다음 파트에서는 이 검증을 보호된 API 앞에 세웁니다.
