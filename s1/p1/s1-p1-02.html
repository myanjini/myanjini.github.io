백엔드와 REST API

REST API는 프로그램끼리 데이터를 주고받는 약속입니다. 이 과정에서 만드는 모든 기능이 이 약속 위에서 움직이므로, 용어부터 정확히 잡고 갑니다.

프론트엔드와 백엔드

도서관 앱에서 책을 검색한다고 생각해 봅시다. 검색창과 결과 목록이 보이는 화면이 프론트엔드입니다. 검색어를 받아 데이터베이스에서 책을 찾고 결과를 돌려주는 프로그램이 백엔드입니다. 우리는 이 과정에서 백엔드를 만듭니다.

프론트엔드와 백엔드는 서로 다른 컴퓨터에서 실행되는 경우가 많습니다. 그래서 둘 사이에 "이렇게 요청하면 이렇게 답한다"는 약속이 필요하고, 이 약속을 API(Application Programming Interface)라고 부릅니다.

REST의 네 가지 핵심

REST는 웹에서 API를 설계할 때 널리 쓰는 원칙입니다. 처음에는 다음 네 가지만 기억하면 됩니다.

자원은 URI로 이름을 붙입니다

도서, 저자, 회원처럼 다루는 대상을 자원이라고 합니다. 자원에는 /books, /books/1처럼 명사로 된 주소(URI)를 붙입니다. /books는 도서 전체, /books/1은 1번 도서 하나를 뜻합니다.

할 일은 HTTP 메서드로 나타냅니다

메서드하는 일예시
GET조회GET /books 도서 목록 보기
POST새로 만들기POST /books 도서 등록
PUT전체 바꾸기PUT /books/1 1번 도서 정보를 통째로 교체
PATCH일부 바꾸기PATCH /books/1 1번 도서의 가격만 수정
DELETE삭제DELETE /books/1 1번 도서 삭제

같은 /books/1이라도 메서드가 다르면 전혀 다른 일을 합니다. 주소에는 "무엇을", 메서드에는 "어떻게"를 담는다고 생각하면 됩니다.

데이터는 JSON으로 주고받습니다

요즘 API는 대부분 JSON 형식으로 데이터를 주고받습니다. Python의 딕셔너리와 모양이 거의 같습니다.

{
  "id": 1,
  "title": "파이썬 첫걸음",
  "author": "김하늘",
  "price": 18000
}

요청은 서로 독립적입니다

서버는 앞선 요청을 기억하지 않습니다. 이것을 무상태성이라고 합니다. 그래서 로그인한 사용자라면 요청할 때마다 "나는 누구다"라는 정보를 함께 보내야 합니다. 3일차 인증 단원에서 이 정보를 토큰으로 보내는 방법을 배웁니다.

상태 코드로 결과를 알려 줍니다

서버는 응답할 때마다 세 자리 숫자로 결과를 알려 줍니다. 첫 자리만 보아도 누구의 문제인지 알 수 있습니다.

범위뜻자주 보는 코드
2xx성공200 성공, 201 새로 만들어짐, 204 성공했지만 돌려줄 내용 없음
4xx요청한 쪽의 문제400 잘못된 요청, 401 로그인 필요, 403 권한 없음, 404 없음, 422 데이터 형식 오류
5xx서버의 문제500 서버 내부 오류

참고

REST는 법처럼 정해진 규칙이 아니라 설계 원칙입니다. 회사마다 조금씩 다르게 적용하지만, 자원은 명사 URI로, 동작은 메서드로 나타낸다는 기본은 거의 같습니다.
