정리: REST API의 구성 요소

핵심 요약

  • API는 프로그램끼리 데이터를 주고받는 약속이고, 우리는 서버 쪽 API를 만듭니다.
  • REST에서는 자원을 명사 URI로 나타내고, 할 일은 GET, POST, PUT, PATCH, DELETE 메서드로 나타냅니다.
  • 데이터는 JSON으로 주고받고, 서버는 앞선 요청을 기억하지 않습니다.
  • 상태 코드의 첫 자리로 결과를 판단합니다. 2xx는 성공, 4xx는 요청한 쪽의 문제, 5xx는 서버의 문제입니다.

확인 퀴즈

새 도서를 등록하는 요청으로 가장 알맞은 것은 무엇인가요?

새 자원을 만들 때는 자원 모음 주소(/books)에 POST 요청을 보냅니다.

서버가 404를 돌려주었습니다. 무슨 뜻인가요?

404는 요청한 주소의 자원을 찾을 수 없다는 뜻입니다. 4로 시작하므로 요청한 쪽을 먼저 점검합니다.

다음 중 REST 원칙에 가장 잘 맞는 URI는 무엇인가요?

자원 이름은 소문자 복수형 명사로 쓰고, 개별 자원은 뒤에 식별자를 붙입니다.
