공개 API 호출해 보기

인터넷에 공개된 연습용 API를 직접 호출해, 요청과 응답이 실제로 어떻게 생겼는지 눈으로 확인합니다.

실습 목표브라우저와 curl로 GET, POST 요청을 보내고 상태 코드와 응답 본문을 읽을 수 있습니다.

사용할 도구

  • JSONPlaceholder: 연습용으로 공개된 가짜 API입니다. 게시글(posts) 자원을 제공합니다.
  • curl: 명령어로 HTTP 요청을 보내는 프로그램입니다. Windows 10 이상과 macOS에 기본으로 들어 있습니다.

Windows PowerShell을 쓴다면

PowerShell에서 curl은 다른 명령의 별칭이라 결과가 다르게 나옵니다. curl.exe라고 입력하거나 명령 프롬프트(cmd)를 사용하세요.

  1. 브라우저로 게시글 하나 조회하기

    브라우저 주소창에 다음 주소를 입력합니다.

    https://jsonplaceholder.typicode.com/posts/1

    JSON이 화면에 나타나면 성공입니다. id, title, body, userId 네 항목이 보입니다. 브라우저 주소창에 주소를 넣는 것은 GET 요청을 보내는 것과 같습니다.

  2. curl로 상태 코드까지 보기

    명령 프롬프트나 터미널을 열고 다음을 입력합니다. -i는 응답의 머리 부분(헤더)까지 보여 달라는 옵션입니다.

    curl -i https://jsonplaceholder.typicode.com/posts/1

    첫 줄에 HTTP/2 200 또는 HTTP/1.1 200 OK가 보입니다. 이어지는 줄에는 content-type: application/json 같은 헤더가 있고, 빈 줄 아래에 JSON 본문이 있습니다.

  3. 쿼리 문자열로 걸러 보기

    curl https://jsonplaceholder.typicode.com/posts?userId=1

    주소 뒤의 ?userId=1을 쿼리 문자열이라고 합니다. 1번 사용자가 쓴 게시글만 목록으로 돌아옵니다. 자원은 그대로 /posts이고 조건만 덧붙였다는 점을 눈여겨보세요.

  4. 없는 자원 요청하기

    curl -i https://jsonplaceholder.typicode.com/posts/9999

    상태 코드가 404로 바뀌고 본문은 {}로 비어 있습니다. 서버가 "그런 자원은 없다"고 알려 준 것입니다.

  5. POST로 새 게시글 보내기

    이번에는 데이터를 보내 새 게시글을 만들어 봅니다. -X POST는 메서드, -H는 헤더, -d는 보낼 본문입니다.

    Windows 명령 프롬프트:

    curl -i -X POST https://jsonplaceholder.typicode.com/posts -H "Content-Type: application/json" -d "{\"title\": \"hello\", \"body\": \"first post\", \"userId\": 1}"

    macOS 터미널:

    curl -i -X POST https://jsonplaceholder.typicode.com/posts -H "Content-Type: application/json" -d '{"title": "hello", "body": "first post", "userId": 1}'

    상태 코드 201과 함께 "id": 101이 붙은 JSON이 돌아옵니다. 201은 "새로 만들어졌다"는 뜻입니다. 연습용 API라서 실제로 저장되지는 않으므로, 다시 /posts/101을 조회하면 404가 나옵니다.

결과 기록하기

각 요청의 결과를 아래 표에 적어 둡니다. 입력한 내용은 브라우저에 저장됩니다.

요청이 아예 안 될 때

기관 네트워크에서 외부 사이트가 막혀 있을 수 있습니다. 브라우저에서도 열리지 않으면 강사에게 알려 주세요. curl에서만 실패한다면 주소를 정확히 입력했는지, PowerShell이라면 curl.exe로 입력했는지 확인합니다.
