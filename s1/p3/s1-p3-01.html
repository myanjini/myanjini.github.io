경로 연산과 HTTP 메서드

이 파트의 학습 목표경로 파라미터와 쿼리 파라미터로 조회 API를 구현할 수 있습니다.

요청이 들어왔을 때 어떤 함수가 처리할지 정하는 방법을 배웁니다. FastAPI에서는 이것을 경로 연산이라고 부릅니다.

경로 연산의 세 요소

경로 연산은 "어떤 메서드로, 어떤 주소에 요청이 오면, 어떤 함수를 실행한다"는 묶음입니다.

@app.get("/books")          # 메서드: GET, 주소: /books
def list_books():           # 실행할 함수
    return BOOKS

함수 위에 붙은 @app.get(...)을 데코레이터라고 합니다. 함수를 FastAPI 앱에 등록하는 표시라고 생각하면 됩니다. 함수 이름은 자유롭게 지어도 되지만, 하는 일이 드러나게 짓습니다. 이 이름은 API 문서에도 표시됩니다.

메서드마다 데코레이터가 있습니다

데코레이터메서드주로 하는 일
@app.get()GET조회
@app.post()POST생성
@app.put()PUT전체 수정
@app.patch()PATCH일부 수정
@app.delete()DELETE삭제

같은 주소라도 메서드가 다르면 다른 함수가 처리합니다. 아래 두 함수는 주소가 같지만 서로 다른 경로 연산입니다.

@app.get("/books")
def list_books():
    ...                      # 도서 목록 조회


@app.post("/books")
def create_book():
    ...                      # 새 도서 등록

선언 순서가 결과를 바꿀 때

FastAPI는 위에서부터 차례로 주소를 비교해 처음 맞는 함수를 실행합니다. 그래서 다음처럼 쓰면 문제가 생깁니다.

@app.get("/books/{book_id}")
def get_book(book_id: int):
    ...


@app.get("/books/popular")   # 이 함수는 실행되지 않습니다.
def popular_books():
    ...

/books/popular로 요청하면 첫 번째 함수가 먼저 걸리고, popular를 정수 book_id로 바꾸지 못해 오류가 납니다. 고정된 주소(/books/popular)를 값이 들어가는 주소(/books/{book_id})보다 위에 선언해야 합니다.
