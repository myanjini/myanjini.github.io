async def와 def

FastAPI 예제를 보면 def와 async def가 섞여 있습니다. 둘 중 무엇을 써야 하는지 기준만 간단히 잡고 갑니다.

기다리는 시간이 문제입니다

서버가 하는 일 중에는 데이터베이스 응답이나 다른 서버의 응답을 기다리는 시간이 많습니다. async def로 만든 함수는 기다리는 동안 다른 요청을 먼저 처리할 수 있습니다. 식당 직원이 한 테이블의 음식이 나올 때까지 주방 앞에 서 있지 않고, 그사이 다른 테이블의 주문을 받는 것과 같습니다.

선택 기준

상황선택
함수 안에서 await를 붙여 쓰는 라이브러리를 호출한다async def
await를 쓰지 않는 일반 라이브러리를 호출한다def
어느 쪽인지 잘 모르겠다def

FastAPI는 일반 def 함수를 별도의 작업 공간에서 실행해 주므로, def로 써도 다른 요청이 막히지 않습니다. 이 과정의 실습 코드도 대부분 def로 작성합니다.

이것만은 피하세요

async def 함수 안에서 time.sleep()처럼 기다리는 동안 멈춰 있는 함수를 부르면, 그동안 서버 전체가 다른 요청을 처리하지 못합니다. async def를 쓸 때는 기다리는 작업도 await로 기다릴 수 있는 것을 써야 합니다.
