첫 API 만들기

첫 FastAPI 앱을 직접 작성해 실행하고, 브라우저와 API 문서 화면에서 응답을 확인합니다.

실습 목표GET /와 GET /health가 동작하는 main.py를 만들 수 있습니다.

  1. main.py 작성

    VSCode에서 book-api 폴더 바로 아래에 main.py를 만들고 다음 코드를 입력합니다.

    main.py
    from fastapi import FastAPI

app = FastAPI(title="도서 관리 API")


@app.get("/")
def read_root():
    return {"message": "도서 관리 API입니다."}


@app.get("/health")
def health_check():
    # 서버가 요청에 응답할 수 있는지 확인하는 용도입니다.
    return {"status": "ok"}

    FastAPI(title=...)에 적은 이름은 API 문서 화면의 제목으로 쓰입니다.

  2. 서버 실행

    VSCode 터미널(가상환경이 켜진 상태)에서 실행합니다.

    fastapi dev main.py

    Application startup complete.가 보이면 준비가 끝난 것입니다.

  3. 브라우저로 두 주소 확인

    두 주소를 차례로 열어 응답을 확인합니다.

    주소기대하는 응답
    http://127.0.0.1:8000/{"message":"도서 관리 API입니다."}
    http://127.0.0.1:8000/health{"status":"ok"}

    없는 주소인 http://127.0.0.1:8000/hello도 열어 보세요. {"detail":"Not Found"}가 나오는데, 이것이 404 응답입니다.

  4. API 문서 화면에서 호출

    http://127.0.0.1:8000/docs를 엽니다. 이 화면을 Swagger UI라고 부릅니다.

    1. GET /health를 눌러 펼칩니다.
    2. Try it out을 누르고 Execute를 누릅니다.
    3. 아래 Responses 영역에서 상태 코드 200과 응답 본문을 확인합니다.

    앞으로 만드는 API는 대부분 이 화면에서 먼저 시험합니다.

  5. 자동 재시작 확인

    서버를 켜 둔 채로 read_root의 메시지를 "도서 관리 API에 오신 것을 환영합니다."로 바꾸고 저장합니다. 터미널에 재시작 로그가 지나간 뒤 브라우저를 새로 고치면 바뀐 메시지가 보입니다.

확인 체크리스트

문제 해결

증상원인과 해결
Could not import module "main" 또는 파일을 찾지 못함main.py가 없는 폴더에서 실행했습니다. 터미널의 현재 위치가 book-api인지 확인합니다.
포트가 이미 사용 중이라는 오류다른 터미널에서 서버가 이미 켜져 있을 수 있습니다. 그 서버를 끄거나 fastapi dev main.py --port 8001처럼 다른 포트를 씁니다.
저장했는데 결과가 그대로파일을 저장했는지(VSCode 탭의 동그라미 표시) 확인하고 브라우저를 새로 고칩니다.
