Pydantic 모델

이 파트의 학습 목표Pydantic 모델과 Field 제약으로 POST 요청 본문을 검증할 수 있습니다.

도서를 등록할 때는 제목, 저자, 가격처럼 여러 값을 한꺼번에 받아야 합니다. 이런 데이터의 모양과 규칙을 정해 두는 도구가 Pydantic입니다.

왜 규칙이 필요할까요

클라이언트가 항상 올바른 데이터를 보낸다는 보장은 없습니다. 제목을 빠뜨리거나, 가격에 음수를 넣거나, 숫자 자리에 글자를 넣을 수 있습니다. 이런 데이터가 그대로 저장되면 나중에 찾기 어려운 문제가 생깁니다. 그래서 서버는 데이터를 받는 입구에서 먼저 검사해야 합니다. 5일차 개발 보안 단원에서도 이 "입구 검사"가 가장 먼저 등장합니다.

BaseModel로 데이터 모양 정하기

from pydantic import BaseModel, Field


class BookCreate(BaseModel):
    title: str = Field(min_length=1, max_length=100)
    author: str = Field(min_length=1, max_length=50)
    price: int = Field(ge=0, le=1_000_000)
    isbn: str | None = None

BaseModel을 상속한 클래스에 필드 이름과 타입을 적으면, 그 자체가 "이런 모양의 데이터만 받겠다"는 규칙이 됩니다.

필수 항목과 선택 항목

필드선언뜻
titlestr = Field(...)기본값이 없으므로 반드시 보내야 합니다.
isbnstr | None = None보내지 않아도 되고, 그러면 None이 들어갑니다.

Field로 세부 규칙 정하기

규칙뜻예
min_length, max_length문자열의 최소, 최대 길이제목은 1자 이상 100자 이하
ge, le숫자의 최솟값, 최댓값(같은 값 포함)가격은 0 이상 1,000,000 이하
gt, lt숫자의 최솟값, 최댓값(같은 값 제외)수량은 0보다 큼
pattern문자열이 따라야 할 정규 표현식ISBN은 숫자 13자리

ge는 greater than or equal(크거나 같음), le는 less than or equal(작거나 같음)의 줄임말입니다. 1_000_000의 밑줄은 숫자를 읽기 쉽게 쓰는 Python 표기로, 값은 1000000과 같습니다.

알아 두면 좋은 점

Pydantic은 바꿀 수 있는 값은 알아서 바꿔 줍니다. 가격에 문자열 "15000"을 보내면 정수 15000으로 바꿔 받습니다. 하지만 "만오천"처럼 바꿀 수 없는 값은 오류로 처리합니다.
