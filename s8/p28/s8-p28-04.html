헬스 체크 확장

지금의 /health는 서버가 켜져 있기만 하면 "ok"라고 답합니다. 데이터베이스가 멈춰도 "ok"라면 헬스 체크가 제 역할을 못 합니다.

실습 목표데이터베이스 연결까지 확인하는 /health를 만들고, 장애 때 503을 돌려줄 수 있습니다.

  1. /health 바꾸기

    app/main.py
    @app.get("/health", tags=["기본"])
def health_check(db: SessionDep):
    try:
        db.execute(text("SELECT 1"))  # 데이터베이스에 가장 가벼운 질의를 보내 봅니다.
    except SQLAlchemyError:
        logger.exception("데이터베이스 연결 확인 실패")
        return JSONResponse(status_code=503, content={"status": "error", "database": "unreachable"})
    return {"status": "ok", "database": "ok"}

    가져오기 세 줄(from sqlalchemy import text, from sqlalchemy.exc import SQLAlchemyError, from app.dependencies import SessionDep)을 추가합니다. SELECT 1은 데이터를 읽지 않고 연결만 확인하는 가장 가벼운 질의입니다. 503(Service Unavailable)은 "지금은 일시적으로 처리할 수 없다"는 뜻으로, 로드 밸런서는 이 응답을 보고 해당 서버로 요청을 보내지 않습니다.

  2. 테스트 고치기

    응답 모양이 바뀌었으므로 테스트도 고치고, 요청 ID 테스트를 하나 더합니다.

    tests/test_books.py
    def test_health(client):
    response = client.get("/health")
    assert response.status_code == 200
    assert response.json() == {"status": "ok", "database": "ok"}


def test_response_has_request_id(client):
    response = client.get("/health")
    assert len(response.headers["X-Request-ID"]) == 16
    pytest

  3. 컨테이너에서 확인

    docker compose up -d --build
docker compose stop db
    상태/health 응답내 결과
    db 실행 중200, {"status":"ok","database":"ok"}
    db 멈춤503, {"status":"error","database":"unreachable"}

    S8-P27-04의 헬스 체크를 넣었다면, db를 멈추고 1분 30초쯤 지나 docker compose ps를 보면 api가 (unhealthy)로 바뀝니다. docker compose start db로 되돌리면 다시 (healthy)가 됩니다.
