logging 설정과 요청 ID

모든 로그를 JSON 한 줄로 쓰는 설정과, 요청마다 ID를 붙여 한 요청의 로그를 묶는 방법을 강사 화면으로 봅니다.

로그 설정 파일

app/logging_config.py
"""로그 설정: 모든 로그를 한 줄짜리 JSON으로 표준 출력에 씁니다."""
import json
import logging
import sys
from contextvars import ContextVar
from datetime import datetime, timezone

# 지금 처리 중인 요청의 ID. 요청마다 따로 보관됩니다.
request_id_var: ContextVar[str] = ContextVar("request_id", default="-")

# LogRecord가 원래 가진 속성 이름. 이 밖의 속성은 extra로 넘긴 값입니다.
_STANDARD_KEYS = set(logging.LogRecord("", 0, "", 0, "", None, None).__dict__) | {"message", "taskName", "color_message"}


class JsonFormatter(logging.Formatter):
    def format(self, record: logging.LogRecord) -> str:
        data = {
            "time": datetime.fromtimestamp(record.created, timezone.utc).isoformat(timespec="milliseconds"),
            "level": record.levelname,
            "logger": record.name,
            "message": record.getMessage(),
            "request_id": request_id_var.get(),
        }
        for key, value in record.__dict__.items():  # extra로 넘긴 값을 덧붙입니다.
            if key not in _STANDARD_KEYS:
                data[key] = value
        if record.exc_info:
            data["error"] = self.formatException(record.exc_info)
        return json.dumps(data, ensure_ascii=False, default=str)


def setup_logging(level: str = "INFO") -> None:
    handler = logging.StreamHandler(sys.stdout)
    handler.setFormatter(JsonFormatter())
    root = logging.getLogger()
    root.handlers = [handler]
    root.setLevel(level)
    # uvicorn의 로그도 같은 형식으로 내보내고, 요청 기록은 우리 미들웨어가 남기므로 끕니다.
    for name in ("uvicorn", "uvicorn.error"):
        logging.getLogger(name).handlers = []
        logging.getLogger(name).propagate = True
    logging.getLogger("uvicorn.access").disabled = True
부분하는 일
ContextVar요청마다 따로 보관되는 변수입니다. 요청 여러 개가 동시에 처리되어도 서로의 ID가 섞이지 않습니다.
JsonFormatter로그 한 건을 JSON 한 줄로 바꿉니다. 시각은 UTC로 적습니다.
extra로 넘긴 값logger.info("도서 대여", extra={"book_id": 3})처럼 넘긴 값이 JSON 항목으로 붙습니다.
setup_logging모든 로그가 지나가는 뿌리 로거(root)에 JSON 출력을 하나 달고, uvicorn의 로그도 같은 형식으로 모읍니다. uvicorn이 남기던 요청 기록은 우리 미들웨어가 더 자세히 남기므로 끕니다.

요청 ID 미들웨어

요청이 동시에 여러 개 처리되면 로그가 뒤섞입니다. 요청이 들어올 때 무작위 ID를 하나 정해 두면, 그 요청을 처리하는 동안 어디서 남긴 로그든 같은 ID가 붙어 한 요청의 로그만 골라 볼 수 있습니다.

app/main.py
logger = logging.getLogger("app.request")


@app.middleware("http")
async def log_requests(request: Request, call_next):
    request_id_var.set(uuid.uuid4().hex[:16])  # 이 요청에서 남기는 모든 로그에 같은 ID가 붙습니다.
    start = time.perf_counter()
    info = {"method": request.method, "path": request.url.path}
    try:
        response = await call_next(request)  # 실제 경로 함수가 여기서 실행됩니다.
    except Exception:
        info["duration_ms"] = round((time.perf_counter() - start) * 1000, 1)
        logger.exception("처리하지 못한 오류", extra={**info, "status": 500})
        raise  # 응답은 FastAPI의 기본 처리에 맡깁니다. 5일차에 안전한 오류 응답으로 바꿉니다.
    duration_ms = round((time.perf_counter() - start) * 1000, 1)
    response.headers["X-Request-ID"] = request_id_var.get()
    response.headers["X-Process-Time"] = f"{duration_ms}ms"
    logger.info("요청 처리", extra={**info, "status": response.status_code, "duration_ms": duration_ms})
    return response

2일차의 처리 시간 미들웨어를 이 미들웨어로 바꿉니다. 응답 헤더 X-Request-ID로 ID를 돌려주므로, 사용자가 "이 요청에서 오류가 났다"고 알려 올 때 ID만 받으면 그 요청의 로그를 바로 찾을 수 있습니다.

처리하지 못한 오류

경로 함수에서 예상하지 못한 예외가 나면 logger.exception이 오류 내용(트레이스백)을 error 항목에 담아 ERROR 로그를 남기고, 예외는 그대로 다시 던집니다. 사용자에게 가는 500 응답은 아직 FastAPI 기본 처리에 맡깁니다. uvicorn도 같은 오류를 한 번 더 기록하는데, 5일차에 전역 예외 처리기를 만들면서 오류 응답과 로그를 함께 정리합니다.
