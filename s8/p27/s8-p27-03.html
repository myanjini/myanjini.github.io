PostgreSQL로 전환

API와 PostgreSQL을 Compose로 함께 실행하고, 마이그레이션을 PostgreSQL에 적용합니다. 컨테이너를 지웠다 다시 만들어도 데이터가 남는지 확인합니다.

실습 목표Docker Compose로 API와 PostgreSQL을 실행하고, 컨테이너에서 마이그레이션을 적용할 수 있습니다.

  1. 드라이버 설치와 설정 변경

    pip install "psycopg[binary]"
pip freeze > requirements.txt

    app/config.py에 extra="ignore"를 추가하고, .env에 POSTGRES_PASSWORD를 추가합니다(앞 페이지). pytest를 실행해 여전히 모두 통과하는지 확인합니다.

  2. compose.yaml 만들기

    앞 페이지의 compose.yaml을 book-api 폴더에 만듭니다. 앞 파트의 book-api 컨테이너가 남아 있다면 지웁니다(docker rm -f book-api).

  3. 실행

    docker compose up -d --build
docker compose ps

    --build는 이미지를 새로 만든 뒤 실행하라는 뜻입니다. docker compose ps에서 두 컨테이너가 모두 Up이고 db에 (healthy)가 붙어 있으면 됩니다. Compose는 컨테이너 이름을 폴더이름-서비스이름-번호로 붙입니다.

    NAME             IMAGE          COMMAND                  SERVICE   STATUS                   PORTS
book-api-api-1   book-api-api   "uvicorn app.main:ap…"   api       Up Less than a second    0.0.0.0:8000->8000/tcp
book-api-db-1    postgres:18    "docker-entrypoint.s…"   db        Up 5 seconds (healthy)   5432/tcp

  4. PostgreSQL에 마이그레이션 적용

    docker compose run --rm api alembic upgrade head
...
INFO  [alembic.runtime.migration] Running upgrade  -> 0c8fecfaba35, create authors and books
INFO  [alembic.runtime.migration] Running upgrade 0c8fecfaba35 -> 6609552f735e, create users
INFO  [alembic.runtime.migration] Running upgrade 6609552f735e -> 75c10e653c84, add owner_id to books
...
INFO  [alembic.runtime.migration] Running upgrade b52ac449e359 -> 2bece52fa7b7, create loans

    docker compose run --rm api는 api 서비스와 같은 설정으로 일회용 컨테이너를 만들어 명령 하나만 실행하고 지웁니다. SQLite에서 만든 리비전 7개가 PostgreSQL에도 차례로 적용됩니다. 리비전 번호는 내 파일과 다릅니다. 테이블을 직접 확인합니다.

    docker compose exec db psql -U bookapi -d bookapi -c '\dt'

    authors, books, users, refresh_tokens, stock_logs, loans, alembic_version이 보이면 성공입니다. PowerShell에서 따옴표 때문에 오류가 나면 docker compose exec db psql -U bookapi -d bookapi로 들어가 \dt를 입력하고 \q로 나옵니다.

  5. 동작 확인

    새 PostgreSQL은 비어 있습니다. 로컬 SQLite의 데이터는 옮겨 오지 않습니다. Swagger UI(http://127.0.0.1:8000/docs)에서 다음 순서로 확인합니다.

    순서할 일기대하는 결과내 결과
    1user1, user2 가입201
    2docker compose exec api python -m app.make_admin user2@example.com관리자로 바꿨습니다.
    3user2로 로그인해 저자 등록201
    4user1로 로그인해 재고 2권인 도서 등록201
    5user1이 그 도서 대여, 반납201, 200
    6user1이 표지 이미지 업로드 후 주소 열기이미지가 보임

  6. 데이터가 남는지 확인

    docker compose down
docker compose up -d

    down은 컨테이너와 네트워크를 지우지만 볼륨은 남깁니다. 다시 올린 뒤 GET /books에 등록한 도서가 있고, 표지 주소도 그대로 열리면 성공입니다. docker volume ls로 book-api_db-data와 book-api_uploads를 확인합니다.

    docker compose down -v

    -v를 붙이면 볼륨까지 지워 데이터베이스와 업로드 파일이 모두 사라집니다. 처음부터 다시 시작하고 싶을 때만 씁니다.

확인 체크리스트

문제 해결

증상원인과 해결
password authentication failed for user "bookapi"처음 실행한 뒤 .env의 POSTGRES_PASSWORD를 바꿨습니다. 비밀번호는 볼륨을 처음 만들 때만 정해집니다. 실습 중이라면 docker compose down -v로 볼륨을 지우고 다시 올립니다.
relation "books" does not exist마이그레이션을 적용하지 않았습니다.
db가 계속 Restarting이거나 볼륨 관련 오류볼륨 경로를 /var/lib/postgresql/data로 적었는지 확인합니다. 18판은 /var/lib/postgresql입니다.
The "POSTGRES_PASSWORD" variable is not set.env에 값을 넣지 않았거나, book-api 폴더가 아닌 곳에서 명령을 실행했습니다.
No module named 'psycopg'requirements.txt를 갱신하지 않고 빌드했습니다. 갱신 후 docker compose up -d --build
