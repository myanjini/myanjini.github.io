다중 컨테이너와 Compose

이 파트의 학습 목표Docker Compose로 API와 PostgreSQL을 함께 실행할 수 있습니다.

실제 서비스는 API 하나로 끝나지 않고 데이터베이스와 함께 실행됩니다. 여러 컨테이너를 하나의 파일로 정의하고 한 번에 실행하는 Docker Compose를 배웁니다.

왜 PostgreSQL인가요

SQLite는 파일 하나로 동작해 개발하기 편하지만, 여러 요청이 동시에 쓰기를 하면 한 번에 하나씩 기다려야 하고, 서버 여러 대가 같은 데이터를 함께 쓸 수 없습니다. 실제 서비스에서는 별도 프로그램으로 실행되는 데이터베이스 서버를 씁니다. 이 과정은 PostgreSQL을 쓰고, 7일차에는 AWS가 관리해 주는 PostgreSQL인 RDS로 옮깁니다. 2일차부터 SQLAlchemy와 Alembic을 써 왔기 때문에 코드는 거의 바꾸지 않고 주소만 바꾸면 됩니다.

컨테이너 하나에 프로그램 하나

API와 데이터베이스를 한 컨테이너에 넣지 않고 따로 실행합니다. 각자 따로 고치고, 다시 시작하고, 늘릴 수 있기 때문입니다. 대신 여러 컨테이너의 이미지, 환경 변수, 연결, 시작 순서를 관리해야 하는데, docker run 명령을 여러 번 길게 치는 대신 Docker Compose로 compose.yaml 파일 하나에 적고 docker compose up 한 번으로 실행합니다.

Compose의 구성 요소

요소뜻도서 API에서
서비스(service)함께 실행할 컨테이너 하나하나의 정의api, db
네트워크(network)Compose가 자동으로 만드는 내부 네트워크. 서비스 이름이 곧 주소입니다.API는 데이터베이스를 db:5432로 찾습니다.
볼륨(volume)컨테이너 밖에 데이터를 보관하는 저장 공간. 컨테이너를 지워도 남습니다.db-data(데이터베이스 파일), uploads(표지 이미지)
환경 변수 파일Compose는 같은 폴더의 .env를 자동으로 읽어 ${이름} 자리에 값을 채웁니다.${POSTGRES_PASSWORD}, ${SECRET_KEY}

데이터베이스 포트(5432)를 내 PC에 열지 않은 것도 의도한 것입니다. 데이터베이스에 접속해야 하는 것은 API뿐이므로, 바깥에서 닿는 길을 만들지 않습니다. 7일차에 RDS를 인터넷에서 닿지 않는 프라이빗 서브넷에 두는 것과 같은 생각입니다.
