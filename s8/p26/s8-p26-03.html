이미지 빌드와 실행

도서 API 이미지를 만들고 컨테이너로 실행합니다. 환경 변수를 넘기는 방법, 컨테이너 안에서 명령을 실행하는 방법, 레이어 캐시까지 직접 확인합니다.

실습 목표Dockerfile로 이미지를 만들고, 포트와 환경 변수를 지정해 컨테이너를 실행할 수 있습니다.

  1. Docker 확인

    Docker Desktop을 실행하고, 터미널에서 확인합니다. Server: 부분까지 나오면 준비된 것입니다.

    docker version

    로컬에서 실행 중인 uvicorn이 있으면 끕니다. 같은 8000번 포트를 쓰기 때문입니다.

  2. 패키지 목록 갱신

    이미지는 requirements.txt로만 패키지를 설치합니다. 오전 CI 실습 뒤에 설치한 것이 있다면 갱신합니다.

    pip freeze > requirements.txt

  3. Dockerfile과 .dockerignore 만들기

    앞 페이지의 두 파일을 book-api 폴더에 만듭니다.

  4. 이미지 만들기

    docker build -t book-api .
docker images book-api

    -t book-api는 이미지 이름, 마지막 .은 "이 폴더의 Dockerfile과 파일로 만든다"는 뜻입니다. 처음에는 베이스 이미지와 패키지를 내려받느라 몇 분 걸립니다.

  5. 비밀 키 없이 실행해 보기

    docker run --rm book-api
...
pydantic_core._pydantic_core.ValidationError: 1 validation error for Settings
secret_key
  Field required [type=missing, input_value={}, input_type=dict]

    이미지에는 .env가 없으므로 SECRET_KEY를 찾지 못하고 바로 멈춥니다. 2일차에 기본값을 두지 않은 덕분에, 비밀 키 없이 실행되는 사고를 막았습니다. --rm은 멈춘 컨테이너를 바로 지우라는 뜻입니다.

  6. 환경 변수와 포트를 지정해 실행

    비밀키 자리에 S3-P9에서 만든 비밀 키를 넣습니다. 한 줄로 입력합니다.

    docker run -d --name book-api -p 8000:8000 -e SECRET_KEY=비밀키 -e DATABASE_URL=sqlite:///./data/books.db book-api
    옵션뜻
    -d뒤에서 실행하고 터미널을 돌려줍니다.
    --name book-api컨테이너 이름. 이후 명령에서 이 이름으로 가리킵니다.
    -p 8000:8000내 PC의 8000번 포트로 오는 연결을 컨테이너의 8000번 포트로 넘깁니다(내 PC:컨테이너).
    -e 이름=값컨테이너에 환경 변수를 넘깁니다. 설정 클래스가 이 값을 읽습니다.
    DATABASE_URLSQLite 파일을 appuser가 쓸 수 있는 data 폴더에 만듭니다.

    브라우저에서 http://127.0.0.1:8000/health를 열면 {"status":"ok"}가 보입니다. docker ps로 실행 중인 컨테이너도 확인합니다.

  7. 오류를 로그로 찾고 컨테이너 안에서 고치기

    http://127.0.0.1:8000/books를 열면 Internal Server Error가 나옵니다. 컨테이너의 출력을 봅니다.

    docker logs book-api
...
sqlalchemy.exc.OperationalError: (sqlite3.OperationalError) no such table: books

    컨테이너 안의 데이터베이스는 새로 만들어져 테이블이 없습니다. docker exec로 실행 중인 컨테이너 안에서 마이그레이션을 실행합니다.

    docker exec book-api alembic upgrade head
docker exec book-api id

    다시 /books를 열면 {"items":[],"total":0,...}가 나옵니다. 두 번째 명령은 uid=1000(appuser)처럼 관리자가 아닌 사용자로 실행 중임을 보여 줍니다.

  8. 레이어 캐시 확인

    app/main.py 맨 아래에 주석 한 줄(# 캐시 확인)을 추가하고 다시 빌드합니다.

    docker build -t book-api .
...
 => CACHED [3/6] COPY requirements.txt .
 => CACHED [4/6] RUN pip install --no-cache-dir -r requirements.txt
 => [5/6] COPY . .

    패키지 설치는 CACHED로 건너뛰고 코드 복사부터 다시 해서 몇 초 만에 끝납니다. 확인했으면 주석을 지웁니다.

  9. 정리

    docker stop book-api
docker rm book-api

    컨테이너를 지우면 안에서 만든 data/books.db도 함께 사라집니다. 데이터를 남기는 방법은 다음 파트에서 배웁니다.

확인 체크리스트

문제 해결

증상원인과 해결
error during connect, Is the docker daemon running?Docker Desktop이 실행되지 않았습니다. 실행하고 고래 아이콘이 멈출 때까지 기다립니다.
port is already allocated8000번 포트를 다른 프로그램(로컬 uvicorn, 이전 컨테이너)이 쓰고 있습니다. 끄거나 -p 8001:8000처럼 바꿉니다.
빌드 중 No matching distribution found for pywin32Windows 전용 패키지가 requirements.txt에 들어갔습니다. 그 줄을 지웁니다.
Conflict. The container name "/book-api" is already in use같은 이름의 컨테이너가 남아 있습니다. docker rm -f book-api 뒤 다시 실행합니다.
unable to open database fileDATABASE_URL을 빼서 쓰기 권한이 없는 /app에 파일을 만들려 했습니다. ./data/books.db로 지정합니다.
