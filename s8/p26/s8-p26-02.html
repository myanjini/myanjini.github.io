Dockerfile 작성

도서 API의 Dockerfile과 .dockerignore를 한 줄씩 읽어 봅니다.

Dockerfile

book-api 폴더 바로 아래에 확장자 없이 Dockerfile이라는 이름으로 만듭니다.

Dockerfile
# 1. 베이스 이미지: Python 3.12가 설치된 가벼운 리눅스
FROM python:3.12-slim

# 2. Python 실행 설정: .pyc 파일을 만들지 않고, 출력을 모아 두지 않고 바로 내보냅니다.
ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1

# 3. 컨테이너 안의 작업 폴더
WORKDIR /app

# 4. 패키지 목록만 먼저 복사해 설치합니다. 코드만 바뀌면 이 단계는 캐시를 씁니다.
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 5. 나머지 소스 코드 복사(.dockerignore에 적은 것은 빠집니다)
COPY . .

# 6. 관리자(root)가 아닌 사용자를 만들고, 이 사용자가 쓸 폴더만 쓰기 권한을 줍니다.
RUN useradd --create-home appuser \
    && mkdir -p uploads logs data \
    && chown appuser uploads logs data
USER appuser

# 7. 컨테이너가 시작할 때 실행할 명령
EXPOSE 8000
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
명령하는 일
FROM바탕이 될 이미지입니다. python:3.12-slim은 Python 공식 이미지 중 꼭 필요한 것만 넣은 가벼운 판입니다. 첫 빌드 때 Docker Hub에서 내려받습니다.
ENV컨테이너 안의 환경 변수입니다. PYTHONUNBUFFERED=1이 없으면 출력이 한동안 모였다가 나와서, 로그가 늦게 보입니다.
WORKDIR이후 명령을 실행할 폴더입니다. 없으면 만듭니다.
COPY내 PC의 파일을 이미지 안으로 복사합니다. requirements.txt만 먼저 복사하는 것은 레이어 캐시를 살리기 위해서입니다.
RUN이미지를 만드는 동안 명령을 실행합니다. --no-cache-dir는 pip가 내려받은 파일을 남기지 않아 이미지를 작게 합니다.
USER이후 명령과 컨테이너 실행을 이 사용자로 합니다.
EXPOSE이 컨테이너가 8000번 포트를 쓴다고 알려 주는 표시입니다. 실제로 열려면 실행할 때 -p가 필요합니다.
CMD컨테이너가 시작할 때 실행할 명령입니다.

왜 0.0.0.0인가요

지금까지 uvicorn은 기본값 127.0.0.1에서 실행했습니다. 이 주소는 "같은 컴퓨터 안에서만"이라는 뜻입니다. 컨테이너는 따로 떨어진 컴퓨터처럼 동작하므로 127.0.0.1로 실행하면 컨테이너 밖(내 PC의 브라우저)에서 접속할 수 없습니다. 0.0.0.0은 "어디서 오는 연결이든 받는다"는 뜻입니다.

관리자가 아닌 사용자로 실행

컨테이너 안의 기본 사용자는 관리자(root)입니다. API에 보안 구멍이 있어 공격자가 명령을 실행하게 되었을 때, root라면 컨테이너 안의 모든 것을 바꿀 수 있습니다. 그래서 일반 사용자 appuser를 만들어 실행하고, 이 사용자는 업로드(uploads), 기록(logs), SQLite 파일(data) 폴더에만 쓸 수 있게 합니다. 코드 파일은 고칠 수 없습니다. 이렇게 꼭 필요한 권한만 주는 원칙을 최소 권한이라고 하며, 5일차 이후 보안과 AWS 단원에서 계속 나옵니다.

.dockerignore

COPY . .은 폴더 전체를 복사합니다. 이미지에 들어가면 안 되는 파일은 .dockerignore에 적어 뺍니다. 작성 방법은 .gitignore와 같습니다.

.dockerignore
# 이미지에 넣지 않을 파일
.venv/
.git/
.github/
__pycache__/
*.pyc

# 비밀 값과 내 PC의 데이터
.env
*.db
uploads/
logs/
data/

# 테스트와 그 결과물
tests/
.pytest_cache/
.coverage
htmlcov/
뺀 것이유
.env비밀 키가 이미지에 들어가면 이미지를 받은 누구나 꺼내 볼 수 있습니다. 비밀 값은 실행할 때 환경 변수로 넣습니다.
.venv/내 PC(Windows나 macOS)용으로 설치한 패키지라 리눅스 컨테이너에서 쓸 수 없습니다. 이미지 안에서 새로 설치합니다.
*.db, uploads/내 PC의 개발 데이터입니다. 이미지는 코드만 담고, 데이터는 따로 관리합니다.
tests/ 등실행에 필요 없는 파일을 빼면 이미지가 작아지고 빌드가 빨라집니다.
