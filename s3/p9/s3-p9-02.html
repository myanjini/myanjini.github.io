Settings 클래스 적용

설정 파일과 .env를 만들고, 앱이 설정값을 읽어 쓰도록 바꿉니다.

실습 목표pydantic-settings로 설정을 분리하고, 비밀 값은 Git에 올라가지 않게 관리할 수 있습니다.

  1. 패키지 확인

    pip show pydantic-settings

    정보가 나오면 이미 설치된 것입니다. not found가 나오면 설치합니다.

    pip install pydantic-settings

  2. config.py 만들기

    앞 페이지의 app/config.py를 그대로 작성합니다.

  3. .env.example과 .gitignore 만들기

    book-api 폴더(가장 바깥)에 두 파일을 만듭니다.

    .env.example
    # 이 파일을 .env로 복사한 뒤 값을 채웁니다. .env는 Git에 올리지 않습니다.
APP_NAME=도서 관리 API
DATABASE_URL=sqlite:///./books.db
SECRET_KEY=change-me
CORS_ORIGINS=["http://localhost:5173"]
    .gitignore
    # 가상환경
.venv/

# 비밀정보가 들어 있는 설정 파일
.env

# 실행하면 생기는 파일
__pycache__/
*.db

  4. .env 만들고 비밀 키 채우기

    예시 파일을 복사해 .env를 만듭니다.

    copy .env.example .env

    macOS에서는 cp .env.example .env입니다. 다음 명령으로 추측하기 어려운 비밀 키를 만들고, 출력된 값을 .env의 SECRET_KEY= 뒤에 붙여 넣습니다.

    python -c "import secrets; print(secrets.token_hex(32))"

    secrets는 보안에 쓰는 난수를 만드는 Python 표준 모듈입니다. 비밀 키는 직접 지어내지 않고 이렇게 만듭니다.

  5. main.py에서 설정 쓰기

    app/main.py
    from app.config import settings

app = FastAPI(
    title=settings.app_name,
    ...
)


@app.get("/", tags=["기본"])
def read_root():
    return {"message": f"{settings.app_name}에 오신 것을 환영합니다."}

    .env의 APP_NAME을 바꾸고 서버를 다시 시작하면 문서 제목이 바뀌는 것을 확인합니다. .env는 .py 파일이 아니라서 고쳐도 서버가 자동으로 다시 시작되지 않으니, Ctrl + C로 끄고 다시 실행합니다.

  6. 비밀 키가 없을 때 확인

    .env의 SECRET_KEY 줄 앞에 #을 붙여 주석으로 만들고 서버를 다시 실행해 봅니다.

    pydantic_core._pydantic_core.ValidationError: 1 validation error for Settings
secret_key
  Field required [type=missing, input_value={...}, input_type=dict]

    서버가 시작하지 않고 어떤 설정이 빠졌는지 알려 줍니다. 확인했으면 #을 지워 원래대로 돌립니다.
