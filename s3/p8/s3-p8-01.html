1일차 복습

이 파트의 학습 목표Depends로 공통 로직을 의존성으로 분리할 수 있습니다.

2일차를 시작하기 전에 1일차에 만든 코드를 짧게 되짚습니다. 오늘 배울 내용은 모두 이 코드 위에 쌓입니다.

질문답
클라이언트가 보낸 JSON은 어디서 검사하나요?app/schemas.py의 입력 모델(BookCreate, BookUpdate)이 검사합니다. 규칙을 어기면 함수가 실행되기 전에 422가 나갑니다.
응답에 내부 값이 나가지 않게 하는 장치는?경로 데코레이터의 response_model=BookRead입니다.
새 도서를 등록하면 어떤 상태 코드가 나가나요?201입니다. 삭제는 204, 없는 도서는 404, ISBN 중복은 409입니다.
오류 응답의 모양은?{"code": "...", "message": "..."}입니다. AppError를 내면 예외 처리기가 이 모양으로 바꿉니다.
서버는 어떻게 실행하나요?book-api 폴더에서 fastapi dev app/main.py를 실행합니다.

오늘의 흐름

오전에는 반복되는 코드를 의존성으로 묶고, 설정값을 코드 밖으로 빼낸 뒤, 데이터베이스를 연결합니다. 오후에는 데이터베이스로 수정과 삭제를 완성하고 테이블 사이의 관계를 다룹니다. 하루가 끝나면 서버를 다시 시작해도 데이터가 사라지지 않는 도서 API가 완성됩니다.
