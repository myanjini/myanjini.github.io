캡슐화와 디버그 코드

개발하면서 잠깐 넣은 코드가 그대로 운영에 나가는 일은 생각보다 흔합니다. KISA 가이드의 캡슐화 유형과 이어지는 내용을 정리합니다.

제거되지 않고 남은 디버그 코드

이런 코드가 남아 있으면 안 됩니다
print(f"로그인 시도: {form.username} / {form.password}")   # 개발 중에 확인하려고 넣은 출력
breakpoint()                                                # 디버거 정지점
@app.get("/debug/settings")                                 # 확인용으로 만든 API
def show_settings():
    return settings.model_dump()                            # 비밀 키까지 모두 응답
코드위험
비밀번호를 출력하는 print컨테이너 로그에 비밀번호가 그대로 남습니다(S8에서 출력은 모두 로그가 됩니다).
breakpoint()운영 서버에서 그 줄에 오면 요청이 멈춥니다.
확인용 API인증 없이 설정과 비밀 키를 보여 줍니다. 만든 사람도 잊어버려 OWASP API9(부적절한 자산 관리)가 됩니다.

찾는 방법은 다음과 같습니다. 6일차에는 bandit 같은 자동 점검 도구를 CI에 넣어 이런 코드를 푸시할 때마다 찾게 합니다.

git grep -n -E "print\(|breakpoint\(|pdb|/debug|/test"
