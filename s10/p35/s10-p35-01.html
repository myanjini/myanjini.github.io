에러처리 보안약점

이 파트의 학습 목표오류 응답과 로그를 통한 정보 노출을 막을 수 있습니다.

오류는 반드시 일어납니다. 문제는 오류가 났을 때 무엇을 보여 주고, 무엇을 기록하고, 어떻게 처리하느냐입니다.

에러처리 보안약점 3가지

KISA 보안약점뜻예
오류 메시지를 통한 정보 노출오류 응답에 내부 정보가 담겨 공격자에게 단서를 줍니다.스택 트레이스, SQL 문장, 파일 경로, 라이브러리 버전
오류 상황 대응 부재오류를 잡고도 아무것도 하지 않아 잘못된 상태로 계속 진행합니다.except: pass
부적절한 예외 처리너무 넓게 잡거나 잘못 처리해 진짜 문제를 숨깁니다.모든 예외를 잡아 200으로 응답

나쁜 예와 고친 예

나쁜 예
# 오류 상황 대응 부재: 파일 삭제가 실패해도 아무도 모릅니다.
try:
    path.unlink()
except Exception:
    pass

# 부적절한 예외 처리: 오류인데 성공처럼 응답합니다.
try:
    book_service.delete_book(db, user, book_id)
except Exception as e:
    return {"result": "ok", "error": str(e)}   # 내부 메시지까지 그대로 내보냅니다.
고친 예
# 예상한 상황만 좁게 잡고, 처리하지 못한 예외는 위로 올려 전역 처리기에 맡깁니다.
path.unlink(missing_ok=True)          # 파일이 없는 상황은 정상으로 봅니다.

try:
    data = file.file.read(MAX_COVER_SIZE + 1)
except OSError:
    logger.exception("업로드 파일 읽기 실패")  # 자세한 내용은 로그에만
    raise AppError(400, "UPLOAD_FAILED", "파일을 읽지 못했습니다.")  # 사용자에게는 정해진 문구만

담는 것정해진 오류 코드와 문구, 요청 ID예외 종류, 트레이스백, 요청 정보
담지 않는 것트레이스백, SQL, 경로, 버전비밀번호, 토큰, 개인정보 원문
