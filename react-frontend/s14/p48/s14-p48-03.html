정리: 성능: 코드 분할과 렌더링 최적화

핵심 요약

  • 큰 라이브러리를 쓰는 화면은 lazy와 Suspense로 분할해 필요한 사용자만 내려받게 합니다.
  • memo, useMemo, useCallback은 측정한 뒤 느린 곳에만 씁니다.
  • 빌드 결과의 파일 크기와 Profiler 기록으로 개선 전후를 비교합니다.

확인 퀴즈

lazy(() => import('./dashboard/DashboardPage'))의 효과로 옳은 것은 무엇인가요?

동적 import는 빌드 시 별도 파일을 만들고, 그 화면을 처음 그릴 때 내려받습니다.

memo를 쓰기 알맞은 경우는 무엇인가요?

memo는 비교 비용이 있으므로 효과가 측정되는 곳에만 씁니다.
