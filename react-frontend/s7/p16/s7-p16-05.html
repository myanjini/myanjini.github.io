정리: 인증 연동

핵심 요약

  • 액세스 토큰은 메모리, 리프레시 토큰은 sessionStorage에 두고 tokenStore로만 접근합니다.
  • 요청 인터셉터는 토큰을 붙이고, 응답 인터셉터는 401에서 한 번만 재발급하며, 동시 재발급은 하나의 Promise로 묶습니다.
  • AuthProvider가 로그인 상태를 Context로 공유하고, 새로고침 후에는 재발급 흐름으로 상태를 복원합니다.
  • 로그인 오류 메시지는 하나로 통일하고, 429 잠금은 Retry-After로 안내합니다.
  • 화면의 접근 제어는 사용자 경험을 위한 것이며, 실제 권한 검사는 백엔드가 합니다.

확인 퀴즈

여러 요청이 동시에 401을 받았을 때 재발급을 한 번만 하는 이유는 무엇인가요?

백엔드는 재발급 때 리프레시 토큰을 새로 바꾸므로 진행 중인 재발급 Promise를 공유해야 합니다.

프론트엔드에서 관리자 메뉴를 숨기는 것에 대한 설명으로 옳은 것은 무엇인가요?

프론트엔드 코드는 조작될 수 있으므로 권한 판단은 항상 백엔드가 합니다.
