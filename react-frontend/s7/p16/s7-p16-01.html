로그인 상태 공유: Context

로그인한 사용자 정보는 상단 메뉴, 상세 화면의 버튼, 접근 제어 등 여러 컴포넌트가 필요로 합니다. props로 여러 단계를 거쳐 전달하면 중간 컴포넌트까지 불필요한 props를 받아야 합니다. Context는 컴포넌트 트리의 위쪽에서 값을 제공하고, 아래쪽 어디서든 useContext로 바로 꺼내 쓰게 하는 React 기능입니다.

Context 객체와 그 값을 꺼내는 훅은 src/auth/useAuth.js에 둡니다. AuthProvider 바깥에서 useAuth를 호출하면 실수를 바로 알 수 있도록 오류를 던집니다.

src/auth/useAuth.js
import { createContext, useContext } from 'react';

export const AuthContext = createContext(null);

export function useAuth() {
  const context = useContext(AuthContext);
  if (!context) throw new Error('useAuth는 AuthProvider 안에서만 사용할 수 있습니다.');
  return context;
}

값을 제공하는 컴포넌트는 src/auth/AuthProvider.jsx입니다. 컴포넌트와 훅을 다른 파일로 나눈 이유는, Vite의 HMR이 "컴포넌트만 내보내는 파일"에서 가장 안정적으로 동작하기 때문입니다.

src/auth/AuthProvider.jsx
import { useCallback, useEffect, useMemo, useState } from 'react';
import * as authApi from '../api/auth';
import { setOnAuthExpired } from '../api/client';
import { tokenStore } from './tokenStore';
import { AuthContext } from './useAuth';

export default function AuthProvider({ children }) {
  const [user, setUser] = useState(null); // { id, email, role }
  // 리프레시 토큰이 남아 있을 때만 "확인 중" 상태로 시작합니다.
  const [initializing, setInitializing] = useState(() => Boolean(tokenStore.getRefresh()));

  const loadMe = useCallback(async () => {
    const me = await authApi.fetchMe();
    setUser(me);
    return me;
  }, []);

  useEffect(() => {
    // 재발급까지 실패하면 client.js가 이 함수를 불러 로그인 상태를 지웁니다.
    setOnAuthExpired(() => setUser(null));
  }, []);

  // 새로고침 직후: 액세스 토큰은 메모리에서 사라졌지만 리프레시 토큰이 남아 있으면
  // /auth/me 호출이 401 -> 재발급 -> 재요청 흐름을 거쳐 로그인 상태를 되살립니다.
  useEffect(() => {
    if (!tokenStore.getRefresh()) return;
    loadMe()
      .catch(() => tokenStore.clear())
      .finally(() => setInitializing(false));
  }, [loadMe]);

  const login = useCallback(
    async (email, password) => {
      const tokens = await authApi.login(email, password);
      tokenStore.save(tokens);
      return loadMe();
    },
    [loadMe],
  );

  const logout = useCallback(async () => {
    const refreshToken = tokenStore.getRefresh();
    try {
      if (refreshToken) await authApi.logout(refreshToken);
    } finally {
      // 서버 호출이 실패해도 브라우저의 토큰은 반드시 지웁니다.
      tokenStore.clear();
      setUser(null);
    }
  }, []);

  const value = useMemo(
    () => ({ user, initializing, isAdmin: user?.role === 'admin', login, logout }),
    [user, initializing, login, logout],
  );

  return <AuthContext.Provider value={value}>{children}</AuthContext.Provider>;
}

AuthProvider의 동작을 정리합니다.

  • initializing은 새로고침 직후 로그인 상태를 복원하는 동안 true입니다. 리프레시 토큰이 없으면 확인할 것이 없으므로 처음부터 false로 시작합니다. 이 값이 있어야 S7-P16-03의 보호 라우트가 "아직 확인 중"인 사용자를 로그인 화면으로 잘못 보내지 않습니다.
  • 새로고침 후 복원은 별도 코드 없이 S7-P15-04의 인터셉터가 처리합니다. 메모리의 액세스 토큰이 없으니 /auth/me는 401을 받고, 인터셉터가 재발급 후 다시 요청합니다. Network 탭에서 me(401), refresh(200), me(200) 순서로 확인할 수 있습니다.
  • 로그아웃은 try...finally로 작성해 서버 호출이 실패해도 브라우저의 토큰은 반드시 지웁니다.
  • isAdmin은 user.role === 'admin'으로 계산해 함께 제공합니다.
  • login과 logout을 useCallback으로, 제공하는 값을 useMemo로 감쌌습니다. Context 값이 매번 새 객체로 만들어지면 값을 쓰는 모든 컴포넌트가 불필요하게 다시 그려지므로, 실제로 바뀐 경우에만 새 값을 만들도록 한 것입니다.

마지막으로 src/main.jsx에서 앱을 AuthProvider로 감쌉니다. AuthProvider보다 바깥에 BrowserRouter를 두어, 인증 관련 컴포넌트에서도 라우터 기능을 쓸 수 있게 합니다.

src/main.jsx
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import { BrowserRouter } from 'react-router';
import App from './App.jsx';
import AuthProvider from './auth/AuthProvider.jsx';
import './index.css';

createRoot(document.getElementById('root')).render(
  <StrictMode>
    <BrowserRouter>
      <AuthProvider>
        <App />
      </AuthProvider>
    </BrowserRouter>
  </StrictMode>,
);
