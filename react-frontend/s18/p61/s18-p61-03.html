정리: 보안 점검과 S3 배포

핵심 요약

  • 기능, 인증과 보안, 관제, 도커라이징, 배포 자동화 점검표로 병합 전에 빠진 부분을 찾습니다.
  • 병합하면 CI를 거쳐 S3에 자동 배포되며, 배포 결과 요약의 주소로 확인합니다.
  • 문제는 증상(오류 메시지, 상태 코드, 요청 주소)에서 출발해 원인을 좁힙니다.

확인 퀴즈

배포 후 웹사이트 주소로 접속했더니 403 Forbidden이 나왔습니다. 가장 먼저 확인할 것은 무엇인가요?

버킷의 파일을 공개로 읽을 수 없으면 S3가 403을 돌려줍니다.

배포 후 API 요청이 S3 주소의 /api/...로 나간다면 원인은 무엇인가요?

S3에는 /api 프록시가 없으므로 절대 주소로 빌드해야 합니다.
