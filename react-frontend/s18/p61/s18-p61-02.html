병합, 배포, 문제 해결

  1. 점검을 마친 풀 리퀘스트를 main에 병합합니다.
  2. Actions 탭에서 Deploy 워크플로가 끝나면 요약의 사이트 주소로 접속해 미니 프로젝트 기능을 시연 순서대로 확인합니다.
  3. 문제가 생기면 아래 표에서 증상을 찾아 원인을 좁힙니다.
증상 가능한 원인 확인 방법과 해결
Console에 "blocked by CORS policy" 백엔드 CORS_ORIGINS에 현재 출처가 없음 주소창의 출처(localhost인지 127.0.0.1인지, 포트)를 확인하고 백엔드에 등록 (S5)
화면에 "서버에 연결할 수 없습니다." 백엔드 중지, 주소 오류, CORS 차단 curl http://127.0.0.1:8000/health, .env.development의 주소, Console의 CORS 메시지 (S6)
환경 변수를 바꿨는데 반영되지 않음 개발 서버가 시작할 때만 읽음 개발 서버 재시작, 운영은 이미지 재빌드 (S6, S15)
로그인 요청이 422 JSON으로 보냄 URLSearchParams로 폼 형식 전송 (S6, S8)
표지 업로드가 422 Content-Type을 직접 지정, 필드 이름이 file이 아님 FormData를 그대로 넘기고 필드 이름 확인 (S6, S9)
새로고침하면 로그아웃됨 리프레시 토큰 미저장, 재발급 실패 Session Storage 값과 refresh 요청 결과 확인 (S8)
재발급 요청이 계속 반복됨 재발급 요청이 인터셉터를 거침, 재시도 표시 누락 기본 axios로 재발급, _retried 확인 (S8)
개발 중 같은 요청이 두 번 보임 StrictMode의 의도된 동작 첫 요청이 취소되는지 확인 (S3, S6)
목록에 이전 검색 결과가 잠깐 덮어씀 이전 요청 미취소 이펙트 정리 함수에서 abort() (S6)
대여 시각이 9시간 어긋남 시간대 없는 UTC 문자열 Z를 붙여 해석 (S9)
차트가 그려지지 않거나 높이가 0 ResponsiveContainer의 부모 크기 없음 height 지정, 부모 요소의 너비 확인 (S13)
운영에서 새로고침하면 404 SPA 대체 응답 누락 try_files ... /index.html (S15)

배포 단계에서 자주 만나는 문제는 다음과 같습니다.

증상 가능한 원인 확인 방법과 해결
AWS 인증 스텝이 Not authorized to perform sts:AssumeRoleWithWebIdentity 신뢰 정책의 저장소, 환경 이름 불일치, id-token: write 누락 신뢰 정책의 sub 값과 워크플로의 environment, 저장소 이름 비교 (S16-P56)
aws s3 sync가 AccessDenied 역할 권한 정책의 버킷 이름 오류 권한 정책의 Resource와 S3_BUCKET 변수 비교
웹사이트 주소가 403 Forbidden 버킷 정책 없음 또는 퍼블릭 액세스 차단 켜짐 버킷 정책과 퍼블릭 액세스 차단 설정 확인 (S16-P55)
배포했는데 예전 화면이 보임 index.html이 캐시됨 업로드 명령의 --cache-control "no-cache" 확인, 강력 새로고침
화면은 뜨는데 API 요청이 /api/...로 나감 VITE_API_BASE_URL 변수 미등록 production 환경 변수 확인 후 다시 배포
배포 후 CORS 오류 백엔드 CORS_ORIGINS에 S3 주소 없음, 주소 끝 / 오류 메시지의 출처와 등록 값을 글자 그대로 비교
