권한과 쓰기 기능 구현

파트 목표권한에 따라 화면을 나누고, 쓰기 기능을 useMutation으로 구현해 오류와 캐시 갱신을 처리할 수 있습니다.

설계 문서의 권한 표와 쓰기 기능을 구현합니다. 주제 2(저자 관리)를 예로 들면 다음 순서입니다. 쓰기 기능이 없는 주제(1, 5, 6)는 이 시간에 권한 처리와 화면 완성도를 높이고, 남는 시간에 다른 주제의 쓰기 기능 하나를 더합니다.

  1. 라우트를 RequireAuth로 감싸고, 관리자 전용이면 화면 안에서 user.role을 확인해 안내 문구를 보여 줍니다. 메뉴도 관리자에게만 보이게 합니다. 화면을 숨기는 것은 편의일 뿐이고 실제 권한 검사는 백엔드가 한다는 점을 기억합니다(S12-P40-01).
  2. 쓰기 요청은 useMutation으로 만듭니다. 성공하면 관련 쿼리를 무효화하고, 실패하면 오류 코드별로 안내합니다.
const queryClient = useQueryClient();
const create = useMutation({
  mutationFn: createAuthor,
  onSuccess: () => queryClient.invalidateQueries({ queryKey: ['authors'] }),
});

// 제출할 때
create.mutate({ name }, {
  onSuccess: () => setName(''),
});

// 화면
{create.error?.code === 'DUPLICATE_AUTHOR' && <p role="alert">이미 등록된 저자입니다.</p>}
<button disabled={create.isPending}>{create.isPending ? '등록 중...' : '등록'}</button>
  1. 삭제처럼 되돌릴 수 없는 동작은 확인 단계를 둡니다. 브라우저의 confirm도 되지만, 화면 안에 "정말 삭제할까요?"와 확인, 취소 버튼을 보여 주는 방식이 테스트하기 쉽습니다.
  2. 다음 경우를 모두 확인합니다.
