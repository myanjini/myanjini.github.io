정리: 프론트엔드 관점의 HTTP와 JSON

핵심 요약

  • 요청 본문 형식은 JSON, 폼, 멀티파트 세 가지이며 API마다 요구하는 형식을 정확히 맞춰야 합니다.
  • 상태 코드의 범위(2xx, 4xx, 5xx)로 성공과 실패를 먼저 나누고, 204처럼 본문이 없는 성공도 있습니다.
  • JSON에는 날짜와 undefined가 없으므로 변환 과정에서 생기는 차이를 의식해야 합니다.

확인 퀴즈

JSON.stringify({ a: 1, b: undefined })의 결과로 알맞은 것은 무엇인가요?

JSON에는 undefined가 없으므로 값이 undefined인 속성은 결과에서 빠집니다.

도서 삭제 API가 204를 돌려줄 때 주의할 점은 무엇인가요?

204 No Content는 본문 없는 성공 응답입니다.
