Nginx 설정 작성

nginx 폴더를 만들고 두 파일을 작성합니다.

보안 헤더: nginx/security-headers.conf

S12-P41-01에서 정리한 보안 헤더와 CSP입니다.

nginx/security-headers.conf
# 모든 응답에 붙일 보안 헤더 (교안 "프론트엔드 개발 보안" 단원 참고)
add_header X-Content-Type-Options "nosniff" always;
add_header X-Frame-Options "DENY" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Permissions-Policy "camera=(), microphone=(), geolocation=()" always;
add_header Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data: blob:; connect-src 'self'; font-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'" always;

always를 붙이면 200뿐 아니라 404, 500 같은 오류 응답에도 헤더가 붙습니다.

서버 설정: nginx/default.conf

nginx/default.conf
server {
    listen 8080;
    server_name _;
    root /usr/share/nginx/html;
    index index.html;
    server_tokens off;  # 응답 헤더에서 Nginx 버전을 숨깁니다.

    # 1) 백엔드 API: /api/books -> http://api:8000/books
    location /api/ {
        proxy_pass http://api:8000/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        client_max_body_size 3m;  # 표지 2MB 제한보다 약간 크게 둡니다.
    }

    # 2) 빌드 결과물: 파일 이름에 해시가 있으므로 오래 캐시합니다.
    location /assets/ {
        include /etc/nginx/snippets/security-headers.conf;
        add_header Cache-Control "public, max-age=31536000, immutable";
        try_files $uri =404;
    }

    # 3) 나머지 주소는 모두 index.html을 돌려줘 React Router가 처리하게 합니다.
    location / {
        include /etc/nginx/snippets/security-headers.conf;
        add_header Cache-Control "no-cache";
        try_files $uri $uri/ /index.html;
    }
}

세 개의 location 블록이 각각 다음 역할을 합니다.

1) /api/ 프록시. proxy_pass http://api:8000/;의 마지막 /가 중요합니다. 이 슬래시가 있으면 요청 경로에서 location에 맞은 /api/ 부분을 잘라 내고 나머지를 붙입니다. 따라서 /api/books?q=1은 백엔드의 /books?q=1로 전달됩니다. 슬래시를 빼면 /api/books가 그대로 전달되어 백엔드에서 404가 납니다. api는 Compose 서비스 이름이며, 같은 Compose 네트워크 안에서 호스트 이름으로 쓸 수 있습니다. X-Forwarded-For, X-Real-IP 헤더로 실제 사용자의 IP를 백엔드에 전달하고, client_max_body_size는 표지 업로드 제한(2MB)보다 약간 크게 잡아 Nginx가 먼저 거절하지 않게 합니다.

2) /assets/ 장기 캐시. Vite는 빌드 결과물의 파일 이름에 내용의 해시를 넣습니다(index-C5lRxo5C.js). 내용이 바뀌면 이름도 바뀌므로 같은 이름의 파일은 영원히 같은 내용입니다. 그래서 1년 동안 캐시하고(immutable) 다시 확인하지 않게 합니다.

3) 나머지 경로와 SPA 대체 응답. try_files $uri $uri/ /index.html;은 요청한 파일이 있으면 그 파일을, 없으면 index.html을 돌려줍니다. 사용자가 http://localhost:8080/books/7을 직접 입력하거나 새로고침하면 Nginx에는 /books/7이라는 파일이 없습니다. 이때 index.html을 돌려줘야 React Router가 주소를 보고 상세 화면을 그립니다. 이 설정이 없으면 첫 화면에서 메뉴로 이동할 때는 잘 되다가 새로고침하면 404가 나는 문제가 생깁니다. index.html에는 no-cache를 지정해, 새 버전을 배포하면 브라우저가 바로 새 index.html과 그 안에 적힌 새 해시 파일을 받게 합니다.

add_header 상속 주의. Nginx는 한 location 블록 안에 add_header가 하나라도 있으면 바깥(server 블록)에 적은 add_header를 상속하지 않습니다. 캐시 헤더를 추가하는 블록마다 보안 헤더가 사라지는 실수가 흔하므로, 이 설정은 보안 헤더를 별도 파일로 만들어 각 location에서 include합니다.

server_tokens off는 응답 헤더와 오류 페이지에서 Nginx 버전을 숨깁니다. 백엔드 과정 S10-P35에서 다룬 "불필요한 정보 노출 줄이기"와 같은 취지입니다.

이 설정은 다음 파트에서 이미지로 만들어 실행하며 확인합니다. 설정 파일을 작성하면서 다음을 스스로 점검합니다.

  1. /api/books?skip=10은 백엔드에 어떤 경로로 전달됩니까? proxy_pass 끝의 /를 빼면 어떻게 바뀝니까?
  2. /assets/index-abc.js가 없는 파일이면 무엇을 돌려줍니까? /books/7과 다르게 처리하는 이유는 무엇입니까?
  3. location /assets/ 블록에서 include 줄을 지우면 이 경로의 응답에서 어떤 헤더가 사라집니까?
