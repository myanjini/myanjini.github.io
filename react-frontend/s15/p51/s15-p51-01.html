리버스 프록시와 SPA 대체 응답

파트 목표Nginx로 정적 파일 제공, SPA 대체 응답, API 리버스 프록시, 보안 헤더를 설정할 수 있습니다.

리버스 프록시는 클라이언트의 요청을 대신 받아 뒤에 있는 서버로 전달하고, 받은 응답을 다시 클라이언트에 돌려주는 서버입니다. 브라우저 입장에서는 프록시가 곧 서버이므로, 뒤에 백엔드가 몇 개 있든 출처는 하나로 보입니다. S5에서 개발 서버의 프록시로 CORS 없이 API를 부르는 방법을 비교했는데, 운영 환경에서는 Nginx가 이 역할을 맡습니다.

SPA에는 웹 서버가 꼭 해 줘야 할 일이 하나 더 있습니다. React Router가 만드는 /books/7 같은 주소는 브라우저 안에서만 의미가 있고, 서버에는 그런 파일이 없습니다. 목록에서 링크를 눌러 이동할 때는 서버에 요청하지 않으므로 문제가 없지만, 그 주소에서 새로고침하거나 주소를 직접 입력하면 브라우저가 서버에 /books/7을 요청합니다. 이때 서버가 404를 돌려주면 화면이 깨집니다. 그래서 웹 서버는 없는 경로에 index.html을 돌려주고, 화면을 그리는 일은 React Router에 맡겨야 합니다. 이것을 SPA 대체 응답(fallback)이라고 합니다.
