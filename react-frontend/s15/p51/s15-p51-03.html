정리: Nginx와 리버스 프록시

핵심 요약

  • Nginx가 정적 파일 제공과 /api/ 리버스 프록시를 함께 맡으면 화면과 API가 같은 출처가 되어 CORS가 필요 없습니다.
  • SPA는 try_files로 없는 경로에 index.html을 돌려줘야 새로고침과 직접 접속이 동작합니다.
  • 해시가 붙은 파일은 오래 캐시하고 index.html은 매번 확인하게 하며, 보안 헤더는 location마다 include합니다.

확인 퀴즈

location / { try_files $uri $uri/ /index.html; }의 역할은 무엇인가요?

새로고침이나 직접 접속한 /books/7 같은 주소도 화면이 정상으로 그려집니다.

캐시 헤더를 추가한 location 블록에서 보안 헤더가 사라지는 이유는 무엇인가요?

그래서 보안 헤더를 별도 파일로 만들어 각 location에서 include합니다.
