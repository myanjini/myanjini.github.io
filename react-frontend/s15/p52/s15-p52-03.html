정리: 멀티 스테이지 Dockerfile

핵심 요약

  • 멀티 스테이지 빌드는 빌드 도구가 있는 단계와 실행 단계를 나눠, 최종 이미지에 결과물만 담습니다.
  • 의존성 목록을 먼저 복사하고 npm ci로 설치하면 캐시를 활용하면서 재현 가능한 빌드를 만듭니다.
  • root가 아닌 사용자로 실행하고 헬스 체크를 두며, .dockerignore로 불필요한 파일을 제외합니다.

확인 퀴즈

멀티 스테이지 빌드의 효과로 옳은 것은 무엇인가요?

빌드에만 필요한 도구는 첫 단계에 남고, 실행 단계에는 dist만 복사됩니다.

Dockerfile에서 COPY package.json package-lock.json ./를 소스 전체 복사보다 먼저 두는 이유는 무엇인가요?

레이어 캐시는 앞 단계의 입력이 같으면 재사용됩니다.
