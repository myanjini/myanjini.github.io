이미지 빌드와 단독 실행

이미지를 빌드합니다.

docker build -t react-frontend .
docker image ls react-frontend

최종 이미지에는 Node.js와 소스 코드, node_modules가 없으므로 수십 MB 수준입니다. 1단계에 쓴 node:24-alpine 이미지 크기와 비교해 봅니다.

이 이미지를 혼자 실행하면 Nginx가 시작하면서 proxy_pass의 api라는 이름을 찾지 못해 바로 종료됩니다. Compose로 함께 실행하기 전에 확인만 해 보려면, api라는 이름이 내 컴퓨터를 가리키게 지정하고 백엔드를 로컬의 8000 포트에서 실행해 둡니다.

docker run --rm -d --name web-test -p 8080:8080 --add-host api:host-gateway react-frontend
docker ps --filter name=web-test   # 잠시 뒤 STATUS가 healthy
docker logs web-test

확인할 내용은 다음과 같습니다.

  1. curl -I http://localhost:8080/books/3의 상태가 200이고, content-security-policy와 x-frame-options 헤더가 있으며, Server 헤더에 버전이 없습니다.
  2. curl http://localhost:8080/api/health가 백엔드의 헬스 체크 결과를 돌려줍니다.
  3. docker exec web-test id의 결과가 uid=101(nginx)처럼 root가 아닙니다.
  4. 확인이 끝나면 docker stop web-test로 정리합니다.
