운영 빌드 만들고 확인하기

운영 빌드에서는 API 주소를 같은 출처의 상대 경로 /api로 지정합니다. 프로젝트 루트에 .env.production을 만듭니다.

.env.production
# 운영 빌드(npm run build)에서 사용하는 값입니다.
# Nginx가 /api 경로를 백엔드로 전달하므로 같은 출처의 상대 경로를 씁니다.
VITE_API_BASE_URL=/api

이 값으로 빌드하면 axios의 baseURL이 /api가 되어 /api/books, /api/auth/token처럼 요청하고, toAssetUrl은 표지 주소를 /api/covers/...로 만듭니다.

Vite의 환경 변수는 빌드할 때 코드에 새겨진다는 점을 다시 강조합니다. 컨테이너를 실행할 때 환경 변수를 바꿔도 이미 만든 JavaScript 파일은 바뀌지 않습니다. 환경마다 다른 값이 필요하면 이미지를 따로 빌드하거나, 이 과정처럼 상대 경로를 써서 환경과 무관한 값으로 만듭니다.

이제 운영 빌드를 직접 만들어 확인합니다.

  1. npm run build를 실행합니다. 빌드 출력에서 dist/index.html, dist/assets/index-...js, dist/assets/DashboardPage-...js, dist/assets/index-...css가 만들어지는 것을 확인합니다. 파일 이름의 뒷부분은 내용에서 계산한 해시입니다.
  2. dist/index.html을 열어 봅니다. 개발용 src/main.jsx 대신 /assets/index-...js를 불러오도록 바뀌어 있습니다.
  3. 빌드 결과물에 API 주소가 어떻게 새겨졌는지 확인합니다.
grep -o '"/api"' dist/assets/index-*.js | head -1
grep -c "127.0.0.1:8000" dist/assets/index-*.js

첫 명령은 "/api"를 찾고, 두 번째 명령은 0을 출력해야 합니다. 개발용 주소가 운영 빌드에 들어가지 않았다는 뜻입니다.

  1. 소스맵이 없는지 확인합니다. ls dist/assets에 .map 파일이 없어야 합니다(S12-P41-02).
  2. npm run preview로 빌드 결과물을 미리 봅니다. 이 미리보기 서버는 운영용이 아니며 /api 프록시도 없으므로, 화면은 뜨지만 API 요청은 실패합니다. Network 탭에서 요청이 http://localhost:4173/api/books로 나가는 것을 확인합니다. 이 요청을 백엔드로 전달하는 역할을 다음 파트에서 Nginx가 맡습니다.
  3. 같은 코드를 다른 API 주소로 빌드할 수 있는지 확인합니다. 명령에서 지정한 환경 변수는 .env.production보다 우선합니다.
VITE_API_BASE_URL=https://api.example.com npm run build
grep -c "api.example.com" dist/assets/index-*.js
npm run build   # 다시 /api로 되돌립니다.

S16의 S3 배포에서는 이 방법으로 백엔드의 공개 주소를 넣어 빌드합니다.
