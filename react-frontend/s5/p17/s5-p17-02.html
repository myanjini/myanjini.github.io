사전 요청 관찰하기

아직 백엔드가 http://localhost:5173을 허용하지 않은 상태에서 관찰합니다.

  1. Console에서 Authorization 헤더를 붙인 요청을 보냅니다. Network 탭에서 OPTIONS 요청이 먼저 나가고 실패한 뒤, 본 요청(GET /auth/me)은 아예 나가지 않는 것을 확인합니다.
await fetch('http://127.0.0.1:8000/auth/me', { headers: { Authorization: 'Bearer test' } });

  1. 같은 요청에서 Authorization 헤더를 빼면 단순 요청이 되어 사전 요청 없이 바로 나갑니다. 두 경우의 차이를 Network 탭에서 비교합니다.

  2. curl로 사전 요청을 흉내 내어 서버가 지금 어떻게 답하는지 확인합니다. Access-Control-Allow-Origin 헤더가 없거나 400이 돌아옵니다. 다음 파트에서 설정을 고친 뒤 같은 명령을 다시 실행해 비교합니다.

curl -i -X OPTIONS http://127.0.0.1:8000/books \
  -H "Origin: http://localhost:5173" \
  -H "Access-Control-Request-Method: POST" \
  -H "Access-Control-Request-Headers: authorization,content-type"
  1. 백엔드 로그에서 OPTIONS 요청을 찾아봅니다. 이 로그는 S14-P47의 로그 분석 화면에서도 다시 만납니다.
docker compose logs api --no-log-prefix | grep OPTIONS
  1. S1-P3-03의 API 표에서 이 과정이 호출할 API를 단순 요청과 사전 요청으로 나눠 봅니다. 앞 페이지의 표와 비교해 확인합니다.
