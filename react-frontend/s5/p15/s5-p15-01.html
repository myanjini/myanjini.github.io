백엔드로 첫 요청 보내기

파트 목표다른 출처의 백엔드로 요청을 보내 CORS 오류를 관찰하고, 출처의 정의로 그 원인을 설명할 수 있습니다.

S4까지는 샘플 데이터를 썼습니다. 이제 진짜 백엔드에 요청을 보내 봅니다. 먼저 백엔드가 실행 중인지 확인하고, 이번 파트의 관찰을 위해 백엔드가 아직 프론트엔드 주소를 허용하지 않은 상태로 둡니다. 백엔드 프로젝트의 .env에 CORS_ORIGINS 값이 있고 그 안에 http://localhost:5173이 이미 들어 있다면, 잠시 지우고 docker compose up -d로 API 컨테이너를 다시 만듭니다.

연결을 확인하는 연습용 컴포넌트를 만들고 App에서 함께 보여 줍니다.

src/practice/FirstRequest.jsx
import { useEffect, useState } from 'react';

// S5 실습: 다른 출처(127.0.0.1:8000)의 백엔드에 첫 요청을 보내 CORS 동작을 관찰합니다.
export default function FirstRequest() {
  const [message, setMessage] = useState('요청 전');

  useEffect(() => {
    fetch('http://127.0.0.1:8000/books?limit=3')
      .then((response) => response.json())
      .then((page) => setMessage(`도서 ${page.total}권을 받았습니다.`))
      .catch((error) => setMessage(`실패: ${error.message}`));
  }, []);

  return <p>백엔드 연결 확인: {message}</p>;
}
src/App.jsx
import FirstRequest from './practice/FirstRequest';
import StaticBookPage from './practice/StaticBookPage';

export default function App() {
  return (
    <>
      <FirstRequest />
      <StaticBookPage />
    </>
  );
}
Access to fetch at 'http://127.0.0.1:8000/books?limit=3' from origin 'http://localhost:5173'
has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present on the
requested resource.

Network 탭에서 해당 요청을 눌러 봅니다. 요청은 실제로 서버에 도착했고, 서버는 200 응답까지 보냈습니다. 백엔드 로그(docker compose logs api)에도 GET /books 요청이 200으로 기록되어 있습니다. 그런데도 JavaScript는 응답을 읽지 못했습니다. 서버가 거절한 것이 아니라 브라우저가 응답을 JavaScript에 넘겨주지 않은 것입니다. S1-P4-03에서는 같은 코드가 잘 동작했는데, 무엇이 달라졌을까요? 이 차이를 이해하는 것이 이 장의 목표입니다.
