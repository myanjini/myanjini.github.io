fetch 오류 처리의 함정

fetch를 처음 쓸 때 가장 많이 하는 실수는 "404나 500이 오면 catch로 간다"고 생각하는 것입니다. fetch는 응답을 받기만 하면 상태 코드와 관계없이 성공으로 처리합니다. catch로 가는 경우는 네트워크 연결 실패, CORS 차단, 요청 취소처럼 응답 자체를 받지 못했을 때뿐입니다.

try {
  const response = await fetch('http://127.0.0.1:8000/books/999999');
  console.log('여기에 도달합니다. status =', response.status); // 404
} catch (error) {
  console.log('네트워크 오류나 CORS 차단일 때만 여기로 옵니다.');
}

따라서 fetch를 쓸 때는 response.ok를 직접 확인하는 함수를 만들어 두는 것이 좋습니다.

async function requestJson(url, options = {}) {
  let response;
  try {
    response = await fetch(url, options);
  } catch (error) {
    if (error.name === 'AbortError') throw error; // 취소는 그대로 전달
    throw new Error('서버에 연결할 수 없습니다.');
  }
  if (response.status === 204) return null;        // 본문 없는 성공
  const body = await response.json().catch(() => null);
  if (!response.ok) {
    const error = new Error(body?.message ?? `요청 실패 (${response.status})`);
    error.status = response.status;
    error.code = body?.code;
    throw error;
  }
  return body;
}

이 함수가 하는 일은 세 가지입니다. 연결 실패와 HTTP 오류를 구분하고, 204처럼 본문이 없는 응답을 처리하며, 백엔드의 {"code", "message"} 오류 본문을 오류 객체에 담습니다. S5-P11-02에서는 같은 일을 axios 인터셉터로 한 곳에서 처리합니다.
