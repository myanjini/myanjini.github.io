요청 취소와 시간 제한

사용자가 목록을 보다가 다른 화면으로 이동하면, 이전 화면에서 보낸 요청은 더 이상 필요 없습니다. 응답이 늦게 도착해 사라진 화면의 상태를 바꾸려 하거나, 검색 조건을 빠르게 바꿀 때 먼저 보낸 요청의 응답이 나중에 도착해 최신 결과를 덮어쓰는 문제가 생길 수 있습니다. AbortController로 이런 요청을 취소합니다.

const controller = new AbortController();
fetch('http://127.0.0.1:8000/books', { signal: controller.signal })
  .then((r) => r.json())
  .catch((error) => {
    if (error.name === 'AbortError') console.log('취소되었습니다.');
  });
controller.abort(); // 요청 취소

React에서는 useEffect의 정리 함수에서 abort()를 호출하는 것이 기본 패턴입니다. S3에서 본 StrictMode의 "실행, 정리, 다시 실행"도 이 패턴으로 자연스럽게 처리됩니다. 첫 요청은 정리 단계에서 취소되고 두 번째 요청만 화면에 반영됩니다.

useEffect(() => {
  const controller = new AbortController();
  fetch(url, { signal: controller.signal }).then(/* ... */);
  return () => controller.abort();
}, [url]);

응답이 너무 오래 걸릴 때 포기하는 시간 제한은 AbortSignal.timeout(밀리초)로 간단히 만들 수 있습니다.

await fetch('http://127.0.0.1:8000/health', { signal: AbortSignal.timeout(3000) });
