백엔드 CORS 설정 고치기

파트 목표백엔드 CORS 설정으로 오류를 해결하고, 프록시라는 다른 방법과 CORS에 대한 흔한 오해를 설명할 수 있습니다.

백엔드 과정 S3-P9-04에서 app/main.py에 다음 설정을 넣었습니다. 허용 출처는 설정값 cors_origins, 즉 환경 변수 CORS_ORIGINS에서 읽습니다.

app.add_middleware(
    CORSMiddleware,
    allow_origins=settings.cors_origins,
    allow_methods=["*"],
    allow_headers=["*"],
)

1) 허용 출처 등록

백엔드 프로젝트의 .env에 프론트엔드 개발 서버의 출처를 넣습니다. 값의 형식은 백엔드 S3-P9-02에서 정의한 Settings를 따르며, list[str] 타입이라면 다음처럼 JSON 배열로 적습니다.

CORS_ORIGINS=["http://localhost:5173"]

컨테이너가 이 값을 받을 수 있도록 compose.yaml의 api 서비스 environment에도 한 줄을 추가합니다. Compose는 같은 폴더의 .env에서 ${CORS_ORIGINS} 값을 읽어 넣어 줍니다.

  api:
    environment:
      DATABASE_URL: postgresql+psycopg://bookapi:${POSTGRES_PASSWORD}@db:5432/bookapi
      SECRET_KEY: ${SECRET_KEY}
      CORS_ORIGINS: ${CORS_ORIGINS}

2) 노출할 응답 헤더 추가 (권장)

로그인 화면에서 잠금 시간을 안내하고 관제 화면에서 요청 ID를 활용할 수 있도록 expose_headers를 추가합니다. 이 설정이 없어도 이 교안의 화면은 동작하지만, S8의 로그인 잠금 안내가 기본값(15분)으로 표시됩니다.

app.add_middleware(
    CORSMiddleware,
    allow_origins=settings.cors_origins,
    allow_methods=["*"],
    allow_headers=["*"],
    expose_headers=["Retry-After", "X-Request-ID", "X-Process-Time"],
)

3) 적용과 확인

cd book-api
docker compose up -d --build api

curl로 사전 요청을 흉내 내어 서버의 응답 헤더를 직접 확인합니다.

curl -i -X OPTIONS http://127.0.0.1:8000/books \
  -H "Origin: http://localhost:5173" \
  -H "Access-Control-Request-Method: POST" \
  -H "Access-Control-Request-Headers: authorization,content-type"

응답이 200 OK이고 access-control-allow-origin: http://localhost:5173이 있으면 성공입니다. Origin을 http://evil.example로 바꿔 다시 보내면 400 Bad Request와 함께 access-control-allow-origin 헤더가 빠진 응답이 옵니다. 브라우저의 화면을 새로고침하면 이제 "도서 N권을 받았습니다."가 표시됩니다.

allow_origins=["*"]로 모든 출처를 허용하면 빠르게 오류를 없앨 수 있지만, 백엔드 과정 S3-P9-03에서 강조했듯이 피해야 합니다. 허용 출처는 실제로 사용하는 주소만 명시적으로 적습니다.

설정을 고친 뒤 S5-P17-02 실습의 1번과 3번을 다시 실행해 결과를 비교합니다. 확인이 끝나면 src/App.jsx에서 FirstRequest를 지우고 StaticBookPage만 남겨 둡니다.
