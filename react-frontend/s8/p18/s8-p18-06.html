정리: 쓰기 기능: 등록, 수정, 삭제, 표지 업로드, 대여와 반납

핵심 요약

  • 프론트엔드 검증은 빠른 안내를 위한 것이고, 백엔드가 거절할 수 있다는 전제로 오류를 처리합니다.
  • 입력 칸의 문자열은 한 함수에서 API 본문(정수, null)으로 변환하고, PATCH는 바뀐 필드만 보냅니다.
  • 422는 칸별 메시지로, 409는 업무 규칙 위반으로 구분해 안내합니다.
  • 파일 업로드는 FormData로 보내고, 크기와 확장자는 미리 검사하되 최종 판단은 백엔드에 맡깁니다.
  • 시간대 표시가 없는 UTC 시각은 Z를 붙여 해석해야 사용자의 시간대로 올바르게 표시됩니다.

확인 퀴즈

도서 수정 화면에서 PATCH 본문에 바뀐 필드만 담는 이유는 무엇인가요?

백엔드는 요청에 들어 있는 필드만 반영하므로 바뀐 필드만 보내는 것이 안전합니다.

백엔드가 "2026-11-23T06:58:12"처럼 시간대 없는 UTC 시각을 보냈습니다. 그대로 new Date()로 표시하면 한국에서는 어떻게 되나요?

시간대 표시가 없으면 현지 시각으로 해석되므로 실제(UTC+9)보다 9시간 이른 시각이 표시됩니다.
