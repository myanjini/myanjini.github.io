정리: 인터셉터와 자동 재발급

핵심 요약

  • 요청 인터셉터는 토큰을 붙이고, 응답 인터셉터는 401에서 한 번만 재발급한 뒤 원래 요청을 다시 보냅니다.
  • 재발급 요청은 인터셉터 없는 기본 axios로 보내고, 로그인 같은 인증 경로는 재시도에서 제외합니다.
  • 동시에 여러 401이 와도 재발급 Promise를 공유해 재발급은 한 번만 일어나게 합니다.

확인 퀴즈

여러 요청이 동시에 401을 받았을 때 재발급을 한 번만 하는 이유는 무엇인가요?

백엔드는 재발급 때 리프레시 토큰을 새로 바꾸므로 진행 중인 재발급 Promise를 공유해야 합니다.

로그인 요청(/auth/token)의 401에서 재발급을 시도하지 않는 이유는 무엇인가요?

401의 의미가 경로마다 다르므로 인증 경로는 재시도 대상에서 뺍니다.
