실습10분S4-P9-05

출처를 바꿔 가며 관찰하기

  1. S4-P9-02의 설정을 적용한 상태에서 http://localhost:5173을 열고 Network 탭에서 books?limit=3 요청을 선택합니다. Request Headers의 Origin과 Response Headers의 access-control-allow-origin을 찾아 값이 같은지 확인합니다.
  2. 개발 서버를 npm run dev -- --host 127.0.0.1로 다시 실행하고 http://127.0.0.1:5173으로 접속합니다. CORS 오류가 다시 나는 이유를 S4-P8-02의 표로 설명합니다. 확인이 끝나면 다시 npm run dev로 실행합니다.
  3. Console 탭에서 다음 코드를 실행해 사전 요청이 생기는지 Network 탭에서 확인합니다. 목록에 OPTIONS 요청이 먼저 나타나야 합니다. (응답은 인증이 없어서 401이지만, 사전 요청이 일어나는 것을 확인하는 것이 목적입니다.)
await fetch('http://127.0.0.1:8000/auth/me', { headers: { Authorization: 'Bearer test' } });
  1. 백엔드 로그에서 "method": "OPTIONS"인 요청 로그를 찾아봅니다. 이 로그는 S10의 로그 분석 화면에서도 다시 만납니다.
docker compose logs api --no-log-prefix | grep OPTIONS
  1. 실습이 끝나면 src/App.jsx에 넣은 임시 코드를 지웁니다.
