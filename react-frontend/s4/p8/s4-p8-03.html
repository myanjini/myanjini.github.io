동일 출처 정책(SOP)

동일 출처 정책(Same-Origin Policy)은 한 출처에서 실행되는 스크립트가 다른 출처의 자원을 함부로 읽지 못하게 하는 브라우저의 기본 보안 규칙입니다.

이 규칙이 왜 필요한지 상황을 떠올려 봅니다. 사용자가 사내 관리 시스템에 로그인한 상태로 다른 탭에서 악성 사이트를 열었습니다. 동일 출처 정책이 없다면 악성 사이트의 스크립트가 사내 시스템에 요청을 보내고, 브라우저에 남아 있는 로그인 정보가 함께 전송되어, 돌아온 응답(직원 목록, 내부 문서)을 그대로 읽어 공격자 서버로 보낼 수 있습니다. 동일 출처 정책은 이 마지막 단계인 응답 읽기를 막습니다.

동일 출처 정책이 막는 것과 막지 않는 것을 정확히 구분해야 합니다.

막는 것 (다른 출처일 때) 막지 않는 것
fetch, XMLHttpRequest로 받은 응답을 스크립트가 읽기 <img>, <script>, <link>, <video>로 다른 출처 자원을 불러와 표시하기
다른 출처 <iframe> 안의 DOM에 접근하기 <form>으로 다른 출처에 제출하기, 링크로 이동하기
다른 출처의 localStorage, sessionStorage 읽기 요청 자체를 서버로 보내기(단, S4-P9-01의 사전 요청 대상은 예외)

오른쪽 열이 중요합니다. 동일 출처 정책은 주로 "읽기"를 막을 뿐 "보내기"를 완전히 막지는 않습니다. S4-P8-01에서 서버 로그에 요청이 남은 이유가 이것입니다. 그래서 동일 출처 정책만으로는 다른 사이트가 사용자 몰래 요청을 보내는 공격(CSRF)을 막을 수 없으며, S9에서 별도의 대책을 다룹니다.
