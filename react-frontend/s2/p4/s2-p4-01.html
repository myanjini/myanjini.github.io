JSON

JSON(JavaScript Object Notation)은 데이터를 주고받기 위한 텍스트 형식입니다. 이름은 JavaScript에서 왔지만 Python, Java 등 거의 모든 언어가 지원합니다. 백엔드 과정에서 Pydantic 모델이 응답을 JSON으로 바꿔 보냈다면, 프론트엔드에서는 그 JSON 텍스트를 다시 JavaScript 값으로 바꿔 사용합니다.

문법 규칙

  • 값의 종류는 객체({}), 배열([]), 문자열, 숫자, 불리언(true, false), null 여섯 가지뿐입니다.
  • 객체의 키와 문자열은 반드시 큰따옴표(")로 감쌉니다. 작은따옴표는 허용되지 않습니다.
  • 마지막 항목 뒤에 쉼표를 붙일 수 없습니다.
  • 주석을 쓸 수 없습니다. (이 교안의 JSON 예시에 있는 // 주석은 설명을 위한 것이며 실제 JSON에는 넣을 수 없습니다.)

언어별 자료형 대응

JSON JavaScript Python(백엔드)
객체 {} Object dict, Pydantic 모델
배열 [] Array list
문자열 string str
숫자 number int, float
true, false boolean True, False
null null None

JSON에 없는 것들

JSON으로 데이터를 주고받을 때 자주 겪는 문제는 대부분 "JSON에 없는 자료형"에서 생깁니다.

  • 날짜와 시각: JSON에는 날짜 자료형이 없어서 "2026-11-23T06:58:12" 같은 문자열로 보냅니다. 프론트엔드에서 new Date()로 바꿔야 날짜로 다룰 수 있습니다. 특히 시간대 표시(Z, +09:00)가 없는 문자열은 브라우저가 현지 시각으로 해석하므로, 백엔드가 UTC로 저장한 값을 표시할 때 9시간이 어긋날 수 있습니다. 이 문제는 S8의 대여 화면에서 해결합니다.
  • undefined: JavaScript의 undefined는 JSON에 없습니다. 객체를 JSON으로 바꿀 때 값이 undefined인 속성은 아예 빠집니다. PATCH 요청에서 "보내지 않은 필드"와 "null로 지운 필드"가 다르게 처리되는 이유가 여기에 있습니다.
  • 아주 큰 정수: JavaScript의 number는 2의 53제곱보다 큰 정수를 정확히 표현하지 못합니다. ISBN처럼 숫자로만 된 긴 식별자를 백엔드가 문자열로 다루는 이유이기도 합니다.
