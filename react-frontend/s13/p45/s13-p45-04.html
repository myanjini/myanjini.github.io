정리: 폴링, 요청 기록, 지표 계산

핵심 요약

  • 폴링은 앞 요청이 끝난 뒤 예약하고, 탭이 보이지 않으면 쉬며, 화면을 떠나면 멈춥니다. TanStack Query의 refetchInterval이 이 규칙을 지킵니다.
  • axios 인터셉터에서 요청 시작 시각과 응답 상태를 기록하면 별도 서버 없이 브라우저가 겪은 응답 시간과 오류를 집계할 수 있습니다.
  • 지표 계산은 순수 함수로 분리해 테스트하고, 경로의 숫자는 {id}로 묶어 같은 API로 집계합니다.

확인 퀴즈

폴링을 setInterval 대신 앞 요청이 끝난 뒤 다음 요청을 예약하는 방식으로 구현하는 이유는 무엇인가요?

setInterval은 응답이 늦어도 정해진 간격마다 요청을 쌓습니다.

오류율 계산에서 4xx를 제외한 이유는 무엇인가요?

서비스 장애 지표에는 5xx와 연결 실패만 셉니다. 4xx가 급증하면 따로 살펴볼 신호입니다.
