XSS(크로스 사이트 스크립팅)

XSS는 공격자가 넣은 스크립트가 다른 사용자의 브라우저에서 실행되는 공격입니다. 예를 들어 도서 제목에 <img src=x onerror="...">를 넣어 등록했는데, 목록 화면이 이 제목을 HTML로 해석해 그린다면 목록을 연 모든 사용자의 브라우저에서 onerror의 코드가 실행됩니다. 그 코드는 해당 사이트의 출처로 실행되므로 동일 출처 정책의 보호를 받지 못합니다. 같은 출처의 sessionStorage를 읽을 수 있고, 사용자 대신 API를 호출할 수도 있습니다.

백엔드 과정 S9-P31에서는 입력과 저장 단계의 XSS 대책을 다뤘습니다. 프론트엔드는 출력 단계를 책임집니다.

React의 기본 방어

JSX의 중괄호에 넣은 값은 React가 항상 텍스트로 이스케이프합니다. <p>{book.title}</p>에 HTML 태그가 들어 있어도 태그로 해석되지 않고 글자 그대로 표시됩니다. 이 과정의 모든 화면은 이 방식으로만 데이터를 출력하므로 기본적으로 안전합니다.

React에서 위험해지는 지점

위험한 코드 이유 대책
dangerouslySetInnerHTML={{ __html: value }} 문자열을 HTML로 해석해 넣습니다. 이름 그대로 위험합니다. 쓰지 않습니다. 꼭 HTML을 보여 줘야 하면 DOMPurify로 정화한 값만 넣습니다.
element.innerHTML = value React를 거치지 않고 DOM에 HTML을 넣습니다. textContent를 쓰거나 React로 그립니다.
<a href={userUrl}>, window.location = userUrl, window.open(userUrl) javascript:로 시작하는 주소는 클릭 시 코드를 실행합니다. React 19는 href의 javascript: 주소를 차단하지만, 코드에서 직접 대입하는 경우는 막아 주지 않습니다. new URL(userUrl)로 해석해 http:, https:인지 확인합니다.
eval, new Function, 문자열을 넘긴 setTimeout 문자열을 코드로 실행합니다. 쓰지 않습니다. S11의 CSP가 이를 막습니다.

HTML을 꼭 보여 줘야 하는 경우(예: 관리자가 작성한 공지)에는 검증된 정화 라이브러리를 사용합니다.

import DOMPurify from 'dompurify'; // npm install dompurify

function Notice({ html }) {
  // 스크립트, 이벤트 속성(onerror 등), javascript: 주소를 제거한 HTML만 넣습니다.
  return <div dangerouslySetInnerHTML={{ __html: DOMPurify.sanitize(html) }} />;
}
