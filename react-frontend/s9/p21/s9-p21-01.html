의존성과 공급망 보안

프론트엔드 프로젝트는 직접 설치한 패키지 몇 개에 딸려 오는 수백 개의 간접 의존성을 포함합니다. 이 중 하나라도 취약하거나 악성으로 바뀌면 빌드 결과물에 그대로 들어갑니다. 백엔드 과정 S11-P37에서 pip-audit로 파이썬 의존성을 점검한 것처럼 다음을 실천합니다.

실천 사항 방법
알려진 취약점 점검 npm audit로 확인하고, 운영 의존성만 보려면 npm audit --omit=dev를 씁니다.
설치 결과 고정 package-lock.json을 Git에 포함하고, CI와 Docker 빌드에서는 잠금 파일 그대로 설치하는 npm ci를 씁니다(S11).
패키지 출처 확인 npm audit signatures로 레지스트리 서명을 확인합니다. 설치 전 패키지 이름의 철자를 확인합니다. 인기 패키지와 비슷한 이름의 악성 패키지(타이포스쿼팅)가 있습니다.
의존성 최소화 몇 줄로 구현할 수 있는 기능 때문에 패키지를 추가하지 않습니다.
꾸준한 갱신 GitHub Dependabot 같은 도구로 갱신 알림을 받습니다. 차트처럼 큰 라이브러리는 메이저 버전 변경 시 동작을 확인합니다.
외부 CDN 스크립트 가능하면 사용하지 않습니다. 써야 한다면 integrity 속성(SRI)으로 내용이 바뀌지 않았는지 검증합니다.
