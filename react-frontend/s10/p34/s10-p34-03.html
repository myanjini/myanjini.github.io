정리: TanStack Query로 조회 다루기

핵심 요약

  • 서버 상태는 서버에 원본이 있는 사본이므로 캐시, 중복 제거, 신선도 관리가 필요합니다.
  • useQuery는 쿼리 키로 캐시를 구분하고, 조건을 키에 넣으면 조건별로 따로 캐시됩니다.
  • 응답으로 최신 데이터를 받았다면 setQueryData로 캐시를 바로 바꿀 수 있습니다.

확인 퀴즈

목록 화면의 쿼리 키에 검색 조건을 넣는 이유는 무엇인가요?

같은 키는 같은 데이터입니다. 조건이 다르면 다른 키여야 합니다.

4xx 오류를 재시도하지 않도록 설정한 이유는 무엇인가요?

404나 422는 다시 보내도 같은 결과입니다. 일시적인 장애(연결 실패, 5xx)만 재시도합니다.
