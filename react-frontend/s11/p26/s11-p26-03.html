AWS 배포와의 연결

백엔드 과정 S13~S15에서 API를 ECR 이미지로 EC2에 배포하고, ALB로 HTTPS를 적용했습니다. 프론트엔드 이미지도 같은 방법으로 ECR에 올려 EC2에서 함께 실행할 수 있습니다. 이때 ALB는 모든 요청을 web 컨테이너로 보내고, web의 Nginx가 /api/를 내부의 api 컨테이너로 전달하는 구성이 이 교안의 Compose 구조와 가장 가깝습니다. HTTPS로 서비스하게 되면 security-headers.conf에 add_header Strict-Transport-Security "max-age=31536000" always;를 추가해 브라우저가 이후 접속을 항상 HTTPS로 하게 합니다.

정적 파일만 제공하면 되므로 S3와 CloudFront로 프론트엔드를 배포하는 방법도 널리 쓰입니다. 이 경우 화면과 API의 출처가 달라질 수 있으므로, S4의 CORS 설정을 운영 도메인 기준으로 다시 구성하거나 CloudFront에서 /api/* 경로를 ALB로 전달하도록 구성합니다.
