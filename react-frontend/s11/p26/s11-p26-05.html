정리: 도커라이징과 통합 실행

핵심 요약

  • 운영 환경은 Vite 개발 서버가 아니라 빌드 결과물을 Nginx 같은 웹 서버로 제공합니다.
  • Nginx가 정적 파일 제공과 /api/ 리버스 프록시를 함께 맡으면 화면과 API가 같은 출처가 되어 CORS가 필요 없습니다.
  • SPA는 try_files로 없는 경로에 index.html을 돌려줘야 새로고침과 직접 접속이 동작합니다.
  • 멀티 스테이지 빌드, npm ci, root가 아닌 사용자 실행으로 작고 재현 가능하며 안전한 이미지를 만듭니다.
  • 프록시 뒤의 백엔드는 신뢰할 프록시를 지정한 뒤 X-Forwarded-For를 사용해야 합니다.

확인 퀴즈

Nginx의 try_files $uri $uri/ /index.html;이 필요한 이유는 무엇인가요?

/books/7 같은 경로는 실제 파일이 없으므로 index.html을 돌려줘야 React Router가 화면을 그립니다.

운영 구성에서 CORS 설정이 필요 없는 이유는 무엇인가요?

브라우저는 localhost:8080 하나의 출처만 보므로 교차 출처 요청이 생기지 않습니다.

멀티 스테이지 Dockerfile의 최종 이미지에 들어가는 것은 무엇인가요?

빌드 단계의 결과물만 Nginx 이미지에 복사하므로 작고 안전한 이미지가 됩니다.
