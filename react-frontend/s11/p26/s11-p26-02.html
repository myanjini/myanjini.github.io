Compose로 통합 실행

백엔드 프로젝트의 compose.yaml(S8-P27)에 web 서비스를 추가합니다. S1-P2-02에서 두 프로젝트를 같은 workspace 폴더에 나란히 두었으므로 build에 상대 경로를 씁니다.

services:
  db:
    # (기존 설정 그대로)

  api:
    # (기존 설정 그대로)

  web:
    build: ../book-admin-web
    ports:
      - "8080:8080"
    depends_on:
      - api
    restart: unless-stopped

volumes:
  db-data:
  uploads:

실행하고 상태를 확인합니다.

cd book-api
docker compose up -d --build
docker compose ps

db, api, web 세 서비스가 모두 실행 중이고 web이 잠시 뒤 healthy가 되면 성공입니다. 브라우저에서 http://localhost:8080으로 접속합니다.

운영 구성에서 함께 점검할 사항

  • 이 구성에서는 브라우저가 api에 직접 접속할 필요가 없습니다. 실제 운영에서는 api 서비스의 ports 설정을 지워 외부에서 8000 포트로 바로 접속하지 못하게 하고, 모든 요청이 Nginx를 거치게 합니다. 실습 중에는 Swagger UI 확인을 위해 남겨 둬도 됩니다.
  • 백엔드는 로그인 실패 기록에 요청자의 IP를 남깁니다(S10-P34). Nginx를 거치면 백엔드가 보는 접속 IP는 Nginx 컨테이너의 주소가 됩니다. 실제 사용자의 IP를 쓰려면 Uvicorn을 --proxy-headers 옵션과 함께 실행하고 --forwarded-allow-ips에 프록시(Nginx)의 주소를 지정해, Nginx가 넘긴 X-Forwarded-For 값을 신뢰하게 해야 합니다. 신뢰할 프록시를 지정하지 않고 이 헤더를 무조건 믿으면, 공격자가 헤더를 위조해 로그인 잠금을 피할 수 있습니다.
  • 운영 환경의 CORS_ORIGINS에는 개발용 http://localhost:5173이 필요 없습니다. 같은 출처로 제공되므로 CORS 허용 목록을 비우거나 실제로 필요한 출처만 남깁니다.
