E2E 테스트

파트 목표Playwright로 실제 브라우저에서 화면 흐름을 검증하고, CI에서도 돌아가도록 API를 가로챌 수 있습니다.

E2E(End-to-End) 테스트는 실제 브라우저를 띄워 사용자가 하는 대로 주소를 열고, 입력하고, 클릭하며 화면 흐름 전체를 검증합니다. 컴포넌트 테스트가 jsdom이라는 흉내 낸 환경에서 화면 하나를 보는 것과 달리, E2E는 라우팅, 실제 CSS, 실제 네트워크 요청까지 포함합니다.

E2E는 느리고 깨지기 쉬우므로 꼭 지켜야 할 핵심 흐름 몇 개만 둡니다. 이 과정에서는 "목록에서 상세로 이동", "로그인 후 이동", "로그인하지 않으면 보호된 화면에서 로그인 화면으로"를 E2E로 지킵니다.

백엔드 처리 방식은 두 가지입니다. 실제 백엔드를 함께 띄우면 가장 사실적이지만, CI에서는 백엔드와 데이터베이스까지 준비해야 합니다. 이 과정은 Playwright의 page.route로 브라우저가 보내는 API 요청을 가로채 가짜 응답을 돌려줍니다. 사전 요청(OPTIONS)과 CORS 헤더까지 직접 응답해야 한다는 점이 MSW와 다릅니다. 실제 브라우저는 CORS를 검사하기 때문입니다.
