정리: Playwright E2E

핵심 요약

  • E2E 테스트는 실제 브라우저로 핵심 흐름만 검증하며, 개수는 적게 유지합니다.
  • page.route로 API를 가로채면 백엔드 없이도 CI에서 E2E를 돌릴 수 있으며, 이때 CORS 헤더와 사전 요청도 직접 처리합니다.
  • 실패 원인은 --headed, --ui, trace로 단계별 화면을 보며 찾습니다.

확인 퀴즈

page.route로 API를 가로챌 때 OPTIONS 요청에도 응답해야 하는 이유는 무엇인가요?

E2E는 실제 브라우저에서 돌아가므로 교차 출처 규칙이 그대로 적용됩니다.

E2E 테스트를 적게 두는 이유는 무엇인가요?

핵심 흐름만 E2E로 지키고 나머지는 빠른 단위, 컴포넌트 테스트에 맡깁니다.
