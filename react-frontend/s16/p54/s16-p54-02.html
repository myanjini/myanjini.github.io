CI 워크플로 작성과 실행

CI 워크플로를 작성합니다. workflow_call은 다음 파트의 배포 워크플로가 이 워크플로를 불러 쓸 수 있게 합니다.

.github/workflows/ci.yml
# CI: 코드가 main에 들어가기 전에 린트, 단위 테스트, 빌드, E2E 테스트를 자동으로 실행합니다.
name: CI

on:
  pull_request:
    branches: [main]
  workflow_call: # 배포 워크플로(deploy.yml)가 배포 전에 이 워크플로를 불러 씁니다.

permissions:
  contents: read

jobs:
  test:
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@v6

      - uses: actions/setup-node@v6
        with:
          node-version: 24
          cache: npm # package-lock.json을 기준으로 내려받은 패키지를 캐시합니다.

      - name: 의존성 설치
        run: npm ci

      - name: 린트
        run: npm run lint

      - name: 단위, 컴포넌트 테스트
        run: npm run test:run

      - name: 빌드
        run: npm run build

      - name: Playwright 브라우저 설치
        run: npx playwright install --with-deps chromium

      - name: E2E 테스트
        run: npm run test:e2e
        env:
          CI: true

      - name: 실패 시 E2E 보고서 보관
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-report
          path: playwright-report
          retention-days: 7

워크플로에서 볼 부분은 다음과 같습니다.

  • permissions: contents: read로 워크플로가 받는 GitHub 토큰의 권한을 읽기로 줄입니다. 필요한 권한만 주는 원칙은 CI에도 적용됩니다.
  • cache: npm은 내려받은 패키지를 캐시해 다음 실행을 빠르게 합니다.
  • E2E 테스트는 CI=true 환경에서 재시도 2회, 기존 서버 재사용 안 함으로 동작합니다(playwright.config.js).
  • 실패했을 때만 Playwright 보고서를 결과물(artifact)로 올려, 실행 화면에서 내려받아 원인을 볼 수 있게 합니다.

GitHub에 저장소를 만들고 실행해 봅니다.

  1. GitHub에서 react-frontend 저장소를 만들고, 로컬 프로젝트를 연결해 main 브랜치를 올립니다.
git remote add origin https://github.com/<계정>/react-frontend.git
git push -u origin main
  1. 기능 브랜치를 만들고 일부러 테스트를 깨뜨려 풀 리퀘스트를 엽니다.
git switch -c ci-test
# src/utils/date.js의 formatDate가 빈 문자열 대신 '없음'을 돌려주게 고칩니다.
git commit -am "CI 실패 확인용 변경"
git push -u origin ci-test
  1. GitHub의 풀 리퀘스트 화면에서 CI가 실행되고 실패하는 것을 확인합니다. "Details"를 눌러 어느 스텝의 어느 테스트가 실패했는지 찾습니다.
  2. 변경을 되돌려 다시 push하면 CI가 다시 실행되어 통과합니다.
  3. 저장소의 Settings > Branches에서 main에 규칙을 추가합니다. "Require a pull request before merging"과 "Require status checks to pass"를 켜고, 필수 검사로 test를 고릅니다. 이제 CI를 통과하지 않은 코드는 main에 들어갈 수 없습니다.
