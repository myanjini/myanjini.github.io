정리: CI: 테스트 자동화

핵심 요약

  • GitHub Actions는 워크플로, 트리거, 잡, 러너, 스텝으로 구성되며 .github/workflows의 YAML로 정의합니다.
  • CI는 풀 리퀘스트마다 린트, 단위 테스트, 빌드, E2E를 실행하고, 브랜치 보호 규칙으로 통과한 코드만 병합되게 합니다.
  • 워크플로의 토큰 권한은 필요한 만큼만 줍니다.

확인 퀴즈

풀 리퀘스트에서 CI가 실패한 코드가 main에 병합되지 않게 하려면 무엇을 설정해야 하나요?

필수 상태 검사로 지정한 잡이 통과해야 병합 버튼이 활성화됩니다.

GitHub Actions에서 같은 러너에서 실행되는 스텝의 묶음을 무엇이라고 하나요?

워크플로는 하나 이상의 잡으로, 잡은 여러 스텝으로 이루어집니다.
