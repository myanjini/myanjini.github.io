정리: S3 정적 웹 호스팅

핵심 요약

  • S3 정적 웹 호스팅은 버킷에 빌드 결과물을 올려 서버 없이 프론트엔드를 서비스하며, 인덱스와 오류 문서를 index.html로 지정합니다.
  • S3에는 프록시가 없어 화면과 API가 다른 출처가 되므로, 절대 API 주소로 빌드하고 백엔드 CORS에 S3 주소를 등록합니다.
  • 실제 서비스에서는 HTTPS, 보안 헤더, 비공개 버킷, 캐시를 위해 S3 앞에 CloudFront를 둡니다.

확인 퀴즈

S3 웹사이트에 배포한 화면이 API를 부를 때 CORS 설정이 필요한 이유는 무엇인가요?

S3에는 /api를 넘겨 주는 프록시가 없어 브라우저가 백엔드로 교차 출처 요청을 보냅니다.

CloudFront를 S3 앞에 두는 이유로 알맞지 않은 것은 무엇인가요?

환경 변수는 여전히 빌드 시점에 결정됩니다.
