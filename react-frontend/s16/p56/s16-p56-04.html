정리: CD: OIDC, 자동 배포, 롤백

핵심 요약

  • OIDC를 쓰면 GitHub Actions가 장기 액세스 키 없이 실행할 때마다 임시 자격 증명을 받습니다.
  • 배포 역할의 신뢰 정책은 저장소와 환경을 제한하고, 권한 정책은 해당 버킷의 쓰기와 지우기만 허용합니다.
  • 배포 워크플로는 CI 통과 후에만 실행되며, 커밋을 지정한 수동 실행으로 롤백합니다.

확인 퀴즈

GitHub Actions에서 AWS에 OIDC로 인증할 때의 장점은 무엇인가요?

유출될 장기 비밀이 없고, 신뢰 정책으로 쓸 수 있는 저장소와 환경을 제한합니다.

배포 워크플로에서 id-token: write 권한이 필요한 이유는 무엇인가요?

S3 쓰기 권한은 AWS 역할이 주고, 이 권한은 역할을 맡는 데 필요한 토큰을 받기 위한 것입니다.
