정리: XSS, 토큰 보호, CSRF

핵심 요약

  • 프론트엔드 코드는 공개되고 조작될 수 있으므로 보안 결정은 백엔드가 하고, 프론트엔드는 사용자의 브라우저를 보호합니다.
  • React의 JSX 출력은 XSS를 기본으로 막지만, dangerouslySetInnerHTML, innerHTML, 사용자 입력 주소로의 이동은 직접 관리해야 합니다.
  • 토큰 저장 위치는 피해 범위를 줄이는 수단이며, 헤더 기반 토큰 전송은 CSRF에 강합니다.

확인 퀴즈

React 화면에서 XSS가 일어날 수 있는 코드는 무엇인가요?

JSX 중괄호 출력은 이스케이프되지만 dangerouslySetInnerHTML은 문자열을 HTML로 해석합니다.

토큰을 Authorization 헤더로 보내는 구조가 CSRF에 강한 이유는 무엇인가요?

쿠키와 달리 Authorization 헤더는 자동 전송되지 않으므로 다른 사이트가 사용자 토큰으로 요청할 수 없습니다.
