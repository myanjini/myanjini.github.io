XSS 동작 확인

1) XSS 동작 확인

임시 컴포넌트를 만들어 이스케이프와 dangerouslySetInnerHTML의 차이를 확인합니다. 확인이 끝나면 반드시 지웁니다. 아래 문자열은 이미지 로딩 오류 시 같은 출처의 sessionStorage를 읽어 출력하는 코드로, XSS가 토큰을 읽을 수 있음을 보여 줍니다.

// src/pages/XssLab.jsx (실습 후 삭제)
const payload = `<img src="x" onerror="console.log('읽힘:', sessionStorage.getItem('book-admin.refresh'))">`;

export default function XssLab() {
  return (
    <section>
      <h2>1. JSX 출력 (안전)</h2>
      <p>{payload}</p>
      <h2>2. dangerouslySetInnerHTML (위험)</h2>
      <div dangerouslySetInnerHTML={{ __html: payload }} />
    </section>
  );
}

App.jsx에 <Route path="xss" element={<XssLab />} />를 잠시 추가하고 로그인한 상태로 /xss를 엽니다. 1번은 글자 그대로 보이고, 2번은 Console에 리프레시 토큰이 출력됩니다. 확인 후 파일과 라우트를 지웁니다. 같은 종류의 인라인 코드가 CSP로 차단되는 모습은 S15에서 Nginx로 보안 헤더를 적용한 뒤 확인합니다.
