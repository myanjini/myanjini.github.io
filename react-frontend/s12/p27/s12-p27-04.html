확장 과제

학습한 내용을 응용해 다음 과제에 도전합니다. 난이도 순서로 배치했습니다.

  1. 저자 관리 화면. 관리자 전용으로 저자 목록과 등록 화면을 만듭니다. POST /authors의 409 DUPLICATE_AUTHOR, 일반 사용자의 403을 처리합니다. 저자 삭제(DELETE /authors/{author_id})에서 도서가 남아 있으면 409 AUTHOR_HAS_BOOKS를 안내합니다.
  2. 저자별 도서 목록. 도서 상세의 저자 이름을 누르면 GET /authors/{author_id}/books 결과를 보여 주는 화면으로 이동합니다.
  3. 표지 미리보기. 업로드 전에 URL.createObjectURL(file)로 고른 이미지를 미리 보여 주고, 화면을 떠날 때 URL.revokeObjectURL로 정리합니다.
  4. 대시보드 기간 필터. 로그 분석에 시작, 끝 시각 필터를 추가하고, 선택한 구간의 지표만 다시 계산합니다. 필터는 차트 위 한 줄에 배치합니다.
  5. 대시보드 경보. 오류율이나 p95 응답 시간이 기준값을 넘으면 KPI 카드를 주의 상태로 표시하고, 기준값을 화면에서 바꿀 수 있게 합니다. 일시적인 튐에 경보가 울리지 않도록 "연속 3회 초과" 같은 조건을 설계합니다.
  6. 서버 상태 관리 라이브러리. TanStack Query를 도입해 S5-P12-05의 반복 코드(로딩, 오류, 취소)를 대체하고, 대여 후 목록을 자동으로 다시 불러오도록 캐시 무효화를 적용합니다.
  7. HttpOnly 쿠키 기반 리프레시 토큰. 백엔드가 리프레시 토큰을 HttpOnly; Secure; SameSite=Strict 쿠키로 발급하고, /auth/refresh가 쿠키에서 토큰을 읽도록 바꿉니다. 프론트엔드는 withCredentials를 설정하고 sessionStorage 저장을 제거합니다. 백엔드 CORS의 allow_credentials 설정과 CSRF 대책을 함께 설계합니다(S9).
  8. 통계 API와 Grafana. 백엔드에 도서, 대여 현황 통계 API를 추가해 대시보드에 업무 지표를 늘리고, 같은 데이터를 Grafana의 PostgreSQL 데이터 소스로 연결해 직접 만든 대시보드와 비교합니다.
