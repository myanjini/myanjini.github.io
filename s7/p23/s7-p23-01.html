fixture와 테스트 격리

이 파트의 학습 목표fixture와 의존성 재정의로 테스트를 서로 격리할 수 있습니다.

좋은 테스트는 언제, 어디서, 몇 번을 실행해도 같은 결과를 냅니다. 이를 위해 테스트를 서로 떼어 놓는 방법과, 그 도구인 fixture를 배웁니다.

테스트 격리

앞 파트의 테스트는 개발용 데이터베이스를 함께 썼기 때문에 서로 영향을 주었습니다.

문제앞 파트에서 본 모습
앞선 실행이 남긴 데이터두 번째 실행에서 같은 ISBN 때문에 409
미리 있어야 하는 데이터user1과 1번 저자가 없는 컴퓨터에서는 실패
개발 데이터 오염실행할 때마다 "테스트 도서"가 쌓임
느슨한 검증도서가 몇 권 있을지 몰라 total >= 0으로만 검사

해결 방법은 테스트마다 빈 데이터베이스를 새로 만들고, 테스트가 끝나면 버리는 것입니다. 이렇게 테스트끼리 영향을 주지 않게 하는 것을 테스트 격리라고 합니다. 격리된 테스트는 실행 순서를 바꿔도, 하나만 골라 실행해도 결과가 같습니다.

fixture

fixture는 테스트에 필요한 준비물을 만들어 주는 함수입니다. 테스트 함수의 매개변수에 fixture 이름을 적으면 pytest가 테스트 전에 그 함수를 실행해 결과를 넣어 줍니다. 2일차의 의존성 주입과 같은 생각입니다.

import pytest


@pytest.fixture
def numbers():
    print("준비")       # 테스트 전에 실행
    yield [1, 2, 3]     # 이 값이 테스트에 들어갑니다.
    print("정리")       # 테스트가 끝나면 실행(실패해도 실행)


def test_sum(numbers):  # 매개변수 이름 = fixture 이름
    assert sum(numbers) == 6

yield 앞은 준비, 뒤는 정리입니다. get_db가 세션을 열고 닫던 것과 같은 모양입니다. fixture는 다른 fixture를 매개변수로 받을 수도 있어, 준비물을 쌓아 올릴 수 있습니다.

fixture의 범위

scope몇 번 만드나요어디에 쓰나요
function(기본값)테스트 함수마다 새로데이터베이스처럼 테스트가 바꾸는 준비물. 이 과정은 모두 이 범위를 씁니다.
module테스트 파일마다 한 번만드는 데 오래 걸리고 테스트가 바꾸지 않는 준비물
sessionpytest 실행 전체에서 한 번외부 서버 연결처럼 가장 무거운 준비물

범위를 넓히면 빨라지지만 테스트끼리 준비물을 함께 쓰게 되어 격리가 약해집니다. 처음에는 기본값(function)을 쓰고, 정말 느릴 때만 넓힙니다.

conftest.py

여러 테스트 파일이 함께 쓰는 fixture는 tests/conftest.py에 둡니다. pytest가 이 파일을 자동으로 읽으므로 테스트 파일에서 따로 가져오지 않아도 됩니다.
