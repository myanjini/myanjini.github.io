테스트용 DB 연결

앱은 get_db로 개발용 데이터베이스에 연결합니다. 테스트할 때만 이 연결을 테스트 전용 데이터베이스로 바꿔 끼우는 방법을 강사 화면으로 봅니다.

의존성 바꿔 끼우기

FastAPI 앱에는 app.dependency_overrides라는 딕셔너리가 있습니다. 여기에 {원래 의존성: 대신 쓸 함수}를 넣으면, 모든 경로 함수가 원래 의존성 대신 그 함수를 씁니다. 코드를 한 줄도 고치지 않고 데이터베이스만 바꿀 수 있는 것은 2일차에 세션을 Depends(get_db)로 받게 만들어 두었기 때문입니다.

app.dependency_overrides[get_db] = override_get_db  # 이제 get_db 대신 override_get_db가 불립니다.
...
app.dependency_overrides.clear()                     # 테스트가 끝나면 원래대로

메모리 SQLite

주소를 sqlite://로만 적으면 파일 없이 메모리 안에만 데이터베이스를 만듭니다. 빠르고, 테스트가 끝나면 흔적이 남지 않습니다. 다만 메모리 데이터베이스는 연결마다 따로 생기므로, StaticPool로 연결을 하나만 만들어 모든 세션이 같은 데이터베이스를 보게 합니다.

engine = create_engine("sqlite://", connect_args={"check_same_thread": False}, poolclass=StaticPool)

Alembic 대신 create_all을 쓰는 이유

테스트에서는 모델로 바로 테이블을 만드는 Base.metadata.create_all을 씁니다. 테스트마다 리비전을 처음부터 적용하면 느리기 때문입니다. 대신 리비전과 모델이 어긋나는 실수는 테스트가 잡지 못하므로, 리비전을 만든 뒤에는 2일차처럼 직접 열어 보는 습관을 계속 지킵니다.

테스트 전용 설정

.env는 Git에 올리지 않으므로 다른 사람의 컴퓨터나 CI 서버에는 없습니다. 그러면 SECRET_KEY가 없어 앱을 불러오는 순간 오류가 납니다. 그래서 conftest.py 맨 위에서 앱을 불러오기 전에 환경 변수로 테스트용 키를 넣습니다. 환경 변수는 .env보다 먼저 쓰이므로 내 컴퓨터에서도 같은 키로 테스트합니다. 이 키는 테스트에서만 쓰이므로 코드에 적어도 괜찮습니다.

conftest.py 전체

tests/conftest.py
import os

# app을 불러오기 전에 테스트용 비밀 키를 넣습니다. 환경 변수는 .env보다 먼저 쓰입니다.
# .env가 없는 CI 서버에서도 테스트가 돌아가게 하려는 것입니다.
os.environ["SECRET_KEY"] = "test-secret-key-only-for-pytest-0123456789"

import pytest
from fastapi.testclient import TestClient
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker
from sqlalchemy.pool import StaticPool

from app.database import Base, get_db
from app.main import app
from app.models import Author

# 메모리 안에만 만드는 SQLite. 파일이 생기지 않고, 연결을 하나만 써서 테이블을 함께 봅니다.
engine = create_engine("sqlite://", connect_args={"check_same_thread": False}, poolclass=StaticPool)
TestingSessionLocal = sessionmaker(bind=engine, autoflush=False)


@pytest.fixture
def db_session():
    """테스트마다 빈 테이블을 만들고, 테스트가 끝나면 모두 지웁니다."""
    Base.metadata.create_all(bind=engine)
    session = TestingSessionLocal()
    yield session
    session.close()
    Base.metadata.drop_all(bind=engine)


@pytest.fixture
def client(db_session):
    """테스트용 데이터베이스를 쓰는 TestClient"""

    def override_get_db():
        session = TestingSessionLocal()
        try:
            yield session
        except Exception:
            session.rollback()
            raise
        finally:
            session.close()

    app.dependency_overrides[get_db] = override_get_db  # get_db 대신 이 함수를 쓰게 합니다.
    yield TestClient(app)
    app.dependency_overrides.clear()  # 다른 테스트에 영향을 주지 않도록 원래대로 돌립니다.


@pytest.fixture
def author_id(db_session):
    """테스트용 저자. API를 거치지 않고 데이터베이스에 바로 넣습니다."""
    author = Author(name="테스트 저자")
    db_session.add(author)
    db_session.commit()
    return author.id


@pytest.fixture
def auth_headers(client):
    """가입하고 로그인한 사용자의 Authorization 헤더"""
    client.post("/auth/signup", json={"email": "tester@example.com", "password": "test-pass-123"})
    response = client.post("/auth/token", data={"username": "tester@example.com", "password": "test-pass-123"})
    return {"Authorization": f"Bearer {response.json()['access_token']}"}

fixture가 쌓이는 모습

db_session은 한 테스트 안에서 한 번만 만들어집니다. 여러 fixture가 같은 fixture를 받아도 같은 것을 나눠 씁니다. 테스트가 끝나면 db_session의 yield 뒤가 실행되어 모든 테이블을 지우므로, 다음 테스트는 다시 빈 데이터베이스에서 시작합니다.
