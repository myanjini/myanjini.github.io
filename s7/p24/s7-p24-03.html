커버리지 측정

테스트를 20개 썼는데, 코드의 어디까지 시험했을까요? 테스트가 실행한 줄과 실행하지 않은 줄을 세어 주는 커버리지를 측정합니다.

커버리지 측정

pip install pytest-cov
pytest --cov=app --cov-report=term-missing

--cov=app은 app 폴더의 코드를 측정하라는 뜻이고, --cov-report=term-missing은 실행되지 않은 줄 번호까지 터미널에 보여 달라는 뜻입니다. 결과는 다음과 비슷합니다(빈 파일은 줄였습니다).

보고서 읽기

파일낮은 이유어떻게 볼까요
services/loans.py 29%대여 테스트를 아직 쓰지 않았습니다.가장 먼저 채울 곳입니다. 트랜잭션과 권한 검사가 모두 들어 있는 중요한 코드입니다.
services/covers.py 48%업로드 테스트가 없습니다.파일을 다루므로 테스트용 임시 폴더가 필요합니다.
routers/authors.py 48%저자 API를 거치지 않고 저자를 데이터베이스에 바로 넣었습니다.필요하면 저자 API 테스트를 더합니다.
database.py 53%테스트에서는 get_db를 바꿔 끼웠으므로 원래 get_db는 실행되지 않습니다.의도한 결과입니다.
make_admin.py 0%명령줄 도구라 API 테스트가 부르지 않습니다.의도한 결과입니다.

HTML 보고서

pytest --cov=app --cov-report=html

htmlcov/index.html을 브라우저로 열면 파일별로 코드를 보여 주며, 실행되지 않은 줄을 붉게 칠해 줍니다. 어떤 if 분기가 시험되지 않았는지 한눈에 보입니다. htmlcov 폴더와 .coverage 파일은 실행할 때마다 생기는 결과물이므로 .gitignore에 추가합니다.

.gitignore
# 테스트 실행 결과
.pytest_cache/
.coverage
htmlcov/

커버리지 100%가 목표는 아닙니다

커버리지는 "실행되었는가"만 셉니다. 어떤 줄이 실행되었더라도 그 결과를 assert로 확인하지 않았다면 시험한 것이 아닙니다. 반대로 make_admin.py처럼 테스트할 가치가 낮은 코드도 있습니다. 숫자를 올리는 것보다 중요한 규칙과 오류 분기가 빠지지 않았는지 찾는 도구로 씁니다. 실무에서는 80% 안팎을 기준으로 삼는 팀이 많습니다.
