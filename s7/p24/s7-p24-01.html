인증 흐름 테스트 전략

이 파트의 학습 목표인증이 필요한 API를 테스트하고 커버리지로 빠진 부분을 찾을 수 있습니다.

인증과 권한을 시험하려면 서로 다른 사용자가 여럿 필요합니다. 필요할 때마다 사용자를 만들어 주는 fixture를 설계합니다.

무엇을 시험하나요

3일차 시험 표를 떠올리면 시험할 목록이 나옵니다. 정상 흐름만이 아니라 막혀야 할 요청이 정말 막히는지 확인하는 것이 인증 테스트의 핵심입니다.

사용자를 만들어 주는 함수를 주는 fixture

앞 파트의 auth_headers는 정해진 사용자 한 명만 만듭니다. 테스트마다 필요한 사용자 수와 역할이 다르므로, 이번에는 사용자를 만드는 함수를 돌려주는 fixture를 만듭니다. 이런 fixture를 팩토리(factory) fixture라고 부릅니다.

tests/conftest.py
@pytest.fixture
def make_user(client, db_session):
    """사용자를 만들고 로그인해 Authorization 헤더를 돌려주는 함수를 줍니다."""

    def _make_user(email: str, role: str = "user") -> dict:
        password = "test-pass-123"
        client.post("/auth/signup", json={"email": email, "password": password})
        if role != "user":
            user = db_session.scalar(select(User).where(User.email == email))
            user.role = role
            db_session.commit()
        response = client.post("/auth/token", data={"username": email, "password": password})
        return {"Authorization": f"Bearer {response.json()['access_token']}"}

    return _make_user


@pytest.fixture
def auth_headers(make_user):
    """일반 사용자 한 명의 Authorization 헤더"""
    return make_user("tester@example.com")
코드하는 일
_make_user(email, role)가입, 필요하면 역할 변경, 로그인까지 하고 헤더를 돌려줍니다. 테스트 안에서 원하는 만큼 부를 수 있습니다.
db_session으로 역할 변경관리자를 만드는 API는 없습니다(S5-P17). 3일차에 make_admin 도구로 데이터베이스를 직접 고쳤던 것처럼, 테스트도 데이터베이스를 직접 고칩니다.
