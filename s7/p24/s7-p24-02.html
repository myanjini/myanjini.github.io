인증 테스트 작성

인증과 권한 테스트를 작성합니다. 같은 모양의 테스트를 값만 바꿔 여러 번 실행하는 parametrize도 함께 씁니다.

실습 목표사용자별 헤더를 준비하는 fixture로 401, 403, 토큰 재발급 테스트를 작성할 수 있습니다.

  1. conftest.py 고치기

    가져오기 두 줄을 고치고, 맨 아래의 auth_headers를 앞 페이지의 make_user와 새 auth_headers로 바꿉니다.

    tests/conftest.py
    from sqlalchemy import create_engine, select

from app.models import Author, User

    바꾼 뒤 pytest를 실행해 도서 테스트 10개가 그대로 통과하는지 먼저 확인합니다.

  2. 값만 다른 테스트를 하나로: parametrize

    "토큰 없음"과 "위조한 토큰"은 보내는 헤더와 기대하는 오류 코드만 다르고 나머지는 같습니다. 이럴 때 @pytest.mark.parametrize로 값 목록을 주면 pytest가 값마다 테스트를 한 번씩 실행합니다.

    @pytest.mark.parametrize("headers, code", [
    ({}, "NOT_AUTHENTICATED"),                                     # 헤더 없음
    ({"Authorization": "Bearer abc.def.ghi"}, "INVALID_TOKEN"),    # 위조한 토큰
])
def test_create_book_without_valid_token_returns_401(client, author_id, headers, code):
    ...

    실행 결과에는 test_create_book_without_valid_token_returns_401[headers0-NOT_AUTHENTICATED]처럼 값마다 따로 표시됩니다.

  3. 인증 테스트 작성

    tests/test_auth.py를 만듭니다. 아래 표의 테스트를 먼저 직접 써 보고, 막히면 펼쳐 봅니다.

    테스트 이름시험할 내용
    test_signup_does_not_return_password가입 응답에 password와 hashed_password가 없다.
    test_signup_with_duplicate_email_returns_409대소문자만 다른 이메일로 다시 가입하면 409
    test_login_with_wrong_password_returns_401틀린 비밀번호로 로그인하면 401, INVALID_CREDENTIALS
    test_me_with_token토큰으로 /auth/me를 부르면 내 이메일
    test_create_book_without_valid_token_returns_401위의 parametrize 테스트
    test_update_others_book_returns_403다른 사람이 수정하면 403
    test_admin_can_update_others_book관리자는 수정할 수 있음
    test_refresh_token_can_be_used_only_once첫 재발급은 200이고 새 리프레시 토큰을 받으며, 같은 토큰으로 두 번째는 401
    test_logout_blocks_refresh로그아웃 204 뒤에 재발급하면 401
    tests/test_auth.py 전체 펼치기
    tests/test_auth.py
    import pytest

from tests.helpers import create_book


def test_signup_does_not_return_password(client):
    response = client.post("/auth/signup", json={"email": "new@example.com", "password": "test-pass-123"})
    assert response.status_code == 201
    body = response.json()
    assert body["email"] == "new@example.com"
    assert "password" not in body and "hashed_password" not in body


def test_signup_with_duplicate_email_returns_409(client):
    client.post("/auth/signup", json={"email": "dup@example.com", "password": "test-pass-123"})
    response = client.post("/auth/signup", json={"email": "DUP@example.com", "password": "test-pass-123"})
    assert response.status_code == 409


def test_login_with_wrong_password_returns_401(client, make_user):
    make_user("user1@example.com")
    response = client.post("/auth/token", data={"username": "user1@example.com", "password": "wrong-pass"})
    assert response.status_code == 401
    assert response.json()["code"] == "INVALID_CREDENTIALS"


def test_me_with_token(client, auth_headers):
    response = client.get("/auth/me", headers=auth_headers)
    assert response.status_code == 200
    assert response.json()["email"] == "tester@example.com"


@pytest.mark.parametrize("headers, code", [
    ({}, "NOT_AUTHENTICATED"),                                     # 헤더 없음
    ({"Authorization": "Bearer abc.def.ghi"}, "INVALID_TOKEN"),    # 위조한 토큰
])
def test_create_book_without_valid_token_returns_401(client, author_id, headers, code):
    response = client.post("/books", json={"title": "x", "author_id": author_id, "price": 1}, headers=headers)
    assert response.status_code == 401
    assert response.json()["code"] == code


def test_update_others_book_returns_403(client, make_user, author_id):
    owner = make_user("owner@example.com")
    other = make_user("other@example.com")
    book = create_book(client, owner, author_id)
    response = client.patch(f"/books/{book['id']}", json={"price": 1}, headers=other)
    assert response.status_code == 403


def test_admin_can_update_others_book(client, make_user, author_id):
    owner = make_user("owner@example.com")
    admin = make_user("admin@example.com", role="admin")
    book = create_book(client, owner, author_id)
    response = client.patch(f"/books/{book['id']}", json={"price": 1}, headers=admin)
    assert response.status_code == 200


def test_refresh_token_can_be_used_only_once(client, make_user):
    make_user("user1@example.com")
    tokens = client.post("/auth/token", data={"username": "user1@example.com", "password": "test-pass-123"}).json()

    first = client.post("/auth/refresh", json={"refresh_token": tokens["refresh_token"]})
    assert first.status_code == 200
    assert first.json()["refresh_token"] != tokens["refresh_token"]

    second = client.post("/auth/refresh", json={"refresh_token": tokens["refresh_token"]})
    assert second.status_code == 401


def test_logout_blocks_refresh(client, make_user):
    make_user("user1@example.com")
    tokens = client.post("/auth/token", data={"username": "user1@example.com", "password": "test-pass-123"}).json()
    assert client.post("/auth/logout", json={"refresh_token": tokens["refresh_token"]}).status_code == 204
    response = client.post("/auth/refresh", json={"refresh_token": tokens["refresh_token"]})
    assert response.status_code == 401

  5. 테스트가 정말 잡아내는지 확인

    테스트가 항상 통과하기만 한다면 정말 검사하고 있는지 알 수 없습니다. app/services/books.py의 check_can_modify에서 raise 줄 앞에 return을 넣어 권한 검사를 일부러 망가뜨리고 실행해 봅니다.

    def check_can_modify(book: Book, user: User) -> None:
    if user.role == "admin" or book.owner_id == user.id:
        return
    return  # 일부러 망가뜨림
    raise AppError(403, "FORBIDDEN", "이 도서를 수정하거나 삭제할 권한이 없습니다.")

    test_update_others_book_returns_403이 assert 200 == 403으로 실패하면 테스트가 제 역할을 하는 것입니다. 넣었던 줄을 지웁니다.
