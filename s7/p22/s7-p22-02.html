테스트가 필요한 이유

테스트 코드를 쓰는 데도 시간이 듭니다. 그 시간을 들일 만한 이유와, 테스트의 종류, 그리고 모든 테스트가 따르는 기본 모양을 배웁니다.

테스트가 필요한 이유

이유설명
고친 곳이 아닌 곳이 망가집니다어제 get_db에 rollback을 넣었을 때, 이 변경이 회원가입에는 영향이 없을까요? 사람이 매번 모든 기능을 다시 확인할 수는 없습니다. 이미 되던 기능이 새 변경 때문에 깨지는 것을 회귀(regression)라고 하며, 자동 테스트가 이것을 잡아 줍니다.
고칠 용기가 생깁니다테스트가 있으면 구조를 바꾸는 작업(어제의 계층 분리 같은)을 하고 나서 명령 한 번으로 "동작은 그대로인가"를 확인할 수 있습니다.
살아 있는 설명서가 됩니다test_return_others_loan_returns_403라는 테스트 이름만 봐도 "남의 대여를 반납하면 403"이라는 규칙을 알 수 있습니다.

단위 테스트와 통합 테스트

종류무엇을 시험하나요이 과정의 예특징
단위 테스트함수나 클래스 하나를 따로 떼어 시험합니다.hash_password가 원문과 다른 값을 만드는가빠르고, 실패하면 원인이 어디인지 바로 압니다.
통합 테스트여러 부분이 함께 동작하는 것을 시험합니다.POST /books로 등록하면 데이터베이스에 저장되고 201이 오는가실제 사용에 가깝지만 조금 느리고, 실패하면 원인을 찾아야 합니다.

API 서버에서는 요청부터 데이터베이스까지 한 번에 지나가는 통합 테스트가 가장 쓸모 있는 경우가 많습니다. 이 과정의 테스트도 대부분 FastAPI의 TestClient로 API를 호출하는 통합 테스트입니다. 계산이 복잡한 함수처럼 따로 확인할 가치가 있는 곳에는 단위 테스트를 더합니다.

준비, 실행, 검증

모든 테스트는 세 부분으로 이루어집니다. 영어 첫 글자를 따서 AAA(Arrange, Act, Assert) 패턴이라고도 합니다.

def test_hash_is_not_plain_password():
    # 준비: 시험에 필요한 값과 상태를 만듭니다.
    password = "practice-pass-1"
    # 실행: 시험할 동작을 한 번 합니다.
    hashed = hash_password(password)
    # 검증: 결과가 기대한 대로인지 확인합니다.
    assert hashed != password
    assert hashed.startswith("$argon2id$")

assert 조건은 Python 문법으로, 조건이 거짓이면 그 자리에서 테스트를 실패시킵니다. 테스트 하나는 한 가지 동작만 시험하는 것이 좋습니다. 실패했을 때 이름만 보고도 무엇이 깨졌는지 알 수 있기 때문입니다.
