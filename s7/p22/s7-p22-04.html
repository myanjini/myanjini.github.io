CRUD 테스트 작성

도서 등록, 조회, 수정, 삭제를 테스트로 적습니다. 다 쓰고 나면 테스트를 두 번 실행해 보는데, 두 번째에 무슨 일이 일어나는지 잘 봐 둡니다.

실습 목표TestClient로 인증이 필요한 CRUD API의 테스트를 작성하고 실행할 수 있습니다.

  1. 설치와 설정

    pip install pytest를 실행하고, 앞 페이지대로 pytest.ini, tests/__init__.py(빈 파일), tests/test_security.py, tests/test_books.py를 만듭니다. pytest -v로 5개가 통과하는지 확인합니다.

  2. 도우미 함수 추가

    도서 등록, 수정, 삭제는 로그인해야 합니다. 테스트마다 로그인 코드를 반복하지 않도록 도우미 함수를 만듭니다. 지금은 개발용 데이터베이스(books.db)에 있는 user1과 1번 저자를 그대로 씁니다.

    tests/test_books.py
    def login(email: str = "user1@example.com", password: str = "practice-pass-1") -> dict:
    """로그인해 Authorization 헤더를 만듭니다. 개발용 데이터베이스의 user1을 씁니다."""
    response = client.post("/auth/token", data={"username": email, "password": password})
    assert response.status_code == 200
    return {"Authorization": f"Bearer {response.json()['access_token']}"}


def create_book(headers: dict, **fields) -> dict:
    """테스트에 쓸 도서를 등록하고 응답 본문을 돌려줍니다."""
    data = {"title": "테스트 도서", "author_id": 1, "price": 10000} | fields
    response = client.post("/books", json=data, headers=headers)
    assert response.status_code == 201
    return response.json()

    {...} | fields는 두 딕셔너리를 합치는 문법으로, 기본값에 fields로 받은 값을 덮어씁니다. create_book(headers, title="조회 테스트")처럼 필요한 항목만 바꿔 쓸 수 있습니다.

  3. CRUD 테스트 작성

    먼저 아래 테스트 이름과 설명만 보고 직접 작성해 봅니다. 막히면 펼쳐 봅니다.

    테스트 이름시험할 내용
    test_create_bookISBN 9790000000017, 재고 2로 등록하면 201이고, 응답의 제목, 재고, 저자 번호가 보낸 값과 같다.
    test_get_book등록한 도서를 번호로 조회하면 200이고 제목이 같다.
    test_update_book가격을 20000으로 수정하면 200이고, 다시 조회해도 20000이다.
    test_delete_book삭제하면 204이고, 다시 조회하면 404다.
    테스트 코드 펼치기
    tests/test_books.py
    def test_create_book():
    # 준비
    headers = login()
    data = {"title": "테스트 도서", "author_id": 1, "price": 15000, "isbn": "9790000000017", "stock": 2}
    # 실행
    response = client.post("/books", json=data, headers=headers)
    # 검증
    assert response.status_code == 201
    body = response.json()
    assert body["title"] == "테스트 도서"
    assert body["stock"] == 2
    assert body["author"]["id"] == 1
    assert body["owner_id"] is not None


def test_get_book():
    book = create_book(login(), title="조회 테스트")
    response = client.get(f"/books/{book['id']}")
    assert response.status_code == 200
    assert response.json()["title"] == "조회 테스트"


def test_update_book():
    headers = login()
    book = create_book(headers)
    response = client.patch(f"/books/{book['id']}", json={"price": 20000}, headers=headers)
    assert response.status_code == 200
    assert response.json()["price"] == 20000
    # 다시 조회해도 바뀐 값이 나와야 합니다.
    assert client.get(f"/books/{book['id']}").json()["price"] == 20000


def test_delete_book():
    headers = login()
    book = create_book(headers)
    response = client.delete(f"/books/{book['id']}", headers=headers)
    assert response.status_code == 204
    assert client.get(f"/books/{book['id']}").status_code == 404

    질문. 두 번째 실행에서 test_create_book이 409로 실패한 이유는 무엇일까요? 이 테스트 방식에 어떤 문제가 더 있을까요?

    예시 답안 보기

    첫 번째 실행에서 ISBN 9790000000017인 도서가 개발용 데이터베이스에 저장되었고, 두 번째 실행에서 같은 ISBN으로 등록하려 해서 중복 409가 났습니다. 테스트 결과가 코드가 아니라 데이터베이스에 무엇이 남아 있는지에 따라 달라진 것입니다.

    문제는 더 있습니다. 실행할 때마다 개발용 데이터베이스에 "테스트 도서"가 쌓입니다. user1이나 1번 저자가 없는 컴퓨터(동료의 PC, CI 서버)에서는 처음부터 실패합니다. test_list_books에서 total이 몇 개일지 미리 알 수 없어 >= 0처럼 느슨하게 검증할 수밖에 없었던 것도 같은 이유입니다. 다음 파트에서 테스트마다 깨끗한 데이터베이스를 쓰게 만들어 해결합니다.
