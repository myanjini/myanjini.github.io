AWS 보안 점검 항목

이 파트의 학습 목표AWS 보안 점검 항목에 따라 내 배포 환경을 점검하고 조치할 수 있습니다.

5일차와 6일차에는 코드의 보안약점을 점검했습니다. 클라우드에 배포한 서비스는 코드가 안전해도 설정 하나 때문에 뚫릴 수 있습니다. 실제 클라우드 사고의 상당수는 공개된 버킷, 너무 넓은 권한, 열린 포트 같은 "설정 실수"에서 시작합니다. 이번 파트에서는 AWS 설정을 점검 항목에 따라 확인합니다.

다섯 가지 점검 영역

영역확인할 것흔한 실수이 과정에서 한 조치
계정루트 사용자를 쓰지 않고, 루트와 내 사용자에 MFA가 있는가루트로 매일 로그인, 루트 액세스 키 생성IAM 사용자나 Identity Center로만 로그인(S12-P40)
권한사람, 서버, 배포 파이프라인에 필요한 권한만 있는가AdministratorAccess를 서버 역할에 붙임, Resource: *EC2 역할과 배포 역할을 자원 단위로 좁힘(S12-P41, S15)
네트워크인터넷에 열린 포트가 꼭 필요한 것뿐인가22번이나 DB 포트를 0.0.0.0/0에 엶ALB의 80, 443만 공개, EC2는 ALB만, RDS는 EC2만(S15-P52)
암호화저장 데이터와 전송 구간이 암호화되는가RDS 암호화 끔, DB 연결에 SSL 미사용, HTTP로 로그인RDS 암호화, sslmode=require, S3 기본 암호화, SecureString, HTTPS 과정(S13-P46, S15-P52)
공개 범위S3 버킷, 스냅샷, 이미지가 의도치 않게 공개되지 않았는가버킷을 공개로 바꿔 이미지 제공, RDS 스냅샷 공개 공유퍼블릭 액세스 차단 유지, 미리 서명된 URL(S15-P50)

애플리케이션과 AWS를 함께 봅니다

보안은 가장 약한 곳에서 깨집니다. 보안 그룹을 아무리 좁혀도 비밀 키가 Git 기록에 남아 있으면 소용없고, 코드가 완벽해도 RDS가 공개되어 있으면 데이터가 샙니다. 그래서 배포 전 점검표(부록 C)는 애플리케이션 7개 항목과 AWS 7개 항목을 한 장에 담았습니다.

부록 C 번호점검 항목이 과정에서 배운 곳
1비밀 값이 코드와 저장소에 없고 Parameter Store로만 전달S10-P33, S14-P47
2오류 응답에 스택 트레이스, DB 오류, 내부 경로 노출 없음S10-P35
3운영 환경의 디버그 설정과 API 문서 공개 여부S10-P35, S14-P49
4CORS 허용 Origin을 운영 주소로만 제한S3-P9(CORS 설정), 이번 실습에서 조치
5로그인 실패 제한과 토큰 만료 시간S5-P18, S10-P34
6업로드 파일 검증과 S3 퍼블릭 접근 차단S6, S9-P31, S15-P50
