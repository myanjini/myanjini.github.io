범위는 작게

하루 일정이므로 기능은 주 자원 1~2개로 제한합니다. 기능을 많이 만드는 것보다, 작은 기능을 "인증, 권한, 검증, 테스트, 점검, 배포"까지 끝까지 마무리하는 것이 평가에서 훨씬 중요합니다. 시작은 도서 API의 구조(설정, 인증, 오류 처리, 로그, Dockerfile, 워크플로)를 재사용한 시작 템플릿으로 합니다(S17-P58-01).

배포는 지금 구성을 다시 씁니다

프로젝트는 지금의 EC2, RDS, ALB, 배포 워크플로를 그대로 써서 배포합니다. RDS에는 프로젝트용 데이터베이스를 새로 만들고, Parameter Store에는 프로젝트용 경로의 비밀 값을 두며, 서버의 도서 API 컨테이너를 프로젝트 컨테이너로 바꿉니다. 자세한 순서는 S18-P61에서 안내합니다.
