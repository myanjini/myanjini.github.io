불필요한 자원 정리

9일차에 쓰지 않을 자원을 지금 정리하고, 과정이 끝나는 날 지울 자원의 목록(부록 G)을 만들어 둡니다.

실습 목표내 자원 목록을 만들고, 쓰지 않을 자원을 의존 순서에 맞게 정리할 수 있습니다.

부록 G 정리 목록 양식 내려받기(Markdown)

  1. 내 자원 목록 만들기

    Windows에서 실행할 때

    아래 명령에는 bash 문법(이름=값, $(...) 등)이 들어 있습니다. 내 PC가 Windows라면 명령 프롬프트가 아니라 Git Bash에서 실행합니다(S12-P40-03). EC2 서버의 접속 화면에서 실행하는 명령은 그대로 입력합니다.

    aws resourcegroupstaggingapi get-resources --tag-filters Key=Owner,Values=student07 \
  --query "ResourceTagMappingList[].ResourceARN" --output text | tr '\t' '\n' | sort > my-resources.txt
wc -l my-resources.txt

    목록을 양식의 "이름 또는 ID" 칸에 옮깁니다. 7일차에 만든 DB 서브넷 그룹이나 대상 그룹처럼 목록에 없는 것이 있다면 태그가 빠진 것이므로 콘솔에서 찾아 함께 적습니다.

  2. 9일차에 쓸지 정하기

    자원권장이유
    ALB, EC2, RDS, ECR, Parameter Store, IAM 역할, VPC유지9일차 프로젝트 배포와 발표 시연에 그대로 씁니다.
    CloudWatch 로그 그룹과 경보, SNS 주제유지프로젝트 배포에서도 같은 구성을 씁니다.
    S3 표지 버킷유지(프로젝트에서 파일 업로드를 쓰지 않으면 비우고 삭제)버킷은 비어 있으면 요금이 거의 없습니다.
    ECR의 오래된 이미지정리최근 두 개와 버전 태그(1.0.0, 1.1.0)만 남깁니다.
    시험용으로 만든 것(교육장 IP 규칙의 잔재, 시험 SNS 구독 등)정리남겨 둘 이유가 없습니다.

    ALB는 요금이 가장 큰 자원 가운데 하나입니다. 프로젝트를 ALB 없이 시연하기로 했다면 지금 지우고, EC2 보안 그룹에 내 IP의 8000번 규칙을 다시 넣습니다. 이 경우 배포 워크플로의 확인 단계도 고쳐야 하므로, 특별한 이유가 없다면 유지를 권장합니다.

  3. 오래된 이미지 정리

    aws ecr describe-images --repository-name book-api --query "sort_by(imageDetails,&imagePushedAt)[].[imagePushedAt,join(',',imageTags)]" --output text
2026-11-23T14:20:31+09:00	1.0.0,git-4f2c9a1
2026-11-24T10:05:12+09:00	1.1.0,git-7b0d3e2
2026-11-24T11:41:55+09:00	git-9c2e5d1
2026-11-24T15:10:08+09:00	git-3f1a7b2
2026-11-24T15:16:40+09:00	git-a81c4f0

aws ecr batch-delete-image --repository-name book-api --image-ids imageTag=git-3f1a7b2

    지울 것은 장애 실습에서 만든 잘못된 이미지처럼 다시 쓸 일이 없는 것입니다. 지금 서버에서 도는 태그와 직전 태그는 롤백을 위해 남깁니다. 실무에서는 ECR 수명 주기 정책으로 "태그 없는 이미지는 하루 뒤 삭제, 최근 20개만 유지" 같은 규칙을 자동으로 적용합니다.
