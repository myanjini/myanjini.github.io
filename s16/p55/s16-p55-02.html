장애 시나리오 안내

이번 실습에서는 두 가지 장애를 직접 일으키고 대응합니다. 둘 다 실제 운영에서 자주 일어나는 유형입니다. 실습 전에 시나리오를 확인합니다.

시나리오 A: 잘못된 이미지 배포

항목내용
상황누군가 Dockerfile을 고치다 실수로 uvicorn의 포트를 8000에서 8080으로 바꿨습니다. 테스트는 Dockerfile을 실행하지 않으므로 모두 통과하고, 배포 워크플로가 운영에 배포합니다.
증상컨테이너는 실행 중이지만 healthcheck가 실패해 unhealthy, ALB 대상도 unhealthy, 사용자는 502. 배포 워크플로의 확인 단계가 실패합니다.
복구 목표직전 정상 이미지로 2분 안에 되돌리기
배울 점테스트를 통과해도 운영에서 실패할 수 있다. 배포 직후 확인과 빠른 롤백이 안전망이다.
실습용으로 잘못 바꾸는 Dockerfile의 마지막 줄
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8080", "--no-server-header"]

시나리오 B: DB 연결 오류

항목내용
상황DB 암호를 교체하다가 Parameter Store의 DATABASE_URL에 틀린 암호를 넣고 앱을 다시 시작했습니다.
증상앱은 뜨지만 /health가 503("database": "unreachable"), DB를 쓰는 API는 모두 실패합니다. 로그에 ERROR가 쌓입니다.
복구 목표로그에서 원인을 찾고, Parameter Store의 이전 버전 값으로 되돌리기
배울 점로그의 오류 메시지와 요청 ID로 원인을 좁히고, 설정 값도 버전 기록이 있으면 되돌릴 수 있다.

실습 수칙

장애는 내 자원에만 일으킵니다(부록 E의 수칙 5). 시작하기 전에 지금 정상인 이미지 태그와 Parameter Store의 현재 버전 번호를 적어 둡니다. 실습이 끝나면 반드시 정상 상태로 되돌리고 확인합니다.
