Alembic 설정

Alembic을 설치하고 우리 프로젝트의 모델과 설정을 읽도록 연결하는 과정을 강사 화면으로 봅니다.

설치와 초기화

pip install alembic
alembic init migrations

book-api 폴더에서 실행하면 다음 파일과 폴더가 생깁니다.

book-api/
├── alembic.ini          Alembic 설정 파일
├── migrations/
│   ├── env.py           마이그레이션을 실행할 때 읽는 파이썬 파일
│   ├── script.py.mako   리비전 파일의 틀
│   └── versions/        리비전 파일이 쌓이는 곳
└── app/

env.py에 우리 프로젝트 연결하기

migrations/env.py를 열고 target_metadata = None 줄을 찾아 아래 코드로 바꿉니다.

migrations/env.py
from app import models  # noqa: F401  모델을 불러와야 Base.metadata에 테이블이 등록됩니다.
from app.config import settings
from app.database import Base

# 데이터베이스 주소는 alembic.ini가 아니라 앱 설정(.env)에서 읽습니다.
config.set_main_option("sqlalchemy.url", settings.database_url)

# 자동 생성할 때 비교할 기준: 우리가 정의한 모델
target_metadata = Base.metadata
코드하는 일
config.set_main_option("sqlalchemy.url", ...)데이터베이스 주소를 alembic.ini에 따로 적지 않고 S3-P9의 .env 설정을 그대로 씁니다. 주소와 비밀번호를 한곳에서만 관리합니다.
target_metadata = Base.metadata자동 생성할 때 "이상적인 모습"으로 삼을 기준입니다. 모델과 실제 데이터베이스를 비교해 차이를 찾아 줍니다.

같은 파일 아래쪽 run_migrations_online 함수의 context.configure(...)에는 한 줄을 추가합니다.

migrations/env.py
        context.configure(
            connection=connection,
            target_metadata=target_metadata,
            render_as_batch=True,  # SQLite에서 열 변경을 안전하게 처리합니다.
        )

SQLite는 열을 바꾸는 기능이 제한적이라, Alembic이 새 테이블을 만들어 옮기는 방식(batch)으로 처리하게 하는 옵션입니다.

create_all 지우기

이제 테이블은 Alembic이 만듭니다. app/main.py에서 Base.metadata.create_all(...) 줄과, 그 때문에 넣었던 from app import models, from app.database import Base, engine 줄을 지웁니다. 둘이 함께 있으면 누가 테이블을 만들었는지 헷갈리고, Alembic 기록과 실제 데이터베이스가 어긋납니다.

alembic.ini는 언제 고치나요

기본 설정의 prepend_sys_path = . 덕분에 Alembic이 app 패키지를 찾을 수 있어 이 과정에서는 alembic.ini를 고치지 않습니다. 파일 안의 sqlalchemy.url 예시 줄은 env.py에서 덮어쓰므로 그대로 둡니다.
