검색, 정렬, 페이지네이션

도서가 많아지면 목록 조회에 검색, 정렬, 페이지 정보가 필요합니다. 데이터베이스 쿼리로 이 기능을 만드는 방법을 강사 화면으로 봅니다.

제목으로 검색하기

select(Book).where(Book.title.contains("파이썬"))
# SQL: SELECT ... FROM books WHERE title LIKE '%' || ? || '%'

contains는 그 글자가 제목 어딘가에 들어 있는 도서를 찾습니다. 검색어는 ? 자리로 따로 전달되어 SQL 문장에 섞이지 않습니다.

조건을 모아서 걸기

conditions = []
if q is not None:
    conditions.append(Book.title.contains(q))
if author is not None:
    conditions.append(Book.author == author)

stmt = select(Book).where(*conditions)

검색 조건이 있을 때만 목록에 넣고, where(*conditions)로 한꺼번에 겁니다. 목록 앞의 *는 목록을 풀어 하나씩 넘기는 문법이고, 조건이 여러 개면 모두 만족하는(AND) 도서만 찾습니다. 조건이 하나도 없으면 전체를 가져옵니다.

정렬 기준은 정해진 값만 받습니다

SORT_OPTIONS = {
    "id": Book.id,
    "price": Book.price,
    "-price": Book.price.desc(),
}

sort: Literal["id", "price", "-price"] = Query(default="id")

stmt = stmt.order_by(SORT_OPTIONS[sort], Book.id)

Literal은 "이 세 값 중 하나만 받는다"는 타입입니다. 다른 값을 보내면 422가 납니다. 정렬 열 이름은 SQL에 값이 아니라 문장 일부로 들어가므로, 사용자가 보낸 문자열을 그대로 쓰면 위험합니다. 허용한 값만 받아 미리 짝지어 둔 정렬 방법으로 바꾸는 이 방식은 5일차 SQL 삽입 실습에서 다시 나옵니다.

정렬 뒤에 Book.id를 한 번 더 붙인 이유는, 가격이 같은 도서끼리도 순서가 매번 같게 나오도록 하기 위해서입니다. 순서가 흔들리면 페이지를 넘길 때 같은 도서가 두 번 나오거나 빠질 수 있습니다.

전체 개수 함께 알려 주기

total = db.scalar(select(func.count()).select_from(Book).where(*conditions))

화면에서 "전체 37권 중 1~10권"처럼 보여 주거나 마지막 페이지를 계산하려면 전체 개수가 필요합니다. 같은 조건으로 개수만 세는 쿼리를 한 번 더 실행합니다. 응답도 목록 대신 다음 모양으로 바뀝니다.

{
  "items": [ { "id": 1, "title": "파이썬 첫걸음", ... } ],
  "total": 2,
  "skip": 0,
  "limit": 10
}

응답 모양을 바꾸는 것은 약속을 바꾸는 일

목록이던 응답이 객체로 바뀌면, 이 API를 쓰던 화면 코드는 모두 고쳐야 합니다. 실제 서비스에서는 처음부터 이 모양으로 설계하거나, 바꿀 때 API 버전을 나눕니다. 우리는 아직 이 API를 쓰는 화면이 없으니 지금 바꿉니다.
