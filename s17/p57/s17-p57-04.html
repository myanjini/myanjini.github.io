설계 자기 점검

명세를 다 썼으면 구현하기 전에 스스로 점검합니다. 질문에 내 명세로 답해 보고, 답하지 못하면 명세를 고칩니다. 지금 고치는 것이 코드를 고치는 것보다 훨씬 쌉니다.

질문 1. (권한 누락) 데이터를 바꾸는 API(POST, PATCH, PUT, DELETE) 가운데 "인증/권한" 칸이 "없음"인 것이 있나요?

예시 답안 보기

회원가입과 로그인 말고는 없어야 합니다. 있다면 누구나 데이터를 바꿀 수 있다는 뜻입니다. 특히 URI에 {id}가 들어간 수정, 삭제 API는 "로그인 사용자"만으로는 부족하고, "소유자 본인" 같은 객체 수준의 권한이 있어야 합니다. 예시에서는 모임 수정, 삭제, 참가자 명단이 "개설자 본인, 관리자"입니다.

질문 2. (권한 누락) 조회 API가 돌려주는 데이터 가운데 남에게 보이면 안 되는 것이 있나요?

예시 답안 보기

응답 모델의 필드를 하나씩 봅니다. 이메일, 연락처, 내부 메모 같은 값이 목록 응답에 그대로 있으면 누구나 모을 수 있습니다. 예시에서는 참가자 명단을 개설자만 보게 하고, 그 안에서도 이메일을 가렸습니다. 비밀번호 해시는 어떤 응답에도 넣지 않습니다.

질문 3. (입력 검증 누락) 요청으로 받는 문자열에 모두 최대 길이가 있고, 숫자에 모두 범위가 있나요? 목록 API에 페이지 크기 상한이 있나요?

예시 답안 보기

최대 길이가 없으면 아주 긴 값으로 저장 공간과 응답을 키울 수 있고, 페이지 크기 상한이 없으면 limit=1000000 한 번으로 서버를 느리게 할 수 있습니다. 예시에서는 검색어 최대 50자, 페이지 번호 1~1000, 한 페이지 10개로 고정했습니다.

질문 4. (상태 충돌) 수량, 정원, 재고처럼 "남은 개수"가 있는 자원이 있나요? 동시에 요청이 오면 어떻게 되나요?

예시 답안 보기

있다면 그 개수를 줄이는 API는 경쟁 조건 대책이 필요합니다(S11-P36). 명세의 상태 코드에 409를 넣고, 보안 요구사항에 "조건부 UPDATE"를 적어 둡니다. 예시의 정원이 여기에 해당합니다.

질문 5. (범위 과다) 내 API를 모두 구현하고 테스트까지 쓰려면 몇 시간이 걸릴까요? 12시 50분까지 끝낼 수 있나요?

예시 답안 보기

도서 API를 만들어 본 경험으로 보면, CRUD 다섯 개와 권한 검사는 한 시간, 핵심 기능 하나와 테스트는 한 시간쯤 걸립니다. 남은 오전 시간은 세 시간이므로, 자원 1~2개, API 10개 안팎이 한계입니다. 넘는다면 "범위에서 뺀 것"으로 옮깁니다. 기능 하나를 덜 만드는 것보다, 만든 기능에 권한 검사나 테스트가 없는 것이 훨씬 큰 감점입니다.

질문 6. 내 보안 요구사항마다 확인 테스트가 하나 이상 있나요?

예시 답안 보기

테스트가 없는 요구사항은 "지켰다"고 말할 근거가 없습니다. 발표에서 "남의 모임은 고칠 수 없습니다"라고 말하려면, 그것을 확인하는 테스트가 통과하는 화면을 보여 줄 수 있어야 합니다.
