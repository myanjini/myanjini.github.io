오전이 거의 끝났습니다. 지금 상태를 냉정하게 보고, 오후에 꼭 끝낼 것과 버릴 것을 정합니다. 오후 첫 시간은 보안 점검과 배포에 써야 하므로, 기능 구현에 쓸 수 있는 시간은 사실상 지금뿐입니다.

질문 1. 최소 요건(S16-P56-03) 여섯 가지 가운데 지금 끝난 것과 남은 것은 무엇인가요?

예시 답안 보기

1~3번(CRUD와 입력 검증, 인증과 권한, 테스트 3개 이상)은 오전에 끝나 있어야 합니다. 4~6번(보안 점검, AWS 배포, README)은 오후 S18-P61에서 합니다. 1~3번 가운데 남은 것이 있다면 그것이 최우선입니다.

질문 2. 남은 시간에 꼭 끝내야 할 기능은 무엇인가요? 그 기능이 없으면 발표 시연이 안 되나요?

예시 답안 보기

시연 시나리오(로그인, 자원 만들기, 핵심 기능 한 번, 남의 자원에 접근해 막히는 장면)에 필요한 기능만 "꼭"입니다. 예시라면 모임 등록, 참가 신청, 정원 초과 409, 남의 모임 수정 403입니다. 내 모임 목록이나 모집 마감은 없어도 시연이 됩니다.

질문 3. 동작은 하지만 테스트가 없는 기능이 있나요? 테스트는 있지만 실패하는 것이 있나요?

예시 답안 보기

실패하는 테스트를 남긴 채 배포 워크플로를 돌리면 배포가 되지 않습니다. 기능을 고칠 시간이 없다면 그 기능을 빼고(라우터 등록 해제), 범위에서 뺀 것으로 기록합니다. 테스트를 지우거나 건너뛰게 만들어 통과시키지 않습니다.

질문 4. 명세와 코드가 다른 곳이 있나요?

예시 답안 보기

구현하다 보면 상태 코드나 경로가 바뀌기 마련입니다. 제출물은 명세와 코드가 같아야 하므로, 다른 곳은 명세를 코드에 맞게 고칩니다. Swagger UI(/docs)의 목록과 명세의 API 목록을 나란히 놓고 비교하면 빠릅니다.
