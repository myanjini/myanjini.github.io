중간 코드 자기 점검

구현을 계속하기 전에, 지금까지의 코드가 권한과 오류를 제대로 처리하는지 질문으로 점검합니다. 직접 요청을 보내 확인하고 답을 적습니다.

질문 1. 다른 사용자가 내 자원을 수정하면 어떤 상태 코드가 나오나요? 그리고 자원은 정말 바뀌지 않았나요?

예시 답안 보기

예시에서는 403이고, 다시 조회하면 제목이 그대로입니다. 상태 코드만 보고 끝내지 말고 "바뀌지 않았다"까지 확인합니다. 검사를 값을 바꾼 뒤에 하는 실수를 하면, 응답은 403인데 값은 이미 바뀌어 있을 수 있습니다. 테스트에서도 같은 순서로 확인합니다(S17-P60-02).

질문 2. 없는 번호로 수정하면 어떻게 되나요? 남의 자원과 같은 응답이 나와야 하나요?

예시 답안 보기

없는 번호는 404입니다. 공개된 자원이라면 남의 것은 403, 없는 것은 404로 달라도 됩니다. 존재를 숨겨야 하는 자원이라면 두 경우 모두 404로 같게 답해야, 번호를 바꿔 가며 남의 자원이 있는지 알아내는 것을 막을 수 있습니다.

질문 3. 토큰 없이, 위조한 토큰으로, 만료된 토큰으로 쓰기 API를 부르면 각각 어떤 응답이 나오나요?

예시 답안 보기

세 경우 모두 401입니다. 토큰이 없으면 NOT_AUTHENTICATED, 위조나 만료면 INVALID_TOKEN이고, 응답 헤더에 WWW-Authenticate: Bearer가 있습니다. 500이 나온다면 토큰 검사 전에 다른 코드가 실행되고 있는 것입니다.

질문 4. 요청 본문에 소유자 필드(owner_id 같은 값)를 넣어 보내면 어떻게 되나요?

예시 답안 보기

422여야 합니다. 201이 나오고 소유자가 바뀐다면, 입력 모델이 InputModel을 상속하지 않았거나 입력 모델에 그 필드가 들어 있는 것입니다(대량 할당, S9-P32).

질문 5. 오류 응답 본문에 SQL, 파일 경로, 트레이스백 같은 내부 정보가 보이나요?

예시 답안 보기

보이면 안 됩니다. 템플릿의 오류 처리는 처리하지 못한 예외를 정해진 문구와 요청 ID로만 답합니다. 일부러 500을 일으켜(예: 서비스에 1 / 0을 잠시 넣음) 응답에는 요청 ID만, 로그에는 트레이스백이 남는지 확인하고 원래대로 돌립니다.

질문 6. 관리자는 무엇을 할 수 있어야 하나요? 지금 코드에서 그렇게 되나요?

예시 답안 보기

명세의 권한 표에 적은 대로입니다. 예시에서는 관리자가 남의 모임을 수정, 삭제하고 명단을 볼 수 있습니다(check_can_modify의 첫 조건). 관리자에게 필요 없는 권한까지 주지 않았는지도 함께 봅니다.
