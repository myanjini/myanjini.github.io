## 유형별 점검

유형마다 "내 코드에서 해당하는 곳"을 찾아 적습니다. 해당하는 곳이 없으면 "해당 없음"과 이유를 적습니다.

| 유형 | 점검 질문 | 내 코드에서 해당하는 곳 | 결과(안전, 조치함, 해당 없음) |
|---|---|---|---|
| 입력데이터 검증 및 표현 | 모든 입력에 길이와 범위 규칙이 있는가, SQL을 문자열로 조립하는 곳이 없는가 |  |  |
| 보안기능 | 데이터를 바꾸는 API에 인증이 있고, {id} 경로에 소유자 검사가 있는가 |  |  |
| 시간 및 상태 | 개수나 상태를 바꾸는 곳에 동시 요청 대책이 있는가 |  |  |
| 에러처리 | 오류 응답에 내부 정보가 없고, 예외를 삼키는 곳이 없는가 |  |  |
| 코드오류 | 처리하지 않은 None, 닫지 않은 자원이 없는가 |  |  |
| 캡슐화 | 응답에 비밀번호 해시, 전체 이메일 같은 값이 없고, 디버그 코드가 없는가 |  |  |
| API 오용 | 위험한 함수(eval, pickle, shell=True)를 쓰지 않고, 패키지에 알려진 취약점이 없는가 |  |  |
