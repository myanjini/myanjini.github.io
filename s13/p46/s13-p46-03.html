RDS 만들고 연결하기

프라이빗 서브넷에 RDS PostgreSQL을 만들고, EC2에서만 접속되는지 확인한 뒤, 도서 API의 데이터베이스를 SQLite에서 RDS로 바꿉니다. RDS가 만들어지는 데 10분쯤 걸리므로, 기다리는 동안 다음 페이지(S13-P46-04)를 읽습니다.

실습 목표인터넷에서 닿지 않는 RDS를 만들고, 도서 API를 SSL로 연결해 마이그레이션과 데이터 저장을 확인할 수 있습니다.

  1. 마스터 암호 만들기

    내 PC에서 만듭니다. 이 값은 오늘 오후 Parameter Store에 옮길 때까지 암호 관리자나 안전한 메모에 둡니다. 채팅이나 공유 문서에 붙여 넣지 않습니다.

    python -c "import secrets; print(secrets.token_urlsafe(24))"
Qm3...(32자)

  2. DB 서브넷 그룹 만들기

    RDS 콘솔의 서브넷 그룹, DB 서브넷 그룹 생성을 누릅니다.

    항목값
    이름book-api-db-subnets
    설명book-api private subnets
    VPCbook-api-vpc
    가용 영역ap-northeast-2a, ap-northeast-2c
    서브넷프라이빗 서브넷 두 개만(10.0.11.0/24, 10.0.12.0/24)

  3. RDS 만들기

    데이터베이스 생성을 누르고 앞 페이지의 표대로 입력합니다. 태그에 Owner를 넣고 데이터베이스 생성을 누릅니다. 상태가 "생성 중"에서 "사용 가능"이 될 때까지 기다리며 S13-P46-04를 읽습니다.

  4. 엔드포인트와 설정 확인

    aws rds describe-db-instances --db-instance-identifier book-api-db --query "DBInstances[0].[DBInstanceStatus,Endpoint.Address,PubliclyAccessible,StorageEncrypted,DBSubnetGroup.DBSubnetGroupName,EngineVersion]" --output text
available	book-api-db.xxxxxxxxxxxx.ap-northeast-2.rds.amazonaws.com	False	True	book-api-db-subnets	18.1

    퍼블릭 액세스(PubliclyAccessible)가 False, 암호화(StorageEncrypted)가 True인지 확인합니다. 엔드포인트를 복사해 둡니다.

  5. 내 PC에서는 닿지 않는지 확인

    nslookup book-api-db.xxxxxxxxxxxx.ap-northeast-2.rds.amazonaws.com
...
Address: 10.0.11.152

    엔드포인트 이름은 인터넷에서도 조회되지만, 돌려주는 주소가 사설 IP(10.0.11.x)입니다. 내 PC에서는 이 주소로 갈 길이 없으므로 접속할 수 없습니다. 퍼블릭 액세스를 끈 결과입니다.

  6. EC2에서 psql로 접속

    Session Manager로 EC2에 접속해 PostgreSQL 클라이언트를 설치하고 접속합니다. sslmode=require는 SSL로 암호화한 연결만 쓰겠다는 뜻입니다.

    sudo dnf install -y postgresql17
psql "host=book-api-db.xxxxxxxxxxxx.ap-northeast-2.rds.amazonaws.com port=5432 dbname=bookapi user=bookapi sslmode=require"
Password for user bookapi: (마스터 암호 입력, 화면에 보이지 않음)
psql (17.x, server 18.1)
SSL connection (protocol: TLSv1.3, cipher: TLS_AES_256_GCM_SHA384, compression: off)
Type "help" for help.

bookapi=> select current_user, current_database();
 current_user | current_database
--------------+------------------
 bookapi      | bookapi
(1 row)

bookapi=> \q

    "SSL connection" 줄이 보이면 암호화된 연결입니다. 이번에는 일부러 sslmode=disable(암호화하지 않음)로 접속해 봅니다. RDS가 SSL이 아닌 연결을 거부하는 것을 확인합니다.

    psql "host=book-api-db.xxxxxxxxxxxx.ap-northeast-2.rds.amazonaws.com dbname=bookapi user=bookapi sslmode=disable"
psql: error: connection to server at "book-api-db.xxxx..." (10.0.11.152), port 5432 failed: FATAL:  no pg_hba.conf entry for host "10.0.1.87", user "bookapi", database "bookapi", no encryption

  7. DATABASE_URL 바꾸기

    설정 파일의 DATABASE_URL 줄을 RDS 주소로 바꿉니다. 주소 끝의 ?sslmode=require를 빠뜨리지 않습니다.

    nano ~/book-api.env
    ~/book-api.env의 DATABASE_URL 줄
    postgresql+psycopg://bookapi:마스터암호@book-api-db.xxxxxxxxxxxx.ap-northeast-2.rds.amazonaws.com:5432/bookapi?sslmode=require

    주소의 각 부분은 S8에서 본 것과 같습니다. postgresql+psycopg(드라이버), bookapi:암호(사용자와 암호), 엔드포인트:5432(서버와 포트), /bookapi(데이터베이스 이름), ?sslmode=require(연결 옵션)입니다.

  8. 마이그레이션 적용

    RDS의 데이터베이스는 비어 있으므로 테이블을 만듭니다. 앱 컨테이너를 바꾸기 전에, 같은 이미지로 일회용 컨테이너를 띄워 마이그레이션만 실행합니다.

    docker run --rm --env-file ~/book-api.env book-api alembic upgrade head
INFO  [alembic.runtime.migration] Context impl PostgresqlImpl.
INFO  [alembic.runtime.migration] Will assume transactional DDL.
INFO  [alembic.runtime.migration] Running upgrade  -> 0c8fecfaba35, create authors and books
...
INFO  [alembic.runtime.migration] Running upgrade 238c2bf6cf4b -> 142ae5dfcb3f, unique active loan

    Context impl PostgresqlImpl이 보이면 SQLite가 아니라 PostgreSQL에 적용된 것입니다.

  9. 앱 컨테이너 교체

    설정은 컨테이너를 만들 때 읽히므로, 기존 컨테이너를 지우고 새로 만듭니다. SQLite 볼륨(book-data)은 더 쓰지 않으므로 빼고, 표지 이미지 볼륨은 그대로 둡니다.

    Windows에서 실행할 때

    아래 명령에는 bash 문법(이름=값, $(...) 등)이 들어 있습니다. 내 PC가 Windows라면 명령 프롬프트가 아니라 Git Bash에서 실행합니다(S12-P40-03). EC2 서버의 접속 화면에서 실행하는 명령은 그대로 입력합니다.

    docker rm -f book-api
docker run -d --name book-api -p 8000:8000 --env-file ~/book-api.env \
  -v book-uploads:/app/uploads --restart unless-stopped book-api
curl -s localhost:8000/health
{"status":"ok","database":"ok"}

    내 PC의 /docs에서 회원가입을 하고, EC2의 psql로 RDS에 저장되었는지 확인합니다.

    psql "host=book-api-db.xxxxxxxxxxxx.ap-northeast-2.rds.amazonaws.com dbname=bookapi user=bookapi sslmode=require" -c "select email from users"
       email
-------------------
 user2@example.com
(1 row)

    SQLite에 넣었던 데이터는 RDS로 옮겨지지 않습니다. 실습이므로 새로 가입합니다. 실제 서비스라면 데이터를 옮기는 작업(마이그레이션 계획)이 따로 필요합니다.

증상원인과 해결
psql이 한참 기다리다 시간 초과보안 그룹 문제입니다. book-api-db-sg의 출처가 book-api-sg인지, EC2에 book-api-sg가 붙었는지 확인합니다.
password authentication failed암호가 다릅니다. 콘솔의 "수정"에서 마스터 암호를 새로 정할 수 있습니다.
database "bookapi" does not exist초기 데이터베이스 이름을 비웠습니다. psql로 dbname=postgres에 접속해 CREATE DATABASE bookapi;를 실행합니다.
앱 로그에 invalid literal for int()암호나 주소에 :, @, / 같은 문자가 있어 DATABASE_URL이 잘못 나뉘었습니다. 영문자와 숫자, -, _만 쓴 암호로 바꿉니다.
