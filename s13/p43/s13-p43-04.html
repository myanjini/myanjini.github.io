보안 그룹 만들기

설계표의 7일차 보안 그룹 두 개를 만듭니다. API 서버용은 내 공인 IP에서 오는 8000번만, DB용은 API 서버 보안 그룹에서 오는 5432번만 허용합니다.

실습 목표출처를 IP와 보안 그룹으로 지정한 인바운드 규칙을 만들고, 규칙이 설계표와 같은지 확인할 수 있습니다.

  1. 내 공인 IP 다시 확인

    curl https://checkip.amazonaws.com
203.0.113.25

  2. API 서버용 보안 그룹

    VPC 콘솔(또는 EC2 콘솔)의 보안 그룹, 보안 그룹 생성을 누릅니다.

    항목값
    보안 그룹 이름book-api-sg
    설명book-api EC2: 8000 from my IP
    VPCbook-api-vpc(기본 VPC가 아닌지 꼭 확인)
    인바운드 규칙유형 "사용자 지정 TCP", 포트 8000, 소스 "사용자 지정" 203.0.113.25/32(내 IP), 설명 "student PC"
    아웃바운드 규칙기본값(모든 트래픽, 0.0.0.0/0) 그대로
    태그Owner = 내 식별자

    소스 목록의 "내 IP"를 고르면 콘솔이 내 공인 IP를 자동으로 채워 줍니다. 22번(SSH) 규칙은 만들지 않습니다.

  3. DB용 보안 그룹

    항목값
    보안 그룹 이름book-api-db-sg
    설명book-api RDS: 5432 from book-api-sg
    VPCbook-api-vpc
    인바운드 규칙유형 "PostgreSQL"(포트 5432가 자동으로 채워짐), 소스 "사용자 지정"에서 book-api-sg를 검색해 고름
    아웃바운드 규칙기본값 그대로
    태그Owner = 내 식별자

    소스 칸에 sg-를 입력하면 보안 그룹 목록이 나옵니다. IP 주소가 아니라 sg-로 시작하는 ID가 들어가야 합니다.

  4. CLI로 확인

    aws ec2 describe-security-groups --filters Name=vpc-id,Values=vpc-0a1b2c3d4e5f67890 Name=group-name,Values=book-api-* --query "SecurityGroups[].{name:GroupName,id:GroupId,in:IpPermissions[].{port:FromPort,cidr:IpRanges[].CidrIp,sg:UserIdGroupPairs[].GroupId}}"
[
    {
        "name": "book-api-sg",
        "id": "sg-0aaa1111bbbb2222c",
        "in": [ { "port": 8000, "cidr": ["203.0.113.25/32"], "sg": [] } ]
    },
    {
        "name": "book-api-db-sg",
        "id": "sg-0ddd3333eeee4444f",
        "in": [ { "port": 5432, "cidr": [], "sg": ["sg-0aaa1111bbbb2222c"] } ]
    }
]

    DB 보안 그룹 규칙의 sg 값이 API 서버 보안 그룹의 id와 같은지 확인합니다. 출력은 보기 좋게 줄을 맞춘 예시입니다.
