실습 VPC 구성

설계표대로 실습 VPC를 만들고, 만든 결과를 콘솔의 리소스 맵과 CLI로 확인합니다. 마지막으로 모든 자원에 Owner 태그를 붙입니다.

실습 목표가용 영역 2곳에 퍼블릭 서브넷 2개와 프라이빗 서브넷 2개를 가진 VPC를 만들고, 라우팅을 확인할 수 있습니다.

  1. 마법사 열기

    콘솔의 리전이 서울인지 확인한 뒤 VPC 콘솔을 열고 VPC 생성을 누릅니다. 생성할 리소스에서 VPC 등을 고릅니다.

  2. 설정 입력

    앞 페이지의 표대로 입력합니다. 가용 영역은 "AZ 사용자 지정"을 펼쳐 첫 번째를 ap-northeast-2a, 두 번째를 ap-northeast-2c로 고릅니다. 서브넷 CIDR 블록 사용자 지정을 펼쳐 네 칸을 설계표 값으로 바꿉니다.

    칸값
    ap-northeast-2a의 퍼블릭 서브넷10.0.1.0/24
    ap-northeast-2c의 퍼블릭 서브넷10.0.2.0/24
    ap-northeast-2a의 프라이빗 서브넷10.0.11.0/24
    ap-northeast-2c의 프라이빗 서브넷10.0.12.0/24

  3. 미리 보기 확인 후 생성

    오른쪽 미리 보기에 VPC 1개, 서브넷 4개, 라우팅 테이블, 인터넷 게이트웨이 1개가 보이고 NAT 게이트웨이가 없는지 확인한 뒤 VPC 생성을 누릅니다. 1분 안에 모든 단계가 "성공"으로 바뀝니다. VPC 보기를 누르고 리소스 맵 탭을 열면 서브넷, 라우팅 테이블, 인터넷 게이트웨이가 선으로 이어진 그림을 볼 수 있습니다.

  4. CLI로 확인

    내 PC의 터미널에서 확인합니다. 아래 명령의 --query는 결과에서 필요한 값만 골라내고, --output table은 표로 보여 줍니다.

    aws ec2 describe-vpcs --filters Name=tag:Name,Values=book-api-vpc --query "Vpcs[].[VpcId,CidrBlock]" --output table
-------------------------------------------
|              DescribeVpcs               |
+------------------------+----------------+
|  vpc-0a1b2c3d4e5f67890 |  10.0.0.0/16   |
+------------------------+----------------+

aws ec2 describe-subnets --filters Name=vpc-id,Values=vpc-0a1b2c3d4e5f67890 --query "Subnets[].[Tags[?Key=='Name']|[0].Value,AvailabilityZone,CidrBlock]" --output table
---------------------------------------------------------------------------------------
|                                   DescribeSubnets                                   |
+----------------------------------------------+------------------+-------------------+
|  book-api-subnet-public1-ap-northeast-2a     |  ap-northeast-2a |  10.0.1.0/24      |
|  book-api-subnet-public2-ap-northeast-2c     |  ap-northeast-2c |  10.0.2.0/24      |
|  book-api-subnet-private1-ap-northeast-2a    |  ap-northeast-2a |  10.0.11.0/24     |
|  book-api-subnet-private2-ap-northeast-2c    |  ap-northeast-2c |  10.0.12.0/24     |
+----------------------------------------------+------------------+-------------------+

    vpc-로 시작하는 VPC ID는 사람마다 다릅니다. 아래 명령에서도 내 값으로 바꿔 씁니다. 자원 이름은 마법사가 정한 규칙에 따라 붙으므로 위와 조금 다를 수 있습니다.

  5. 라우팅 확인

    aws ec2 describe-route-tables --filters Name=vpc-id,Values=vpc-0a1b2c3d4e5f67890 --query "RouteTables[].[Tags[?Key=='Name']|[0].Value,Routes[].[DestinationCidrBlock,GatewayId]]" --output text
book-api-rtb-public
10.0.0.0/16	local
0.0.0.0/0	igw-0123456789abcdef0
book-api-rtb-private1-ap-northeast-2a
10.0.0.0/16	local
book-api-rtb-private2-ap-northeast-2c
10.0.0.0/16	local
...

    퍼블릭 라우팅 테이블에만 0.0.0.0/0 → igw-... 경로가 있는지 확인합니다. 이름표가 없는 라우팅 테이블이 하나 더 보이면 VPC를 만들 때 자동으로 생기는 기본(main) 라우팅 테이블입니다.

  6. Owner 태그 붙이기

    VPC 안의 자원 ID를 모아 한 번에 태그를 붙입니다. 아래 명령은 bash 문법(VPC=값, $(...))이므로 Windows에서는 명령 프롬프트가 아니라 Git Bash에서 실행합니다(S12-P40-03).

    VPC=vpc-0a1b2c3d4e5f67890
IDS=$(aws ec2 describe-subnets --filters Name=vpc-id,Values=$VPC --query "Subnets[].SubnetId" --output text)
RTS=$(aws ec2 describe-route-tables --filters Name=vpc-id,Values=$VPC --query "RouteTables[].RouteTableId" --output text)
IGW=$(aws ec2 describe-internet-gateways --filters Name=attachment.vpc-id,Values=$VPC --query "InternetGateways[].InternetGatewayId" --output text)
aws ec2 create-tags --resources $VPC $IDS $RTS $IGW --tags Key=Owner,Value=student07

aws ec2 describe-subnets --filters Name=tag:Owner,Values=student07 --query "length(Subnets)"
4

    마지막 명령은 Owner 태그가 붙은 서브넷의 수를 셉니다. 4가 나오면 됩니다. CLI 대신 콘솔의 각 자원 화면에서 태그 탭으로 붙여도 됩니다.

확인내 결과
VPC ID
퍼블릭 서브넷 ID(2a)
프라이빗 서브넷 ID 2개
인터넷 게이트웨이 ID

이 값들을 적어 두는 이유

VPC ID와 서브넷 ID는 다음 페이지의 보안 그룹, EC2, RDS를 만들 때 계속 고르게 됩니다. 콘솔에서는 이름으로 고를 수 있지만, CLI로 확인하거나 문제를 찾을 때 ID가 필요합니다.
