VPC 생성 과정 보기

VPC를 이루는 자원(VPC, 서브넷, 라우팅 테이블, 인터넷 게이트웨이)은 하나씩 따로 만들 수도 있지만, 콘솔의 "VPC 등" 마법사를 쓰면 설계한 구성을 한 번에 만들 수 있습니다. 실습 전에 마법사의 각 칸이 설계표의 무엇에 해당하는지 확인합니다.

두 가지 만들기 방식

방식만드는 것언제 쓰나요
VPC만VPC 하나만 만듭니다. 서브넷, 라우팅 테이블, 인터넷 게이트웨이를 하나씩 따로 만들고 연결해야 합니다.구성 요소의 관계를 하나씩 익히거나, 특별한 구성이 필요할 때
VPC 등VPC와 서브넷, 라우팅 테이블, 인터넷 게이트웨이를 함께 만들고 서로 연결합니다. 만들기 전에 결과를 그림(미리 보기)으로 보여 줍니다.일반적인 퍼블릭과 프라이빗 구성을 빠르게 만들 때(이번 실습)

마법사의 설정과 설계표

마법사 항목이번 실습 값설계표의 근거
이름 태그 자동 생성book-apiR7. 모든 자원 이름이 book-api-로 시작합니다.
IPv4 CIDR 블록10.0.0.0/16VPC 주소 범위
IPv6 CIDR 블록없음이 과정은 IPv4만 씁니다.
가용 영역(AZ) 수2(ap-northeast-2a, ap-northeast-2c)RDS 서브넷 그룹과 ALB가 두 가용 영역을 요구합니다.
퍼블릭 서브넷 수2EC2, 8일차 ALB
프라이빗 서브넷 수2RDS
서브넷 CIDR 블록 사용자 지정10.0.1.0/24, 10.0.2.0/24, 10.0.11.0/24, 10.0.12.0/24기본값(/20)을 설계표 값으로 바꿉니다.
NAT 게이트웨이없음R5. 시간당 요금이 비쌉니다(S12-P40-04).
VPC 엔드포인트없음이 과정에서는 쓰지 않습니다.
DNS 호스트 이름, DNS 확인둘 다 활성화RDS 엔드포인트 같은 이름을 VPC 안에서 주소로 바꾸는 데 필요합니다.

마법사는 퍼블릭 서브넷용 라우팅 테이블 하나와 프라이빗 서브넷용 라우팅 테이블을 만듭니다. 퍼블릭용에는 인터넷 게이트웨이로 가는 경로가 들어가고, 프라이빗용에는 VPC 안 경로(local)만 들어갑니다. 이 차이가 "퍼블릭"과 "프라이빗"을 만듭니다.

NAT 게이트웨이 칸을 꼭 확인합니다

NAT 게이트웨이를 "1개의 AZ에"나 "AZ당 1개"로 두고 만들면, 만든 순간부터 시간당 요금이 붙습니다. 만들기를 누르기 전에 미리 보기 그림에 NAT 게이트웨이가 없는지 한 번 더 확인합니다. 실수로 만들었다면 바로 강사에게 알리고 삭제합니다. 삭제한 뒤 연결된 탄력적 IP도 해제해야 요금이 멈춥니다.

태그 규칙

마법사가 붙여 주는 Name 태그와 별도로, 모든 자원에 Owner 태그를 붙입니다(부록 E). 태그는 자원에 붙이는 "키=값" 이름표입니다. 비용 화면에서 태그로 묶어 보거나, 정리할 때 내 자원만 골라내는 데 씁니다. 이번 실습에서는 마법사로 만든 뒤 CLI 명령 한 번으로 모든 자원에 Owner 태그를 붙입니다.

태그 키값예
Namebook-api-로 시작하는 이름(마법사가 붙임)book-api-vpc, book-api-subnet-public1-ap-northeast-2a
Owner내 식별자(기관이 안내한 학생 번호나 아이디)student07

마법사로 만든 VPC에서 프라이빗 서브넷을 프라이빗으로 만드는 것은 무엇인가요?

이름이나 숫자는 사람이 알아보기 위한 것입니다. 인터넷으로 가는 길이 있는지는 라우팅 테이블이 정합니다.
