EC2 만들고 접속하기

앞 페이지의 표대로 EC2 서버를 만들고, Session Manager로 접속해 서버의 기본 상태를 점검합니다. IAM 역할과 IMDSv2가 제대로 동작하는지도 서버 안에서 직접 확인합니다.

실습 목표IAM 역할을 붙인 EC2를 만들고, SSH 키 없이 Session Manager로 접속해 서버 상태를 확인할 수 있습니다.

  1. 인스턴스 시작

    EC2 콘솔에서 인스턴스 시작을 누르고 앞 페이지의 표대로 입력합니다. 오른쪽 요약에서 VPC, 보안 그룹, IAM 역할을 확인하고 인스턴스 시작을 누릅니다.

  2. 실행 확인

    인스턴스 목록에서 상태가 "실행 중"이 되고, 상태 검사가 모두 통과할 때까지 2~3분 기다립니다. CLI로도 확인할 수 있습니다.

    aws ec2 describe-instances --filters Name=tag:Name,Values=book-api-server Name=instance-state-name,Values=running --query "Reservations[].Instances[].[InstanceId,InstanceType,PublicIpAddress,IamInstanceProfile.Arn]" --output text
i-0123456789abcdef0	t3.micro	3.35.120.45	arn:aws:iam::123456789012:instance-profile/book-api-ec2-role

  3. Session Manager로 접속

    인스턴스를 고르고 연결, Session Manager 탭, 연결을 누르면 브라우저에 터미널이 열립니다. "연결" 버튼이 비활성이면 SSM 에이전트가 등록될 때까지 2~5분 더 기다린 뒤 새로 고칩니다.

    Session Manager는 기본으로 sh 셸로, /usr/bin 폴더에서 시작합니다. 익숙한 bash로 바꾸고 홈 폴더로 이동합니다.

    sh-5.2$ bash
[ssm-user@ip-10-0-1-87 bin]$ cd ~
[ssm-user@ip-10-0-1-87 ~]$ whoami
ssm-user

    ssm-user는 Session Manager가 만든 운영체제 사용자로, 비밀번호 없이 sudo(관리자 권한으로 실행)를 쓸 수 있습니다. 프롬프트의 ip-10-0-1-87은 서버의 사설 IP(10.0.1.87)입니다. 퍼블릭 서브넷 10.0.1.0/24 안의 주소인지 확인합니다.

  4. 서버 기본 상태 점검

    Windows에서 실행할 때

    아래 명령에는 bash 문법(이름=값, $(...) 등)이 들어 있습니다. 내 PC가 Windows라면 명령 프롬프트가 아니라 Git Bash에서 실행합니다(S12-P40-03). EC2 서버의 접속 화면에서 실행하는 명령은 그대로 입력합니다.

    cat /etc/os-release | head -2
NAME="Amazon Linux"
VERSION="2023"

nproc; free -m | head -2
2
               total        used        free      shared  buff/cache   available
Mem:             916         180         512           0         222         600

df -h /
Filesystem        Size  Used Avail Use% Mounted on
/dev/nvme0n1p1    8.0G  1.6G  6.4G  20% /

curl -s https://checkip.amazonaws.com
3.35.120.45

    마지막 명령은 서버가 인터넷으로 나갈 수 있는지와, 바깥에서 보이는 서버의 공용 IP를 함께 확인합니다. 콘솔에 보이는 퍼블릭 IP와 같아야 합니다.

  5. IAM 역할과 IMDSv2 확인

    aws sts get-caller-identity --query Arn --output text
arn:aws:sts::123456789012:assumed-role/book-api-ec2-role/i-0123456789abcdef0

curl -s -o /dev/null -w "%{http_code}\n" http://169.254.169.254/latest/meta-data/
401

TOKEN=$(curl -s -X PUT http://169.254.169.254/latest/api/token -H "X-aws-ec2-metadata-token-ttl-seconds: 60")
curl -s -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/iam/security-credentials/
book-api-ec2-role

    서버 안의 AWS CLI는 액세스 키 없이도 역할(assumed-role/book-api-ec2-role)로 요청합니다. 토큰 없이 메타데이터를 조회하면 401(인증 필요)이 돌아오고, PUT으로 토큰을 받은 뒤에야 역할 이름이 보입니다. URL만 바꿔 GET을 보내게 하는 SSRF로는 자격 증명을 꺼내기 어렵다는 것을 확인했습니다.

  6. 권한 범위 확인

    aws s3 ls
An error occurred (AccessDenied) when calling the ListBuckets operation: User: arn:aws:sts::123456789012:assumed-role/book-api-ec2-role/i-0123456789abcdef0 is not authorized to perform: s3:ListAllMyBuckets ...

    역할에 S3 권한을 주지 않았으므로 거부됩니다. 최소 권한이 서버 안에서도 지켜지고 있습니다. S3 권한은 8일차에 필요한 만큼만 더합니다.

확인할 것고치는 방법
인스턴스에 IAM 역할이 붙었나요?인스턴스 선택, 작업, 보안, IAM 역할 수정에서 book-api-ec2-role을 고르고, 몇 분 기다립니다.
퍼블릭 IP가 있나요?없으면 서버가 Systems Manager로 나갈 수 없습니다. 인스턴스를 종료하고 "퍼블릭 IP 자동 할당: 활성화"로 다시 만듭니다.
퍼블릭 서브넷에 만들었나요?서브넷의 라우팅 테이블에 인터넷 게이트웨이 경로가 있는지 확인합니다.
보안 그룹의 아웃바운드를 지웠나요?아웃바운드에 HTTPS 443(또는 모든 트래픽)이 있어야 합니다.
만든 지 5분이 안 됐나요?Systems Manager 콘솔의 "Fleet Manager"에 인스턴스가 나타날 때까지 기다립니다.
