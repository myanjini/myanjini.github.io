인스턴스 시작 과정 보기

EC2 콘솔의 "인스턴스 시작" 화면은 위에서 아래로 한 페이지에 모든 설정이 나옵니다. 실습 전에 각 칸에 무엇을 넣을지, 왜 그 값인지 정리합니다.

화면의 칸이번 실습 값이유
이름 및 태그이름 book-api-server, 태그 추가 Owner = 내 식별자R7. "추가 태그 추가"에서 Owner를 넣고 리소스 유형에 인스턴스와 볼륨을 모두 고릅니다.
애플리케이션 및 OS 이미지(AMI)Amazon Linux 2023 AMI, 아키텍처 64비트(x86)SSM 에이전트와 AWS CLI가 들어 있고, IMDSv2만 허용합니다.
인스턴스 유형t3.micro(또는 기관 안내)소형, x86_64
키 페어(로그인)키 페어 없이 계속 진행R3. Session Manager로만 접속합니다.
네트워크 설정: VPCbook-api-vpc기본 VPC가 아닌지 확인합니다.
네트워크 설정: 서브넷book-api-subnet-public1-ap-northeast-2a퍼블릭 서브넷, 가용 영역 a
퍼블릭 IP 자동 할당활성화7일차에는 내 PC에서 퍼블릭 IP로 접속하고, NAT 없이 서버가 밖으로 나가야 합니다.
방화벽(보안 그룹)기존 보안 그룹 선택: book-api-sg새 보안 그룹을 만들게 두면 22번을 0.0.0.0/0에 여는 규칙이 기본으로 들어갑니다.
스토리지8GiB gp3(기본값)Docker 이미지 몇 개에 충분합니다.

고급 세부 정보: 메타데이터 버전V2만(토큰 필요)Amazon Linux 2023의 기본값입니다. 바뀌어 있지 않은지만 확인합니다.
고급 세부 정보: 사용자 데이터비워 둠설치 과정을 직접 해 보기 위해서입니다.

자주 하는 실수

(1) 네트워크 설정의 "편집"을 누르지 않아 기본 VPC에 만드는 것, (2) 보안 그룹을 "보안 그룹 생성"으로 둔 채 넘어가 22번이 열리는 것, (3) IAM 인스턴스 프로파일을 고르지 않아 Session Manager에 연결되지 않는 것이 가장 흔합니다. "인스턴스 시작"을 누르기 전에 오른쪽 요약 화면에서 세 가지를 확인합니다. IAM 역할은 인스턴스를 만든 뒤에도 "작업, 보안, IAM 역할 수정"으로 붙일 수 있습니다.

Session Manager가 연결되는 조건

Session Manager는 서버 안의 SSM 에이전트가 AWS Systems Manager 서비스에 먼저 연결을 맺는 방식입니다. 그래서 인바운드 포트는 필요 없지만, 아래 조건이 모두 맞아야 합니다.
