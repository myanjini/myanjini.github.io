서버에 Docker 설치하기

이 파트의 학습 목표EC2에 Docker를 설치하고 도서 API 컨테이너를 실행할 수 있습니다.

S8에서는 Docker Desktop을 설치 프로그램으로 깔았습니다. 서버에는 화면이 없으므로 명령으로 패키지를 설치하고, 서버가 켜질 때 Docker가 자동으로 시작되게 설정합니다. 실습 전에 각 명령의 뜻을 정리합니다.

패키지 설치: dnf

Amazon Linux 2023은 dnf라는 패키지 관리자로 프로그램을 설치합니다. 내 PC의 pip install이 Python 패키지를 PyPI에서 받아 설치하듯, dnf install은 운영체제용 프로그램을 Amazon Linux 저장소에서 받아 설치합니다. 운영체제 전체에 설치하므로 관리자 권한이 필요해 앞에 sudo를 붙입니다.

설치 명령
sudo dnf install -y docker git
sudo systemctl enable --now docker
sudo usermod -aG docker ssm-user
명령뜻
sudo dnf install -y docker gitDocker 엔진과 Git을 설치합니다. -y는 "설치할까요?" 질문에 미리 예라고 답하는 옵션입니다.
sudo systemctl enable --now dockersystemctl은 서버의 백그라운드 프로그램(서비스)을 관리합니다. enable은 부팅할 때 자동 시작, --now는 지금 바로 시작입니다.
sudo usermod -aG docker ssm-userssm-user를 docker 그룹에 추가합니다. 이 그룹에 속한 사용자는 sudo 없이 docker 명령을 쓸 수 있습니다. 그룹 변경은 새로 접속해야 적용됩니다.

docker 그룹은 관리자와 같습니다

docker 그룹에 속한 사용자는 컨테이너를 통해 서버의 모든 파일에 접근할 수 있어 사실상 관리자 권한을 가집니다. 서버에 접속할 수 있는 사람이 이미 sudo를 쓸 수 있는 실습 환경이라 편의를 위해 추가하지만, 여러 사람이 함께 쓰는 서버라면 신중하게 정합니다.

Compose와 Buildx 플러그인

Amazon Linux 저장소의 Docker 패키지에는 docker compose 명령을 제공하는 Compose 플러그인이 들어 있지 않습니다. 또 최신 Compose는 이미지를 만들 때 Buildx 플러그인(0.17 이상)을 요구합니다. 그래서 두 플러그인을 GitHub에 공개된 공식 배포 파일로 내려받아 Docker 플러그인 폴더에 넣습니다. 이 과정에서는 오늘 오후(S14)에 운영용 Compose 파일로 서버를 실행할 때 쓰므로 지금 함께 설치해 둡니다.

플러그인 설치 명령
sudo mkdir -p /usr/local/lib/docker/cli-plugins
sudo curl -fsSL -o /usr/local/lib/docker/cli-plugins/docker-compose \
  https://github.com/docker/compose/releases/latest/download/docker-compose-linux-x86_64
BUILDX_VERSION=v0.39.1
sudo curl -fsSL -o /usr/local/lib/docker/cli-plugins/docker-buildx \
  https://github.com/docker/buildx/releases/download/$BUILDX_VERSION/buildx-$BUILDX_VERSION.linux-amd64
sudo chmod +x /usr/local/lib/docker/cli-plugins/docker-compose /usr/local/lib/docker/cli-plugins/docker-buildx
부분뜻
/usr/local/lib/docker/cli-pluginsDocker가 추가 명령(플러그인)을 찾는 폴더입니다. 여기에 있는 docker-compose 파일이 docker compose 명령이 됩니다.
curl -fsSL -o 파일 주소주소의 파일을 내려받아 저장합니다. -f는 실패하면 오류로 끝내고, -L은 다른 주소로 넘겨주면 따라갑니다.
releases/latest/download/...Compose의 가장 최신 배포 파일 주소입니다.
BUILDX_VERSION=v0.39.1Buildx는 파일 이름에 버전이 들어가므로 버전을 정해 받습니다. 더 새 버전이 나왔다면 GitHub의 docker/buildx 배포 페이지에서 확인해 바꿔도 됩니다.
chmod +x파일에 실행 권한을 줍니다.
linux-x86_64, linux-amd64서버의 프로세서 종류(x86_64)용 파일입니다. Graviton 서버라면 aarch64, arm64를 받습니다.

소스는 Git으로 받습니다

서버에서 이미지를 만들려면 도서 API의 소스 코드가 서버에 있어야 합니다. S7에서 GitHub 저장소에 올려 두었으므로 git clone으로 받습니다. .env와 데이터베이스 파일은 Git에 올리지 않았으므로(.gitignore), 서버에서 따로 만듭니다. 이렇게 소스는 저장소에서, 비밀 값은 서버에서 따로 준비하는 것이 배포의 기본 모양입니다.

서버에서 빌드하는 것은 오늘 오전까지만

서버에서 소스를 받아 이미지를 만드는 방식은 단계를 눈으로 확인하기 좋지만, 서버마다 빌드 결과가 달라질 수 있고 서버에 Git 접근 권한이 필요합니다. 오늘 오후에는 이미지를 한 번만 만들어 ECR에 올리고, 서버는 그 이미지를 받아 실행만 하도록 바꿉니다(S14-P48).
